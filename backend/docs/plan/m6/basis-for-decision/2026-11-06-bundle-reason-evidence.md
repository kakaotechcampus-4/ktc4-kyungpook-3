# 묶음 응답의 재촉 이유·근거·요약을 읽을 때 계산하기

- 기록일: 2026-11-06
- 관련 마일스톤: M6 (이슈 #394)

## 문제와 제약

- #363 에서 메시지 화면을 실제 API 로 옮기며, BE 응답에 없던 시안 요소를 지웠다. #394 결정 댓글(FE, 2026-11-05)은 그중 재촉 이유 문장, 근거 링크, 목록 요약만 되살리기로 했고, "BE 가 묶음 응답에 값을 더하면 FE 가 되살린다"고 정했다.
- 근거: 최종 배포 전에 BE 작업을 늘리지 않는다.
- `Reminder`·`ReminderBundle` 에는 이유·근거를 담는 컬럼이 없다.
- 시안의 근거 링크는 Discord 채널 메시지 주소였지만, BE 는 DM 의 메시지 id 만 갖고 있고 채널 id 가 없다. 채팅 회의 발화에도 Discord id 가 없다.
- 허락 범위: FE 웹 API 응답 필드 추가. DB·마이그레이션·AI 계약·권한은 바꾸지 않는다.

## 실제 검토한 선택지

1. 계산 방식
   - A. 응답할 때 기존 데이터로 계산
   - B. 리마인드를 만들 때 이유·근거 컬럼에 저장(마이그레이션)
   - C. BE 는 날짜 같은 사실만 주고 문장은 FE 가 만듦
2. 근거 링크가 가리킬 것
   - A. 이유 문장이 말하는 마지막 소식(팀원 답장이면 대화, 태스크 변경이면 태스크 상세)을 앱 안에서 연다
   - B. 태스크가 나온 회의·채팅 발화(회의록)
   - C. 근거 링크를 빼고 문장만
3. 목록 요약: BE 가 `summary` 로 준다 / FE 의 지금 계산(`외 N건`)을 그대로 둔다
4. 단위: 이유·근거를 리마인드(태스크)마다 / 묶음당 한 문장
5. "진행 소식"의 범위: 스케줄러가 응답으로 보는 기준 그대로 / 태스크 변경만

## 선택과 이유

1. A. DB 를 건드리지 않아 #394 의 "BE 작업을 늘리지 않는다"와 맞는다. PM 이 만든 재촉은 답장이 와도 남으므로, 문장이 최신 소식을 따라가는 편이 맞다. 문장과 함께 구조화한 근거도 주므로 FE 가 날짜만 따로 쓸 수 있다(C 를 포함).
2. A. 문장이 말하는 마지막 소식과 링크가 같은 것을 가리킨다. Discord 주소는 채널 id 를 모으도록 DB 와 AI 봇을 바꿔야 해서 범위 밖이다. 응답은 `evidence: {kind: reply | task_change, at, message_id}` 이고, 링크는 FE 가 묶음의 `thread_id`, 리마인드의 `task_id` 로 만든다.
3. BE 가 준다. #394 결정 댓글과 맞고, 문구를 바꿀 때 BE 한 곳만 고친다.
4. 리마인드마다. 한 묶음에 PM 재촉과 스케줄러 재촉이 섞일 수 있고 근거도 태스크마다 다르다. 요약은 묶음에 하나다.
5. 스케줄러 기준 그대로(같은 대화의 팀원 메시지, 또는 사람이 바꾼 태스크 상태·마감). 화면의 "진행 소식 없음"과 실제 재촉·자동 막힘 판단이 갈리지 않게 하려는 것이다. 상수는 `scheduler.py` 의 것을 가져와 정의를 한곳에 둔다. 태스크 생성 이전 소식은 세지 않는다.

## 장단점과 감수한 제약

- 묶음을 응답할 때 리마인드마다 조회가 2~3번 늘어난다. 지금 규모에서는 문제가 없다고 봤다.
- 같은 대화에서 다른 태스크에 대해 한 답장도 소식으로 센다. 스케줄러의 대화 단위 응답 판정과 같은 한계다(#382 리뷰에서 지적됨).
- 근거 링크가 Discord 원문이 아니라 앱 안 화면이다. 시안과 다른 점으로 남는다.
- 처음 만들 때 마감이 있던 스케줄러 재촉에서 나중에 마감이 지워지면 마감 구절 없이 소식 문장만 나간다(합의 범위 밖의 경우라 구현에서 정함).

## 영향 범위와 재검토 조건

- 메시지 묶음 응답(`BundleResponse.summary`, `ReminderResponse.reason`·`evidence`). 팀원 화면은 지금처럼 묶음을 받지 않는다.
- Discord 채널·메시지 id 를 모으게 되면 근거 링크를 원문 주소로 바꿀지 다시 본다.
- 답장 대상 업무를 고르거나 연결하게 되면(#382 후속) "진행 소식"을 태스크 단위로 좁힐지 다시 본다.
- 묶음 수가 늘어 조회가 문제가 되면 대화 단위로 소식을 한 번에 가져오도록 바꾼다.
