# 메시지·알림 설정 저장과 재촉 자동 승인

- 기록일: 2026-11-04
- 관련 마일스톤: M6 (이슈 #339, 기반 PR #329)

## 문제와 제약

- 설정 화면의 알림 토글 3개, 재촉 규칙, PM 알림 방식, 재촉 자동 승인을 서버에 저장하고 스케줄러가 따르게 해야 한다. 지금은 화면 안에서만 바뀐다([FE 계약 §8](../../../../../frontend/docs/contracts/frontend-api-contract.md)).
- 허락 범위: 새 모델과 마이그레이션 1개, 새 경로 2개. 기존 경로·모델은 바꾸지 않는다.
- 스케줄러·승인 흐름은 #329 가 만든 것을 그대로 쓴다. 설정이 꺼진 상태의 동작은 기존과 같아야 한다.
- 로컬 DB 명령은 쓰지 않았다. 마이그레이션은 CI migrations 잡(PG)에서 검증했다.

## 실제 검토한 선택지

대화에서 비교한 선택지만 적는다.

1. 저장 위치
   - A. 새 테이블 `workspace_message_settings`(워크스페이스당 한 행, 행이 없으면 기본값)
   - B. `workspace` 테이블에 컬럼 추가
   - C. JSON 컬럼 하나
2. 자동 승인 시점
   - 가. 재촉을 만들 때 바로 승인
   - 나. 발송 시각이 되었을 때 승인
3. 설정을 바꾼 뒤 이미 만든 제안·묶음: 그대로 둔다 / 취소하거나 시각을 옮긴다
4. 자동 승인을 켜기 전에 이미 시각이 지난 승인 전 묶음: 보내지 않는다 / 켜는 즉시 보낸다
5. PM 이 직접 만든 재촉에도 자동 승인을 적용할지
6. PM 알림 방식·#회의록 요약 값: 읽는 코드를 지금 만들지 / 저장만 하고 둔다
7. 재촉 규칙 범위(며칠 전, 몇 시)

## 선택과 이유

1. 저장 위치는 A. 설정 항목이 늘 때 workspace 테이블을 건드리지 않고, 컬럼 타입·기본값·제약을 DB 에서 걸 수 있다. 행이 없으면 기본값을 돌려주고 처음 바꿀 때 행을 만든다.
2. 자동 승인은 나(발송 시각). 만들 때 승인하면 PM 이 알림을 받고 막을 시간이 없다. 발송 시각에 승인하면 그 전까지 PM 이 보내기 전 확인에서 막을 수 있고, 마지막 응답 재확인도 그대로 거친다. 알림 문구도 "발송 시각에 자동으로 나가요"로 바꿔 안내한다.
3. 설정을 바꿔도 이미 만든 제안은 그대로 둔다. 취소·이동은 PM 이 본 제안을 말없이 바꾸는 일이라 피한다. 새 규칙은 아직 제안되지 않은 것부터 적용한다.
4. 켜기 전에 시각이 지난 승인 전 묶음은 보내지 않는다. 켠 순간 밀린 재촉이 한꺼번에 나가는 것을 막으려고 `auto_approve_since` 를 두고, 그보다 이른 묶음은 자동 승인하지 않는다. 자동 승인은 켠 뒤 발송 시각이 오는 재촉만 대상이다.
5. PM 이 직접 만든 재촉에도 적용한다. 자동 승인은 묶음 단위로 승인 전 묶음을 승인하는 설정이고, PM 이 만든 재촉만 따로 가르면 한 묶음 안에서 동작이 갈린다.
6. PM 알림 방식과 #회의록 요약은 저장만 한다. 지금 PM 알림은 항상 웹(`Notification`)이고 PM DM 경로가 없다. 요약 게시를 봇이 읽는 경로도 없다. 읽는 쪽이 생길 때 그 값을 읽게 한다.
7. 재촉 규칙은 며칠 전 0~3, 시 0~23(한국 시간). 제안 창(발송 3일 전)은 고정이라 며칠 전의 최댓값을 3 으로 두고 `EARLIEST_DUE` 를 그에 맞췄다.

## 장단점과 감수한 제약

- 테이블이 하나 늘고 조회마다 행이 있는지 본다. 스케줄러는 한 틱 안에서 워크스페이스별로 한 번만 읽어 캐시한다.
- 설정을 바꿔도 이미 만든 제안은 그대로라서, 규칙을 바꾼 직후 한동안 옛 규칙의 제안이 남는다.
- 자동 승인은 AI 초안 검증을 거치지 않는다. AI 초안이 발송 시각 전에 오지 않으면 자동 승인 때 규칙 문구가 나간다.
- PM 알림 방식과 요약 값은 저장돼도 아직 동작이 달라지지 않는다. 화면에서 값을 고른 PM 이 다르게 기대할 수 있어, FE 계약에 저장만 한다고 적었다.
- 마이그레이션 `c4e9a71b3d52` 는 CI migrations 잡(PG)이 통과했고, 첫 행 동시 생성은 PG 두 커넥션 테스트로 확인했다.
