# 답장 담당자 변경 승인에서 PM 이 담당자를 고르게 한다

- 기록일: 2026-11-07
- 관련 마일스톤: M6(사용자가 정함). 요청은 이슈 #460, 화면은 #344

## 문제와 제약

답장 속 담당자를 팀원에서 찾지 못한 카드는 `assignee_member_id` 없이 `assignee_raw` 만 싣는다. 이 카드를 승인해도 담당자가 바뀌지 않고 답장 기록에는 `noted` 로 남는다. 사용자(hotpringles)는 PM 이 카드에서 담당자(미정 포함)를 골라 승인하게 정했다(#460).

제약은 다음과 같다.

- 회의 추출 카드와 수동 생성 카드의 담당자 override 는 지금처럼 400 이어야 한다.
- 지금 배포된 FE 는 이 값을 보내지 않으므로, BE 를 먼저 배포해도 화면이 깨지면 안 된다.
- `frontend/` 는 BE 가 고치지 않는다.

## 실제 검토한 선택지

담당자 override 를 받을 카드를 가리는 방법:

| 안 | 내용 | 판단 |
|---|---|---|
| A | `reply_change` 에 같은 `approval_id` 의 `field=assignee` 줄이 있는 카드만 허용 | 채택 |
| B | payload(`change_source`, `category`, `assignee_raw`)로 구분 | PM 이 `POST /approvals` 로 같은 값을 넣을 수 있고, 섞인 카드는 `category` 가 첫 줄 기준이라 달라진다. `assignee_raw` 는 회의 카드에도 있다 |
| C | `task_update` 전체 허용 | 계약이 넓어지고 회의 카드 동작이 바뀐다. 담당자 줄이 없는 답장 카드는 고른 이력이 답장 줄에 이어지지 않는다 |

사용자와 정한 나머지(2026-11-07 설계 확정, #460 댓글):

| 질문 | 선택지 | 결정 |
|---|---|---|
| 찾은 카드도 고칠 수 있나 | 허용 / 못 찾은 카드만 | 허용. 조건이 줄 존재 하나로 끝나고 잘못 찾힌 카드를 반려 없이 고칠 수 있다 |
| 지금 담당자와 같은 사람을 고르면 | `noted` / `approved` | `noted`. FE 계약의 `approved` 는 값이 실제로 바뀐 승인이다 |
| 고르지 않은 승인 | 200 `noted` 유지 / 400 | 유지. 막으면 FE 병합 전 지금 화면의 승인이 깨진다 |
| 못 찾은 카드의 충돌 | 기준값을 남겨 409 / 덮어씀 | 409. 다른 PM 의 변경이 말없이 사라지지 않는다 |
| FE 계약 문서 | 문구 전달 / BE 직접 수정 | 문구 전달. 파트 경계 규칙을 지킨다 |
| 회의 추출의 못 찾은 카드 | 이번 범위 밖 / 함께 처리 | 범위 밖. 이슈는 답장 카드만 요청했다 |

## 선택과 이유

허용 키 판정만 넓힌다(`approvals._normalize_overrides`, `replies.has_assignee_line`). 반영·이력·`_result` 는 기존 경로로 그대로 동작하므로 고치지 않는다. 고른 값은 `manual` 출처 이력으로 남고 답장 줄에 이어져 `approved` 가 된다.

못 찾은 줄에도 `_propose` 가 `base_values.assignee_member_id` 를 남긴다. `assignee_member_id` 값 자체는 싣지 않으므로, 고르지 않은 승인에서는 충돌 검사를 타지 않는다.

## 장단점과 감수한 제약

- 담당자 키가 있을 때 조회가 한 번 늘어난다. PM 처리 빈도가 낮아 `reply_change.approval_id` 인덱스를 추가하지 않았다.
- 이미 만들어진 못 찾은 카드는 기준값이 없어 충돌을 검사하지 않고 덮어쓴다.
- 충돌을 값 검증보다 먼저 본다. 그사이 담당자가 바뀐 카드에 탈퇴자를 고르면 먼저 409 가 나고, 다시 승인할 때 404 가 난다. 카드는 pending 으로 남는다.
- 못 찾은 카드에서 지금 담당자를 고르면 결과는 `noted` 이지만 `payload.task_overrides` 에 고른 값이 남는다. PM 이 실제로 고른 값이라 기록으로 둔다.
- 담당자가 없을 때 판단한 카드는 기준값이 null 이라, 그 뒤 배정되면 기준 null 로 409 가 난다. 실제 충돌이라 그대로 둔다.
- 섞인 카드에서 담당자 값이 틀리면 상태 변경도 함께 취소되고 pending 으로 남는다.

## 영향 범위와 재검토 조건

- API: `PATCH /approvals/{id}` 의 요청 모양은 그대로이고, 담당자 줄이 있는 답장 카드에서 받는 값만 넓어진다. 새 에러 코드, 모델, 마이그레이션, 권한, AI 계약 변경은 없다.
- 다시 볼 때:
  - FE 고르기 화면이 배포된 뒤, BE 도 고르기를 강제할지.
  - 회의 추출의 못 찾은 담당자 카드에도 고르기가 필요할 때.
