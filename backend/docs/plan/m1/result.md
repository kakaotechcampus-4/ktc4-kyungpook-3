## 2026-11-08 추가: 병합 전 가입 단계 응답 경합 해소

사용자가 PR 병합까지 요청해 남아 있던 프론트엔드 리뷰도 처리했다. `SignupCodeStep`의 기존 폼 제출·재발송 대기 상태에서 `busy`를 계산해 코드 확인, 재발송, 이메일 변경을 상호 배제한다. 재발송 중 폼 제출도 무시한다. 부모의 단계 상태나 새 요청 식별자는 추가하지 않았다.

- 지연된 확인·재발송·실패 후 복구 회귀 3개가 수정 전 실패하고 수정 후 통과했다.

## 2026-11-08 추가: 첫 가입 단계와 라우트 스켈레톤 정렬

전체 CI에서 백엔드·AI·프론트엔드 정적 검사는 통과했지만 브라우저 E2E가 297개 통과, 회원가입 스켈레톤 1개 실패였다. 가입은 이메일 인증부터 시작하는데 기존 스켈레톤은 이름·이메일·비밀번호 세 칸을 그렸다. 테스트의 문구만 실제 첫 단계로 바꿔도 1280px와 390px에서 제목이 약 109px 이동하는 실패가 남았다.

`SignupFormSkeleton`을 실제 첫 이메일 폼 한 칸으로 맞추고 대체 인증 버튼을 카카오 버튼 모양으로 정렬했다. 쓰이지 않는 비밀번호 설명 속성도 제거했다. 공통 문구의 좌표 이동을 1px 이하로 검사하는 기존 보장은 유지하고 모바일 폭을 추가했다.

- 수정 후 전체 라우트 스켈레톤 15개·카카오 가입 9개·로그인 스플래시 2개, Chromium 합계 26개 통과.
- 관련 유닛 87개, TypeScript·ESLint·Prettier·diff 검사 통과.
- 대기 중 병합된 #546 메시지 UI와의 조합은 앞서 타입 검사·관련 유닛 83개·실제 브라우저 여정 2개로 별도 검증했다. 이번 수정도 해당 최신 코드와 합쳐 CI를 다시 확인한다.
- 이 기록은 로컬 검증과 이전 CI 실패를 구분한다. 수정 커밋의 전체 CI가 성공하기 전에는 병합 완료로 판단하지 않는다.

## 2026-11-08 추가: 가입 상태와 별칭 모의 저장 규약 통합

대기 중 #553이 `develop`에 병합되어 저장 규약과 복원 E2E가 충돌했다. 가입 인증·카카오 상태와 별칭 후보가 각각 모의 저장 버전 17을 사용했고 공통 기반은 16이었다. 기존 구현은 현재 버전만 복원하고 다른 버전은 버리는 정책이므로, 새 마이그레이터를 만들지 않고 통합 버전을 18로 정했다. 이전 모의 캐시가 초기화되는 기존 동작을 유지하며 운영 DB에는 영향이 없다.

- 서로 다른 버전 17 저장본 두 종류를 거부하고, 현재 18에서 가입 코드·증명·카카오 신원·대기 상태와 별칭·승인 별칭 후보를 함께 저장·복원한다.
- 수정 전 가입 쪽 버전 17이 잘못 복원되는 실패 1건을 확인했다. 수정 후 관련 7파일 유닛 92개, 실제 Chromium 복원 4개·카카오 가입 9개가 통과했다.
- TypeScript·ESLint·Prettier·diff 검사와 독립 코드 리뷰를 통과했다. 실제 백엔드와 마이그레이션은 변경하지 않았다. 새 통합 커밋의 전체 CI를 다시 확인한다.
