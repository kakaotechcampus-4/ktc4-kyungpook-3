# 가입 이름 검증: 규칙과 적용 범위

- 기록일: 2026-11-06
- 관련 마일스톤: M1(인증)
- 관련 이슈: #435 (설계 확정 댓글 2026-11-06)

## 문제와 제약

- `SignupRequest.name` 은 `str` 뿐이라 빈 이름, 공백만 있는 이름, 줄바꿈이 든 이름이 그대로 저장됐다.
- 칸은 `String(100)` 인데 길이 검사가 없고, 짝 없는 서로게이트가 든 이름은 DB insert 에서 `UnicodeEncodeError` 가 났다(테스트로 확인).
- 가입 이름은 PM 의 `display_name` 으로 복사되어(`app/api/workspaces.py`) PM 소개 문구에 나간다. 빈 이름이면 문구가 깨지고, 줄바꿈이 있으면 DM 첫 줄 판별이 어긋난다(코드를 읽고 판단).
- FE 가입 폼은 앞뒤 공백을 지우고 빈 값만 막는다. 최대 길이 기준은 코드와 시안에 없다.
- 열린 PR #441 이 같은 `app/schemas/auth.py` 의 import·email 줄을 고친다.

## 실제 검토한 선택지

설계 초안과 사용자 확정(2026-11-06)에서 비교한 것이다.

| 결정 | 선택지 | 결과 |
|---|---|---|
| 구현 위치 | 스키마의 `validate_name` + `field_validator` / pydantic `Field`·`StringConstraints` / 라우터·서비스 검사 | 스키마 함수. 비밀번호 규칙과 구조·오류 모양이 같다. `Field` 는 제어문자를 막지 못하고 #441 의 변경 줄에 가까워지며, 라우터 검사는 다른 규칙과 위치가 달라진다 |
| 최대 길이 | 100자 / 더 짧은 제품 기준 | 100자. DB 칸, `display_name` 과 같다. 더 짧게 할 제품 기준이 없다 |
| 팀원 표시명 | 이번에 같이 / 후속 이슈로 분리 | 분리. 이슈 범위가 가입이고, 온보딩과 팀원 화면 동작에 영향을 준다 |
| 기존 빈 이름 계정 | 그대로 둠 / 데이터 마이그레이션 | 그대로 둠. 대체할 이름을 지어낼 근거가 없다 |

## 선택과 이유

- 앞뒤 공백은 `str.strip()` 으로 지워 저장한다. FE trim 과 맞추고, 전각 공백도 지운다.
- 지운 뒤 비었거나 모든 글자가 형식 문자(Cf: U+200B, U+FEFF 등)나 공백이면 거절한다. Python `strip` 이 이 글자들을 지우지 못하고 양 끝의 형식 문자에서 멈춰, `"​ ​"` 처럼 안쪽 공백이 남을 수 있기 때문이다(셀프 리뷰에서 발견).
- 안쪽에 제어문자(Cc), 줄·문단 구분자(Zl, Zp), 짝 없는 서로게이트(Cs)가 있으면 몰래 지우지 않고 거절한다. Cs 는 구현 중 테스트에서 DB 오류가 드러나 더했다.
- ZWJ 는 Cf 지만 다른 글자와 함께면 허용한다. 이모지 조합 이름을 막지 않으려는 것이다.
- 길이는 코드 포인트로 센다. FE 가 기본 길이(UTF-16)로 100자를 세면 FE 쪽이 더 엄격해, FE 를 통과한 값이 길이로 막히지 않는다.
- 규칙은 요청 스키마에만 붙인다. `UserResponse` 에 붙이면 기존 빈 이름 계정의 응답이 깨진다.

## 장단점과 감수한 제약

- 한글 채움 문자(U+3164 등)는 글자(Lo)로 분류돼 통과한다. 이번에 막지 않는다.
- 유니코드 정규화(NFC)는 하지 않는다.
- 안쪽에 탭이나 제어문자가 있는 이름은 FE 를 통과하고 BE 에서 400 이 될 수 있다. 드문 입력이라 폼 상단의 일반 오류 문구로 둔다.
- 기존 빈 이름 계정의 유무는 운영 DB 를 조회하지 않아 모른다.

## 영향 범위와 재검토 조건

- 코드: `app/schemas/auth.py`. 모델·마이그레이션 변경 없음.
- 계약: 경로·필드·오류 코드는 그대로다. 예전에 201 이던 입력 일부가 400 이 되고, 응답 이름은 앞뒤 공백이 지워진 값이다. 잘못된 이름과 이미 있는 이메일이 함께 오면 409 대신 400 이다.
- 재검토: 카카오 가입(#427)을 구현하면 외부에서 받은 이름에는 요청 스키마가 적용되지 않으므로, 서비스에서 `validate_name` 을 부를지와 실패 처리를 정한다. 제품 기준이 정해지면 `NAME_MAX_LENGTH` 와 테스트 경계를 바꾼다.
