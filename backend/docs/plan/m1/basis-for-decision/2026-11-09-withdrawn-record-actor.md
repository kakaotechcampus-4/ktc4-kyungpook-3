# #575 영구 탈퇴자의 익명 기록 주체

## 문제와 작업 근거

2026-11-09, [#575](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/575)의 확정 정책을 구현하기 위한 첫 준비 단위다. 다른 구성원이 남은 공동 기록은 보존하면서 탈퇴자의 이름·개인 연결을 지워야 한다. 이 기록은 계정 탈퇴 API나 개인정보 전체 정리가 완료됐다는 뜻이 아니다.

이 문서는 초기 선택의 근거를 보존한다. 이어서 구현한 계정 트랜잭션·정리 영수증·실패 대응의 선택은 [전체 정리 프로토콜 결정](2026-11-09-withdrawal-cleanup-protocol.md)에 있다.

기존 Member는 권한·프로필·작성자 참조를 함께 맡는다. User만 지우면 Member 프로필이 남고, Member를 물리 삭제하면 MessageThread의 CASCADE로 공동 대화가 사라진다. 기존 is_deleted는 명단 비활성화이며 이름·Discord ID를 이력용으로 남긴다.

## 검토한 두 선택지

- 개인정보를 지운 Member를 작성자 식별용으로 보존한다. 기존 기록의 FK와 응답 ID를 유지하고 활성 권한 경계에서 영구 탈퇴를 구별한다.
- RecordActor를 추가하고 기록용 Member FK 16개를 옮긴다. 프로필과 기록 주체를 분리할 수 있지만 조회·응답·마이그레이션의 변경 범위가 커진다.

첫 번째를 선택했다. 공동 기록의 기존 참조를 유지하면서 별도 영구 탈퇴 상태와 DB 제약으로 프로필 재연결을 막는 비용이 더 작다고 판단했다. 두 번째의 장점이 모든 이름·JSON 복사본 정리까지 해결하는 것은 아니다.

## 데이터 불변식과 권한 경계

[Member](../../../../app/models/models.py)의 withdrawn_at가 있으면 user_id·discord_user_id·notion_name은 NULL, display_name은 `탈퇴한 사용자`, role은 member, is_deleted는 true, deleted_at는 필수다. DB CHECK로 강제한다. 직접 별칭을 지우는 erase_profile은 계정 전체 탈퇴 작업이 아니며 라우터에 공개하지 않는다.

영구 탈퇴한 Member는 새로운 프로필 수정·초대·발송의 대상이 될 수 없다. 기존 user_id=NULL Discord 명단과도 구분한다. 재가입자는 새 User와 새 초대를 사용해야 하며, 그 전체 계정 처리 트랜잭션은 후속 단위다.

## 공동 메시지와 과거 계약

영구 탈퇴자의 대화는 PM 목록·상세·읽음에 남긴다. 본문·메시지 ID·작성자 참조를 보존하고 표시명은 익명 Member에서 읽는다. 새 웹 발송과 봇 발송 대상에서는 제외하고, 늦은 초안·DM 결과·답장 판단의 저장도 거절한다.

기존 is_deleted만 설정한 명단 비활성화의 PM 상세 200·unread 0·읽음 POST 404는 그대로 둔다. [기존 읽음 결정](../../m6/basis-for-decision/2026-11-07-message-unread-count.md)은 수정하지 않는다. 새 영구 탈퇴 상태의 읽음 처리는 이번 변경에서 추가한 동작이다.

과거 [재촉 이유의 이름 보존 결정](../../m6/basis-for-decision/2026-11-06-bundle-reason-evidence.md)은 계정 영구 탈퇴의 이름 삭제 정책과 다르다. 저장된 알림·예약 문구·AI 이름 캐시를 지우는 전체 흐름은 후속 정리 범위이며 이번 표시명 변경만으로 완료됐다고 하지 않는다.

## 마지막 PM과 화면 지원

[탈퇴 계획 서비스](../../../../app/services/account_withdrawal.py)는 모든 활성 소속을 읽어 보존·단독 공간 삭제·PM 이전 필요를 구분한다. 계정이 없는 활성 Discord 팀원도 인원에 포함한다. 마지막 PM 조건에서 다른 PM은 로그인 계정이 연결돼 있어야 한다.

계획 조회는 예약이나 권한 승인이 아니다. 실제 탈퇴 명령은 같은 조건을 잠금 안에서 다시 확인해야 한다. 그 원자적 명령은 이번 단위에서 구현하지 않는다. MemberResponse.has_login_account는 User ID를 노출하지 않고 FE가 PM 이전 대상을 판단하는 정보다.

## 검증과 감수한 제약

실제 실행 결과와 미검증 항목은 [M1 결과](../result.md)에 기록한다. 이 문서의 대안 비교는 현재 구현 선택이며 과거 팀 합의를 추정한 기록이 아니다. 계정·세션 삭제, 구조화된 식별 복사본 전체, 단독 공간 파일·AI 정리, 재가입 전 과정은 후속 단위에 남는다. 자유 본문 자동 익명화와 이미 게시된 외부 결과 회수도 구현 완료로 취급하지 않는다.
