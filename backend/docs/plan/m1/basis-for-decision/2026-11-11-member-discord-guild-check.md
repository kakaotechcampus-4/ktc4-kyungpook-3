# 팀원의 디스코드 계정은 연결한 서버의 멤버일 때만 붙인다

- 날짜: 2026-11-11
- 상태: 결정됨

## 배경

PM 은 `POST /members`·`PATCH /members/{id}` 로 팀원에 아무 `discord_user_id` 나 붙일 수 있었다. 서버는 같은 워크스페이스 안에서 겹치지 않는지만 봤다. 그래서 다른 워크스페이스가 남의 디스코드 계정을 팀원에 붙여 DM 답장을 가져갈 수 있었다.

## 검토한 선택지

계정이 그 팀의 것인지 확인하는 방법

- 연결한 서버의 멤버인지 Discord 에 물어본다: 이미 닉네임 별칭에 쓰는 `GET /guilds/{guild_id}/members/{user_id}` 를 앞당기면 된다 / 팀원 저장이 Discord 응답에 묶인다
- 본인이 디스코드로 로그인해 계정을 증명하게 한다: 가장 확실하다 / 로그인 계정이 없는 팀원(디스코드로만 녹음에 나오는 사람)을 붙일 수 없고 FE 흐름이 새로 필요하다
- 답장을 받는 쪽에서 워크스페이스를 가린다: 붙이는 일은 그대로 열려 있고 DM 은 계속 나간다

Discord 가 답하지 않을 때

- 저장을 막는다(실패 시 닫힘): 확인하지 않은 계정이 붙지 않는다 / Discord 장애 동안 계정을 붙일 수 없다
- 저장하고 나중에 확인한다: 장애에도 붙는다 / 확인 전까지 DM 이 나갈 수 있어 막으려던 일이 그대로 일어난다

## 결정

계정을 새로 붙일 때 연결한 서버의 멤버인지 Discord 에 물어보고, 확인되지 않으면 저장하지 않는다.

- 연결한 서버가 없으면 409 `INTEGRATION_NOT_CONNECTED`, 서버에 없는 계정(Discord 404 Unknown Member·Unknown User, 사용자 ID 꼴이 아니어서 400)이면 새 코드 409 `DISCORD_USER_NOT_IN_GUILD` 다
- 봇 토큰이 없거나 Discord 가 그 밖의 답을 주거나 답하지 않으면 502 `DISCORD_API_FAILED` 로 막는다. 서버를 찾지 못하는 404(Unknown Guild)와 403 은 봇 쪽 문제라 계정 탓으로 보지 않는다
- 연결 풀기(`null`)와 지금과 같은 값을 다시 보내는 PATCH 는 확인하지 않는다
- 같은 워크스페이스의 다른 팀원이 쓰는 계정은 Discord 를 부르기 전에 지금처럼 409 `DISCORD_USER_ALREADY_MAPPED` 로 막는다
- Discord 를 부르는 동안 DB 트랜잭션을 열지 않는다. 서버 ID 를 읽고 커밋한 뒤 부르고, 끝나면 PM 권한과 워크스페이스를 다시 잠그고 서버가 그대로인지 본다. 그 사이 연결이 끊기거나 다른 서버로 바뀌었으면 409 `INTEGRATION_NOT_CONNECTED` 이고, PATCH 대상 팀원이 지워졌으면 404 `MEMBER_NOT_FOUND` 다
- 닉네임 별칭은 이 확인에서 받은 서버 사용자 정보로 넣는다. Discord 를 두 번 부르지 않는다
- 봇이 DM 을 가져갈 때도 디스코드 서버를 연결하지 않은 워크스페이스의 DM 은 넘기지 않고 `failed`(`discord_not_linked`) 로 닫는다. 연결을 끊은 뒤 남은 DM 이 나가지 않게 하는 두 번째 막이다

## 남긴 것

- 이미 저장된 팀원의 계정은 다시 확인하지 않았고 데이터도 고치지 않았다
- FE 는 새 코드의 문구를 따로 두지 않았다

## 다시 볼 조건

- Discord 장애로 팀원 연결이 자주 막힌다는 말이 나오면 재시도나 나중 확인을 본다
- 본인 확인이 필요해지면 디스코드 로그인으로 증명하는 흐름을 본다
