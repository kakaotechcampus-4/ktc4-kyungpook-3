# 소켓 테스트의 DB 연결을 분리하고 인증 세션 종료를 확인한다

- 기록일: 2026-11-09
- 관련 마일스톤: M0 검증 기반. 계획이 비어 있어 이번 작업으로 완료를 판정하지 않는다.

## 문제와 제약

다중 탭 소켓 검사가 사용하는 메모리 SQLite의 `StaticPool`은 HTTP 쓰기와 인증 세션에 연결 하나를 나눠 준다. 인증 세션의 rollback이 다른 세션에서 flush한 실제 메시지를 없애는 반례를 재현했다. 별도로 PostgreSQL에서는 소켓 task 취소 후 남은 worker thread의 인증 조회와 픽스처의 `DROP TABLE`이 교착했다.

운영 권한 검사와 소켓 테스트의 본문·기대값·프레임 대기 제한을 보존해야 한다. 운영 코드에는 테스트의 `drop_all` 정리 단계가 없다.

## 실제 검토한 선택지

| 선택지 | 실제 확인 결과 |
|---|---|
| 소켓 검사에도 메모리 SQLite 공유 연결 유지 | 실제 다중 탭 종료와 미완료 메시지 유실을 재현 |
| 소켓 검사만 파일 SQLite의 독립 연결 사용 | 원래 다중 탭 검사 30회 통과, 미완료 메시지 보존 |
| 소켓 task가 끝나면 인증 세션 확인 없이 DB 정리 | 원본 develop과 첫 연결 분리 수정본 모두 PostgreSQL outbox 검사 정리에서 교착 재현 |
| 인증 세션이 닫힌 것을 관찰한 뒤 DB 정리 | 동일 PostgreSQL outbox 10회와 소켓·탈퇴 122개 통과 |

## 선택과 이유

다른 API의 메모리 SQLite 기본값과 PostgreSQL 구성을 유지하고 소켓 검사만 파일 DB로 바꾼다. 소켓 픽스처의 세션 factory를 context manager로 감싸고 `Condition`과 활성 세션 수를 사용한다. factory가 만든 실제 세션이 닫힌 뒤에만 수를 줄인다.

정리할 때 테스트 세션을 먼저 닫아 남은 잠금을 해제한다. 이후 활성 인증 세션이 0인지 확인하고 기존 DB 정리로 넘긴다. 고정 sleep이나 재시도 대신 실제 자원 종료를 관찰해 DB 삭제 순서를 보장한다.

## 장단점과 감수한 제약

인증 세션이 열려 있는 동안 테스트 DB를 지우지 않는다. 파일 생성과 세션 수 추적이 테스트 픽스처에 추가된다. 정리 대기는 20초 안에 끝나지 않으면 실패한다. 기존 프레임 대기 제한 20초는 변경하지 않는다.

이 관찰 장치는 소켓 검사에만 적용된다. 다른 코드에서 별도 세션 factory를 도입하면 해당 테스트의 자원 소유·정리 순서도 따로 확인해야 한다. Windows 로컬 검증은 `SIGALRM`만 대체했으므로 제출 코드 그대로의 Linux CI를 별도로 확인한다.
