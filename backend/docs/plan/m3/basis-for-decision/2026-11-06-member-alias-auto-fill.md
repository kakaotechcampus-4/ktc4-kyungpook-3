# 담당자 별칭 자동 채우기: 후보 검색·이름 별칭·닉네임 별칭

- 기록일: 2026-11-06
- 관련 마일스톤: M3(담당자 매칭·게이트)
- 관련 이슈: #459 BE PR ① (설계 확정 댓글 2026-11-06). 승인 때 별칭 저장(`assignee_type`)은 PR ②에서 한다.

## 문제와 제약

- 담당자는 별칭 표(`member_alias`)로만 찾는데, 별칭을 만드는 길이 PM 수동 등록 API 하나뿐이고 그 API를 부르는 화면이 없어 표가 사실상 비어 있었다. 이름으로 지목된 담당자 대부분이 못 찾음(`not_found`) → PM 보류(`hold`)였다.
- 찾기는 글자 완전 일치뿐이라 AI가 원문 그대로 보내는 "하은이가", "지민님"은 별칭이 있어도 못 찾았다. AI 채점 코드(`ai/extract/eval_golden_set.py` `_name_candidates`)는 "BE가 님·조사를 뗀 후보로 찾는다"고 가정하고 있었다.
- 별칭 출처 값(`source`)은 manual·discord_profile·learned 셋이었고, 칼럼은 `String(20)`에 체크 제약이 없다.
- 매칭에 쓴 별칭이 확인됨(`verified`)이어야 auto 가 가능하고, 확신도 0.5 미만이면 `hold`다(`matching.py` `decide_create_gate`).
- 모델 변경(`AliasSource` 값 추가)과 데이터 마이그레이션 1건은 사용자가 허락했다(2026-11-06). DB 표 구조와 API 경로·필드는 바꾸지 않는다.

## 선택과 이유

- 후보 규칙은 `matching.name_candidates` 한 곳이다. AI `_name_candidates`와 조사 목록·순서까지 같게 복제하고 (길이 내림차순, 글자) 로 정렬한다. `resolve_assignee`와 미매칭 판정(`resolved_texts`)이 같은 "처음 걸린 후보" 규칙을 쓴다. "하은"은 후보가 하은, 하 순서라 "하"로 잘못 가지 않는다.
- 자동 별칭 규칙은 `app/services/member_aliases.py`에 모았다. 라우터(`members.py`, `workspaces.py`)는 부르기만 한다.
  - 이름 별칭은 flush 하지 않고 `member.aliases`에 붙여 팀원과 함께 커밋한다. 같은 디스코드 계정 중복이 `_commit_member`의 409 처리 안에서 나도록 하기 위해서다.
  - 닉네임은 팀원 커밋 뒤 Integration 의 guild ID 를 읽고 `db.commit()`으로 트랜잭션을 닫은 다음 부른다. #270 처럼 외부 호출 동안 DB 연결을 잡지 않기 위해서다. 모든 실패는 경고 로그(토큰·주소 없이)로만 남긴다.
- 기존 팀원은 데이터 마이그레이션 `1032faab5855`(down_revision `b0d32ee4abcb`, #345 머지 뒤. 열린 PR #454 는 아직 `537911f267dc` 뒤라 머지 때 맞춰야 한다)가 채운다. 앱 코드가 나중에 바뀌어도 마이그레이션은 그대로여야 해서 규칙을 import 하지 않고 복제했고, 테스트가 앱 `name_alias_forms`와 같은지 비교한다. downgrade 는 `source=display_name` 행을 지운다.
- PR #463 리뷰 반영
  - 이름이 그대로인 PATCH 에서 디스코드 계정을 바꾸거나 풀면, 지운 닉네임과 겹쳐 건너뛰었던 이름 꼴만 다시 채운다. PM 이 지운 다른 이름 별칭은 되살리지 않는다(이슈 규칙 ⑧).
  - PM 이 자동 별칭(`display_name`·`discord_profile`)과 같은 글자를 `POST /members/{id}/aliases` 로 등록하면, 그 행을 요청 값(기본 manual, 확인됨)으로 올린다. 그래야 겹침 규칙이 다른 팀원의 자동 별칭을 막고, 이름을 바꿔도 지워지지 않는다.
  - Discord 를 기다리는 동안 다른 요청이 계정을 바꾸거나 팀원을 지웠으면 닉네임을 넣지 않는다.
  - 한 글자 별칭으로 찾으면 담당자는 채우되 확인 필요로 둔다(미매칭 판정도 해결로 보지 않음). 조사를 떼면 "하은" → "하"처럼 한 글자 후보가 생겨, 팀에 없는 사람이 김하에게 자동 배정될 수 있었다. "조사를 떼서 생긴 한 글자 후보만" 확인 필요로 두는 안, 한 글자 후보를 버리는 안(두 글자 이름 팀원을 조사 붙여 부르면 못 찾음), 그대로 두는 안과 비교해 규칙이 가장 짧은 이 안을 사용자가 골랐다. 두 글자 이름 팀원("준이가" → 이준)은 auto 대신 PM 검토로 간다.
  - 이름·디스코드 계정을 바꾸는 PATCH 는 팀원 행을 잠그고(`with_for_update`) 최신 값으로 다시 읽는다. 같은 팀원을 동시에 고치면 두 요청이 같은 별칭을 넣어 `uq_alias_per_member` 로 500 이 났다. PM·초대 검사가 잠그는 행보다 뒤에 잠가 교착을 피한다. SQLite 는 행 잠금을 무시해 테스트는 잠금 쿼리가 나가는지만 확인한다.
  - 별칭 등록 API 는 `source=display_name` 을 받지 않는다(400 `INVALID_REQUEST`). 서버만 쓰는 값이고, FE 계약의 source 목록(manual·discord_profile·learned)에는 원래 없다.
- "님" 꼴("동우님")은 별칭으로 넣지 않는다. 찾을 때 "님"을 떼므로 필요 없고, 봇 힌트도 `member_forms`가 따로 만든다.

## 장단점과 감수한 제약

- `discord_user_id`가 있는 `POST`·`PATCH /members`는 응답이 최대 3초 늦어질 수 있다.
- 자동 별칭끼리 겹치는 이름(김민수·이민수의 "민수")은 애매함이 되어 PM 보류로 간다. PM이 별칭을 정리해야 풀린다.
- 후보 규칙을 BE·AI 두 곳에 두므로 한쪽만 바꾸면 어긋난다. AI 에 바꿀 때 알려 달라고 요청한다.
- 이미 디스코드가 연결된 팀원은 다시 연결할 때까지 닉네임 별칭이 없다.
- 닉네임이 이름 꼴과 같으면(김동우의 닉네임 "동우") 같은 팀원이 같은 글자를 이미 가져 닉네임 행을 만들지 않는다. 그 뒤 이름을 바꾸면(김동우 → 김동후) `display_name` "동우"가 지워져, 디스코드가 연결돼 있어도 "동우"로 찾지 못한다. 한 팀원이 같은 글자를 두 행으로 가질 수 없어서(`uq_alias_per_member`) 감수했고, 디스코드를 다시 연결하면 복구된다(PR #463 리뷰).

## 영향 범위와 재검토 조건

- FE 계약: 경로·필드 변경 없음. `source`에 `display_name` 값 추가, `unresolved-aliases` 해결 판정 기준 변경, 디스코드 연결 응답 지연 가능성을 PR ② 뒤 `[BE→FE]` 이슈에 묶어 알린다.
- AI: `members/names`의 `aliases`가 늘어난다. 한글 닉네임이 힌트에 새로 들어가 힌트 토큰이 늘 수 있다.
- 재검토: 자동 별칭끼리의 애매함이 PM 보류를 크게 늘리면 겹침 규칙을, 3초 지연이 문제가 되면 조회 시점을 다시 본다. 기존 연결 팀원 닉네임 채우기는 따로 정한다.
