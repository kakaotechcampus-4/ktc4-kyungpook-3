# 테크스펙

Manager's Manager 의 기술 명세 요약이다. 각 쪽에는 결론과 근거 수치만 적고, 설계 이유는 [AI 로직](../design/ai/index.md)과 결정 기록으로 링크한다.

## 배경과 목표

| 구분 | 내용 |
|---|---|
| 누구 | 대학생 팀 프로젝트의 PM. 회의는 디스코드에서 하고 보드는 Notion 에 둔다 |
| 문제 | 회의 중에는 누가 무엇을 언제까지 맡았는지 받아 적지 못한다. 회의 뒤에는 기억에 기대어 보드를 고치고, 기존 할 일의 변경이 먼저 빠진다. 마감이 다가오면 재촉도 PM 몫이다 |
| 왜 디스코드 | 참가자별 오디오를 따로 받아서 화자 분리 모델 없이 첫 회의부터 발화마다 화자가 정해진다. 디스코드 밖 회의는 녹음 업로드로 받는다([트레이드오프 1](tradeoffs.md#1-입력-왜-디스코드인가)) |
| 목표 | 회의가 끝나면 사람이 옮겨 적지 않아도 할 일이 보드에 들어간다. 확실한 것만 자동으로 넣고, 틀릴 수 있는 것은 이유와 함께 PM 에게 묻는다. 마감 전 재촉과 답장 반영까지 잇는다 |
| 목표가 아닌 것 | 회의록 요약 도구, 실시간 자막. 하지 않기로 한 것은 [스펙 아웃](history.md#스펙-아웃-하지-않기로-한-것) |

## 한 페이지 요약

| 구분 | 한 줄 |
|---|---|
| 문제 | 회의에서 정한 할 일·담당·마감과 기존 할 일의 변경이 말로만 남고, PM 이 기억에 기대어 Notion 보드를 고친다. 회의 뒤 재촉도 PM 몫이다 |
| 해결 | 회의 음성·업로드·채팅에서 새 할 일과 기존 task 변경을 뽑아 근거(원문·화자·시각)를 붙이고, 조건을 모두 만족한 것만 자동 반영, 나머지는 PM 확인 뒤 Task·Notion 에 반영한다. 마감 전 재촉 DM 과 답장 판단까지 한다 |
| 구조 | AI 워커·봇(전사 → 다단계 판단 → 근거 검증) → Backend(FastAPI + PostgreSQL/pgvector: 매칭·게이트·승인·Notion outbox) → Frontend(React SPA·PWA). EC2 한 대에 세 파트를 올린다 |
| 핵심 장치 | 판단 경로(judge)에서는 값을 만든 모델과 다른 모델(Jev)이 근거를 검증하고, 전사 오인식 검사와 자동 생성 스위치까지 세 관문을 지나야 auto 다. 기본 경로는 legacy 추출이다(`MM_EXTRACT_PATH` 가 비면 legacy) |
