# 개인정보처리방침

> 2026-11-09 승인한 제품 정책을 반영한 게시 준비본입니다. `[확인 필요]` 항목과 게시 버전·시행일을 채운 뒤 서비스 화면에 반영합니다. [확정 내용과 게시 상태](README.md)를 함께 확인합니다.

- 제품 정책 확정일: 2026-11-09
- 기존 동의 API의 초안 식별값: 2026-11-08
- 공개 버전·시행일: 실제 서비스 게시 시 확정

현재 동의 API의 `2026-11-08`은 기존 초안 식별값입니다. 실제 게시 때 본문의 새 버전을 정하고 BE의 동의 버전과 FE의 표시 버전을 함께 갱신합니다. 기존 테스트 동의 기록은 이번 본문에 대한 동의로 간주하지 않습니다.

Manager's Manager(이하 "운영자")는 Manager's Manager(이하 "서비스")를 운영합니다. 현재 운영 범위는 팀원·멘토·심사위원 중심의 교육·평가용 시범 운영입니다. 이 준비본은 확정된 제품 정책과 현재 코드의 처리 범위를 설명합니다.

## 1. 처리 목적

| 목적 | 내용 |
|---|---|
| 회원 관리 | 가입, 로그인, 본인 확인, 비밀번호 재설정 |
| 회의 정리 | 회의 음성을 글로 옮기고, 할 일과 변경 사항을 찾아 회의록과 태스크 후보를 만듦 |
| 협업 기능 | 워크스페이스 팀원 관리, 담당자 연결, 리마인드 메시지, 알림 |
| 외부 연동 | 이용자가 연결한 Notion 에 태스크 반영, 디스코드 봇의 녹음과 메시지 |
| 안전한 운영 | 로그인 시도 제한, 오류 대응 |

## 2. 처리 항목

| 구분 | 항목 |
|---|---|
| 가입 | 이메일, 이름, 비밀번호(해시로 저장), 로그인 방식. 카카오 로그인은 카카오 계정 식별값과 프로필 이미지 주소 |
| 워크스페이스 | 팀원 표시 이름, 역할, 디스코드 사용자 ID, Notion 이름, 담당자 별칭 |
| 회의 | 회의 음성, 전사 문장과 화자·시각, 회의록, 찾아낸 할 일과 근거 문장 |
| 디스코드 채팅 | 워크스페이스에 연결한 채널의 메시지(할 일을 찾는 데 사용) |
| 메시지 | 리마인드 메시지와 답장 |
| 연동 | Notion·디스코드 연동 토큰 |
| 알림 | 브라우저 푸시 구독 정보(구독 주소와 암호화 키) |
| 자동 생성 | 로그인 세션, 로그인 시도 제한용 이메일·IP 정보(서버 메모리에 저장. 15분은 제한 판정에 쓰는 시간이며 최대 보관기간이 아님. 보관·파기 기준은 공개 전 확인 필요) |
| 탈퇴 정리 확인 | 이름·이메일을 포함하지 않는 요청 식별자, 요청 키의 해시, 파일·AI 정리 상태 |

## 3. 보유 기간과 파기

| 항목 | 보유 기간 |
|---|---|
| 계정·개인 연결 정보 | 탈퇴 접수 때 계정·모든 세션·푸시 구독·본인의 연동 식별자·팀원 프로필·별칭 삭제. 파일·AI 사본 정리는 별도 확인 |
| 회의 음성 | 성공 인계 뒤 원본·파생 음성 삭제. [PR #568](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/pull/568) 병합 완료. 외부 업체 사본은 5항 참조 |
| 처리하지 못한 디스코드 녹음 | 처리 포기 뒤 7일 보관 후 삭제. PR #568 병합 완료 |
| 처리하지 못한 업로드 음성 | 실패한 웹 업로드 원본 즉시 삭제. 화자 지정 대기는 최대 7일. 미인계 음성은 24시간 정리 대상. [PR #567](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/pull/567) 병합 완료 |
| 전사·회의록 | 별도 자동 만료기간 없이 회의나 워크스페이스가 삭제될 때까지 보관. 회의 삭제의 운영 활성화 조건은 아래 참조 |
| 공동 태스크·이력·메시지 | 다른 구성원이 남은 공간에서는 보존하고 탈퇴 작성자를 `탈퇴한 사용자`로 표시. 단독 활성 공간의 탈퇴 때는 공간 기록과 함께 삭제 |
| 로그인 세션 | 7일. 만료된 세션은 주기적으로 삭제 |
| Notion 에 반영된 태스크 | 이용자의 Notion 에 남으며 이용자가 관리 |

마지막 PM은 로그인 가능한 다른 팀원에게 PM 권한을 넘긴 뒤 탈퇴합니다. 다른 활성 팀원이 있는데 넘길 사람이 없으면 탈퇴를 거절합니다. 유일한 활성 멤버인 공간은 권한 이전 없이 탈퇴하고 공간의 회의·태스크·메시지도 함께 삭제합니다. 활성 Discord 전용 팀원도 단독 여부에 포함합니다.

계정 접근은 즉시 종료합니다. 파일·AI 정리가 남으면 `개인정보 정리 중`을 표시하고 실제 정리를 확인한 뒤 `탈퇴 완료`로 표시합니다. 정리 실패·활성 작업·소유 근거가 불명확한 과거 자료는 완료로 먼저 표시하지 않습니다. 취소 유예기간은 없고, 정리 대기 중에도 같은 이메일·카카오로 새 계정을 만들 수 있습니다. 이전 소속·PM 권한은 복구하지 않으며 새 초대가 필요합니다.

공동 기록 참조와 재시도를 위한 Member 식별자·정리 영수증·삭제 표식은 남습니다. 이름·이메일을 지우더라도 모든 잔여 식별자가 법적으로 익명정보라는 뜻은 아닙니다. 이 자료와 동의 기록·백업의 보관·파기 기준은 공개 전에 확인합니다. 공동 기록의 자유 본문·음성 전체를 자동 익명화하거나, 이미 Notion·Discord에 게시된 결과를 회수하는 기능은 이 로컬 정리 범위에 포함하지 않습니다. 다른 구성원이 사용하는 공동 연동도 계정 탈퇴만으로 일괄 철회하지 않습니다.

회의 삭제 기능이 활성화되면 전사·회의록·추출·근거를 삭제하고 이미 생성된 태스크는 유지합니다. 태스크에는 `원본 회의가 삭제되어 근거를 볼 수 없음`을 표시합니다. 여러 회의가 합쳐진 승인 대기 카드는 삭제한 회의의 기여만 제거하고 남은 회의 내용으로 재구성합니다. 현재 회의 삭제는 서버 설정의 기본값이 비활성입니다. 새 워커·과거 계보 대조·별도 테스트를 확인한 뒤 활성화하는 [운영 절차](../../deploy/README.md#회의-삭제-활성화-576)를 적용하며, 코드 병합만으로 운영에서 사용할 수 있다고 표시하지 않습니다.

## 4. 제3자 제공

서비스는 회의 정리와 이용자가 연결한 기능을 위해 5항의 외부 처리 경로로 정보를 전송합니다. 실제 처리 목적과 계약에 따라 제3자 제공·처리 위탁·국외 이전을 구분하고 필요한 고지와 동의를 적용합니다. 외부 업체 정책 링크는 상세 조건을 확인하기 위한 자료이며, 우리 서비스가 해야 하는 안내와 보호 조치를 대신하지 않습니다.

외부 호출이 발생하는 처리 시점에 네트워크 API로 정보를 전송합니다. 실제 업체별 국외 이전 국가·시기·방법·연락처·목적·보관 기간·거부 절차는 게시 전에 안내에 반영합니다. 외부 AI 전송을 원하지 않는 이용자는 회의 업로드·녹음 처리를 시작하지 않고 문의 이메일로 처리정지를 요청할 수 있습니다. 그 경우 해당 AI 회의 정리 기능은 제공할 수 없습니다. 이미 전송된 자료의 삭제 가능 범위는 업체 조건과 구분해 안내합니다. 서비스의 실제 요청 차단·처리정지 흐름은 공개 전 확인 대상입니다.

pyannoteAI는 처리 워커의 음성 사본을 처리 후 삭제한다고 설명합니다. DPA는 요청 입력·설정·참조와 메타데이터를 별도 항목으로 두며 계약 기간 및 계약 종료 후 18개월 보관을 설명합니다. 이를 음성 원본 보관기간과 혼동하거나 모든 정보가 48시간 안에 삭제된다고 안내하지 않습니다. 음성 포함 범위·백업 예외에 대한 미확인 사항은 기존 확인 작업에 남깁니다. 공식 문서는 고객 데이터의 모델 학습 미사용을 설명하며, 이용자가 별도 동의해 지원팀에 공유하는 예시는 검증·테스트에 이용될 수 있다고 설명합니다.

Elice의 일반 개인정보처리방침은 우리 ML API 입력의 보관 기간·처리 국가·학습 미사용을 보장하는 근거로 사용하지 않습니다. [#578](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/578)의 확인 결과를 실제 사용하는 엔드포인트별로 반영합니다. pyannoteAI EU 설정은 [#577의 완료 보고](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/577#issuecomment-6738493396)를 근거로 기록하며 이번 문서 작업에서 계정에 로그인해 재확인하지는 않았습니다.

Elice 장애 대응 GPU 전사 경로도 별도 처리 경로입니다. 운영 주체·처리 위치·보관·삭제 조건을 확인하고 사용 시 안내에 포함합니다. 우리 서버에서 파일을 지우는 것과 외부 업체·백업의 사본 삭제는 구분합니다.

## 6. 학습에 쓰지 않음

서비스에서 받은 회의 음성, 전사, 메시지는 인공지능 학습과 모델 개선에 쓰지 않습니다. 회의 정리를 위해서만 처리합니다.

이는 운영자의 활용 방침입니다. 외부 공급사의 학습 사용·보관 조건까지 확인됐다는 뜻은 아닙니다.

## 7. 회의 참석자의 개인정보

녹음하거나 올린 회의에는 가입하지 않은 참석자의 음성이 들어 있을 수 있습니다. 회의를 녹음하거나 올리는 이용자가 참석자에게 미리 알리고 필요한 동의를 받아야 합니다. 현재 디스코드 봇의 녹음 고지에는 녹음·전사와 외부 서비스 Elice로의 음성 전송 안내가 포함돼 있습니다. 웹 업로드 화면에도 외부 전송을 안내합니다. 고지 코드의 존재가 모든 참석자의 동의를 확보했다는 뜻은 아닙니다. 실제 녹음 시작·재입장·업로드 흐름에서 안내가 전달되는지는 운영 검증으로 확인합니다. 참석자도 아래 창구로 자신의 정보에 대한 요청을 할 수 있습니다.

## 8. 이용자의 권리

이용자는 `managersmanager.noreply@gmail.com`으로 개인정보 열람·정정·삭제·처리정지를 요청할 수 있습니다. 요청할 때 대상 계정, 워크스페이스나 회의, 원하는 조치를 알려 주세요. 비밀번호·인증번호는 보내지 마세요.

운영자는 필요한 범위에서 본인과 권한을 확인하고 관련 법령의 기한에 따라 처리 결과를 답변합니다. 공동 기록이나 외부 게시물 때문에 요청 범위 전체를 바로 처리할 수 없으면 사유와 가능한 조치를 안내합니다. 화면의 계정 탈퇴와 공동 기록 보존 범위는 3항을 따릅니다. 메일의 실제 수신·답변 흐름은 게시 전에 확인합니다.
