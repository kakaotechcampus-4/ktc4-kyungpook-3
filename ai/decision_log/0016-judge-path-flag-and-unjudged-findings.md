# 0016. 판단 파이프라인은 추출 단계의 추출기로 끼우고, 판단하지 못한 발화가 남으면 다시 돌린 뒤 인계한다

- 날짜: 2026-09-30
- 상태: 결정됨. 기본 경로는 아직 옛 추출기다. 서버에서 새 경로를 돌려 본 뒤 기본값을 바꾼다

## 배경

판단 파이프라인(`judge.pipeline.run`)이 모듈로만 있고 봇과 워커는 옛 추출기(`extract_tasks`)를 부른다. 이것을 회의 후처리에 이어야 했다. 조건은 넷이다.

- 후처리는 `recorder.process_session` 하나이고 봇 모드와 워커 모드가 같이 쓴다. 단계는 닫히거나 예외로 실패한다. 실패는 60초부터 두 배씩 미뤄 5회 뒤 포기하고 그때 BE 에 fail 을 보낸다(0013).
- 파이프라인은 실패를 두 모양으로 돌려준다. 회의 전체가 못 도는 실패는 예외, 발화 하나의 실패는 `failures` 목록이다. BE 가 꺼졌거나 서비스 토큰이 틀리면 모든 발화가 유사 검색에서 실패하는데, 그때도 예외가 아니라 항목 0개가 돌아온다.
- BE 는 회의 하나에 추출을 한 번만 받는다. 이미 done 인 회의에 다시 보내면 기존 추출을 돌려주고 새 본문은 버린다.
- 판단 실패는 대기로 남기고 재시도한다. 실패가 정상 후보 0건으로 저장되면 안 되고, 재실행으로 중복이 생기면 안 된다(#78 리뷰).

## 검토한 선택지

어디에 끼울지. 추출 단계의 추출기를 바꿔 끼우는 것, 전사와 추출 사이에 단계를 하나 더 두는 것, `on_session_saved` 훅에 붙이는 것을 비교했다. 단계를 더 두면 매니페스트 상태와 BE 의 `failed_stage` 가 늘고 복구 코드가 그만큼 갈린다. 훅은 워커 모드와 복구 경로에서 불리지 않는다. 추출기를 바꿔 끼우면 단계 구조, 재시도, 회의 잠금이 그대로라 두 모드가 같이 바뀐다.

경로를 무엇으로 고를지. 키가 있으면 자동으로 새 경로로 가는 것과 명시 플래그를 비교했다. 자동은 토큰 하나가 빠지면 말없이 옛 경로로 가고, 같은 회의에서 다른 모양의 결과가 BE 로 간다. 알아채기 어렵다. 명시 플래그로 했다.

발화 몇 개만 실패했을 때. 넷을 비교했다.

| 안 | 하는 일 | 버리거나 고른 이유 |
|---|---|---|
| 바로 인계 | 성공한 항목만 보내고 실패는 기록만 | 실패한 결정이 빠진 채 끝난다. BE 가 회의당 한 번만 받아서 나중에 넣을 수도 없다 |
| 끝까지 재시도 | 실패가 하나라도 있으면 5회까지 다시 돌리고 포기하면 BE fail | 발화 하나 때문에 회의 전체가 안 넘어간다 |
| 실패한 발화만 다시 | 전사의 partial 과 같은 규칙 | 비용이 가장 적다. `run()` 에 그런 진입점이 없고 실패 기록이 발화를 들고 있지 않아서 지금은 못 한다 |
| 다시 돌린 뒤 인계 | 인계를 미루고 파이프라인을 통째로 다시 돌린다. 상한에 닿으면 가장 나은 결과로 인계 | 골랐다. 남의 모듈을 안 바꾸고 된다 |

화자 표기. 1단계는 전사본의 `speaker` 를 그대로 LLM 에 보여 주는데 그 값은 디스코드 uid 다. uid 그대로 넘기는 것, 파이프라인에 이름 인자를 요청하고 기다리는 것, 내 쪽에서 전사본의 화자를 이름으로 바꿔 넣고 결과를 uid 로 되돌리는 것을 비교했다. BE 는 1인칭 담당자를 uid 로 찾으므로(`resolve_speaker`) BE 로 가는 값은 uid 여야 하고, LLM 은 "너가", "그분" 을 풀려면 이름이 필요하다. 셋째로 했다. uid 표기가 해소를 얼마나 망치는지는 실제 호출로 재지 않았다. 코드에서 읽은 예상이다.

새 항목의 확신도. `to_item` 은 `task_confidence` 를 보내지 않아서 BE 에서 새 항목이 전부 hold 가 된다. 인계에서 고정값을 넣는 것도 봤지만 값의 출처가 둘로 갈려서 하지 않았다. 파이프라인이 준 그대로 보낸다.

## 결정

- 경로. `MM_EXTRACT_PATH=legacy|judge`. `recorder.build_extractor` 한 곳에서 고른다. 모르는 값이면 봇과 워커가 시작할 때 멈춘다. `judge` 인데 설정(Terra·Luna 키와 주소, BE 주소·워크스페이스·서비스 토큰, 모듈)이 없으면 추출기를 만들지 않고 단계를 "판단 경로 설정 없음(이름들)" 으로 건너뛴다. 옛 경로로 넘어가지 않는다.
- 유사 검색. `capture.handoff.BeClient.similar_tasks` 가 `POST /workspaces/{id}/tasks/similar` 를 `X-Service-Token` 으로 부른다. 실패는 빈 목록이 아니라 예외다. 빈 목록은 "비슷한 task 없음" 이라 실패를 그렇게 돌려주면 있는 task 가 새 항목으로 또 만들어진다.
- 전부 실패. 항목이 하나도 없고 실패만 있으면 `JudgeAllFailed` 로 바꿔 단계 실패로 센다. 빈 추출을 등록하지 않는다.
- 발화 몇 개만 실패. 결과를 파일에 둔 채 `ExtractIncomplete` 로 단계 실패를 세고, 기존 백오프 뒤에 파이프라인을 다시 돌린다. 다시 돌린 결과는 실패가 앞의 것보다 많지 않을 때만 바꿔 끼운다. 1단계가 돌릴 때마다 발화를 다르게 묶을 수 있어서다. 상한에 닿거나 다음 실패가 포기가 되는 차례면 가장 나은 결과로 단계를 닫고 `extract_partial`, `extract_failures` 를 매니페스트에 남긴다. 재실행은 인계 전에만 하고 결과 파일을 통째로 바꾸므로 중복이 생기지 않는다.
- 인계. 매니페스트에 `items` 가 있으면 변환 없이 보낸다. 빈 문자열만 null 로 바꾼다(BE 가 빈 문자열을 "못 찾은 담당자" 로 계산한다). BE 가 저장한 수가 보낸 수보다 적으면 `be.dropped_items`, 끝내 판단하지 못한 발화가 있으면 `be.missing_findings` 를 남긴다.
- 화자. `judge_path.speaker_labels` 가 uid 를 이름으로 바꾼다. 같은 이름이 또 나오면 "이름(2)" 로 갈라 되돌릴 수 있게 한다. 되돌릴 수 없는 화자는 비워서 BE 가 PM 확인으로 보내게 한다.

기본값과 근거.

| 환경 변수 | 기본값 | 근거 |
|---|---|---|
| `MM_EXTRACT_PATH` | `legacy` | 새 경로를 실제 LLM 과 BE 로 끝까지 돌려 본 적이 없다. 켜기 전에는 지금 동작이 한 줄도 안 바뀐다 |
| `MM_EXTRACT_RETRY_MAX` | 2 | 60초, 120초 뒤에 다시 돈다. 전사의 partial 상한(3)보다 작게 둔 이유는 전사는 실패한 구간만 다시 보내지만 이쪽은 회의 전체의 LLM 호출이 다시 나가기 때문이다. 포기 상한(5)보다 작아서 전부 실패가 한두 번 섞여도 부분 결과가 인계된다. 실패율을 재고 정한 값이 아니다 |

비용. 다시 돌릴 때마다 LLM 호출이 회의 하나 분량(1 + 발화 수 + 의미 있는 발화 수)만큼 더 나간다. 실패가 난 회의만 최대 3배다. Terra·Luna 의 호출 단가와 회의 하나의 호출 시간은 아직 재지 않았다.

## 다시 볼 조건

- 파이프라인에 실패한 발화만 다시 돌리는 진입점이 생기면 통째 재실행을 그쪽으로 바꾼다
- `run()` 이 화자 이름을 받게 되면 이름으로 바꿔 넣고 되돌리는 코드를 걷어낸다
- BE 가 추출의 교체나 추가 등록을 받게 되면 "인계 전에 재시도를 끝낸다" 는 전제가 풀린다
- 서버에서 새 경로를 돌려 실패율, 비용, 시간을 잰 뒤 기본값과 재시도 상한을 다시 정한다
- 옛 추출기를 지우면 플래그도 지운다
