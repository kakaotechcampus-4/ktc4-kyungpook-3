# decision_log/

구현 방향을 정할 때 근거와 트레이드오프를 남겨두는 곳입니다. 코드/커밋 메시지에는 "무엇을 했는지"만 남고
"왜 그렇게 했는지"는 금방 사라지므로, 나중에 같은 논쟁을 반복하지 않기 위해 여기 적습니다.

## 언제 새 파일을 만드나

- 여러 선택지 중 하나를 골랐고, 그 선택이 나중에 "왜 이렇게 했지?"라고 물을 만한 것일 때
- 특히 비용/시간/정확도 트레이드오프처럼 정답이 없고 팀 합의가 필요한 결정일 때

사소한 리팩터링이나 버그 픽스는 여기 안 남깁니다(git log 로 충분).

## 파일명

`NNNN-짧은-제목.md` (예: `0001-stt-model-vs-preprocessing.md`). 번호는 그냥 순서, 어겨도 상관없음.

## 템플릿

```markdown
# NNNN. 제목

- 날짜:
- 상태: 검토중 | 결정됨 | 보류 | 번복됨(→ 번복한 파일 링크)

## 배경
왜 이 결정이 필요했는지, 어떤 제약(비용/시간/인원) 안에서 나온 건지.

## 검토한 선택지
- 선택지 A: 장점 / 단점
- 선택지 B: 장점 / 단점

## 결정
무엇을 선택했는지, 근거는 무엇인지.

## 다시 볼 조건
어떤 상황이 되면 이 결정을 재검토해야 하는지 (예: "large 모델이 실제로 더 빠르게 나오면").
```
