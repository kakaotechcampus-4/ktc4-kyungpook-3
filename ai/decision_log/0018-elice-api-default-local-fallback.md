# 0018. 운영 전사는 Elice API 를 기본으로 하고, 로컬은 장애 때 쓴다

- 날짜: 2026-10-07 (측정 2026-10-06, 리뷰 미팅 2026-10-06)
- 상태: 결정됨. [0008](0008-batch-transcription-by-speaker-chunks.md) 이 t3.medium 측정 뒤로 미룬 운영 기본 백엔드를 정한다. 0008 의 다시 볼 조건("t3.medium 에서 로컬 turbo 가 1분 오디오당 30초를 넘거나 4GiB 에 안 들어가면 Elice 를 기본으로 한다")이 이번 측정에서 걸렸다

## 배경

목표는 60분 회의를 회의가 끝나고 10분 안에 전사하는 것이다(기획안의 "회의 종료 뒤 초안 10분 이내", 10/6 리뷰 미팅). 0008 은 전사를 회의가 끝난 뒤 화자별 묶음으로 하기로 했고, API 와 로컬 중 무엇을 운영 기본으로 둘지는 서버 실측 뒤로 미뤘다.

같은 서버(t3.medium, 2 vCPU, 메모리 3.74GiB, BE·DB·봇 운영 중)에서 로컬과 Elice 를 같은 시나리오로 쟀다(#154, 결과 문서 `stt/eval/results/2026-10-06-server-capacity/README.md`).

| | 로컬 large-v3-turbo | 로컬 small | Elice API(회의당 동시 호출 6) |
|---|---|---|---|
| 62.42분 합성 회의 전사 | 84.93분 | 안 쟀다 | 65.07초 |
| 10분 합성 회의 전사 | 14.0 ~ 14.2분 | 안 쟀다 | 8.65 ~ 8.99초 |
| 회의 1분당 전사 | 81.63초(60분 합성) | 24.9 ~ 25.7초(6인 정렬본) | 약 1초 |
| 6인 정렬본 CER | 5.33%, 4.99% | 8.20%, 8.68% | 6.52%, 4.86% |
| 9/29 실녹음 CER | 21.9% | 32.1% | 21.2% |
| 추출에서 놓친 할 일(6인 6번 합 / 9/29 평균) | 4 / 2.67 | 7 / 3.67 | 3 / 1.67 |
| 전사 프로세스 메모리 | PSS 최대 2,305MiB. 서버에 하나만 들어간다 | PSS 791MiB(2.6분 회의) | 120 ~ 490MiB |
| 회의가 겹칠 때 | 워커 2개는 스왑 없이 안 들어가 18초에 멈춤 장치가 껐다 | 안 쟀다 | 회의 5개를 한꺼번에 넣어 9.58초에 모두 끝, 실패 0 |
| 비용 | 하루 6.38 전사시간까지 추가 요금 없음(계산값) | 같음 | 회의 1시간당 162 ~ 338원, 호출마다 최소 1분 과금이면 438 ~ 1,030원(옛 단가로 센 계산값) |

로컬 turbo 로 10분 안에 전사가 끝나는 회의는 7.35분짜리까지다(10분 ÷ 회의 길이 RTF 1.36, 계산값). 회의 1분당 81.63초는 0008 의 30초를 2.7배 넘는다.

## 검토한 선택지

- 로컬 turbo 를 기본으로: 호출 비용이 없고 외부 장애를 타지 않는다. 60분 회의에 85분이 걸려 목표를 못 맞추고, 서버에 프로세스가 하나만 들어가 회의가 겹치면 줄을 선다(두 번째 회의는 약 163분 뒤, 계산값)
- 로컬 small 을 기본으로: 회의 1분당 25초로 0008 의 30초 안이다. 60분 회의면 전사만 약 25분이라 10분 목표는 못 맞추고, CER 이 5% 기준을 넘고 추출에서 놓친 할 일이 turbo 보다 많았다
- 서버를 키우거나 전사 서버를 따로 두기: 이번 측정에 비교할 값이 없고 서버 비용이 는다. 재지 않았다
- Elice API 를 기본으로: 목표를 맞추는 것은 이것뿐이다. 회의 하나 안의 호출을 6개씩 동시에 보내고(6인 정렬본 호출 1·3·6개에 7.26·3.50·2.87초), 회의 여러 개를 같이 처리하고, 메모리를 적게 쓴다. CER 과 추출 결과는 로컬 turbo 와 비슷하거나 나았다. 대신 호출 비용이 들고, 공급자 장애를 탄다(옛 주소가 9/29 ~ 10/6 약 7일, 9/26 약 6시간 응답하지 않았다). 새 엔드포인트는 단어 시각을 주지 않아 한 화자의 턴 여러 개가 회의록 한 줄로 묶인다(10/2 2인 실녹음 7턴이 3줄)

## 결정

- 운영 기본 전사는 Elice API 로 한다(`MM_STT_BACKEND=elice`, 주소는 `ELICE_STT_BASE_URL`). 회의 하나 안의 동시 호출은 6(`stt/batch.py` 의 `default_workers`)
- 로컬 large-v3-turbo 는 Elice 장애 때 쓴다. 지금은 `MM_STT_BACKEND=local` 로 바꿔 봇을 다시 띄우는 수동 전환이다. 그동안 결과는 느리다(60분 회의 약 85분, 한 번에 한 회의)
- 운영 서버의 `.env` 를 바꾸는 일은 이 기록과 따로 한다
- 회의록이 묶음 단위로 남는 문제와 이름 오인식, 짧은 대답은 전사 품질 개선 이슈에서 다룬다

## 다시 볼 조건

- Elice 의 단가와 과금 단위가 확인되어 회의 1시간당 비용이 예산을 넘으면
- Elice 장애가 복구 재시도 상한(약 15분) 안에 풀리지 않는 일이 되풀이되면. 그때는 로컬로 자동 전환하는 장치를 만든다
- 옛 주소가 단어 시각을 다시 주거나, 새 엔드포인트의 문장 시각으로 묶음을 턴마다 되돌릴 수 있게 되면 묶음 설정(`pack_turns`)을 다시 정한다
- 서버 사양이 바뀌어 로컬 전사가 60분 회의를 10분 안에 끝내면
