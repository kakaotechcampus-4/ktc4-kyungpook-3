# 0001. STT 정확도 개선: 모델 크기 vs 전/후처리

- 날짜: 2026-09-08
- 상태: 검토중 (내일 5~6인 실녹음 결과로 확정 예정)

## 배경

Phase 0 통과 기준은 정독 WER 15% 이하, 처리 시간 1분당 30초 이내(`stt_diarization_validation_plan.md` 4장).
`small` 모델은 처리 시간(1분당 8.6초)에 여유가 크지만, WER 을 더 낮출 필요가 있을 때 두 방향이 있다:
모델 크기를 키우거나(`medium`/`large-v3`/`large-v3-turbo`), `small` 을 유지한 채 전/후처리로 보완하는 것.

## 검토한 선택지

- **모델 크기 확대(medium/large 계열)**
  - 장점: 코드 변경 없음, 즉시 적용 가능
  - 단점: 처리 시간이 선형으로 늘어남. 지금까지 측정(CPU int8, 1분 오디오당): small 8.6초 / medium 23.6초 (둘 다 PASS).
    large-v3 는 기준(30초) 초과 가능성이 큼. large-v3-turbo 는 medium 과 비슷할 것으로 예상(2026-09-08 기준 미측정,
    HF 캐시에 다운로드만 완료).
  - 특히 취약: 문장 구조 자체가 깨지는 경우(어순 오류, 통짜 오인식)에는 이쪽이 더 효과적일 가능성.

- **전/후처리 (small 유지)**
  - 장점: 처리 시간 비용 거의 없음. `initial_prompt` 에 팀원 이름·전문용어를 넣으면 고유명사 오인식을 직접 고침 →
    Phase 1(담당자 매칭·마감일 추출)로 오류가 전이되는 걸 줄임. VAD(`--vad`)로 침묵 구간 환각(반복 문장) 억제.
  - 단점: 프롬프트/정규화 규칙을 직접 만들고 튜닝하는 작업이 필요. 모델을 바꾸는 것보다 손이 많이 감.
  - 특히 잘 맞음: 오류가 주로 고유명사·숫자 오인식일 때.

## 결정

아직 미정. 2026-09-08 5~6인 실녹음 테스트에서 small/medium/large-v3/large-v3-turbo 를 모두 돌려
`eval_report.md` 로 비교한 뒤 결정한다 (`stt/transcribe.py --model small,medium,large-v3,large-v3-turbo`).

## 다시 볼 조건

- WER 오류가 주로 고유명사/숫자에 몰려 있으면 → 전/후처리 방향으로 확정, 모델은 small 유지
- WER 오류가 문장 구조 자체에 있고 large 계열에서 뚜렷이 개선되면서 처리 시간도 기준(30초/분) 이내면 → 모델 확대 방향으로 확정
- large-v3 가 기준을 초과하면 large-v3-turbo 만 재평가
