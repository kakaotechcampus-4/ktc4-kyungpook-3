# Whisper large-v3 LoRA 학습 결과 (2026-11-07)

AI Hub 회의 음성으로 large-v3 LoRA 를 두 번 학습했지만 우리 녹음에서 기본 모델을 이기지 못해 쓰지 않는다. 실제 디스코드 6인 회의 3개 중 2개가 나빠졌고 1개는 같았다.

## 팀 녹음 CER

정규화는 `stt.eval.eval.nospace` 와 같다. 값이 낮을수록 좋고, 비교 대상은 모두 g4dn.xlarge 의 vLLM 0.19.1 이다.

| 녹음 | 조건 | 기본 large-v3 | 1차 LoRA | 2차 LoRA |
|---|---|---|---|---|
| 2026-11-04 6인 회의 | 실제 디스코드, 대본 낭독 | 6.72% | 8.06% | 9.14% |
| 2026-10-14 6인 1회의 | 실제 디스코드, 대본 낭독 | 4.57% | 5.91% | 5.91% |
| 2026-10-14 6인 2회의 | 실제 디스코드, 대본 낭독 | 1.29% | 1.29% | 1.29% |
| 6인 정렬본 m01 | 대본 낭독, 시간축 합성 | 6.52% | 4.94% | 5.46% |
| 6인 정렬본 m02 | 대본 낭독, 시간축 합성 | 4.86% | 6.31% | 6.83% |
| 2인 | 실제 디스코드, 대본 낭독 | 10.51% | 10.17% | 9.83% |
| 1인 9/29 | 카페 소음, 대본 낭독 | 21.1% | 20.9% | 18.7% |

6인 회의 두 파일이 나빠지지 않고 평균 CER 이 0.5포인트 이상 낮아지면 쓰기로 미리 정했다. 1차와 2차 모두 m02 가 나빠져 이 기준을 넘지 못했다.

## 표기를 통일한 CER

숫자와 영어 표기 차이를 빼고 다시 채점했다. 고유어 수사와 단위는 숫자로, `에이피아이` 같은 한글 표기는 영어로, `%` 는 `퍼센트` 로 맞췄다. 2026-11-04 회의는 재지 않았다. 통일 규칙은 결과를 본 뒤 만들었으므로 판정에 쓰지 않고 참고만 한다.

| 녹음 | 기본 large-v3 | 1차 LoRA | 2차 LoRA |
|---|---|---|---|
| 6인 m01 | 5.48% | 4.05% | 4.05% |
| 6인 m02 | 4.22% | 4.61% | 4.74% |
| 10/14 1회의 | 5.35% | 6.68% | 6.68% |
| 10/14 2회의 | 1.29% | 1.29% | 1.29% |
| 2인 | 10.51% | 10.17% | 9.83% |
| 1인 9/29 | 19.54% | 19.54% | 17.49% |

9/29 를 뺀 글자 가중 합은 기본 5.28%, 1차와 2차 5.11% 다. 표기를 맞추면 차이가 줄지만 m02 와 10/14 1회의는 그대로 기본이 낫다.

## 나빠진 양상

2차 모델은 m02 에서 11곳이 나빠졌고, 2026-11-04 회의에서 오류가 25글자에서 34글자로 늘었다.

표기 습관이 바뀌었다. 1차는 `한 번에` 를 `1번에` 로, 2차는 반대로 `3명일` 을 `세명일` 로 적었다.

말을 잘못 듣거나 없는 말을 넣었다. `문서화` 가 `문서학` 이 되고, `행사` 가 `회에서` 로 바뀌고, `공유드릴게요` 앞에 같은 말이 한 번 더 붙었다. 사람 이름을 일반 낱말로 바꾸는 오류도 늘었다. 2차의 삽입 비율은 m01 이 1.9% 에서 3.9%, m02 가 1.2% 에서 5.0% 가 됐다.

영어 약어가 약해졌다. `API` 와 `RSS` 를 한글 소리로 풀어 적는 곳이 생겼다.

문장부호도 줄었다. m01 의 마침표가 21개에서 6개로 줄고 쉼표는 없어졌다. 학습 라벨에 쉼표가 거의 없어서다. CER 에는 잡히지 않지만 회의록을 읽는 데 영향을 준다.

## 학습 데이터

AI Hub 464 "주요 영역별 회의 음성인식 데이터" 의 TS2, TS3 를 썼다. 원문은 재배포하지 않고 레포에 넣지 않는다. 팀 녹음은 학습과 체크포인트 선택에 쓰지 않았다.

| 항목 | 1차 | 2차 |
|---|---|---|
| 학습 데이터 | TS2 637회의 | TS2 637회의, TS3 비대면 487회의 |
| 발화 | 113,950개 | 200,330개 |
| 오디오 | 274.4시간 | 484.5시간 |
| 숫자 라벨 | 표기 쪽 | 고유어 수사는 한글, 나머지는 표기 쪽 |
| 문장 끝 | 원문 그대로 | 끝말에 따라 마침표와 물음표 추가 |
| 최대 길이 | 3회독, 조기 종료 | 1.5회독 |
| 고른 체크포인트 | 6,230단계 | 6,260단계 |

두 학습 모두 `form` 의 표기 쪽을 기준으로 소문자 영어는 발음 쪽을 쓰고, 이름을 가린 발화와 알아듣지 못한 발화는 뺐다. 규칙은 [clean.py](clean.py) 에 있다. 검증은 TS2 33회의에서 뽑은 1,500발화로 고정했다.

| 지표 | 1차 | 2차 |
|---|---|---|
| 기본 모델 검증 CER | 8.77% | 8.74% |
| 최고 검증 CER | 4.41% | 4.33% |
| 실행 단계 | 8,900 | 9,390 |

검증 CER 이 절반으로 준 값은 대부분 AI Hub 표기에 맞춘 효과로 본다. 기본 모델이 필러를 빼고 숫자를 다르게 적는 차이가 함께 들어 있고, 팀 녹음에서는 같은 폭으로 줄지 않았다.

## 재현

학습은 g5.xlarge(A10G 24GB), 배치 32, 학습률 0.0001, r=32, alpha=64, `q_proj`·`v_proj` 이고 단계당 7.6초가 걸렸다. `$BUCKET` 은 개인 S3 버킷이다.

```bash
# 1차는 당시 TS2 만 읽은 코드로 돌렸다. 지금 코드에서는 --sets ts2 가 같은 범위다
python train.py $BUCKET --run run-1 --sets ts2 --batch 32 --epochs 3 --max-hours 30
python train.py $BUCKET --run run-2 --batch 32 --epochs 1.5 --max-hours 24
```

측정은 체크포인트를 합쳐 `vllm serve <합친 모델> --served-model-name openai/whisper-large-v3` 로 띄운 뒤 [GPU 서빙 측정](../2026-11-04-gpu-serving/README.md) 과 같은 명령으로 돌렸다. 1차 규칙의 라벨 코드는 지금 `clean.py` 와 다르다. 전사 원자료와 체크포인트는 레포 밖 `mm/eval-runs/2026-11-06-lora/`, `mm/eval-runs/2026-11-07-lora-run2/`, `mm/eval-runs/2026-11-07-lora-extra/`, `mm/eval-runs/2026-11-07-lora-e2e3/` 와 개인 S3 에 있다.
