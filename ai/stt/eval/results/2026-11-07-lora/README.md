# Whisper large-v3 LoRA 학습 결과 (2026-11-07)

AI Hub 회의 음성으로 large-v3 LoRA 를 두 번 학습했지만 우리 녹음에서 기본 모델을 이기지 못해 쓰지 않는다. 실제 디스코드 6인 회의 3개 중 2개가 나빠졌고 1개는 같았다.

## 나빠진 양상

2차 모델은 m02 에서 11곳이 나빠졌고, 2026-11-04 회의에서 오류가 25글자에서 34글자로 늘었다.

표기 습관이 바뀌었다. 1차는 `한 번에` 를 `1번에` 로, 2차는 반대로 `3명일` 을 `세명일` 로 적었다.

말을 잘못 듣거나 없는 말을 넣었다. `문서화` 가 `문서학` 이 되고, `행사` 가 `회에서` 로 바뀌고, `공유드릴게요` 앞에 같은 말이 한 번 더 붙었다. 사람 이름을 일반 낱말로 바꾸는 오류도 늘었다. 2차의 삽입 비율은 m01 이 1.9% 에서 3.9%, m02 가 1.2% 에서 5.0% 가 됐다.

영어 약어가 약해졌다. `API` 와 `RSS` 를 한글 소리로 풀어 적는 곳이 생겼다.

문장부호도 줄었다. m01 의 마침표가 21개에서 6개로 줄고 쉼표는 없어졌다. 학습 라벨에 쉼표가 거의 없어서다. CER 에는 잡히지 않지만 회의록을 읽는 데 영향을 준다.

## 장단점

좋은 점은 소음이 큰 녹음에서 일반 낱말을 더 잘 듣는 것이다. 9/29 CER 이 2.4포인트 낮아졌고 2인도 소폭 낮아졌다. 대본의 `퍼센트`, `메가바이트` 처럼 소리 나는 대로 적는 습관은 정답과 맞는 곳이 늘었다.

나쁜 점은 조용한 실제 회의에서 사람 이름, 약어, 일반 낱말을 틀리거나 없는 말을 넣는 것이다. 회의록의 담당자와 일정이 틀릴 수 있어 CER 차이보다 영향이 크다. 문장부호가 줄어 읽기도 나빠지고, Elice 에는 올릴 수 없어 쓰려면 GPU 서버가 상시로 필요하다.

기본 large-v3 는 조용한 회의에서 안정적이고 Elice 와 같은 결과를 내며 비용이 더 들지 않는다. 대신 소음 녹음의 오류는 그대로 남는다.

### 정답 문장 규칙

라벨의 `form` 은 `(발음)/(표기)` 쌍으로 두 가지 적기를 함께 준다. 공통 규칙은 다음과 같다.

| 라벨 | 처리 |
|---|---|
| `(오티티)/(OTT)` 처럼 표기에 숫자나 대문자가 있음 | 표기 쪽 |
| `(룰을)/(rule을)` 처럼 표기가 소문자 영어 | 발음 쪽 |
| `(...)/(idiom)`, `/(noise)` 같은 태그 | 태그를 지우고 말만 남김 |
| `(())` 알아듣지 못함, `@이름2` 처럼 가린 이름, `*` | 발화를 버림 |
| `(@스핀오프)` 불확실한 말 | 괄호와 `@` 만 지움 |
| `어~`, `음~` 같은 필러 | 지움 |

2차에서 두 가지를 바꿨다.

| 규칙 | 1차 | 2차 |
|---|---|---|
| `(한 번에)/(1번에)` 처럼 고유어 수사로 시작 | 표기 쪽, `1번에` | 발음 쪽, `한 번에` |
| 문장 끝 부호 | 라벨 그대로. 끝 부호가 있는 발화는 약 35%, 쉼표는 거의 없음 | `요`, `다` 로 끝나면 마침표, `까`, `나요`, `죠` 로 끝나면 물음표를 붙임 |

### 학습 방법

| 항목 | 값 |
|---|---|
| 기반 모델 | `openai/whisper-large-v3`, 한국어 전사, 타임스탬프 없음 |
| LoRA | 인코더와 디코더의 모든 어텐션 `q_proj`, `v_proj`. r=32, alpha=64, dropout 0.05. 학습 파라미터 15,728,640개 |
| 정밀도와 메모리 | 가중치 fp32, 연산 bf16 자동 혼합, gradient checkpointing |
| 최적화 | AdamW, 학습률 0.0001, weight decay 0, 기울기 노름 1.0 으로 자름 |
| 학습률 일정 | 처음 500단계 선형 증가, 이후 마지막 단계까지 선형 감소 |
| 배치 | 32발화, 누적 없음. 회독마다 섞음 |
| 평가 | 1/4 회독마다 검증 1,500발화를 탐욕 디코딩으로 전사해 CER 측정. 정규화는 `stt.eval.eval.nospace` 와 같음 |
| 멈춤과 선택 | 최고 CER 을 3번 연속 못 넘으면 멈춤. 평가마다 체크포인트를 저장하고 검증 CER 이 가장 낮은 것을 고름 |
| 장비 | g5.xlarge(A10G 24GB) 1대. GPU 메모리 최대 13.1GB, 단계당 약 7.6초 |

| 회차 | 시작점 | 회독 상한 | 단계 | 평가 간격 | 실제로 돈 단계 | 고른 체크포인트 | 검증 CER (기본 → 최고) | 시간 |
|---|---|---|---|---|---|---|---|---|
| 시범 | 기본 모델 | 400단계 | 400 | 400 | 400 | 없음 | 8.77% → 4.77% | 약 1시간 |
| 1차 | 기본 모델 | 3회독 | 10,680 | 890 | 8,900 (조기 종료) | 6,230 (1.75회독) | 8.77% → 4.41% | 약 19.7시간 |
| 2차 | 기본 모델 | 1.5회독 | 9,390 | 1,565 | 9,390 | 6,260 (1.0회독) | 8.74% → 4.33% | 약 20.5시간 |

2차는 1차 체크포인트에서 이어 가지 않고 기본 모델에서 다시 시작했다. 두 회차의 기본 CER 이 다른 것은 정답 문장 규칙이 바뀌어 검증 정답이 달라졌기 때문이다.

검증 CER 이 절반으로 준 값은 대부분 AI Hub 표기에 맞춘 효과로 본다. 기본 모델이 필러를 빼고 숫자를 다르게 적는 차이가 함께 들어 있고, 팀 녹음에서는 같은 폭으로 줄지 않았다.

### 측정 방법

고른 체크포인트를 기본 모델에 합쳐 fp16 으로 저장하고, g4dn.xlarge 에서 `vllm serve <합친 모델> --served-model-name openai/whisper-large-v3` 로 띄웠다. 운영과 같은 전사 경로(화자별 트랙, 말 구간 묶음)로 [GPU 서빙 측정](../2026-11-04-gpu-serving/README.md) 의 명령을 그대로 돌렸고, 기본 모델도 같은 서버에서 쟀다.
