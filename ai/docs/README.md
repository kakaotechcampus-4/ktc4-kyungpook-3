# docs/

push 할 때마다 "무엇을 했는지" 남기는 진행 로그입니다. `decision_log/`와 헷갈리기 쉬운데 역할이 다릅니다.

| | docs/ | decision_log/ |
|---|---|---|
| 담는 것 | 한 일의 기록 (무엇을/왜/결과) | 트레이드오프 결정의 근거 |
| 시점 | push 할 때마다 | 여러 선택지 중 하나를 고를 때만 |
| 형식 | 날짜 기반, 시간순으로 쌓임 | 번호 기반, 주제별로 하나씩 |

트레이드오프가 있던 결정이면 `docs/` 항목에 자세히 적지 말고 `decision_log/`에 따로 남긴 뒤 링크만 건다 —
같은 내용을 두 곳에 쓰지 않는다.

## 언제 새 파일을 만드나

push 할 때마다 하나. 아주 사소한 수정(오타, 포맷팅)까지 남길 필요는 없고, "코드가 실제로 바뀌었다" 싶으면 남긴다.

## 파일명

`YYYY-MM-DD-짧은-제목.md` (예: `2026-09-22-embedding-threshold.md`). 같은 날 여러 개면 뒤에 `-2`, `-3` 붙인다.

## 템플릿

```markdown
# 제목 (무엇을 했는지 한 줄)

- 날짜: YYYY-MM-DD
- 이슈: #NN
- PR: #NN
- 브랜치: feat/NN-xxx

## 한 일

- 개조식으로 핵심 변경사항 나열
- 코드 변경이면 파일/함수 단위로

## 왜

배경/동기를 짧게. 트레이드오프가 있는 결정이었으면 자세한 근거는 여기 쓰지 않고
`decision_log/NNNN-xxx.md` 링크로 대신한다.

## 결과

검증/테스트 결과. 수치 있으면 표로.

| 항목 | 값 |
|---|---|

## 다음

남은 일, 후속 이슈 링크.
```
