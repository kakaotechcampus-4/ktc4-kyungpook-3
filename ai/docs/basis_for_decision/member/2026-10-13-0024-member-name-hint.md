# 0024. 전사 이름 힌트는 PM 이 온보딩에서 정한 팀원 이름으로 만든다

- 날짜: 2026-10-13
- 상태: 결정됨. [0020](2026-10-09-0020-name-hint-prompt.md) 의 다시 볼 조건("BE 가 봇용 멤버 조회를 열면 BE 멤버 이름과 별칭을 쓴다")을 이어받는다. BE 봇용 조회 경로가 머지된 뒤에 머지한다

## 배경

#198 은 이름 힌트를 디스코드 서버 멤버의 표시 이름으로 만들었다. 측정은 사람이 정한 부르는 이름("환님, 환, 김환")으로 했는데, 운영 서버의 표시 이름은 `yujaehwan2261`, `동우`, `장원준` 이라 실제 프롬프트는 `동우님, 동우, 원준님, 원준, 장원준.` 이었다. 아이디 꼴은 빠지고, 두 글자 표시 이름은 성인지 알 수 없어 떼지 않는다(#175 멘토 리뷰). PM 은 온보딩에서 팀원의 실명을 정하는데(BE `Member.display_name`), 봇은 로그인 세션이 없어 그 명단을 읽지 못했다.

## 검토한 선택지

- 디스코드 표시 이름 그대로: 같은 날 측정에서 9/29 이름 자리 1/4. 명단에 없는 팀원의 이름은 고치지 못한다
- 실명을 먼저 놓기("김동우, 동우, 동우님"): 이름 자리는 3/4 로 같지만 CER 이 9/29 0.48pt, m01 1.06pt 더 높았다
- 디스코드 사용자 ID 로 BE 팀원과 짝지어 화자 이름까지 바꾸기: 이번에 필요한 것은 프롬프트에 넣을 이름 목록뿐이라 범위를 넘는다

## 결정

- 처리할 때(전사 전) 회의 워크스페이스의 팀원 이름과 별칭을 BE 봇용 조회(`GET /workspaces/{workspace_id}/members/names`)로 받아 매니페스트 `hint_members` 에 남긴다. 실패 구간 재전사도 같은 이름을 쓴다
- 꼴은 부르는 이름에 님, 부르는 이름, 실명, 한글 별칭 순이다(`stt.backend.member_forms`). 실명이라 두 글자도 첫 글자를 성으로 보고, 네 글자는 앞 두 글자를 성으로 본다. 15명까지
- 조회가 실패하거나 워크스페이스가 없거나 명단이 비면 디스코드 표시 이름(`hint_names`)으로 만든다. 힌트 때문에 전사를 멈추지 않는다. 프롬프트를 받지 않는 로컬 백엔드면 묻지 않는다
- 측정(결과 문서 `stt/eval/results/2026-10-13-member-hint/README.md`): 9/29 이름 자리 1/4 → 3/4, CER 21.07% → 21.38%, m01 4.94% → 5.33%, m02 같음

## 다시 볼 조건

- 존칭 없이 이름을 부르는 회의 녹음이 생기면 실명 꼴의 효과를 잰다
- 별칭이 PM 의 판단 기록에 쌓이면(지금은 PM 이 직접 만든 것뿐) 별칭이 이름 자리를 더 고치는지 잰다
- 팀원이 15명을 넘는 워크스페이스가 생기면 회의에 들어온 사람(디스코드 사용자 ID)부터 넣는다
