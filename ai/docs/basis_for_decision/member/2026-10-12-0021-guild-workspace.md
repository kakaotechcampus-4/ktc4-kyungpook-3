# 0021. 녹음 봇은 회의마다 디스코드 서버로 워크스페이스를 찾는다

- 날짜: 2026-10-12
- 상태: 결정됨. [0009](2026-09-19-0009-bot-hands-off-to-be-api.md) 의 남은 것("길드와 워크스페이스를 잇는 조회가 BE 에 없다. `BE_WORKSPACE_ID` 하나로 시작한다")을 이어받는다(#199, BE #180·#197)

## 배경

봇은 모든 회의를 `.env` 의 `BE_WORKSPACE_ID` 하나로 보냈다. 다른 팀이 웹 온보딩에서 디스코드 서버를 연결해도 봇은 그 연결을 보지 않았다. 지금은 `DISCORD_GUILD_ID` 로 슬래시 명령을 우리 서버에만 등록해 다른 서버에서는 녹음을 못 하고, 이 값을 비우면 다른 팀의 회의가 우리 워크스페이스로 들어간다.

BE 가 서버로 워크스페이스를 찾는 조회를 열었다(#197). 연결이 있으면 200, 없거나 해제됐으면 409 `INTEGRATION_NOT_CONNECTED`, 서비스 토큰이 틀리면 401 이다. 한 서버는 한 워크스페이스에만 연결된다. 운영 BE 에서 팀 서버를 조회하면 지금 `.env` 와 같은 워크스페이스가 나온다(10/10 확인).

봇은 서버에 있는데 연결이 없는 경우가 있다. 웹에서 연결을 해제하면 BE 는 연결 행만 지우고 봇은 서버에 남는다. 온보딩 밖의 초대 링크로 넣은 봇, 디스코드 승인 뒤 BE 콜백이 실패한 경우도 같다.

## 검토한 선택지

- 조회가 실패하거나 연결이 없으면 `.env` 값으로 대신 보내기: 연결 안 된 서버의 회의가 우리 워크스페이스로 들어가는 문제를 그대로 남긴다
- 값이 있으면 조회하지 않는 개발용 덮어쓰기: 운영 `.env` 에 남아 있으면 조용히 같은 문제가 된다
- 처리할 때마다 최신 연결로 다시 조회하기: BE 회의를 만든 뒤 워크스페이스가 바뀌면 추출 등록이 400 `WORKSPACE_MISMATCH` 로 막힌다
- 연결 없는 서버의 회의도 추출까지 하고 채널에만 올리기: 판단 경로의 유사 검색에 워크스페이스가 필요하고, 보낼 곳이 없을 때 LLM 비용을 쓴다
- 연결 없음을 `/recover` 나 그 서버의 다음 `/record` 때만 다시 묻기: 웹에서 연결해도 사람이 다시 돌려야 이어진다

## 결정

- `/record` 때 서버 ID 로 조회해 매니페스트 `workspace_id` 에 고정한다. 회의 생성, 발화 저장, 추출 등록, 유사 검색이 이 값을 쓴다. `BE_WORKSPACE_ID` 는 코드와 설정에서 지운다
- 비어 있을 때만 묻고, 한 번 정하면 바꾸지 않는다. 처리할 때 비어 있으면 다시 묻는다. 복구 루프가 1분마다 회의당 한 번 묻고, 웹에서 연결하면 다음 바퀴에 이어진다
- 연결이 없으면(409) `/record` 때 채널에 한 번 안내하고 BE 회의를 만들지 않는다. 봇 모드는 전사까지 해 회의록을 채널에 올린다. 워커 모드(운영)는 채널에 올릴 수 없어 전사해도 보일 곳이 없으므로 연결될 때까지 전사하지 않는다. 기다리는 회의는 `workspace_wait` 를 적고 "앞에 N건" 에서 뺀다
- 조회의 일시 실패(연결 실패, 5xx)는 발화 저장 단계의 실패로 세어 기존 재시도 규칙(1·2·4·8분, 5번째에 포기)을 따른다. 401 은 설정 문제라 BE 단계를 건너뛰고 결과 보고에 적는다
- 판단 추출기는 워크스페이스 없이 불리면 분명한 오류로 멈춘다. 유사 검색이 `/workspaces/None/...` 으로 가지 않게 한다

## 다시 볼 조건

- 한 서버를 여러 워크스페이스에 연결하게 되면(지금은 `uq_integration_discord_guild` 로 하나)
- 웹에서 연결을 해제할 때 봇도 서버에서 내보내게 되면 연결 없음 안내를 다시 본다
- 연결을 기다리는 회의가 오래 쌓이면 기다리는 기한을 둔다(지금은 기한이 없다)
- BE 에 봇용 멤버 조회가 생기면 이름 힌트도 같은 워크스페이스의 BE 이름으로 바꾼다
