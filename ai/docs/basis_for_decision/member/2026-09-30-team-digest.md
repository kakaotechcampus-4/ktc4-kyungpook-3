## 한 일

- `.github/workflows/team-digest.yml` 하나에 예약, 권한, 보고 코드를 모두 둔다. 코드는 `shell: python` 단계 안에 있다
  - 예약은 09:07, 09:27, 09:47, 21:07, 21:27, 21:47 KST. 수동 실행 버튼도 있다
  - 열린 PR 과 머지된 PR 을 GitHub API 로 읽는다. 작성자 아이디로 파트 태그를 붙이고 AI, BE, FE, main, 기타 순으로 정렬한다. 같은 파트 안에서는 최근 PR 이 위로 온다
  - PR 마다 코멘트 단 사람을 보인다. 봇(CodeRabbit)과 작성자는 뺀다
  - 다른 PR 위에 쌓은 PR 은 대상 브랜치 대신 그 브랜치의 PR 번호(`→ #104`)를 보인다
  - 2000자를 넘으면 PR 사이에서 나눠 여러 건으로 보낸다
  - 파트 명단(`PARTS`)도 이 파일에 있다

## 왜

레포 웹훅이 PR 과 이슈가 바뀔 때마다 알림을 보내지만 열린 PR 개수와 코멘트 없는 PR 은 한눈에 안 보였다. 그라운드룰 1(develop PR 마다 실질 코멘트)을 지키려면 이게 보여야 한다.

- 예약을 보고마다 세 번 건다. 1팀 `daily-pr-digest.yml` 은 20:47 예약이 9/18~9/22 예정 5번 중 1번만, 그것도 3시간 늦게 돌았다(1팀 Actions 실행 기록). 먼저 돈 실행이 `digest-sent-<날짜>-<am|pm>` artifact 를 남기고 뒤 실행은 그걸 보고 건너뛴다
- 실행 기록의 success 개수로 중복을 거르는 방법은 버렸다. 건너뛴 실행도 success 로 끝나서, 12시간 넘게 밀린 앞 보고 실행이 다음 보고를 막을 수 있다
- 오전과 오후는 실제로 돈 시각이 아니라 발동한 cron 으로 정한다. 시각으로 정하면 다음 날 아침까지 밀린 오후보고가 오전보고로 바뀐다. 다음 보고 시각이 지난 예약 실행은 보내지 않는다
- `concurrency` 로 실행이 차례로 돌게 했다. 밀린 예약이 한꺼번에 풀리면 둘이 동시에 "아직 안 보냄" 을 보고 두 번 보낼 수 있다. 대기하던 실행이 취소돼도 세 실행 모두 같은 보고라 빠지는 내용이 없다. 운영진 알림 워크플로가 concurrency 를 피하는 것은 실행마다 내용이 달라서다
- 파트 태그는 작성자 아이디로 정한다. 1팀은 제목 앞부분(ai, be, fe)으로 정하는데, 우리 제목은 `feat(judge):` 처럼 작업 종류로 시작해서 전부 기타가 된다. hwnv 는 BE PR 7건(#55, #59, #61, #74, #80, #82, #101)을 머지한 기록으로 BE 에 넣었다
- 코드를 `.github/scripts/` 로 빼는 방법과 워크플로 안에 넣는 방법을 비교했다. 빼면 테스트를 레포에 두고 로컬에서 미리보기가 쉽지만 파일이 셋이 된다. 이 레포에는 테스트를 돌릴 CI 도 없어서, 1팀처럼 워크플로 하나만 보면 되게 안에 넣고 테스트는 레포에 넣지 않았다
- 이벤트마다 한 줄 알림은 만들지 않았다. 레포 웹훅(issues, pull_request)이 이미 보낸다
