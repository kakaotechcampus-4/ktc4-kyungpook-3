## 왜

레포 웹훅의 이슈·PR 알림은 디스코드가 정한 모양으로 뜨고 PR 본문이 통째로 들어가서 채널의 다른 메시지를 가렸다. 깃헙 웹훅에도 디스코드에도 본문을 빼는 설정이 없어서 워크플로에서 직접 보낸다. develop PR 리뷰는 알림이 없었다(main PR 리뷰는 운영진 notify-discord 가 보낸다).

- 9/20 이후 main 이 아닌 쪽으로 간 PR 33개를 세었다. 작성자 아닌 사람의 리뷰 18건, 대화 탭 코멘트 5건, 작성자 답글 12건(리뷰 4, 코멘트 8), 봇 18건(리뷰 7, 코멘트 11)이었다. 앞의 23건만 보내서 하루 2줄쯤이다
- 대화 탭 코멘트도 넣었다. 리뷰 대신 대화 탭에 코멘트를 남긴 경우가 5건 있었고, 그라운드룰 1 의 실질 코멘트도 여기에 달린다
- 작성자 답글은 뺐다. 받은 리뷰에 대한 답이라 알림만 늘린다. 리뷰어가 스레드에 답글을 달면 깃헙은 그때마다 리뷰 제출로 쳐서 한 줄씩 뜬다(#105 가 8건, #74 가 6건)
- 보고 워크플로(team-digest.yml)와 파일을 나눴다. 보고는 예약으로 돌고 실행을 차례로 돌리지만(concurrency), 알림은 이벤트마다 바로 돌아야 하고 하나도 취소되면 안 된다. 운영진 알림 워크플로 주석도 같은 이유로 concurrency 를 쓰지 말라고 한다
- pull_request_review 와 issue_comment 이벤트는 브랜치 조건을 걸 수 없다. 운영진 파일처럼 job 의 if 에서 먼저 거르고 코드에서 한 번 더 거른다. 대화 탭 코멘트 이벤트에는 대상 브랜치가 없어서 PR 을 한 번 조회한다

## 남은 것

- 머지 뒤 채널에서 한 줄 알림이 뜨는 것을 보고 레포 웹훅을 끈다(레포 Settings → Webhooks → Active 해제). 디스코드 쪽 웹후크는 보고와 알림이 같이 쓰니 지우지 않는다
- 끄기 전까지는 긴 알림과 한 줄 알림이 같이 온다
