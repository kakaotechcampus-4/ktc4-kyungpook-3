# 0048. Whisper LoRA 모델을 쓰지 않고 기본 large-v3 를 유지한다

- 날짜: 2026-11-07
- 상태: 결정됨

## 배경

[0039](2026-11-04-0039-gpu-stt-server.md) 는 GPU 서버에서 LoRA 를 학습해 CER 이 뚜렷이 낮으면 전사 구성을 다시 보기로 했다. AI Hub 회의 음성으로 1차 274.4시간, 2차 484.5시간을 학습했다.

성공 기준은 측정 전에 정했다. 6인 회의 두 파일이 모두 나빠지지 않고 평균 CER 이 0.5포인트 이상 낮아야 한다. 체크포인트는 AI Hub 검증으로만 고르고 팀 녹음은 마지막 비교에만 썼다.

## 검토한 선택지

| 녹음 | 기본 large-v3 | 1차 LoRA | 2차 LoRA |
|---|---|---|---|
| 2026-11-04 6인 회의 | 6.72% | 8.06% | 9.14% |
| 2026-10-14 6인 1회의 | 4.57% | 5.91% | 5.91% |
| 2026-10-14 6인 2회의 | 1.29% | 1.29% | 1.29% |
| 6인 정렬본 m01 | 6.52% | 4.94% | 5.46% |
| 6인 정렬본 m02 | 4.86% | 6.31% | 6.83% |
| 2인 | 10.51% | 10.17% | 9.83% |
| 1인 9/29 카페 소음 | 21.1% | 20.9% | 18.7% |

- 2차 LoRA 를 쓴다: 카페 소음과 2인 녹음은 좋아진다. 대신 실제 6인 회의가 나빠지고 문장부호가 줄고 사람 이름과 약어 오류가 는다. Elice 에는 올릴 수 없어 GPU 서버를 상시로 켜야 한다.
- 소음이 큰 녹음에만 LoRA 를 쓴다: 표본이 1개라 근거가 없고, 전사기를 고르는 판정을 새로 만들어야 한다.
- 표기 규칙을 고쳐 짧게 더 학습한다: 약 $5 면 해 볼 수 있다. 하지만 표기를 통일해 채점해도 m02 와 10/14 1회의는 기본이 낫고, 이 오류는 표기 규칙으로 고칠 수 없다.
- 전체를 다시 학습한다: 약 $26 이 들고 같은 이유로 개선을 기대할 근거가 없다.
- 기본 large-v3 를 유지한다: 비용이 더 들지 않고 Elice 전사와 장애 대응 전사가 같은 결과를 낸다. 소음 녹음의 개선은 포기한다.

## 결정

기본 large-v3 를 유지한다. 주 전사기는 Elice 그대로이고, 장애 대응 서버도 [0047](2026-11-05-0047-gpu-stt-fallback-path.md) 의 기본 모델을 그대로 쓴다. 추가 학습은 하지 않는다.

학습 데이터의 변환본은 S3 에 남기고 원본 파트는 지웠다. 실제 비용은 $56.50 로 [0039](2026-11-04-0039-gpu-stt-server.md) 의 LoRA 예산 $60 안에 들었다.

측정 값과 나빠진 양상은 [학습 결과](../../../stt/eval/results/2026-11-07-lora/README.md) 에 있다.

## 다시 볼 조건

- 대본 없는 실제 회의 녹음과 정답이 쌓이면 다시 잰다. 지금 녹음은 모두 대본 낭독이라 자유 발화 성능을 재지 못했다.
- 소음이 큰 회의가 운영에서 자주 나오면 소음 데이터로 인코더만 학습하는 방법을 재 본다. 1인 9/29 의 개선은 표본 1개다.
- 주 전사기를 GPU 서버로 바꿀 규모가 되면 그때 같은 녹음으로 다시 비교한다.
