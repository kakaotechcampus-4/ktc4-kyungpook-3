# 0034. 리마인드는 태스크 하나씩 검토하고 나갈 때 한 통으로 묶으며, 봇 DM 은 최대 한 번만 보낸다

- 날짜: 2026-11-04
- 상태: 검토중

## 배경

PM 이 팀원에게 마감 리마인드를 보내고 답장을 받는 기능의 BE 가 없었다. FE 메시지 정책(D-174)은 검토를 태스크 하나 × 수신자 한 명 단위로 하고, 같은 수신자·발송 시각의 재촉은 한 통으로 합쳐 보내기로 정해 두었다. 상태는 예정·발송됨·취소됨·만료됨 넷이다. 봇 DM 발송, 스케줄러, 답장 판단 작업이 이 PR 의 테이블과 API 위에 붙으므로 저장 단위, DM 실패 표시, 봇이 결과를 보고하지 못했을 때의 처리를 여기서 정해야 했다.

## 검토한 선택지

저장 단위

- 리마인드(태스크 × 수신자)와 대화 메시지(실제로 나간 DM 한 통, 팀원 답장)를 나눈다: PM 은 태스크마다 고치고 취소한다. 발송 시각에 같은 수신자·시각의 리마인드를 메시지 한 통으로 묶는다. 봇은 메시지 단위로만 가져간다 / 테이블이 셋(대화, 리마인드, 메시지)
- 메시지 한 통에 태스크 여럿을 붙인다: 테이블이 적다 / 합친 메시지에서 태스크 하나만 빼거나 고치기 어렵다
- 승인 전 제안은 기존 승인 요청(`ApprovalRequest` 의 `reminder_dm`)에 둔다: 테이블을 덜 만든다 / 재촉 제안이 태스크 승인 화면에 섞여 D-174 의 "재촉 검토는 메시지 페이지에서만"과 어긋난다

DM 을 못 보낸 경우

- 상태 넷은 그대로 두고, 나간 메시지에 DM 결과(보냄, 못 보냄과 사유)를 따로 단다: 웹 대화에는 들어갔으니 발송됨이 맞다. FE 정책의 상태 값이 바뀌지 않는다
- 발송 실패 상태를 더한다: 상태 하나로 보인다 / D-174 상태 목록을 바꿔야 하고, 웹으로는 전달된 메시지가 실패로 보인다

봇이 가져간 뒤 결과를 보고하지 않을 때

- 최대 한 번: 10분 안에 보고가 없으면 다시 주지 않고 못 보냄(알 수 없음)으로 둔다 / 실제로 못 나간 DM 이 PM 화면에 실패로만 남는다
- 최소 한 번: 10분 뒤 다시 준다 / 봇이 보내고 보고하기 직전에 멈추면 팀원이 같은 DM 을 두 번 받는다

## 결정

- 리마인드와 대화 메시지를 나눈다. 같은 대화·같은 발송 시각의 승인된 리마인드를 메시지 한 통으로 묶고, 문구는 만든 순서대로 빈 줄로 이어 붙인다(머리말 없음). 승인 요청 테이블은 쓰지 않는다
- 상태는 예정·발송됨·취소됨·만료됨 넷이다. DM 결과와 사유(DM 막힘, 디스코드 미연결, 알 수 없음)는 봇 메시지에 따로 둔다. 디스코드가 연결되지 않은 팀원의 메시지는 봇에 주지 않고 묶는 순간 디스코드 미연결로 표시한다
- 봇 발송은 최대 한 번이다. 늦게 온 보고는 받아서 실제 결과로 고친다
- 예정 상태면 승인한 뒤에도 문구와 시각을 고칠 수 있고 승인은 그대로다. 지난 시각으로 만들거나 고치거나 승인하면 "예정 시각이 지났어요" 오류를 낸다
- 봇 DM 창에 온 팀원 글은 리마인드에 대한 답인지와 상관없이 모두 대화에 넣는다. 디스코드 DM 에는 무엇에 대한 답인지 표시가 없어 가를 수 없다

## 다시 볼 조건

- 같은 DM 이 두 번 가는 것보다 못 나간 DM 이 더 문제가 되면(실패 표시가 자주 보이면) 최소 한 번으로 바꾸고 봇 쪽에서 중복을 막는다
- 태스크 안내 DM 이나 #회의록 요약처럼 태스크 × 수신자 단위가 아닌 메시지를 더할 때 리마인드 테이블에 넣을지 따로 둘지 다시 본다
- 팀원이 봇 DM 을 PM 이 보지 않기를 원하면 답을 기다리는 리마인드가 있을 때만 저장하는 쪽을 다시 본다
