# 임베딩 유사도 검색 threshold 검증 스크립트 추가

- 날짜: 2026-09-23
- 이슈: #64
- PR: #65
- 브랜치: feat/64-embedding-threshold
- 작성자: 유재환

## 한 일

`embedding.find_similar_candidates()` 가 실제로 올바른 후보를 찾아내는지 실제 임베딩 API로
검증하고, threshold 후보값을 도출했다(`judge/eval_embedding_search.py`).

| 카테고리 | 개수 | 목적 |
|---|---|---|
| 명확한 매치 | 10 | task마다 하나씩, 기본 정확도 확인 |
| 명확한 불일치 | 10 | 완전히 다른 도메인, false positive 확인 |
| 짧은 보고 | 5 | "로그인 완료." 같은 극단적으로 짧은 문장 |
| 다중후보 구분 | 8 | 비슷한 후보 중 정확한 것을 골라내는지 |
| 경계 케이스 | 8 | 관련은 있으나 다른 하위작업 — 관찰용, 채점 안 함 |
| 엣지 케이스 | 9 | 부정문/모호함/다중언급 — 관찰 위주 |
| **합계** | **50** | |

## 왜

#62(벡터 검색 연결)는 BE 책임으로 판단해 닫았지만, `embed()`/`find_similar_candidates()` 자체가
실제로 올바른 후보를 찾아내는지, 그리고 BE가 쓸 threshold 값을 근거 있게 정하는 건 여전히
AI 쪽이 검증해야 하는 부분이라 별도로 진행했다.

## 결과

| 항목 | 값 |
|---|---|
| 채점 대상 통과 | 35/36 (97%) |
| 관찰용(AMBIGUOUS) | 14개 별도 |
| 명확한 불일치 최고점 | 0.33 |
| 명확한 매치 최저점 | 0.42 |
| 제안 threshold | ~0.4 |

부정문("~안 하기로 했다")도 여전히 해당 task로 매치됨을 확인 — 임베딩은 후보를 찾는 역할까지만,
"하기로/안 하기로"의 실제 판단은 Terra 2단계 몫.
