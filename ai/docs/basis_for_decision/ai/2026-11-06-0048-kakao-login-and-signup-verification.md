# 0048. 카카오 로그인은 가입 화면을 거치고, 기존 이메일이 같으면 자동으로 잇는다

- 날짜: 2026-11-06
- 상태: 결정됨

## 배경

가입 때 이메일을 확인하지 않아 남이 팀원 이메일로 먼저 가입하면 그 사람의 초대를 받을 수 있었다(0036 의 한계). 이 구멍을 가입 전 코드 인증으로 막으면서 카카오 로그인을 더해야 했다. 초대가 이메일 기준이라 카카오 이메일을 어떻게 믿을지, 이메일이 없는 사용자를 어떻게 받을지, 기존 계정과 이메일이 겹치면 어떻게 할지를 함께 정해야 했다.

## 검토한 선택지

가입 인증 상태를 어디에 둘 것인가

- 작은 코드 행과 서명 토큰: 표가 하나고 API 가 적다 / 증명을 되돌릴 수 없고, 새로고침하면 이메일 단계로 돌아간다
- 서버의 가입 시도 행과 쿠키: 새로고침해도 단계가 남는다 / 조회·취소 API, PG 잠금, 카카오 ID 보관이 더 든다

이메일 없는 카카오 사용자

- 가입을 막는다: 코드가 적다 / 그 사용자는 들어오지 못한다
- 카카오 전용 계정을 만든다: 단계가 적다 / 초대를 받을 수 없고 `User.email` 을 비워 둘 수 있게 계약을 바꿔야 한다
- 코드 인증 가입으로 넘기고 카카오를 잇는다: 초대를 받을 수 있는 일반 계정이 된다 / 카카오 신원을 가입이 끝날 때까지 들고 있어야 한다

카카오가 인증한 이메일이 기존 계정과 같을 때

- 잇지 않고 이메일 로그인을 안내한다: 안전하다 / 그 사용자는 카카오로 들어올 수 없다
- 이 기능 뒤에 가입한 계정만 잇는다: 인증된 계정만 잇는다 / 가입 시각 기준이 필요하고 옛 계정은 카카오를 쓸 수 없다
- 모든 계정을 잇는다: 코드가 가장 적고 옛 사용자도 카카오로 들어온다 / 아래 위험이 남는다

## 결정

작은 코드 행과 서명 토큰을 쓴다. 코드가 맞으면 정규화한 이메일을 담은 30분짜리 증명을 주고, `POST /auth/signup` 은 본문의 이메일을 받지 않는다.

카카오 callback 은 계정을 만들지 않는다. 계정은 가입 화면에서만 생기고 비밀번호도 그곳에서 정한다. 그래서 비밀번호 없는 계정은 생기지 않고 카카오와 이메일 로그인이 함께 된다. 카카오가 인증한 이메일은 코드 없이 쓰고 화면에서 고칠 수 없다. 인증되지 않은 이메일은 믿지 않고 코드 인증을 받는다.

대기 중인 카카오 신원은 서명한 HttpOnly 쿠키에만 둔다. URL 로 넘기면 공격자가 자기 카카오 흐름의 링크를 피해자에게 보내, 피해자가 만든 계정을 공격자 카카오에 묶을 수 있다.

기존 계정 이메일과 카카오 인증 이메일이 같으면 그 계정에 잇고, 이미 다른 카카오에 이어진 계정은 덮어쓰지 않는다.

자동 연결은 인증 없이 만든 옛 계정에도 적용한다. 이미 가입한 사용자를 인증한 것으로 보는 결정과 같은 기준이다. 그래서 옛 계정이 남이 선점한 것이면 진짜 주인이 그 계정에 이어져, 선점자가 비밀번호로 함께 들어올 수 있다. 진짜 주인이 비밀번호를 재설정하면 선점자의 비밀번호와 세션은 사라진다.

전체 메일 발송 상한은 두지 않는다. 사용량이 작고, 상한은 누구나 채워서 가입을 막는 수단이 된다.

## 다시 볼 조건

- 이메일을 선점한 계정이 실제로 나오면 옛 계정 자동 연결을 멈추고 가입 시각 기준을 더한다
- 코드 메일이 악용되거나 메일 계정의 발송 한도에 닿으면 전체 상한이나 IP 기준 제한을 더한다
- 소셜 로그인을 하나 더 넣으면 `User.provider`·`provider_id` 대신 연결 표를 둔다
- `OAUTH_STATE_SECRET` 이 유출되면 가입 증명도 위조되므로 키를 바꾼다. 가입 인증 사고가 나면 키를 나눈다
