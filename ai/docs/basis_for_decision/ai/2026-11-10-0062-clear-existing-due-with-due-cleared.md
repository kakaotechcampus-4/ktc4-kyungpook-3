# 0062. 기존 Task 의 마감을 없애는 결정을 due_cleared 로 보낸다

- 날짜: 2026-11-10
- 상태: 결정됨
- 이슈: #624

## 배경

11/9 4인 테스트 회의(업로드 `681e66ca`)에서 원준 님이 "그 절차는 제가 문서로 정리해 둘게요. 날짜는 아직 못 박겠어요" 라고 했다. 워크스페이스에는 같은 녹음을 앞서 올려 생긴 Task "TV 백업 및 복구 절차 문서화" 가 마감 11/10 으로 있었다.

서버에서 이 발화 하나만 세 번 다시 판단했다(유사 검색은 실제 BE, 쓰기 없음).

| 단계 | 3회 모두 |
|---|---|
| Terra | 기존 Task 의 일정 변경(`schedule`, `is_new=false`). "마감 11/10 이 있는데 미정이라고 했으니 바꿔야 한다" |
| Luna 초안 | 잘리지 않음(`stop`, 추론 142 ~ 187). `{"due_date": null, "due_raw": null, "doc_text": "마감일을 11/10에서 미정으로 변경"}` |
| 파서 | "일정 변경인데 마감이 없다" 로 거부. 로그는 "Luna 응답을 파싱하지 못했습니다" |

막힌 곳이 두 군데였다.

1. 초안 프롬프트는 `due_date` 를 "근거에 마감이 나오면 날짜, 없으면 null, 마감을 없애자고 하면 `none`" 으로 정의한다. "아직 못 박겠다" 에는 날짜도 "없애자" 는 말도 없으니 Luna 는 지시대로 null 을 냈다.
2. `none` 을 냈어도 파이프라인이 다시 실패시킨다. BE `/extractions` 는 `due_date: null` 을 "바꾸지 않음" 으로 받아 마감을 지우는 값을 보낼 칸이 없었다(이번 변경 전의 `DUE_CLEARED_REASON`, 그때 결정 근거는 `2026-10-17-due-revert-to-none.md`).

같은 입력이라 몇 번을 다시 돌려도 실패하는데, 회의 전체 재시도가 두 번 돌아 인계가 6분 30초 늦어졌다(0063).

## 검토한 선택지

마감 해제를 어떻게 다룰지:

- 보낼 수 없는 결정으로 기록하고 재시도 없이 닫는다: AI 만 고치면 된다. 지연은 사라지지만 PM 은 이 결정을 승인 화면에서 못 보고 마감은 11/10 으로 남는다.
- 마감은 두고 설명만 담은 검토 카드를 보낸다: PM 이 보고 직접 지운다. 승인을 누르면 마감이 지워질 거라고 오해할 수 있다.
- 계약에 마감 해제를 더한다(`due_cleared`): BE 를 같이 바꿔야 한다. 확인해 보니 BE 의 승인 반영(`apply_task_updates`), Notion 동기화(`build_properties` 가 `{"date": null}` 을 보냄), FE 승인 표(`fieldValueLabel` 이 null 을 "없음" 으로 그림)는 이미 `due_date: null` 을 마감 지우기로 다룬다. 빈 곳은 요청 스키마와 변경안을 만드는 조건(`extractions.py` 의 `due_date is not None`) 뿐이었다.

null 과 `none` 을 어떻게 가를지:

- 일정 변경인데 `due_date` 와 `due_raw` 가 모두 null 이면 마감 해제로 본다: 기존 테스트에 근거가 "다음 주 화요일로요" 인데 Luna 가 둘 다 null 을 준 경우가 있다. 이건 날짜 계산 실패라 PM 에게 틀린 "마감 → 없음" 이 간다.
- 근거 원문에 날짜 표현이 있는지 코드로 가린다: 판별 함수가 없고 한국어 정규식은 깨지기 쉽다.
- 프롬프트의 `none` 정의에 "아직 못 정했다·미정" 을 더한다: null 은 지금처럼 "못 정함·실패" 로 남는다. 같은 발화 세 번 모두 `none` 을 냈다.

## 결정

계약에 `due_cleared` 를 더하고, null 과 `none` 의 구분은 프롬프트로 고친다.

- AI: 초안 프롬프트의 `none` 에 "마감을 아직 못 정했다·미정이라고 하거나" 를 더한다. `to_item` 은 일정 변경 초안이 `due_cleared` 면 update 항목에 `due_cleared: true` 를 싣는다. 대상 Task 에 원래 마감이 있는지는 BE 가 등록 시점 값으로 다시 보고, 없으면 승인 요청을 만들지 않는다. 처음에는 AI 가 원래 마감이 있을 때만 싣게 했는데, 그러면 답장 판단에서 후보가 하나일 때만 마감 없는 태스크의 해제 알림이 사라졌다(후보가 둘이면 보충 판단이 알렸다). 같은 회의 안에서 앞 카드에 합칠 때는 원래 마감이 없으면 되돌림이라 카드를 없앤다(10/17 결정). 해제 뒤 다시 날짜를 말하면 그 날짜가 이긴다.
- BE: `ExtractionItemCreate.due_cleared`(기본 false). 대상 Task 에 마감이 있으면 변경안에 `"due_date": null` 과 `base_values.due_date` 를 싣는다. update 라 게이트는 항상 `review` 다. `due_date` 가 함께 오면 `due_date` 를 따른다.
- 답장 판단은 지금처럼 `due_clear` 줄로 알리기만 하고 반영하지 않는다(계약의 답장 판단 절). 회의는 PM 이 카드를 보고 승인하지만, 답장은 한 줄이 바로 태스크를 바꿀 수 있어 따로 둔다.

마감을 말하지 않은 것과 미정은 새 할 일에서는 같고(마감 없이 만든다), 기존 할 일에서는 다르다. 마감 얘기가 없는 수정(상태, 담당 변경)마다 마감이 지워지면 안 되므로 `due_date: null` 의 뜻은 바꾸지 않았다.

## 다시 볼 조건

- Terra 가 "날짜 얘기가 아닌데" 일정 변경으로 판단해 해제 카드가 자주 나오면 Terra 프롬프트를 본다. 이번 사례도 같은 녹음을 다시 올린 경우라, 실제 회의에서 얼마나 나오는지는 아직 모른다.
- 답장에서도 마감 해제를 반영하기로 하면 답장 판단 계약을 바꾼다.
