# Jev 근거 판정 평가를 217개 대사로 늘려 0.8 을 다시 본다

- 날짜: 2026-11-07
- 브랜치: `feature/jev-eval-extended`
- 관련: PR #382 멘토 리뷰 1번, 결정 기록 [0031](2026-11-02-0031-evidence-status-by-source-check.md), 자동 생성 스위치(BE PR #526)

## 왜

멘토 리뷰는 "0.8 은 전체 정답률이 아니라 원문 명시 여부에 대한 모델의 판정값"이라고 짚었다. 0031 의 평가는 대사 19개 × 2회였고, 잘못된 certain 0건이어도 이 표본으로는 실제 비율이 최대 17%(Wilson 95% 상한)일 수 있었다. auto 를 열지 판단하려면 표본을 늘리고, 어떤 말에서 틀리는지와 기준값을 바꾸면 무엇이 달라지는지를 봐야 한다.

## 한 일

- 대사를 `judge/golden_set_evidence/` 로 옮겼다. 기존 28개(`base.json`)에 189개(`extended.json`)를 더해 217개다. 회의 날짜는 2026-11-02(월)로 같다.
  - A 명시 약속·지시 + 명시 마감(30), B 마감 없음(18), C 확정 아님 — 조건부·질문·제안·희망·추측·보류·번복·부정·지난 얘기·남의 일·농담(40), D 마감 문제 — 근사·기간·다른 업무의 날짜·번복된 날짜·요일 불일치·연월 오류·시각만·조건부 마감(38), E 여러 줄 — 지시+수락·번복·질문 뒤 수락/거절·협상(21), F 제목과 원문의 일이 다름(12), G 전사 잡음 — 띄어쓰기 오류·추임새·한글 숫자(15), H 채팅체(15).
  - 정답이 False 인 대사(auto 로 새면 안 되는 것)가 189개 중 106개(56%)다. 날짜 라벨은 회의 날짜로 다시 계산해 확인했다.
- `judge/eval_evidence.py` 가 잘못된 certain 비율과 95% 상한, 기준값 0.5~0.95 결과, 유형별 결과, 반복 사이에 판정이 바뀐 대사를 낸다.
- 대사 라벨(모양, 날짜가 지나지 않았는지, 마감 표현의 요일과 날짜가 맞는지, 확정 아닌 할 일에는 마감을 묻지 않는지)과 지표 계산을 `tests/test_eval_evidence.py` 가 지킨다(실제 API 없이 361건).

## 결과 (실제 Jev, 217개 × 3회 = 651회 호출, 응답 없음 0)

전체 요약은 [eval_results/2026-11-07-evidence-extended.json](../../../judge/eval_results/2026-11-07-evidence-extended.json).

3회 반복은 같은 대사를 다시 물은 것이라 서로 독립인 표본이 아니다. 오답률과 신뢰 상한은 **대사 단위**로 본다(반복 중 한 번이라도 틀리면 틀린 대사, 보수적). 반복은 흔들림을 보는 데만 쓴다(#382 멘토 재리뷰).

| 판정 (대사 단위) | 잘못된 certain (auto 로 새는 쪽) | 놓친 certain (PM 확인이 느는 쪽) |
|---|---|---|
| 할 일 (task) | 1/83 = 1.2% (**95% 상한 6.5%**) | 2/134 (재현율 98.5%) |
| 마감 (due) | 1/44 = 2.3% (**95% 상한 11.8%**) | 24/65 (재현율 63.1%) |

참고로 실행 단위로 세면 할 일 3/249(상한 3.5%), 마감 3/132(상한 6.5%)이지만 같은 대사의 반복이 섞여 상한이 실제보다 좁게 나온다.

잘못된 certain 은 할 일 1개, 마감 1개이고 3회 모두 같았다(흔들린 것이 아니라 일관되게 틀림).
- 할 일: "회의록 템플릿은 제가 만들게요" 인데 제목이 "회의록 작성" 이면 yes 0.94~0.99. 원문이 맡은 일과 제목의 일이 조금 다르면 가리지 못한다(F 유형 12개 중 1개).
- 마감: "이십일 까지"(20일)를 11-21 로 계산한 것을 yes 0.81~0.84. 한글로 받아 적은 숫자 날짜의 계산을 놓친다.

기준값별(651회 기준, 잘못된 certain / 놓친 certain):

| 기준값 | 할 일 | 마감 |
|---|---|---|
| 0.7 | 4 / 4 | 9 / 17 |
| 0.75 | 4 / 6 | 5 / 27 |
| **0.8 (지금)** | **3 / 6** | **3 / 55** |
| 0.85 | 3 / 19 | 0 / 84 |
| 0.9 | 3 / 32 | 0 / 124 |

- 할 일은 기준값을 올려도 잘못된 certain 3건(F 1개)이 남는다. 0.97 로 확신하기 때문이다. 기준값이 아니라 질문으로 풀어야 한다.
- 마감은 0.85 에서 잘못된 certain 이 0 이 되지만 놓친 certain 이 84 로 늘어 맞는 마감의 57% 만 certain 이 된다.
- 기준값별 표는 실행 단위(651회)다. 대사 단위로 보면 상한이 위 표처럼 더 넓다.
- 반복 사이 판정이 바뀐 것은 11개, 모두 마감이고 yes 가 0.75~0.86 에서 오갔다. 기준값 근처의 마감 판정은 실행마다 갈린다.
- 유형별로 확정 아님(C, 120회)과 마감 문제(D, 228회)는 잘못된 certain 이 0 이다. 조건부·질문·번복·근사·요일 불일치는 잘 막는다.

## 판단

- 기준값 0.8 은 그대로 둔다. 할 일은 기준값으로 풀리지 않고, 마감은 0.85 로 올리면 맞는 마감의 절반 가까이를 PM 확인으로 보낸다. 마감을 놓치는 쪽(71.8%)은 PM 확인이 늘 뿐 잘못 반영되지 않는다.
- 이 평가는 "근거 원문에 명시됐나"를 재는 것이지 태스크가 맞는지의 정답률이 아니다(멘토 리뷰와 같다). auto 개방은 운영의 PM 승인·수정·반려 결과로 정해야 하므로, 처음 운영은 `AUTO_CREATE_ENABLED=false`(BE PR #526)로 검증만 돌리고 "켰으면 auto 였을 항목" 로그와 PM 결과를 맞춰 본다.
- 후속 후보: 할 일 질문에 "제목의 일과 원문이 맡은 일이 같은가"를 더 분명히 묻기(F 유형), 한글 숫자 날짜를 질문 전에 숫자로 바꾸어 주기. 둘 다 질문을 바꾸면 이 평가를 다시 돌려 확인한다.

## 한계

- 대사는 합성이다(실제 회의에서 뽑은 것이 아니다). 실제 분포의 비율을 그대로 뜻하지 않는다. 실제 회의 전사에서 뽑은 문장을 섞은 표를 후속으로 낸다(#382 재리뷰).
- 정답이 False 인 대사가 할 일 83개, 마감 44개라 0건이어도 상한이 각각 약 4.4%·8% 아래로 내려가지 않는다. 상한을 좁히려면 부정 대사를 더 늘려야 한다.
- 회의 날짜가 하루(월요일)뿐이라 다른 요일 기준의 상대 날짜는 재지 않았다.
