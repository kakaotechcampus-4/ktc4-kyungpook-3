# Elice 전사 장애 때 GPU 서버로 옮기는 경로

- 날짜: 2026-11-05
- 이슈: #393
- PR: #410
- 브랜치: `feature/393-gpu-stt-fallback`

## 한 일

운영 워커의 전사를 사람이 GPU 서버로 옮길 수 있게 했다. 코드 변경은 `stt/elice.py` 의 `ELICE_STT_CA_BUNDLE` 하나다. 값이 있으면 전사 호출의 `verify` 로만 쓰고, 경로에 파일이 없으면 `SttError` 를 낸다.

`deploy/gpu-stt/gpu-stt.sh` 의 `setup`, `on`, `off`, `destroy`, `status` 로 개인 AWS 의 서버를 다룬다. 서버는 지우지 않고 꺼 둔다. `setup` 이 대기 서버를 한 번 만들고 `on` 은 start, `off` 는 stop 이다. `destroy` 는 인증서를 새로 만들 때와 기간이 끝날 때 쓴다. `Role=stt-fallback` 태그가 정확히 맞는 자원만 다루고, 부팅마다 vLLM 시작과 자동 stop 예약을 다시 건다. 전환 절차는 `deploy/gpu-stt/README.md` 에 적었다. 워커에 drop-in 으로 주소와 키를 넣어 운영 `.env` 는 고치지 않는다.

## 왜

Elice 가 멈추면 지금은 CPU 전사로 넘어가 62.42분 회의가 84.93분 걸린다. 초안 10분 기준을 지키려면 측정을 마친 GPU 서버를 장애 때 부를 수 있어야 한다. 호출 경로와 인증서 선택은 [결정 기록 0047](2026-11-05-0047-gpu-stt-fallback-path.md).

## 결과

운영 서버에서 62.42분 합성 회의를 일회성으로 불렀고, 대기 서버를 켜서 운영 서버의 첫 전사 응답까지 잰 값을 더했다. 자세한 수치와 재현 명령은 [측정 결과](../../../stt/eval/results/2026-11-05-gpu-fallback-prod/README.md)에 있다.

| 항목 | 값 |
|---|---|
| `on` 부터 운영 서버의 첫 전사 응답 | 161.8초, 158.6초 |
| 전사 | 166.2초 |
| 합계 | 약 326초 (5.4분), 계산값 |
| `off` | 403.7초, 402.0초 |
| `setup` | 709.6초 |
| 호출 / 실패 / 재시도 | 168 / 0 / 0 |

합계는 장애를 알아채는 시간, 워커 재시작, 추출, 인계를 넣지 않은 값이다. 장애에 걸린 회의를 다시 돌리는 경로는 처음 전사와 달라 이 값으로 말할 수 없다. 자동 stop 은 종료 시각 240초 뒤로 켜서 346.8초에 꺼지기 시작하는 것을 확인했다.

음성 임시 파일은 1MiB 를 넘는 업로드에서만 관측됐고 운영 워커의 묶음은 최대 902,444바이트라 tmpfs 는 넣지 않았다. 60초 WAV 의 78바이트 응답은 운영 경로 밖이라 미확인으로 남긴다.

`pytest` 는 1392개 통과다. 장부 합은 ₩4,702 이고 예약 기준이다. 고정 IP 대기 ₩1,176 과 측정 예약 3건 ₩3,526 이다. 측정 3건을 켠 시간으로 계산하면 약 $1.41(₩1,974)이고 stop 이 진행되는 시간은 과금하지 않는다고 보았다. 대기 디스크와 11/12 뒤의 고정 IP 는 [0039](2026-11-04-0039-gpu-stt-server.md) 의 예산표로 본다. 측정 뒤 대기 서버는 `stopped` 이고 운영 서버에는 파일을 쓰지 않았다. 측정 뒤 스크립트를 고친 부분(`Ready` 태그, 대기 오류, 인증서 거절, `--release-ip`)은 가짜 aws 테스트로 확인했고 실제 AWS 로 다시 돌리지 않았다. 측정에 쓴 대기 서버에는 첫 부팅을 끝낸 것을 확인한 뒤 태그만 붙였다.

## 다음

머지와 배포 뒤 #357 일정을 피해 워커 전환과 복귀를 한 번 리허설한다. 재처리 경로의 시간도 그때 확인한다. 운영 `MM_STT_BACKEND` 값과 재처리 명령의 권한도 그때 본다.

회의가 일부만 전사된 채 인계되면 `--retry` 로 되돌릴 수 없고 재처리는 깨우기 파일을 일찍 지운다. 둘 다 develop 에 있던 동작이라 따로 이슈로 다룬다.

2026-12-31 에 장애 대응 기간이 끝나면 `destroy --release-ip` 로 대기 서버를 지우고 고정 IP 를 놓는다. 실제 회의 음성이 개인 계정을 지나는 범위는 #360 에서 정한다.
