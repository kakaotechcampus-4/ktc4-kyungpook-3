# Elice 전사 장애 때 GPU 서버로 옮기는 경로

- 날짜: 2026-11-05
- 이슈: #393
- PR: #410
- 브랜치: `feature/393-gpu-stt-fallback`

## 한 일

운영 워커의 전사를 사람이 GPU 서버로 옮길 수 있게 했다. 코드 변경은 `stt/elice.py` 의 `ELICE_STT_CA_BUNDLE` 하나다. 값이 있으면 전사 호출의 `verify` 로만 쓰고, 경로에 파일이 없으면 `SttError` 를 낸다.

`deploy/gpu-stt/gpu-stt.sh` 의 `setup`, `on`, `off`, `status` 로 개인 AWS 의 서버를 켜고 끈다. `Role=stt-fallback` 태그가 정확히 맞는 자원만 다루고, 켤 때 정한 시간 뒤 스스로 종료하도록 예약한다. 전환 절차는 `deploy/gpu-stt/README.md` 에 적었다. 워커에 drop-in 으로 주소와 키를 넣어 운영 `.env` 는 고치지 않는다.

## 왜

Elice 가 멈추면 지금은 CPU 전사로 넘어가 62.42분 회의가 84.93분 걸린다. 초안 10분 기준을 지키려면 측정을 마친 GPU 서버를 장애 때 부를 수 있어야 한다. 호출 경로와 인증서 선택은 [결정 기록 0044](2026-11-05-0044-gpu-stt-fallback-path.md).

## 결과

운영 서버에서 62.42분 합성 회의를 일회성으로 불렀다. 각각 한 번 잰 값이고 자세한 수치와 재현 명령은 [측정 결과](../../../stt/eval/results/2026-11-05-gpu-fallback-prod/README.md)에 있다.

| 항목 | 값 |
|---|---|
| `on` 부터 첫 200 | 335초 |
| 전사 | 166.2초 |
| 합계 | 501초 (8.35분) |
| 호출 / 실패 / 재시도 | 168 / 0 / 0 |

합계는 장애를 알아채는 시간, 워커 재시작, 추출, 인계를 넣지 않은 값이다. 장애에 걸린 회의를 다시 돌리는 경로는 처음 전사와 달라 이 값으로 말할 수 없다.

`pytest` 는 1321개 통과다. 비용은 장부 기준 ₩2,502 이고 고정 IP 대기 11/12 까지 ₩1,176, 켜기 1회 예약 ₩1,326 이다. 예약은 1시간으로 잡았고 실제 켜 둔 시간은 약 16분이다. 측정 뒤 인스턴스 0대와 운영 서버의 임시 파일 삭제를 확인했다.

## 다음

머지와 배포 뒤 #357 일정을 피해 워커 전환과 복귀를 한 번 리허설한다. 재처리 경로의 시간과 `--hours 1` 자동 종료도 그때 확인한다. 운영 `MM_STT_BACKEND` 값과 재처리 명령의 권한도 그때 본다.

회의가 일부만 전사된 채 인계되면 `--retry` 로 되돌릴 수 없고 재처리는 깨우기 파일을 일찍 지운다. 둘 다 develop 에 있던 동작이라 따로 이슈로 다룬다.

2026-11-12 에 장애 대응 기간 연장을 정한다. 늘리지 않으면 고정 IP 를 놓는다. 실제 회의 음성이 개인 계정을 지나는 범위는 #360 에서 정한다.
