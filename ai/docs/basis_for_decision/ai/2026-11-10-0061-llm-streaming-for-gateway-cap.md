# 0061. Terra·Luna 호출을 스트리밍으로 받는다

- 날짜: 2026-11-10
- 상태: 결정됨
- 이슈: #624

## 배경

11/9 수동 업로드 회의 두 건의 요약이 "출력 잘림"으로 실패했다. 같은 날 봇 회의 두 건은 저장됐다.

| 회의 | 시도 | 입력 토큰 | 출력 / 그중 추론 | 결과 |
|---|---|---|---|---|
| 봇 21초 | 1 | 669 | 375 / 198 | 저장 |
| 봇 55초 | 1 | 878 | 1133 / 236 | 저장 |
| 업로드 `12be7454` | 1, 2 | 2225 | 2000 / 2000 | 출력 잘림 (BE 시도 상한 2 를 다 써서 요약 없음) |
| 업로드 `681e66ca` (3분 57초) | 1 | 2211 | 2000 / 2000 | 출력 잘림 |
| 업로드 `681e66ca` | 2 (15분 뒤) | 2211 | 1805 / 651 | 저장 |

출력이 정확히 2000 에서 끊겼고 그 2000 을 추론이 다 썼다. 코드(`summary/summarize.py`, `llm.py`)는 출력 상한을 정하지 않으므로 상한은 게이트웨이 쪽 값이다. 같은 입력이어도 추론 길이가 호출마다 달라(2000 과 651) 운에 따라 실패했다.

서버에서 Luna 를 직접 불러 상한을 확인했다(2026-11-10, `reasoning_effort=low`).

| 호출 | 결과 |
|---|---|
| 상한 지정 없음, 비스트리밍 | `finish_reason=length`, 출력 2000, 추론 2000 (입력 65 토큰의 단순 요청) |
| `max_completion_tokens=6000`, 비스트리밍 | 400. 게이트웨이가 "2000-token ceiling this proxy holds a NON-STREAMING reply to" 라고 답했다 |
| `max_completion_tokens=8000`, 스트리밍 | `stop`, 출력 3324, 추론 125, JSON 300개 항목 완전 |
| 상한 지정 없음, 스트리밍, `reasoning_effort=none` | `stop`, 출력 3193 |
| 상한 지정 없음, 스트리밍 | `stop`, 출력 3711, 32초, 조각 사이 최대 공백 8.6초 |

같은 문제가 추출 1단계에도 다가와 있었다. 3분 57초 회의의 1단계 Luna 호출이 출력 1772 ~ 1803 토큰(추론 739 ~ 813)이었다. 회의가 조금만 길어도 잘린다. `generate_json` 은 `finish_reason` 을 보지 않아 잘린 응답이 "파싱 실패"로만 남는다.

## 검토한 선택지

- 출력 상한을 올린다: 게이트웨이가 2000 넘는 값을 400 으로 막아 쓸 수 없다.
- 추론 강도를 낮춘다(`low` → `none`): 추론 몫은 줄지만 본문 자체가 길어지면(60분 회의 요약, 1단계) 여전히 2000 을 넘는다. 판단 품질에 주는 영향도 재지 않았다.
- 1단계와 요약을 구간으로 나눠 여러 번 부른다: 2000 안에 들어가게 할 수 있다. 구간 경계에 걸친 결정, 앞 구간 맥락 넘기기, 합치기를 새로 짜야 한다. 요약은 주제별로 나눠 다시 합치는 단계가 더 필요하다.
- 스트리밍으로 받는다: 게이트웨이 상한이 걸리지 않는다. 호출 모양만 바뀌고 프롬프트와 결과 처리는 그대로다.

## 결정

`llm.py` 의 `MLAPIClient` 가 `generate_json`·`generate_json_once` 모두 스트리밍으로 받는다(`_stream`). 함수 모양과 반환값은 바꾸지 않아 호출하는 쪽(1단계, 판단, 초안, 요약, 답장 판단, 옛 추출)은 그대로다.

같이 바꾼 것:

- SDK 의 timeout 은 조각 사이 대기에만 걸린다. 그래서 시작부터 정한 시간(요약은 `SUMMARY_TIMEOUT_S` 300초, 나머지는 `GENERATE_TIMEOUT_S` 300초)이 지나면 직접 끊는다. 요약은 이 값이 BE 임대 15분보다 짧아야 같은 회의에 돈이 두 번 들지 않는다.
- `finish_reason` 이 `stop` 이 아니면 로그에 남긴다.
- `generate_json` 은 잘린 응답(`length`)을 우연히 파싱돼도 버린다. 잘린 JSON 은 뒤쪽 항목이 빠져 있다.

구간 나누기는 하지 않는다.

## 다시 볼 조건

- 스트리밍으로 확인한 출력은 3711 토큰까지다. 60분 회의 크기(8천 ~ 1만 토큰)의 출력이 끝까지 오는지는 아직 재지 않았다. 긴 회의에서 `finish_reason` 이 `stop` 이 아니거나 300초 상한에 걸리는 로그가 나오면 구간 나누기를 다시 본다.
- 게이트웨이가 스트리밍에도 상한을 걸거나 비스트리밍 상한을 올리면 다시 본다.
