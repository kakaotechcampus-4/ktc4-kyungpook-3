# 0035. 팀원 초대는 이메일 일치로 수락하고, PM 이 수락한 계정을 보고 연결을 끊을 수 있게 한다

- 날짜: 2026-11-04
- 상태: 결정됨

## 배경

PM 이 온보딩에서 디스코드 명단으로 만든 팀원(`Member`)은 웹 계정과 연결되지 않는다(`user_id` 가 null). 그래서 팀원이 가입해도 소속 워크스페이스가 0개이고 들어갈 방법이 없다(#302). PM 이 팀원 이름마다 가입 이메일을 적어 초대하고, 그 이메일로 로그인한 사람이 수락하면 팀원 행과 계정을 잇기로 했다. 수락 전에는 그 워크스페이스에 접근할 수 없다.

가입할 때 이메일을 인증하지 않는다(`backend/app/api/auth.py` signup). 그래서 다른 사람이 팀원의 이메일로 먼저 가입하면 그 초대를 받을 수 있다. 이것을 어떻게 다룰지, 초대가 어떤 상태를 가질지 정해야 했다.

## 검토한 선택지

이메일 인증이 없는 문제

- 이메일 일치로 수락하고, PM 이 초대 목록에서 수락한 계정의 이름·이메일을 보고 연결을 끊는다: 팀원은 로그인하면 바로 초대를 보고 버튼 하나로 들어간다 / PM 이 알아채기 전까지 엉뚱한 계정이 팀원 권한으로 읽을 수 있다
- 위에 초대 코드를 더해 PM 이 코드를 따로 전달하고 수락할 때 입력한다: 이메일을 선점해도 코드 없이는 못 들어온다 / 코드를 전달하고 입력하는 단계가 생겨 "로그인하면 뜬다" 는 흐름이 깨진다
- 가입할 때 이메일 인증을 넣는다: 근본적으로 막는다 / 메일 발송 키와 비용, 인증 API 와 가입 화면 변경이 필요해 이번 범위를 넘는다

초대 상태

- 대기·수락·거절·취소·만료: 깃헙과 같다 / 메일로 알리지 않으니 팀원이 언제 가입할지 모르고, 만료된 초대를 다시 보내는 일이 생긴다
- 대기·수락·거절·취소·연결 끊김, 만료 없음: 오래된 초대는 PM 이 취소하면 된다 / 상태가 하나 늘어난다

이메일 오타

- 이메일 고치기 API: 초대 하나로 이어진다 / 고친 전후 기록이 사라지고 API 가 하나 는다
- 같은 팀원에게 새로 초대하면 열린 초대를 취소한다: 버튼 하나로 고치고 이력이 남는다 / 초대 행이 쌓인다

## 결정

이메일 일치로 수락하고, PM 이 연결을 끊을 수 있게 한다. 팀이 작고 PM 이 팀원 이름을 알고 있어서 수락한 계정 이름을 보면 이상한 것을 알아챌 수 있다. 끊으면 그 팀원의 `user_id` 를 null 로 되돌리고 초대를 연결 끊김으로 바꾼다. 팀원 행과 태스크·이력은 그대로 둔다. 마지막 PM 은 끊지 않는다.

역할이 PM 인 팀원은 초대할 수 없고, 대기 중에 PM 으로 올린 팀원의 초대도 수락할 수 없다. 초대를 수락한 계정이 바로 PM 이 되면 원래 PM 을 내려서 연결 끊기를 막을 수 있기 때문이다. PM 으로 들일 사람은 팀원으로 초대하고, 수락한 뒤 PM 이 역할을 바꾼다. 연결을 끊으면 같은 이메일의 대기 초대도 함께 취소해서 끊긴 계정이 돌아오지 못하게 한다.

상태는 대기·수락·거절·취소·연결 끊김이고 만료는 두지 않는다. 취소(PM 이 수락 전에 닫음)와 거절(받는 사람이 닫음)을 나누는 것은, 거절이 PM 이 그 사람에게 확인해야 할 신호이기 때문이다. 이메일 고치기 API 는 두지 않고 새 초대가 열린 초대를 취소한다. 거절·취소·연결 끊김 뒤 다시 초대할 수 있다. 초대 메일은 보내지 않는다.

한 계정이 한 워크스페이스에서 두 팀원이 되지 않도록, 한 팀원에 열린 초대 하나, 한 워크스페이스에서 같은 이메일의 열린 초대 하나를 DB 의 부분 고유 인덱스로 막고, 수락할 때 이미 소속인지 다시 확인한다.

## 다시 볼 조건

- 다른 사람이 팀원의 이메일로 먼저 가입한 일이 실제로 생기면. 그 경우 이메일이 고유라 진짜 팀원은 같은 이메일로 가입할 수 없어 다른 이메일로 초대받아야 한다. 이것은 가입 이메일 인증으로만 막을 수 있다
- 서비스에 메일 발송이 생기면 초대 메일과 만료를 다시 본다
- 수락한 팀원이 볼 수 있는 범위를 좁히기로 하면(지금은 기존 팀원 권한 그대로)
