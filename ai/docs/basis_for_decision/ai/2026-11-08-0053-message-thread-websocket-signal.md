# 0053. 대화 새 글을 커밋 뒤 웹소켓 신호로 알린다

- 날짜: 2026-11-08
- 상태: 결정됨

## 배경

대화를 열어 둔 PM 과 팀원은 상대의 새 글을 알림 목록 polling(30초)으로만 받는다. 사용자는 카카오톡처럼 바로 보이는 대화를 원했고, 10초 polling 대신 웹소켓을 골랐다(#520). 운영 BE 는 uvicorn `--workers 1` 한 프로세스이고 라우트는 동기 SQLAlchemy 라 스레드 풀에서 돈다. 예약 리마인드 발송은 스케줄러 스레드에서 돈다. 글이 생기는 경로는 웹 답장, PM 글, 봇이 넘긴 디스코드 글, 예약 발송, 봇의 발송 결과 보고와 봇이 가져갈 때 못 보냄으로 닫는 글이다.

## 검토한 선택지

- 서비스가 트랜잭션 안에서 신호를 등록하고, SQLAlchemy `Session` 의 커밋 훅이 바깥 커밋 뒤에 보낸다: 글을 만드는 함수 옆에 한 줄씩이라 경로를 빠뜨리기 어렵고, 롤백된 글은 신호가 없다. 받는 사람(대화 주인과 그 시점 PM 전원)을 등록 때 DB 에서 정하므로 역할이 바뀌면 다음 신호부터 맞다. 훅이 SAVEPOINT 해제와 롤백에서도 불려 바깥 트랜잭션만 다루도록 막아야 한다. 연결표가 프로세스 메모리라 한 프로세스에서만 전부 닿는다.
- 라우트마다 `db.commit()` 뒤에 직접 보낸다: 가장 짧다. 스케줄러까지 부를 곳이 흩어지고, 새 경로를 더할 때 빠뜨리면 polling 으로만 보인다.
- PostgreSQL `LISTEN/NOTIFY`: 커밋에 묶여 정확하고 프로세스를 늘려도 동작한다. 전용 연결과 재접속 관리가 더해지고 sqlite 테스트가 돌지 않는다.

연결의 인증과 범위는 이렇게 골랐다. 소켓은 DB 연결을 물고 있지 않고(풀 5+10), 30초마다 짧은 세션으로 세션과 소속을 다시 확인해 4401·4403 으로 닫는다. 로그아웃이나 비밀번호 재설정으로 세션이 지워진 소켓은 닫힐 때까지 최대 30초 걸린다. 그동안 나가는 것은 대화 id 뿐이다. 계정이 같은 공간의 다른 팀원 행으로 옮겨졌으면 1013 으로 닫아 새 행으로 다시 붙게 한다. 다른 사이트의 요청은 `Origin` 의 `host:port` 가 `Host` 와 같은지로 거절한다. 허용 목록 환경변수는 서버 `.env` 를 고쳐야 해서 쓰지 않았다.

## 결정

첫 번째 안을 골랐다. 소켓은 `thread_updated` 신호만 보내고 화면은 기존 조회를 다시 부른다. 권한 검사는 조회 한 곳에 남는다. 재전송은 없고 화면은 소켓이 열릴 때마다 조회한다. 서버는 받기 전에 연결을 등록해 그 조회 뒤의 글은 신호로 온다. 계약은 `frontend/docs/contracts/frontend-api-contract.md` §5.7 의 대화 신호 웹소켓 항목이다.

## 다시 볼 조건

- BE 프로세스를 둘 이상으로 늘리면 다른 프로세스의 소켓에 신호가 닿지 않는다. 그때 `LISTEN/NOTIFY` 나 Redis pub/sub 로 연결표를 바꾼다.
- 로그아웃 뒤 최대 30초가 문제가 되면 로그아웃·세션 삭제 경로에서 그 세션의 소켓을 바로 닫는다.
- 한 팀원의 소켓 수에 상한이 없다. 소켓마다 메모리와 30초마다 인증 조회 한 번이 든다. 동시 접속이 늘거나 남용이 보이면 팀원당 상한을 둔다.
- 운영 프록시를 거친 연결은 아직 확인하지 않았다. Caddy 가 `Host` 를 바꾸거나 업그레이드를 넘기지 않으면 Origin 검사나 경로를 다시 본다.
