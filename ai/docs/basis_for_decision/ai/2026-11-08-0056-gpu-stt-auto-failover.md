# 0056. Elice 장애 때 워커가 GPU 전사 서버를 스스로 켜고 끈다

- 날짜: 2026-11-08
- 상태: 결정됨
- 이슈: #530

## 배경

[0047](2026-11-05-0047-gpu-stt-fallback-path.md) 의 GPU 대기 서버는 개인 AWS 키가 있는 김동우만 켤 수 있었다. 전환에는 drop-in 과 워커 재시작이 필요했다. 담당자가 없으면 장애 대응이 시작되지 않는다.

#528 리허설에서 GPU 서버가 15구간 중 2구간을 오류 없이 비워 돌려줬다. 같은 회의를 다시 보내 보니 원인은 이름 프롬프트였고 GPU 서버에서만 나타났다. 프롬프트가 있으면 동시 호출과 순차 호출 모두 같은 2구간이 4번 비었다. 없으면 빈 구간이 0이었고 15구간 모두 Elice 무프롬프트와 글자까지 같았다. CER 은 GPU 프롬프트 19.89, GPU 무프롬프트 6.72, Elice 무프롬프트 6.72 였다(회의 1건, 대본 372자). Elice 와 왜 다른지는 아직 모른다. 원자료는 레포 밖 `mm/eval-runs/393-gpu-stt-fallback/2026-11-07-blank-repro/` 에 있다.

## 검토한 선택지

판단을 어디에 둘지 두 설계를 비교했다.

- 워커 프로세스 안의 컨트롤러: 전사 호출마다 길을 고르는 감싸개와 10초마다 도는 상태 기계를 워커에 둔다. 운영 변경은 drop-in 하나다. 길이 메모리에 있어 프로세스 사이 파일 규칙이 없다.
- 워커와 분리된 관리자: systemd 타이머가 30초마다 판단하고 워커는 경로 파일만 읽는다. 관리자가 죽어도 경로 파일 기한이 지나면 Elice 로 돌아온다. 대신 운영 서버에 새 타이머 유닛이 생기고 두 프로세스가 파일로 말한다.

스위치는 두 가지를 비교했다.

- Lambda 함수 URL 과 토큰: 토큰이 새도 켜기, 끄기, 상태만 할 수 있다. 종료 시각(켠 뒤 3시간)과 누적 상한을 운영 서버 밖에서 지킨다. 함수가 하나 더 생긴다.
- 좁은 IAM 키: 함수가 없다. 하지만 누적 상한은 키를 쥔 쪽의 자기 신고뿐이고, 서명 때문에 운영 워커에 boto3 가 필요하다.

빈 구간은 두 가지를 비교했다.

- 빈 응답 감지기: 원인을 그대로 두고 증상을 찾는다. 침묵 구간의 정상 빈 응답과 가르기 어렵다.
- GPU 로 가는 호출에 프롬프트를 싣지 않는다: 원인을 막는다. 장애 동안 이름 힌트를 잃는다.

## 결정

워커 안 컨트롤러를 쓰고, 분리된 관리자 설계에서 세 가지를 가져왔다.

- 실제 호출이 연속 6번 실패하면 바로 기다리게 하고, Elice 확인 3번이 실패해야 켠다.
- 누적 상한은 Lambda 장부(SSM 파라미터) 한 곳에만 둔다.
- GPU 준비는 확인 호출이 글자를 돌려줄 때만으로 본다.

새 타이머 유닛을 두지 않고 `recorder.py` 와 `batch.py` 를 바꾸지 않는 쪽을 골랐다.

스위치는 Lambda 이고 켜기와 끄기를 둘 다 한다. 이슈에는 켜기 전용이라고 적었지만 끄기가 없으면 장애 한 번에 3시간 $1.94 가 들고, 있으면 회의 하나에 약 $0.17 이다(계산값).

GPU 로 가는 호출은 이름과 앞 줄 문맥 프롬프트를 둘 다 싣지 않는다. 프롬프트를 버리는 자리는 호출마다 길을 고르는 한 줄이라 이름, 짧은 묶음의 문맥, 실패 구간 재전사 세 길이 모두 그 줄을 지난다. 이름 힌트를 GPU 로 보내던 옛 drop-in 수동 전환 경로는 지웠다.

사람이 정한 값은 아래와 같다.

| 항목 | 값 |
|---|---|
| 켜기 | 실제 호출 연속 6번 실패, 이어서 Elice 확인 60초 간격 3번 실패 |
| 기다림 상한 | 30분. 지나면 지금의 재시도와 포기로 돌아간다 |
| 복귀 | Elice 확인 5분 간격 3번 연속 성공 |
| 일 없음 끄기 | GPU 호출 10분 없음 |
| 3시간 종료 | 5분 전에 일이 있으면 끄고 다시 켠다 |
| 상한 | 하루 6시간과 켜기 6번, 누적 15시간($9.7) |
| 포기한 회의 | GPU 준비 뒤 이번 장애 중 전사에서 포기한 회의를 다시 돌린다. 장애 전 포기 회의가 있는 서버는 알림만 |
| 수동 조작 | 비공개 운영 채널의 `/gpu on\|off\|status`. 채널 멤버가 곧 권한이다 |
| 알림 | 운영 채널. 사람이 판단할 것에만 `@everyone`, 끈 알림에 비용 |
| 들이는 순서 | `manual` 로 배포, 저장 회의 리허설, `auto` |

회의 음성이 개인 AWS 를 지나는 경로는 #360 에 공지했다.

## 다시 볼 조건

- `manual` 기간의 "자동이었으면 켰습니다" 알림이 장애가 아닐 때 나오면 켜기 문턱을 다시 본다.
- 무프롬프트 GPU 의 빈 구간 0은 회의 1건 값이다. 리허설에서 빈 구간이 나오면 `auto` 로 올리지 않는다.
- Elice 쪽에서도 이름 프롬프트의 CER 이 무프롬프트보다 나빴다(8.33 대 6.72, 회의 1건). Elice 프롬프트를 다시 볼 때 이 기록을 본다.
- stop 과 start 뒤 고정 IP 가 붙어 있다는 가정이 틀리면 Lambda 에 `ec2:AssociateAddress` 를 더한다.
- 2026-12-31 장애 대응 기간이 끝나면 Lambda, 장부 파라미터, 로그 그룹, 대기 서버를 지운다.
- 운영 채널을 공개로 바꾸면 누구나 `/gpu` 를 쓸 수 있다. 채널 공개 여부를 바꿀 때 권한 판단을 다시 본다.
