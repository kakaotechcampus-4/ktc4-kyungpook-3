- 날짜: 2026-11-09
- 이슈: #579
- PR: #580
- 브랜치: feature/579-extract-retry

## 한 일

- `judge/semantic_judge.py` 의 `extract_findings_counted` 가 1단계 응답을 쓰지 못하면(호출이나 JSON 읽기 실패, `findings` 키 없음, 항목 전부 탈락) 같은 프롬프트로 Luna 를 한 번 더 부른다. 두 번째도 실패하면 지금처럼 `FindingExtractionUnavailableError` 를 낸다.
- 첫 실패와 두 번째 실패를 경고 로그에 남긴다. 사유별 탈락 건수와 문장 수만 적고 요약·원문은 남기지 않는다.
- `tests/test_semantic_judge.py` 에 테스트 6개를 더했다. 실패 유형 세 가지에서 바로 다시 부르는지, 두 번 실패하면 세 번째는 부르지 않고 에러를 내는지, 두 실패 모두 로그에 건수가 남고 회의 내용은 들어가지 않는지 본다.

## 왜

11/8 수동 업로드 테스트(3분 57초 회의)에서 1단계가 "Luna 응답을 파싱하지 못했습니다" 로 한 번 실패했다. 회의를 실패로 세고 재시도 대기 60초를 기다린 뒤 다음 바퀴에서 다시 돌아, 업로드에서 BE 인계까지 4분 44초가 걸렸다. 그중 실패한 처리 22초와 대기 60초가 헛걸린 시간이다.

1단계는 BE 에 아무것도 쓰기 전이라 다시 불러도 카드가 중복되지 않는다. 다시 부르는 횟수는 한 번으로 뒀다. 두 번 연속 실패하면 Luna 쪽 장애일 가능성이 커서, 그때는 지금의 회의 단위 재시도(대기가 두 배씩 늘어남)에 맡긴다.
