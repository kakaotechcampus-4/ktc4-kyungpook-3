# 0056. 회의 요약은 BE 대기열로 돌리고 주제는 추출 항목에 단다

- 날짜: 2026-11-07
- 상태: 결정됨

## 배경

회의록 요약 칸은 있지만 채우는 쪽이 없었다. 요약 실패가 회의 처리를 실패로 만들면 안 되고, 인계가 끝난 회의는 워커가 다시 집지 않으며, `POST /extractions` 응답에는 항목 ID 가 없다. 태스크는 대부분 승인 뒤에 생겨서 회의 시점에는 연결할 태스크가 없다. 기존 회의는 두세 건을 재 본 뒤에만 돌려야 한다.

## 검토한 선택지

- 인계 직후 `process_session` 안에서 호출: 가장 빠르고 대기열이 없다 / 멈춘 호출이 다음 회의를 막고, 재처리는 서버 전사 파일에 묶여 지워진 업로드를 못 돌린다. 항목 ID 와 기존 주제를 읽는 BE 경로는 어차피 필요하다
- BE 대기열과 `Extraction` 칸 셋: 새 회의와 재처리가 한 경로이고 표시가 있는 회의만 돈다 / 서비스 경로 넷, 표 넷, 재처리 명령이 늘고 봇이 회의 전문을 읽는다
- 별도 작업 표: 시도 이력과 토큰이 DB 에 남는다 / 표 하나와 실패 보고 경로가 더 필요하다
- 주제를 Task 에 직접 연결: 읽기가 단순하다 / 승인, 반려, 되돌리기, 재승인 네 곳에 동기화 코드가 들어간다
- 주제를 추출 항목에 달고 읽을 때 태스크로 풀기: 승인 코드를 고치지 않고 쿼리 하나로 전이를 모두 다룬다 / 회의 밖에서 만든 태스크에는 주제가 없다

## 결정

BE 가 `Extraction` 칸 셋으로 대기열을 쥐고 워커가 바퀴 끝에 한 건씩 맡는다. 실패 보고 경로는 없고, 15분 임대가 지나면 다시 집혀 회의당 두 번까지 시도한다. 스위치는 `MM_SUMMARY_LLM` 하나이고 비어 있으면 유료 호출이 없다. 봇이 서비스 토큰으로 회의 전문을 읽는 것은 BE 담당과 합의했다.

주제는 `topic_item` 으로 항목에 달고 `_visible_links` 쿼리 하나로 태스크를 찾는다. 반려된 항목만 숨긴다. 주제 없는 태스크에 주제를 추정해 붙이지 않고, 그래프에는 그대로 보이며 유사도 선으로만 잇는다.

## 다시 볼 조건

재처리 뒤 주제 없는 태스크 비율이 높으면 주변 태스크의 주제를 따르는 방식을 더한다. 운영 그래프 응답이 1초를 넘거나 태스크가 1000개에 가까워지면 태스크끼리의 선을 미리 계산해 저장한다. 합성 데이터로 로컬에서 잰 응답 시간은 태스크 500개 1.26초, 1000개 4.81초다. 시도 이력이나 호출당 비용을 DB 에서 봐야 하면 별도 작업 표를 다시 본다.
