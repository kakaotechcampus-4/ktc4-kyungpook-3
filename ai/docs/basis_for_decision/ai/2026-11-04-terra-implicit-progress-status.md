# Terra 2단계가 상태 단어 없는 진척 보고를 status 변경으로 잡게 한다

- 날짜: 2026-11-04
- 이슈: #207
- PR: #308
- 브랜치: fix/207-implicit-progress-status

## 한 일

- `judge/final_judge.py` 의 status 규칙을 "명시적으로 언급됐을 때만" 에서 판단 원칙으로 바꿨다. 발화가 그 작업의 지금 상태를 드러내면 상태 단어가 없어도 채운다. 끝냈다고 보고하면(넘긴 것 포함) done, 손대기 시작하면 in_progress, 필요한 것이 오지 않아 못 하면 blocked, 끝난 일에 다시 손대면 in_progress 다. 검토 대기는 막힘이 아니고, 예정·일부·거의 함은 done 으로 올리지 않는다. 표현 목록은 늘리지 않았다
- `judge/golden_set_stage2/cases.json` 에 합성 케이스 18개를 더했다(39 → 57개). 40 ~ 51번은 사실 보고(완료, 시작, 막힘, 재개, `source=chat` 리마인드 답장 말투), 52 ~ 56번은 완료처럼 들리지만 완료가 아닌 것이다. 53·54번은 일정·범위 변경으로도 읽혀 관찰용이다. 57번은 시작 전(todo) 작업을 거의 다 했다는 답장으로, done 이 아니라 in_progress 여야 한다
- `judge/golden_set_stage2/README.md` 에 새 묶음을 적었다
- `tests/test_final_judge.py` 에 프롬프트가 원칙을 담는지 보는 테스트를 더했다

## 왜

회의 진척은 "붙였어요", "QA 넘겼어요" 처럼 한 일을 사실로 말하는 경우가 많다. 이걸 버리면 태스크가 이전 상태로 남고, 리마인드 답장 판단도 "명세서 올렸어요" 같은 답을 놓친다. 무엇을 완료로 볼지는 [0033](2026-11-04-0033-status-done-handover.md)에 있다.

## 결과

`python -m judge.eval_final_judge` 와 같은 평가를 실제 Terra(`gpt-5.6-terra`, reasoning medium)로 돌렸다. 고치기 전은 develop 프롬프트, 고친 뒤는 이 PR 의 마지막 프롬프트이고 케이스 묶음은 같다. 40번부터는 손으로 만든 합성 발화라 실제 회의 정답률이 아니다.

| 묶음 | 고치기 전 (2회) | 고친 뒤 (3회) |
|---|---|---|
| 기존 1 ~ 39 | 36/37, 36/37 | 37/37, 37/37, 37/37 |
| 기존 진척 23 ~ 25·28 | 3/4, 3/4 | 4/4, 4/4, 4/4 |
| 바뀌는 것 없음 26·27·29·30·33·34 | 6/6, 6/6 | 6/6, 6/6, 6/6 |
| 새 사실 보고 40 ~ 51 | 9/12, 10/12 | 12/12, 12/12, 12/12 |
| 새 완료 아님 52 ~ 56 (채점 3개) | 3/3, 3/3 | 3/3, 3/3, 3/3 |
| 완료 오판 (정답이 done 아닌데 done, 관찰 케이스 포함) | 0, 0 | 0, 0, 0 |
| 호출 에러 | 0 | 0 |

- 고치기 전 실패는 25번(진행 중인데 바뀌는 것 없음으로 봄), 42번(QA 넘김을 진행 중으로 봄, 1/2), 43번(오늘부터 잡았다를 status 없이 담당자 지정으로만 봄), 50번(PR 올리고 리뷰 대기를 진행 중으로 봄)이다
- 23번("로그인 API 붙였고요")은 고치기 전에도 2/2 통과했다. 이슈의 10/11 측정(develop 2/2 실패)과 다르다. 실패가 늘 재현되는 것은 아니다
- 중간 문구 둘은 버렸다. 1차 문구는 QA 넘김과 리뷰 대기를 3회 모두 blocked 로 봤다. 2차 문구("다음 사람에게 넘겼을 때만 done")는 23번을 3회 중 2회 놓쳤다
- 57번은 위 표를 잰 뒤 더했다. 같은 최종 프롬프트로 이 케이스만 3회 돌려 3/3 in_progress 였다. "끝냈는지 확실하지 않으면 지금 상태를 그대로 둔다" 가 todo 를 붙잡아 시작을 놓칠 수 있다는 걱정을 재 본 것이고, 재현되지 않아 프롬프트는 그대로 뒀다
- 반복 수가 적다(2회, 3회). 한 케이스의 정답률은 통과 횟수로만 읽는다
- 비용: 622회, 2,394원. 제3자 표기 단가($2/1M 입력, $12/1M 출력, 1달러 1,450원)로 계산한 추정이고 Elice 실제 단가가 아니다. 1회(56건)는 약 220원
- `pytest`: 1066 passed
