# 봇이 승인된 리마인드를 DM 으로 보내고 팀원 답장을 대화에 넣는다

- 날짜: 2026-11-04
- 이슈: #317
- PR: #PRNUM
- 브랜치: `feature/317-bot-reminder-dm`

## 한 일

`ai/capture/dm.py` 에 `DmCog` 를 더했다. 5초마다 BE 에서 보낼 메시지를 가져와 DM 으로 보내고 결과를 보고한다. 2,000자가 넘는 본문은 나눠 보낸다. 팀원이 봇에게 쓴 DM 은 바로 BE 대화에 넣는다. 30초마다 AI 초안이 필요한 묶음을 가져와 `draft_reminder` 로 쓴 글을 넣는다. BE 설정이 있을 때만 `capture/run_recorder.py` 가 이 Cog 를 붙인다.

발송 결과와 넘기지 못한 답장은 `recordings/.bot/dm/` 파일에 먼저 적어 재시작해도 남긴다. 게이트웨이에 붙을 때마다 끊긴 동안 온 DM 을 기록에서 메운다.

첫 DM 에는 PM 소개를, 그다음부터는 PM 이름을 BE 가 틀로 씌운다(`backend/app/services/messages.py`). 초안은 마감을 묻는 가운데만 쓰도록 프롬프트와 검사를 바꿨다. 첫 DM 이 delivered 되면 승인 전 묶음을 두 번째 틀로 다시 만든다.

두 계약 문서의 리마인드 절을 구현에 맞췄다.

## 왜

PM 이 승인한 리마인드가 팀원에게 실제로 닿고 답장이 PM 에게 돌아와야 리마인드 기능이 돈다. 파일 기록과 메우기는 [결정 기록 0035](2026-11-04-0035-bot-dm-local-journal-and-backfill.md), 문구 틀은 [결정 기록 0037](2026-11-04-0037-reminder-dm-frame.md).

## 결과

로컬 BE 와 테스트 디스코드 서버, 받는 사람 한 명으로 확인했다. 스크린샷은 없다.

| 확인 | 결과 |
|---|---|
| 승인한 리마인드 발송 | 디스코드에 도착, `delivered` |
| 디스코드 답장 기능으로 단 답장 | 201, 대화에 팀원 글 추가 |
| 봇을 끈 동안 보낸 DM | 재시작 직후 대화에 들어옴, 중복 없음 |
| AI 초안 | 승인 후 그 문구로 `delivered` |
| 첫 틀과 두 번째 틀 | 첫 DM 은 소개와 맺음 포함, delivered 뒤 다음 묶음이 소개 없는 틀과 새 초안으로 바뀜 |
| 같은 nonce 로 두 번 전송 | 같은 메시지 id, 글 하나 |

답장 대상 id 전송과 메우기 표시를 읽은 데까지만 옮기는 동작은 단위 테스트로만 확인했다. 실제 디스코드로 다시 돌리지는 않았다.

| 테스트 | 결과 |
|---|---|
| `cd ai && .venv/bin/python -m pytest -q -o addopts=""` | 1150 passed |
| `cd backend && .venv/bin/python -m pytest -q` | 873 passed, 399 skipped |
| 같은 명령, Postgres 연결 | 1267 passed, 5 skipped |

비용은 Luna 5회 15원이다.
