# 0039. GPU 전사 서버는 장애 때만 켜고 주 전사기로 바꾸지 않는다

- 날짜: 2026-11-04
- 상태: 검토중

## 배경

Elice 옛 주소가 9/29 부터 약 7일 응답하지 않았고, 그때의 폴백인 운영 EC2 CPU 의 로컬 turbo 는 회의 1분당 81 ~ 87초가 걸린다. [0019](../member/2026-10-07-0019-elice-api-default-local-fallback.md) 는 Elice 를 기본, 로컬을 장애 대응으로 정했고 장애가 되풀이되면 전환 장치를 다시 보기로 했다. 그래서 GPU 서버를 장애 대응으로 둘지, 사용량이 늘면 주 전사기로 바꿀지 정할 숫자가 필요했다. 이 서버는 이어지는 LoRA 학습 모델을 올릴 바탕이기도 하다.

쓸 수 있는 돈은 개인 AWS 크레딧 $120 이고, 이 안에서 측정, 장애 대응, LoRA 학습까지 끝내야 한다. 크레딧 만료일과 적용 서비스는 아직 확인하지 못했다.

전체 측정값과 재현 명령은 [결과 문서](../../../stt/eval/results/2026-11-04-gpu-serving/README.md) 에 있다.

| 항목 | Elice | T4 large-v3 | T4 turbo | 운영 CPU turbo |
|---|---|---|---|---|
| 6인 CER m01 / m02 | 6.52% / 4.86% | 6.52% / 4.86% | 6.65% / 4.99% | 5.33% / 4.99% |
| 9/29 실녹음 CER | 21.2% | 21.1% | 20.2% | 21.9% |
| 62.42분 합성 전사 | 65.07초 | 159.8초 | 68.9초 | 84.93분 |
| 회의 1시간당 전사 | 62.5초 | 153.6초 | 66.2초 | 81.6분 |
| m01 5개 동시 | 9.58초 | 29.86초 | 12.56초 | 재지 않음 |
| 처리량(회의 길이 기준, m01 10개) | 재지 않음 | 약 25배 | 약 60배 | 0.7배 |

콜드 스타트는 AMI 기본 gp3 로 22.1분, EBS 볼륨 초기화 속도 300MiB/s 로 5.0분이다. 표본은 각 한 번이고, 프로세스만 재시작하면 1분 안에 뜬다.

## 비용 모델

단가는 서울 온디맨드로 g4dn.xlarge $0.647/시간, gp3 $0.0912/GB-월, 스냅샷 $0.05/GB-월, 볼륨 초기화 $0.0041/GB(300MiB/s 등급으로 추정), Spot 은 11월 초 조회값 약 $0.32/시간이다. 환율은 ₩1,400 으로 가정했다.

Elice 단가는 ₩6/60초로 확인했다. 호출마다 최소 1분이 잡히는지는 확인하지 못했다. 보낸 오디오 초로 계산하면 회의 1시간당 오디오 27 ~ 56분, 162 ~ 338원이다. 호출당 최소 1분이면 438 ~ 1,030원이다(#154 계산값).

| 방식 | 고정비 | 쓸 때 드는 돈 | 비고 |
|---|---|---|---|
| Elice | 0 | 회의 1시간당 ₩162 ~ 338 | 팀 크레딧 월 12만원을 LLM 과 나눠 쓴다 |
| 장애 대응, 꺼 둔 대기 | 스냅샷 73GB 월 $3.65(₩5,110) | 켤 때마다 약 $0.39(₩550) | 켤 때 초기화 $0.30, 5분 부팅과 전사와 끄기 전 1분까지 약 8.6분 $0.09 로 계산 |
| 주 전사기 상시, 온디맨드 | 월 $479(₩670,800) | 0 | 인스턴스 730시간 $472 + 디스크 75GB $6.84 |
| 주 전사기 상시, Spot | 월 $240(₩336,600) | 0 | 회수될 수 있고 Spot 할당량이 없다 |
| 서버리스 GPU, 회의마다 | 0 | 회의 1시간당 약 ₩35 + 콜드 스타트 시간 | Modal T4 $0.000164/초 × 153.6초로 계산. CPU·메모리 별도, 콜드 스타트도 과금. RunPod 16GB 등급은 $0.58/시간부터. 둘 다 재지 않았다 |

회의 한 건마다 켜고 끄면 ₩550 으로 Elice 회의 1시간 값의 1.6 ~ 3.4배다. 장애 때 회의를 모아 한 번에 돌리면 그만큼 줄지만, 평소에 Elice 대신 쓸 이유는 없다. 7일 장애 동안 24시간 켜 두면 168시간 $111 로 예산을 거의 다 쓴다. 장애 때도 켜 두지 않고 처리할 회의가 있을 때만 켠다.

## 검토한 선택지

- 지금처럼 CPU 폴백만 둔다: 추가 비용이 없다. 대신 60분 회의가 81.6분 걸려 초안 10분 기준을 넘고, 전사 동안 운영 서버 메모리를 많이 쓴다.
- GPU 서버를 장애 때만 켠다: 평소 고정비가 스냅샷 월 ₩5,110 이다. 62.42분 회의가 부팅 5.0분 + 전사 2.7분, 7.7분에 끝나 10분 안에 들어온다(계산값). CER 이 Elice 와 같아 장애 전후 결과 품질이 달라지지 않는다. 켜고 끄는 절차를 만들어야 한다.
- GPU 서버를 주 전사기로 상시 둔다: 콜드 스타트가 없고 LoRA 모델을 바로 쓸 수 있다. 월 ₩670,800 이면 크레딧 $120 가 약 8일에 끝난다.
- 서버리스 GPU 를 쓴다: 쓰지 않을 때 비용이 0 이고 회의당 값이 가장 싸다. 콜드 스타트와 속도를 재지 않았고, 새 계정과 회의 음성의 외부 전송을 팀이 정해야 한다. 업체별 장애 이력도 보지 않았다.

모델은 turbo 가 2.3배 빠르다. 하지만 62.42분 회의 전사가 2.7분이면 10분 기준 안이고, large-v3 는 Elice 와 전사문이 같으며 LoRA 비교 기준선이기도 하다. 그래서 large-v3 로 둔다.

## 결정

GPU 서버는 장애 대응으로만 두고 주 전사기로 바꾸지 않는다. large-v3 를 넣은 AMI 를 보관하고, 장애 때 볼륨 초기화 300MiB/s 로 g4dn.xlarge 를 띄워 처리할 회의가 있을 때만 켠다. 장애 대응 기간은 2026-11-12 까지이고, AMI 는 LoRA 학습 후 측정이 끝나면 지운다.

우리 규모에서는 Elice 가 싸다. 상시 GPU 가 Elice 와 같아지려면 아래 손익분기처럼 지금보다 수십 팀 규모가 되어야 한다. 폴백 연결 코드는 다음 PR 에서 한다. 그때 운영 서버에서 부를 경로와 인증서를 정해야 한다. 지금 서버는 localhost 로만 받고 AMI 의 자체 서명 인증서는 2026-11-07 에 만료되어, 켤 때 새로 만들어야 한다.

## 다시 볼 조건

상시 GPU 의 손익분기는 월 고정비 ÷ Elice 오디오 1시간 값(₩360)으로 구한다. 회의시간은 회의 1시간당 오디오 27 ~ 56분으로 바꾸고, 팀 수는 팀당 월 회의 40시간을 가정했다.

| 상시 GPU | 월 오디오 | 월 회의시간 | 팀 수 |
|---|---|---|---|
| 온디맨드 ₩670,800 | 1,863시간 | 2,000 ~ 4,140시간 | 50 ~ 104 |
| Spot ₩336,600 | 935시간 | 1,000 ~ 2,080시간 | 25 ~ 52 |

- 월 보낸 오디오가 935시간을 넘기면 Spot 상시를, 1,863시간을 넘기면 온디맨드 상시를 다시 계산한다.
- Elice 호출마다 최소 1분이 잡히는 것으로 확인되면 온디맨드 손익분기가 월 회의 650 ~ 1,530시간으로 내려간다.
- Elice 전사로 크레딧 월 12만원을 넘기면 다시 본다. 전사에만 다 쓴다고 해도 월 오디오 333시간(9 ~ 18팀)이라 상시 GPU 손익분기보다 먼저 온다.
- LoRA 모델이 large-v3 보다 CER 이 뚜렷이 낮으면 다시 본다. Elice 에는 그 모델을 올릴 수 없어 이 표의 비용 비교만으로 정할 수 없다.
- Elice 장애가 복구 재시도 상한을 넘겨 되풀이되면, 켜고 끄는 절차를 자동화할지 정한다.
- 크레딧 만료일이나 적용 서비스가 이 배분과 맞지 않으면 예산표를 고친다.
- 콜드 스타트가 다시 재어도 10분 기준을 넘기면 AMI 를 줄이거나 모델을 다른 저장소에 둔다.
