# 0033. 상태 단어 없는 진척 보고에서 무엇을 완료로 보는가

- 날짜: 2026-11-04
- 상태: 결정됨

## 배경

Terra 2단계 프롬프트(`judge/final_judge.py`)는 status 를 "진행 상태가 명시적으로 언급됐을 때만" 채웠다. 회의와 리마인드 답장에서는 "붙였어요", "QA 넘겼어요", "PR 올렸어요" 처럼 한 일을 사실로 말하는 경우가 많아서, 이 규칙이 "상태 단어가 있을 때만" 으로 읽히면 진척 보고를 버린다(#207). 이슈의 방향은 표현 목록을 늘리지 않고 판단 원칙을 바꾸는 것이다.

원칙으로 바꾸면 경계를 정해야 한다. 잘못 완료로 올리는 것이 놓치는 것보다 나쁘다는 기준(멘토: AI 판단만으로 auto 승격 금지, 판단 불가 허용)과, 남의 검토가 남은 보고(PR 리뷰 전, QA 전)를 어떻게 볼지가 부딪혔다.

## 검토한 선택지

- 남의 확인이 남았으면 완료 아님: PR 만 올림과 리뷰 대기를 완료로 올리지 않는다. 측정에서 이 두 케이스의 완료 오판은 0/6 이었다. 그런데 원칙만으로 쓰면 QA 넘김도 완료가 아니게 된다. QA 만 완료로 두려고 "다음 사람에게 넘겼을 때만 done" 으로 좁히자, 넘길 상대 없이 끝낸 일("로그인 API 붙였고요", 23번)을 3회 중 2회 놓쳤다
- 담당자가 맡은 일을 끝냈다고 보고하면 완료: PR 올림, QA 넘김, 배포, 명세서 올림을 모두 완료로 제안한다. 원칙이 하나라 표현 목록이 필요 없고, #207 본문의 재환 표("QA 넘겼어요" 는 완료)와도 맞다. 머지 전에 태스크가 완료로 보이는 기간이 생긴다
- 표현마다 규칙을 둠("PR 은 아니고 QA 는 맞다"): 이슈의 고칠 방향과 어긋나서 시도하지 않았다

## 결정

담당자가 맡은 일을 끝냈다고 사실로 보고하면(결과물을 다음 사람에게 넘긴 것 포함) done 이다. 넘긴 뒤 남의 검토나 확인을 기다리는 것은 막힘이 아니다. 앞으로 할 예정, 일부만 함, 거의 함처럼 끝냈는지 확실하지 않으면 done 으로 올리지 않고 지금 상태를 둔다.

PR 올림을 완료로 둘 수 있는 것은 자동 반영 문이 따로 있기 때문이다. 지금 AI 의 기존 태스크 수정 제안은 모두 PM 확인을 거친다. 리마인드 답장 판단(앞으로 만들 기능)은 변경마다 신뢰도를 매겨 certain 만 자동 반영하고, 원문에 끝났다고 명시되지 않은 완료는 certain 이 되지 않게 하기로 했다(`notes` 의 P4 몫으로 넘김). "검토 대기는 막힘이 아니다" 를 넣은 것은 1차 문구에서 QA 넘김과 리뷰 대기를 3회 모두 blocked 로 본 측정 때문이다.

측정은 [진행 로그](2026-11-04-terra-implicit-progress-status.md)에 있다. 최종 문구는 56개 케이스(40번부터 합성)에서 3회 모두 52/52, 완료 오판 0건이었다.

## 다시 볼 조건

- 리마인드 답장 판단의 상태 변경 신뢰도 평가가 사실 보고 완료를 certain 으로 내보내면, 자동 반영 전에 이 결정을 다시 본다
- 운영에서 PM 이 "PR 올림 → 완료" 제안을 자주 반려하거나, 리뷰 뒤 같은 태스크가 다시 진행 중으로 돌아가는 일이 잦으면 완료 기준을 머지로 옮긴다
- 상태에 "검토 중" 같은 칸이 생기면 PR 올림과 QA 넘김은 그 상태로 보낸다
