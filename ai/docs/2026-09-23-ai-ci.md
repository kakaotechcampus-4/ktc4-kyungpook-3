# AI 파트 CI(ai-ci.yml) 추가

- 날짜: 2026-09-23
- 브랜치: chore/ai-ci
- 작성자: 유재환

## 한 일

`.github/workflows/ai-ci.yml` 신설 — `ai/**` 변경이 있는 PR(→ develop)마다 `ai/` 전체
pytest 스위트(421개)를 자동 실행. `frontend-ci.yml`과 같은 패턴(프로젝트 단위 1개 워크플로).

## 왜

지금까지 AI 파트 PR엔 테스트를 자동으로 돌리는 CI가 하나도 없었다(확인 결과 `frontend-ci`만
있었고, `convention-check`/`assign-mentor`/`notify-discord`는 테스트가 아니라 `develop→main`
PR 프로세스 자동화용). 사람이 로컬에서 pytest를 안 돌리고 올려도 잡아낼 방법이 없었다.

기능(capture/stt/judge)별로 워크플로를 쪼갤지 고민했는데, 안 쪼개기로 했다:
- `shared/schemas.py`처럼 여러 모듈이 공유하는 파일 하나 고치면 여러 모듈이 동시에 깨질 수
  있어서, 부분 실행은 오히려 위험
- 421개 전체가 44초면 끝나서 쪼갤 만큼 느리지도 않음
- 이미 "기능 단위 분리"는 프로젝트 레벨(frontend-ci/ai-ci)에서 하고 있음

## 결과

secrets(API 키) 불필요 — pytest 스위트는 전부 `FakeLLM`/`NullLLM`/`NullEmbedder` 기반이라
실제 API 호출 없음. 실제 API를 쓰는 `eval_*.py`들은 원래부터 pytest 밖에 있어서 CI 대상이 아님.
