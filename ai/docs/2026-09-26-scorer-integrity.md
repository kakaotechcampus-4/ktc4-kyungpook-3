### 판단 단위의 정답과 앵커 분리

골든셋 라벨은 "이 **문장**이 후보인가"(문장 단위)인데, 판단 단위는 "결정 하나"(스팬)다.
한 기준으로 둘 다 재면 어느 쪽이든 틀린 점수가 나온다.

한 결정이 두 문장에 걸치고 골든셋이 둘 다 `True` 로 라벨한 경우, 앵커는 하나뿐이라
앵커 기준으로만 재면 **나머지 하나가 구조적으로 영원히 놓침**이 된다. `long/case_03` 실측:

```
골든셋 라벨:
  should_flag=True  '로그인 마감은 이번 주 목요일로 하기로 했습니다.'   (일정 결정)
  should_flag=True  '네, 그리고 담당자는 저로 하겠습니다.'              (담당자 자기지칭)

Luna 출력 (결정을 정확히 잡음):
  summary  : 로그인 작업은 이번 주 목요일까지 마감하며, 담당자는 B로 정했습니다.
  evidence : ['로그인 마감은 이번 주 목요일로 하기로 했습니다.',
              '네, 그리고 담당자는 저로 하겠습니다.']     ← 앵커는 뒤쪽
  → 앞 문장이 "놓침"으로 찍힘
```

반대로 근거에 딸려온 문장까지 전부 후보로 세면, "~게 어때요?" 같은 제안이 합의와 한 건으로
묶였을 때 통째로 오탐이 된다(2026-09-23 실측 8건). 그래서 둘을 나눴다.

```
should_flag=True  → 근거 어디에든 들어왔으면 정답   (그 결정이 2단계로 넘어갔는가)
should_flag=False → 앵커일 때만 오답               (잡음을 후보로 세웠는가)
```

### 라벨 밖 출력 · 중복 출력

채점기가 **골든셋 라벨만 순회**하고 출력 쪽은 아무도 안 봤다.

```python
for exp in case["expected"]:          # 라벨 기준으로만
    was_flagged = exp["text"] in flagged
```

**라벨 밖 출력.** 라벨에 없는 문장을 후보로 내면 오답으로도 안 잡히고 경고도 안 떴다.
지금 골든셋은 전 문장에 라벨이 붙어 있어 실제로는 안 터지지만, 그걸 지키는 장치가 없었다 —
기존 테스트가 `라벨 → 문장` 한 방향만 봐서, 라벨을 빠뜨린 케이스를 새로 추가하면 그 문장의
오탐이 조용히 점수에서 빠진다.

**중복 출력.** `flagged` 가 `set` 이라 같은 앵커로 findings 가 두 건 나와도 한 건으로 셌다.
한 결정이 여러 건으로 쪼개지는 건 **`indices` 도입으로 고치려던 문제 그 자체**인데
(잡음 8턴 회의에서 실측), 채점기가 그걸 못 보니 고쳤는지 확인할 방법이 없었다.

## 결과

골든셋 25케이스 (실제 Luna API): **Luna 334/340 (98%)** · 규칙 279/340 (82%).
정답/앵커 분리 전은 330/340 (97%) 이었다.

**놓침(기대=True 인데 못 잡음)이 전부 사라졌다.** 남은 Luna 오답 6건은 전부 오탐이고,
그중 5건이 `"네 그거 확인해볼게요"` / `"나중에 자료로 공유드릴게요"` 계열이다 — 골든셋은
잡담으로 라벨했지만 새 약속에 가까워서 라벨 쪽을 재환님과 정해야 하는 항목(PR #78 에 기재).
즉 지금 남은 오답은 모델 문제가 아니라 **라벨 합의 문제**로 좁혀졌다.

**라벨 밖 출력 0건, 중복 출력 0건.** 이쪽은 점수가 안 움직인 게 결과다 — 부풀려져 있던
점수를 깎은 게 아니라, **`indices` 가 결정 쪼개짐을 실제로 없앴다는 걸 채점기가 처음으로
확인해준 것**이다. 이전 채점기로는 0건인지 아닌지를 알 수가 없었다.
