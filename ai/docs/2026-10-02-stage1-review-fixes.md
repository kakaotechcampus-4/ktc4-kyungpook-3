## 왜

BE 는 `assignee_type=first` 의 담당자를 근거 **마지막 줄의 화자**(`evidence_speaker`)로 찾는다.
"제가 맡을게요"(A) 뒤에 "네, 감사합니다"(B)가 같은 근거로 묶이면 분류는 `first` 로 맞아도 B 가
담당자가 된다. 기존 골든셋은 분류만 재서 이 오류가 점수에 드러나지 않았다.

담당자 줄 번호를 따로 받는 스키마 변경도 검토했지만, `JudgeFinding` 의 "세 값이 같은 줄" 규약을
`to_item()`(#109)·봇 uid 변환(#127)이 쓰고 있어서 먼저 프롬프트로 고치고 측정했다.

멘토가 제안한 안전장치(1인칭인데 근거 화자가 여럿이면 담당자를 확인 필요로)는 **넣지 않았다** —
아래 결과에서 틀린 담당자가 0건이었고, 안전장치는 회차마다 맞게 풀린 6~7건(speaker_dev+test)을 PM 확인으로 돌린다.

## 평가 설계 — 결과를 믿을 수 있게

이전 리뷰(#45, #78)에서 지적받은 것을 지켰다.

- **dev / test 분리.** 프롬프트는 dev 와 기존 세트의 오답만 보고 고쳤고, test 는 마지막에 한 번만 봤다.
  test 를 보고 다시 고치지 않았다
- **데이터를 먼저 고정.** 골든셋과 채점기를 프롬프트 변경 **전에** 커밋했다(`f35e25a`). 결과를 본 뒤 라벨을
  고치지 않았다(애매한 라벨 2건은 아래에 그대로 적었다)
- **구조가 다른 test.** 이름·날짜만 바꾼 변형이 아니라 맞장구 개수, 마감을 누가 말하는지, 이름으로 다시 정리,
  번복, 한 사람의 두 문장처럼 대화 구조를 바꿨다. 프롬프트 예시('오케이', '네네', '든든하네요')는 두 세트에 없는 문장이다
- **반복 측정.** 모델 temperature 가 1 고정이라 같은 조건을 3회씩 돌렸다
- **호출 실패 포함.** 실패를 건너뛰지 않고 세며, 전부 0건이다. 중간에 네트워크가 끊겨 실패 2건이 섞인
  측정은 결과를 버리고 다시 돌렸다
- **분류가 아니라 결과.** 담당자 채점은 assignee_type 이 아니라 BE 가 찾게 될 사람을 본다

### 채점기 수정 (#137 CodeRabbit)

처음 채점기는 라벨 문장을 근거로 든 finding 이 여럿이면 **앵커가 맞는 하나만** 봤다. 같은 결정이 [본인 줄] 과
[본인 줄, 맞장구] 두 건으로 나오면 BE 에 두 항목이 가는데 뒤의 틀린 담당자를 세지 못한다. 이제 그 문장을 근거로
든 finding 을 전부 보고, 하나라도 다른 사람으로 풀리면 틀림으로 센다(이전 채점기에선 실패하는 테스트를 먼저 확인).

같은 채점기로 두 프롬프트를 다시 쟀다. 기준선은 1/30·2/39 → **2/30·4/39** 로 늘었고(이전 채점기가 덜 셌다),
최종은 **0/30·0/39** 그대로다.
