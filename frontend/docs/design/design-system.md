## 0. 확정된 제품 결정 (디자인 전제)

| # | 결정 | 디자인에 미치는 영향 |
|---|---|---|
| 1 | **웹의 사용자는 PM 한 명.** 팀원은 디스코드만 만진다 | 권한·역할 UI 없음. 화면은 "내가 지금 처리할 것" 중심 |
| 2 | **모든 승인은 웹에서.** 디스코드는 알림만 | 디스코드 embed 불필요. **알림 → 해당 카드 딥링크**가 필수 |
| 3 | **신뢰도는 3단 배지로만.** 원시 소수(0.92) 노출 금지 | 배지 3종 + "왜 확인이 필요한지" 이유 캡션이 정보 구조의 축 |
| 4 | **회색은 누를 수 있는 곳에만.** 콘텐츠 면은 흰색 | 카드·패널은 흰 면 + 1px 헤어라인. 회색 채움은 탭·버튼·배지·선택된 행에만 |

## 1. 디자인 원칙

### 1-1. 확정된 사실과 AI의 추측을 눈으로 구분한다

이 제품 화면의 절반은 확률적 산출물이다. 사용자가 "이건 확정인가, AI가 그렇게 본 것인가"를 **읽지 않고 알아야** 한다. 확정도는 색이 아니라 **배지 농도·점·카드 테두리·눌린 면**으로 표현한다.

### 1-2. 회색은 누를 수 있거나 상태를 말하는 것에만 쓴다

콘텐츠가 앉는 면은 전부 흰색이다. 회색 면은 탭·버튼·배지·선택된 행처럼 **누를 수 있거나 등급을 말하는 것**에만 쓴다. 승인 화면에 유채색이 있으면 PM은 전부 훑고 아무것도 판단하지 못한다.

### 1-3. 되돌릴 수 있는 것과 없는 것을 다르게 그린다

노션 게시는 되돌릴 수 있고, 디스코드 DM 발송은 되돌릴 수 없다. 발송 관련 화면은 폭을 좁히고 다른 액션을 같은 화면에 두지 않는다.

### 1-4. 숫자에는 항상 기준 시각을 붙인다

`API 명세서 10%`는 자기보고 값이다. **모든 진행률·상태값 옆에 기준 시각**을 상시 노출하고, 오래된 값은 대비를 낮춘다.

### 1-5. 판단을 유도하는 UI를 만들지 않는다

`전체 승인` 버튼, 신뢰도 점수, 초록 자동 게시 배지는 rubber stamp를 만든다. 자세한 금지 목록은 [12. 금지 목록](#12-금지-목록-donts).

## 2. 시각 톤 (확정)

라이트 모드 한 벌. 옆 창이 노션(라이트)과 번갈아 보이므로 이질감을 만들지 않는다.

| | 값 |
|---|---|
| 기본 모드 | 라이트 |
| 중성 | 차가운 무채 회색. 베이지·블루 기운 없음 |
| 유채색 | **쓰지 않는다.** 상태·리스크도 회색 농도와 점(채움/빈/없음)으로만 |
| 주 액션 | `#202020` 채움, 흰 글자. **화면당 하나** |
| 밀도 | 본문 14px / 행간 1.75. 여유 있게 |

## 3. 컬러

### 3-1. 면 · 경계 · 컨트롤

| 역할 | 용도 | 값 |
|---|---|---|
| `page` | 페이지 배경 | `#FFFFFF` |
| `recessed` | 눌린 면 (근거 블록, 보류 카드) | `#FAFAFA` |
| `card` | 카드·패널 | `#FFFFFF` + `line` |
| `button` | 보조 버튼·칩 면 | `#EDEDED` |
| `badge-strong` | 확인 필요 배지 | `#E5E5E5` |
| `badge-hold` | 보류 배지 | `#EEEEEE` |
| `tab-active` | 활성 탭 | `#F0F0F0` |
| `count` | 탭 건수 배지 | `#E9E9E9` |
| `avatar` | 아바타 배경 | `#EFEFEF` |
| `line` | 기본 헤어라인 | `#E8E8E8` |
| `line-header` | 헤더 하단 | `#EFEFEF` |
| `line-review` | 확인 필요 카드 테두리 | `#C9C9C9` |
| `control-line` | 입력 경계 · 아이콘 | `#949494` |
| `ink` | 제목·본문 | `#171717` |
| `ink-sub` | 보조 설명 | `#5A5A5A` |
| `ink-faint` | 메타·타임스탬프 — **텍스트 최저선** | `#666666` |
| `ink-badge` | 확인 필요 배지 글자 | `#222222` |
| `ink-button` | 회색 버튼 글자 | `#292929` |
| `fill` | 주 액션 채움 | `#202020` |

> **글자에 쓰는 회색은 `#171717` · `#5A5A5A` · `#666666` 셋뿐이다.** `#949494`부터는 입력 경계와 아이콘에만 쓴다. 이보다 연한 색으로 글자를 쓰지 않는다.

### 3-2. 의미색은 없다

`ok` / `warn` / `bad` / `pri` 유채 토큰을 **만들지 않는다.** 포커스 링은 `#222222` 2px + 오프셋 4px. 링크는 `ink`, 호버 시 `ink-sub`.

리스크 3단은 배지 안의 **점**으로만 구분한다.

| 리스크 | 배지 면 | 글자 | 점 |
|---|---|---|---|
| `위험` | `#DCDCDC` | `#1A1A1A` / 700 | **채운 점** 5px |
| `주의` | `#EDEDED` | `#333333` / 600 | **빈 점** (inset 1.5px 링) |
| `정상` | `#F2F2F2` | `#666666` / 600 | 점 없음 |

배지 옆에는 언제나 **진행률 숫자와 마감 날짜**가 함께 있다. 색 정보 없이도 구분돼야 한다.

### 3-3. 확정도 — 배지와 면

| 상태 | 의미 | 카드 | 배지 |
|---|---|---|---|
| `posted` 반영됨 | 확정 사실. 노션에 이미 있다 | 흰 면 + `line` | `자동 반영됨` — 면 `button`, 글자 `#555555`. 점 없음 |
| `review` 확인 필요 | 뽑았지만 필드 하나가 불확실 | 흰 면 + **`line-review`** | 점 + `확인 필요` — 면 `badge-strong`, 글자 `ink-badge` |
| `hold` 보류 | 정보 자체가 부족하다 | **`recessed`** + `line` | `− 보류` — 면 `badge-hold`, 글자 `ink-faint` |

`hold`는 경고가 아니라 미완성이다. 빼기 기호와 눌린 면이 "아직 채워지지 않았다"를 말한다.

폴링이 감지한 **변경 제안**도 `review`를 그대로 쓴다. 새 상태를 만들지 않는다.

### 3-4. 대비 기준

| 대상 | 최소 대비 |
|---|---|
| 본문·라벨 (14px 이하) | 4.5:1 |
| 큰 텍스트 (19px 이상 / 15px bold) | 3:1 |
| 경계선·아이콘 등 비텍스트 | 3:1 |

`ink-faint` `#666666` on `#FFFFFF`는 이 선의 하한이다. 캘린더 부제·로그 목록이 이 선을 넘지 않게 한다.

| 폰트 | 용도 |

| **IBM Plex Sans KR** (캔버스 대체) | 캔버스에 원안 웹폰트를 실을 수 없어 임시 대체. 400 / 500 / 600 / 700 |

### 4-1. 스케일

| 이름 | 크기 / 행간 / 자간 | 굵기 | 용도 |
|---|---|---|---|
| `display` | 64 / 1.28 / −0.045em | 700 | 랜딩 히어로 |
| `h1` | 32 / 1.4 / −0.045em | 700 | 화면 제목 ("확인이 필요한 일 3개") |
| `h2` | 19 / 1.55 / −0.025em | 700 | 섹션·카드 제목 |
| `h2-tight` | 15 / 1.45 | 600 | 목록 행 제목, 섹션 소제목 |
| `body` | 14 / 1.75 / 0 | 400 | 본문 |
| `caption` | 13.5 / 1.85 | 400 | 이유 캡션, 보조 문장 (`ink-sub`) |
| `sm` | 13 / 1.55 | 600 | 버튼, 탭, 필드 값 |
| `xs` | 11.5 / 1.45 | 600 | 배지, 메타, 타임스탬프 |

### 4-2. 한글 규칙

- 본문 행간을 **1.75 미만으로 내리지 않는다.** 캡션은 1.85
- **자간을 조이지 않는다.** 트래킹은 0. 제목만 −0.045em / −0.025em
- 굵기는 400 / 500 / 600 / 700. 버튼·탭·배지는 600
- 한 줄 길이는 본문 **최대 78자** (약 640px)
- 줄바꿈은 `word-break: keep-all`

## 7. 컴포넌트

### 7-1. 배지 — 확정도 3단 (핵심)

원시 신뢰도 숫자를 절대 넣지 않는다.

| 배지 | 라벨 | 면 | 글자 | 점 |
|---|---|---|---|---|
| 확인 필요 | `확인 필요` | `badge-strong` | `ink-badge` | 채운 5px |
| 자동 반영됨 | `자동 반영됨` | `button` | `#555555` | 없음 |
| 보류 | `− 보류` | `badge-hold` | `ink-faint` | 없음 (빼기 기호) |

- 높이 21–22px, 가로 패딩 8–9px, 반경 6, `xs` / 600
- 배지는 **등급만** 말한다. "왜"는 바로 아래 **이유 캡션**이 말한다 (§9-1)

```
확인 필요   발표 준비                    31:05     [확인하기]
담당자 후보가 둘 — 서연 / 지민
```

### 7-2. 상태 칩 — 라이프사이클 vs 리스크

라이프사이클과 리스크는 다른 축이다.

| 축 | 값 | 표현 |
|---|---|---|
| 라이프사이클 | `시작 전` · `진행 중` · `완료` | 무채색 칩 (`button` 면, `ink-sub`) |
| 라이프사이클 예외 | `막힘` | `위험` 배지와 같이 쓴다 |
| 리스크 | `정상` · `주의` · `위험` | §3-2 점 3단 |

한 행에 두 축이 함께 올 수 있다: `진행 중` + `주의`.

### 7-3. 승인 행 · 승인 카드

대시보드는 **행**, 태스크 리스트는 **카드**. 확정도 표면 처리(§3-3)를 그대로 입는다.

**대시보드 행 (위→아래)**

1. 배지 + 태스크명(`h2-tight`) + 근거 시각(모노 `xs`)
2. 이유 캡션 (`caption` / `ink-sub`). `posted`에는 없음
3. 우측 액션 — `확인하기` / `채워 넣기` (`button` 면)

**태스크 카드 추가 필드**

4. 태스크명 / 담당자 / 마감 — 인라인 수정. 비어 있으면 라벨이 `골라 주세요` · `날짜를 정해 주세요`로 바뀌고 입력 경계가 `ink`
5. 근거 블록 (§7-4)
6. 액션 행

| 확정도 | 액션 |
|---|---|
| 반영됨 | `되돌리기` 만. **승인 버튼 없음** |
| 확인 필요 | `반려` · `승인하고 반영` (주 액션 1개) |
| 보류 | `이 건은 버리기` · `직접 채워 넣기`. 승인은 필드를 채운 뒤에만 |

**결정 후**: 카드는 사라지지 않고 `승인함` / `반려됨` 표식을 붙인 채 자리를 유지한다.

주 액션 라벨은 **`승인하고 반영`**. `승인`만 쓰지 않는다 — 동작이 노션 반영임을 밝힌다.

### 7-4. 근거 블록

```
전사문 12:40 · 재환
"API 명세서는 제가 목요일까지 정리해서 올릴게요"
원문 듣기
```

- 배경 `recessed`, 패딩 18×20, 반경 12. 좌측 액센트 색 없음
- 출처는 `xs` / `ink-faint`. 형식: `전사문 12:40 · 재환`
- 인용은 `caption`/`body`, `ink`, 큰따옴표 포함. **요약하지 않고 원문 그대로**
- `원문 듣기` — 녹음의 해당 지점으로 점프
- 근거가 없으면 **`근거 없음 — 회의에서 결정되지 않음`**을 `ink-faint`로 명시

### 7-5. 진행률 바

- 높이 6px, 반경 999, 트랙 `recessed`, 채움 `ink` (리스크는 옆 배지가 말한다)
- 숫자는 tabular
- **기준 시각 상시 노출.** 3일 이상 지난 값은 투명도 60%
- 0%는 빈 트랙 + 좌측 2px 스텁

팀원 헤더의 `평균 33%` 같은 합성 지표는 근거가 약하다. 유지한다면 계산식을 툴팁으로 밝힌다.

### 7-6. 버튼

| 종류 | 면 / 글자 | 용도 |
|---|---|---|
| 주 액션 | `fill` / `#FFFFFF` | 화면당 **1개만** (`승인하고 반영`, `정리 시작하기`, `이대로 발송`) |
| 기본 | `button` / `ink-button` | `확인하기`, `채워 넣기` |
| 고스트 | 투명 / `ink-sub` | `반려`, `이전`, `중단하기` |
| 텍스트 | 투명 / `ink-faint` | `전체 로그`, `원문 듣기` |

- 높이 최소 36px, 가로 패딩 14–18px, 반경 9, 라벨 12.5–13px / 600
- 포커스: `#222222` 2px + 오프셋 4px
- **파괴적 빨강 채움은 `삭제`에만.** `반려`·`보내지 않음`은 고스트

### 7-7. 필드

- 라벨: 12px / 600 / `ink-sub`, 입력 **위**. 채워야 하는 칸의 라벨은 `ink`
- 입력: 최소 42px (로그인·가입 50px), 패딩 13px, 경계 1px `control-line`, 반경 9, 배경 `page`
- 미입력 필수칸: 경계 `ink`
- AI 값은 그대로, PM이 고치면 라벨 옆에 `수정됨` 칩
- 마감일은 달력 피커. 텍스트 입력 금지
- 담당자는 select. `미지정`이 첫 옵션

### 7-8. 팀원 그룹 · 아바타

- 아바타: 이름 첫 글자, 면 `avatar`, 글자 `ink`. 22px (행) / 28–29px (헤더)
- **팀원별 유채 팔레트를 쓰지 않는다.** 사람 구분은 글자로만

### 7-9. 주간 일정 (캘린더)

- 7열 그리드, 오늘 열은 날짜만 `ink` 700. 유채 하이라이트 없음
- 이벤트 칩: 패딩 `sp-1`/`sp-2`, 반경 6, 면 `button`
- 변경된 마감은 원래 위치에 점선 유령 칩, 새 위치에 실선 칩

### 7-10. 반영 로그

- 항목당 1줄, 최신순. `[모노 시각] 동작 — 대상` + 우측 `되돌리기`
- 만료는 `되돌리기 불가` `ink-faint`
- 자동 반영과 PM 승인은 문구로 구분 (`자동 반영 —` / `승인 —`). 색 마커 없음

### 7-11. 앱 셸 · 탭

- 헤더 76px. 좌측 마크 24px + 탭 5개 (`대시보드` `회의록` `태스크` `메시지` `팀`) → 우측 워크스페이스 셀렉트 + 아바타
- 활성 탭: 면 `tab-active`, 글자 `ink` / 600. 하단 바 없음
- `태스크`·`메시지` 건수 배지: `count` 면, 10.5px. **0이면 숨긴다**
- 태스크 화면 내부 뷰: `리스트` / `보드` / `캘린더` 세그먼트

### 7-12. 선택 카드 · 세그먼티드

| 컴포넌트 | 규격 |
|---|---|
| 선택 카드 | 제목 `body`/600 + 설명 `sm`/`ink-sub`. 선택 시 경계 `ink` |
| 세그먼티드 | 선택 항목만 `button` 면. 2–3개 |
| 카운터 | `− [값] +`. 값은 tabular, 최소 폭 56px |

### 7-13. 상태 박스

유채 정보/성공/경고/오류 박스를 쓰지 않는다. 실패는 `recessed` 면 + `ink` 본문 + **대체 경로 버튼** (`해당 구간 들어보기`, `텍스트 회의록으로 업로드`).

### 7-14. 처리 단계 리스트

`음성을 텍스트로 옮기기` → `누가 말했는지 나누기` → `결정사항 뽑아내기` → `담당자와 마감 맞추기`

- 완료: 체크 + 경과 시간(모노)
- 진행 중: 단계명 `ink` + 경과 시간
- 대기: `ink-faint` + `대기`
- 고정 문구: `확인이 끝나기 전에는 Notion에 아무것도 쓰지 않아요`

### 7-15. 빈 상태

아이콘 32px `ink-faint` → 제목(`h2`) → 설명 2줄 이내 → 주 액션 1개.
세로 여백 `sp-10`, 폭 `narrow` 중앙.

### 7-16. 토스트

- 우하단, 면 `page` + `line`, 반경 9, 4초 후 소멸
- 되돌릴 수 있는 동작에는 `되돌리기`
- 오류는 토스트로 처리하지 않는다

### 7-17. 테이블 (담당자 매핑)

- 헤더 `recessed`, `xs`/600/`ink-sub`, 행 높이 40, 구분선 `line`
- 미매칭 행은 `확인 필요` 배지. 미매칭이 남아 있으면 온보딩 완료 버튼 비활성

## 9. 카피 규칙

### 9-1. 이유 캡션 패턴

| 불확실한 것 | 캡션 |
|---|---|
| 담당자 후보 복수 | `담당자 후보가 둘 — 서연 / 지민` |
| 담당자 미지정 | `회의에서 담당자가 정해지지 않음` |
| 마감 모호 | `마감이 "다음 주쯤"으로만 언급됨` |
| 수락 미확인 | `지명은 됐지만 본인 확인이 없음` |
| 전사 불명 | `해당 구간 인식 불가 — 원문 8:15 확인 필요` |

보류 캡션은 한 줄 더 붙일 수 있다: `— 정보가 더 필요해요`

### 9-2. 문장 규칙

- 숫자로 확신을 표현하지 않는다. `신뢰도 0.74` (✕) → `담당자 후보가 둘` (○)
- AI 판단은 단정하지 않는다. `진행률 50%입니다` (✕) → `답장 기준 50%로 봤어요` (○)
- 되돌릴 수 없는 버튼은 동작을 명시한다. `확인` (✕) → `이대로 발송` (○)
- 사용자를 주체로. `AI가 정리했습니다` (✕) → `정리해 드렸어요, 확인해 주세요` (○)
- 해요체. 오류도 해요체 + 원인 + 다음 행동
- 전문용어 비노출. `폴링` `MCP` `STT` (✕) → `1시간마다 확인` `연결` `음성 변환` (○)
- 화면 카피 예외: 태스크명·회의 맥락에 나온 말은 그대로 둘 수 있다 (`STT 파이프라인 튜닝`)

## 12. 금지 목록 (Don'ts)

| 금지 | 이유 |
|---|---|
| **`전체 승인` 버튼** | 게이트를 장식으로 만든다 |
| **신뢰도 소수점** (`0.74`) | 근거 없는 정밀도. 숫자를 본 PM은 원문을 읽지 않는다 |
| **`자동 반영됨`에 승인 버튼** | 자동화 주장이 사라진다. 되돌리기만 |
| **`보류`를 위험으로** | 보류는 정보가 부족한 것이다 |
| **`진행 중`·`시작 전`을 유색으로** | 라이프사이클은 리스크가 아니다 |
| **유채색 토큰** (`ok`/`warn`/`bad`/`pri`) | Foundations V3. 회색 농도와 점으로 충분하다 |
| **기준 시각 없는 진행률** | 자기보고를 실시간 사실로 오해한다 |
| **AI 값과 PM 수정값의 무구분** | 로그·되돌리기 근거가 사라진다 |
| **이모지 아이콘 혼용** | 디스코드로 나가는 본문만 예외 |
| **팀원용 화면·권한 UI** | 웹은 PM 전용 |
| **디스코드 embed 디자인** | 디스코드는 알림만 |
| **요약된 근거 인용** | 원문 그대로여야 검증 가능하다 |
| **오류를 토스트로** | 사라지면 대체 경로를 놓친다 |
| **콘텐츠 면에 회색 채움** | 회색은 컨트롤·상태에만 |
