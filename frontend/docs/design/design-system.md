## 1. 디자인 원칙

### 1-1. 확정된 사실과 AI의 추측을 눈으로 구분한다

이 제품 화면의 절반은 확률적 산출물이다. 사용자가 "이건 확정인가, AI가 그렇게 본 것인가"를 **읽지 않고 알아야** 한다. 확정도는 색이 아니라 **배지·점·카드 테두리·눌린 면**으로 표현한다 (§7-1).

### 1-2. 회색은 누를 수 있거나 상태를 말하는 것에만 쓴다

콘텐츠가 앉는 면은 전부 흰색이다. 회색 면은 탭·버튼·배지·선택된 행처럼 **누를 수 있거나 등급을 말하는 것**에만 쓴다. 승인 화면에 유채색이 많으면 PM은 전부 훑고 아무것도 판단하지 못한다.

### 1-3. 되돌릴 수 있는 것과 없는 것을 다르게 그린다

노션 게시는 되돌릴 수 있고, 디스코드 DM 발송은 되돌릴 수 없다. 되돌릴 수 없는 동작은 라벨에 동작을 명시한다 (`이대로 발송` — §9-2).

### 1-4. 숫자에는 항상 기준 시각을 붙인다

`API 명세서 10%`는 자기보고 값이다. **모든 진행률·상태값 옆에 기준 시각**을 상시 노출하고, 오래된 값은 대비를 낮춘다.

### 1-5. 판단을 유도하는 UI를 만들지 않는다

`전체 승인` 버튼, 신뢰도 점수, 초록 자동 게시 배지는 rubber stamp를 만든다. 자세한 금지 목록은 [12. 금지 목록](#12-금지-목록-donts).

## 3. 컬러

캔버스 22개 화면에서 실제로 쓰이는 색은 15개뿐이다. 정확한 역할별 용례·등장 횟수는
`canvas/Foundations.dc.html`의 "글자에 쓰는 회색" · "면과 선" · "강조·경고" 절 참고 — 여기서는 분류만 요약한다.

### 3-1. 글자

| 단계 | 값 | 용도 |
|---|---|---|
| 먹 | `#171717` | 제목·본문·강조·주 버튼 채움 |
| 보조 | `#5A5A5A` | 설명문·카드 부제 |
| 흐림 | `#666666` | 메타·캡션·시각·날짜 |
| 미세 | `#999999` | 플레이스홀더·비활성 버튼 글자 |

> 위 4단이 기본이지만, 선 색 `#E8E8E8`·`#BDBDBD`·`#C9C9C9`도 비활성 탭 글자나 캘린더의
> 다른 달 날짜 등에 빌려 쓰인다 — 실제로는 7단이다. `#949494`보다 연한 색으로 본문 글자를 쓰지 않는다.

### 3-2. 면 · 선 · 컨트롤

| 역할 | 값 | 용도 |
|---|---|---|
| 바탕 · 카드 | `#FFFFFF` | 페이지와 카드가 앉는 면 |
| 눌린 면 | `#FAFAFA` | 근거 블록·패널·완료 카드 |
| 선택 | `#F0F0F0` | 선택된 행·활성 탭·세그먼트 손잡이 |
| 컨트롤 | `#EDEDED` | 보조 버튼·칩·보류 배지 |
| 비활성 표식 | `#DCDCDC` | 온보딩 스텝 점·토글 트랙 (면이지 테두리가 아니다) |
| 입력 경계 | `#949494` | 입력칸 테두리 — 선 중 가장 진하다 |
| 선 | `#E8E8E8` | 카드 테두리·표 경계·리스트 구분 |
| 구분선 | `#EFEFEF` | 헤더 하단·행과 행 사이 |
| 강조 테두리 | `#C9C9C9` | 지금 봐야 하는 카드 한 겹 |
| 점선 | `#BDBDBD` | 비어 있음·아직 정해지지 않음 |

순수한 `#000000`은 어디에도 쓰지 않는다 — 매스(마스코트)의 몸·눈·타이머 버튼도 `#171717`이다.

### 3-3. 강조 · 경고 — 유일한 유채색

| | 값 | 용도 |
|---|---|---|
| 강조 · 경고 | `#FF6969` | 위험 배지, 비우면 승인이 막히는 입력의 라벨·경계선 |
| 연한 짝 | `#FF8989` | 위 입력의 플레이스홀더에만 |

`ok`/`warn`/`bad`/`pri` 같은 의미색 토큰을 **만들지 않는다.** 이 두 값 밖에서 유채색을 쓰지 않는다.

**`outline` 링은 쓰지 않기로 했다.** 테두리가 있는 컨트롤(아웃라인 버튼·입력·선택 카드)에
링을 더하면 선이 두 겹이 된다. M2 구현은 `:focus` / `:focus-visible` 모두 `outline: none`이다.
캔버스 25장에 들어 있던 `outline: 2px solid #171717; offset 4px`는 정적 목업용이며 구현에 옮기지 않았다.

**그래서 키보드 포커스 표시가 아직 없다 — §13-1은 여전히 미결이다.**
호버·눌림은 면·테두리 색으로 그리지만 둘 다 포인터 전용이라 탭 이동에는 아무 변화가 없다.
M2가 정한 것은 "`outline`을 안 쓴다"까지이고, **그 자리를 무엇으로 채울지는 정해지지 않았다.**
`WCAG 2.2 AA` SC 2.4.7을 충족하려면 M4 화면 작업 전에 `:focus-visible` 표현을 정해 이 절에 채워야 한다.

### 3-4. 확정도 — 배지와 카드 면

| 상태 | 의미 | 카드 | 표시 |
|---|---|---|---|
| 반영됨 | 확정 사실. 노션에 이미 있다 | 흰 면 + `#E8E8E8` | `자동 반영됨` — 면 `#EDEDED`, 점 없음 |
| 확인 필요 | 뽑았지만 필드 하나가 불확실 | 흰 면 + `#C9C9C9`(강조 테두리) | **채움 없음.** 5px 점(`currentColor`) + `확인 필요` 텍스트 |
| 보류 | 정보 자체가 부족하다 | `#FAFAFA`(눌린 면) + `#E8E8E8` | `보류` — 면 `#EDEDED`, 점 없음 |
| 위험 | 마감을 넘길 것 같다 | — | `위험` — 면 `#FF6969` 채움 (유일한 유채 배지) |

`보류`는 경고가 아니라 미완성이다. `확인 필요`는 **배지 필이 아니라 점 하나**로 표현된다 —
회색 배지 필로 그리면 캔버스 실물과 어긋난다. 정확한 마크업은 `canvas/Tasks.dc.html`,
`canvas/Main.dc.html` 참고.

폴링이 감지한 **변경 제안**도 `확인 필요`를 그대로 쓴다. 새 상태를 만들지 않는다.

### 3-5. 대비 기준

| 대상 | 최소 대비 |
|---|---|
| 본문·라벨 (14px 이하) | 4.5:1 |
| 큰 텍스트 (19px 이상 / 15px bold) | 3:1 |
| 경계선·아이콘 등 비텍스트 | 3:1 |

`#666666` on `#FFFFFF`는 이 선의 하한이다. 캘린더 부제·로그 목록이 이 선을 넘지 않게 한다.

## 4. 타이포그래피

| 폰트 | 상태 |
|---|---|
| **나눔스퀘어** (NanumSquare OTF, Neo 아님) | **임베드 완료.** 캔버스 전 화면이 이 웹폰트를 쓴다 |
| 숫자 | 같은 서체의 `font-variant-numeric: tabular-nums`. 별도 모노 서체 없음 |

**굵기는 Light 300 · Regular 400 · Bold 700 · ExtraBold 800 네 단뿐이다.**
`font-weight: 500`을 지정하면 조용히 400(Regular)으로, `600`을 지정하면 조용히 700(Bold)으로
대체된다 — **500은 쓰지 않는다.** 강조하고 싶으면 처음부터 600(=Bold 렌더) 또는 700을 쓴다.

Gothic A1은 후보에서 제외한다. 선언한 어센트보다 글자를 위로 1px 더 그려 배지·버튼의 세로 정렬이 어긋난다.

### 4-1. 실제 쓰이는 구간

제목(h1/h2/h3)은 화면마다 크기가 다르며 정확한 표는 `canvas/Foundations.dc.html`의
"타이포그래피" 절 참고 — 여기서는 몸통 텍스트 기준만 못박는다.

| 이름 | 크기 / 굵기 | 용도 |
|---|---|---|
| 본문 | 13.5 / 400 | 제품 화면 본문 |
| 메타 | 11.5 / 400 | mono. 시각·날짜·카운트 |
| 버튼 · 라벨 · 배지 | 13 / 600 | 캔버스에서 가장 많이 쓰이는 조합(161회) |
| 랜딩 리드 | 18 / 400 | 히어로 아래 한 줄 |
| 랜딩 본문 | 16 / 400 | 섹션 설명 |
| 캡션 | 12.5 / 400 | 카드 밑단·보조 설명 |

### 4-2. 한글 규칙

- 본문 행간을 넉넉하게 유지한다. 캡션은 본문보다 더
- **자간을 조이지 않는다.** 트래킹은 0. 제목만 음수 자간
- 지정 굵기는 사실상 **400 아니면 600**(=Bold 렌더) 둘뿐이다. 버튼·탭·배지는 600
- 한 줄 길이는 본문 기준 넉넉히 잡는다 (약 640px 안쪽)
- 줄바꿈은 `word-break: keep-all`

## 5. 간격 · 레이아웃

**고정된 4px 스케일이 아니다.** 캔버스에서 실제로 쓰는 gap·padding 값의 절반 가까이가
4의 배수가 아니다(9 · 7 · 5 · 3 · 13 · 14 · 18px 등도 흔하다). 새 화면을 그릴 때 인접
화면의 값을 그대로 재사용하고, 임의로 4px 배수에 맞추지 않는다.

### 레이아웃 폭

| 이름 | 폭 | 쓰는 화면 |
|---|---|---|
| 앱 셸 | 본문 최대 **1360px**, 안쪽 컬럼 1000px | 대시보드·태스크·회의록 등 |
| 랜딩 | 텍스트 **1024px**, 목업·카드 **1200px** | 랜딩페이지 |

### 반경 · 경계 · 고도

| 항목 | 값 |
|---|---|
| 반경 | `4` 간트 눈금 / `6` 배지 / `7` 소형 칩 / `8` 온보딩 입력 / `9` 버튼·제품 입력·컨트롤 / `10` 말풍선 / `11` 세그먼트 트랙 / `12` 칸반·인증 카드 / `16` 카드·패널 / `999`·`9999` 알약(두 값 혼용) |
| 경계 | 기본 1px. 지금 봐야 하는 카드만 `#C9C9C9`. 그림자로 고도를 만들지 않는다(거의 안 씀) |
| 헤더 | 높이 **76px**, 하단 `#EFEFEF` — 제품 화면 공통 |
| 입력 높이 | **한 규격이 아니다.** 제품 42px/`#949494`/r9, 온보딩 42px/`#C9C9C9`/r8, 로그인·가입 48px/`#C9C9C9`/r12 |

## 7. 컴포넌트

아래는 구성 원칙이다. 정확한 픽셀·색은 괄호로 표시한 화면 파일의 실제 마크업을 그대로
복사해 재사용한다 — 새로 값을 만들지 않는다.

### 7-1. 배지 — 확정도 (핵심)

원시 신뢰도 숫자를 절대 넣지 않는다. 배지는 §3-4 네 상태를 표시하고, 각 상태의 표현이
서로 다르다(필이 있는 것도, 점만 있는 것도, 유채색인 것도 있다) — 통일된 하나의 "배지"
컴포넌트가 아니라 **상태별로 다른 표현**임을 그대로 유지한다.

- 배지는 **등급만** 말한다. "왜"는 바로 아래 **이유 캡션**이 말한다 (§9-1)
- 참고: `canvas/Tasks.dc.html`, `canvas/Main.dc.html`, `canvas/TasksBoard.dc.html`, `canvas/Foundations.dc.html`

```
확인 필요   발표 준비                    31:05     [확인하기]
담당자 후보가 둘 — 서연 / 지민
```

### 7-2. 상태 칩 — 라이프사이클 vs 리스크

라이프사이클(`시작 전`·`진행 중`·`완료`)과 리스크(`정상`·`주의`·`위험`)는 다른 축이다.
한 행에 두 축이 함께 올 수 있다: `진행 중` + `위험`. 리스크 3단 중 유채색인 건 `위험`뿐이고
나머지는 무채색 칩이다.

### 7-3. 승인 행 · 승인 카드

대시보드는 **행**, 태스크 리스트는 **카드**. 확정도 표면 처리(§3-4)를 그대로 입는다.

**대시보드 행 (위→아래)**

1. 배지(또는 점+텍스트) + 태스크명 + 근거 시각(모노)
2. 이유 캡션. `반영됨`에는 없음
3. 우측 액션 — `확인하기` / `채워 넣기`

**태스크 카드 추가 필드**

4. 태스크명 / 담당자 / 마감 — 인라인 수정. 비어 있으면 라벨이 `골라 주세요` · `날짜를 정해 주세요`로 바뀌고 입력 경계가 먹
5. 근거 블록 (§7-4)
6. 액션 행

| 확정도 | 액션 |
|---|---|
| 반영됨 | `되돌리기` 만. **승인 버튼 없음** |
| 확인 필요 | `반려` · `승인` (주 버튼, 먹 채움) |
| 보류 | `직접 채우기` 등 보조 버튼. 승인은 필드를 채운 뒤에만 |

**결정 후**: 카드는 사라지지 않고 표식을 붙인 채 자리를 유지한다.

주 액션 라벨은 **`승인`**이다. (참고: `canvas/Tasks.dc.html`)

### 7-4. 근거 블록

```
전사문 12:40 · 재환
"API 명세서는 제가 목요일까지 정리해서 올릴게요"
원문 듣기
```

- 배경은 눌린 면(`#FAFAFA`), 좌측 액센트 색 없음
- 출처는 흐림 회색. 형식: `전사문 12:40 · 재환`
- 인용은 먹, 큰따옴표 포함. **요약하지 않고 원문 그대로**
- `원문 듣기` — 녹음의 해당 지점으로 점프
- 근거가 없으면 **`근거 없음 — 회의에서 결정되지 않음`**을 흐림 회색으로 명시

### 7-5. 진행률 바

- 트랙은 눌린 면, 채움은 먹. 리스크는 옆 배지가 말한다 (색으로 이중 표현하지 않는다)
- 숫자는 tabular
- **기준 시각 상시 노출.** 오래된 값은 대비를 낮춘다
- 0%는 빈 트랙

팀원 헤더의 `평균 33%` 같은 합성 지표는 근거가 약하다. 유지한다면 계산식을 툴팁으로 밝힌다 (§13-3).

### 7-6. 버튼

| 종류 | 기본 | hover | 용도 |
|---|---|---|---|
| 주 액션 | 면 `#171717` / 글자 `#FFFFFF` | 면 `#666666` / 글자 `#FFFFFF` | 화면당 **1개만** (`승인`, `정리 시작하기`, `이대로 발송`) |
| 기본 | 면 `#EDEDED` / 글자 `#171717` | 면 `#C9C9C9` / 글자 `#171717` | `확인하기`, `채워 넣기`, `직접 채우기` |
| 고스트 | 면 투명 / 글자 `#5A5A5A` | 면 `#EDEDED` | `반려`, `이전`, `중단하기` |
| 텍스트 | 면 투명 / 글자 `#999999` | 글자 `#666666` | `전체 로그`, `원문 듣기` |
| 아웃라인 | 면 `#FFFFFF` · 테두리 `1px solid #E8E8E8` / 글자 `#171717` | 면 `#EDEDED` (고스트 hover와 같음). 테두리는 유지 | Google 로그인 · 헤더 팀 버튼 |

- 기본 버튼 hover는 **같은 회색이 한 단 진해진 것**이다 (`#EDEDED` → `#C9C9C9`). 차콜 면 + 흰 글자로 바꾸지 않는다 — 면이 다른 버튼이 된다.
- 주 버튼 글자는 항상 흰색이다. 전역 `button { color: inherit }`가 유틸을 이기지 않게 `global.css`는 `@layer base` 안에 둔다.
- 제품은 라운드 9, 랜딩은 알약. 높이는 제품 최소 36px, 랜딩 최대 44px
- **파괴적 빨강 채움은 없다.** `반려`·`보내지 않음`은 고스트로 그린다(§3-3에 삭제 색 토큰이 없다)
- 포커스에 `outline`을 더하지 않는다 (§3-3)

### 7-7. 필드

- 라벨: 12px / **400** / 보조 회색, 입력 **위**. 채워야 하는 칸의 라벨은 먹 또는 경고색
- 입력: 높이·경계·라운드가 화면군마다 다르다 — §5 "입력 높이" 표 참고
- 미입력 필수칸: 경계가 먹 또는 `#FF6969`(승인을 막는 입력)
- 마감일은 달력 피커. 텍스트 입력 금지
- 담당자는 select. `골라 주세요`가 플레이스홀더

### 7-8. 팀원 그룹 · 아바타

- 아바타: 이름 1~2자, 원형, 회색 계열 배경. 정확한 크기·색은 화면마다 다르다 — 재사용할 화면의 값을 그대로 복사한다
- **팀원별 유채 팔레트를 쓰지 않는다.** 사람 구분은 글자로만

### 7-9. 주간 일정 (캘린더)

- 7열 그리드. 유채 하이라이트 없음(위험 배지 제외)
- 이벤트 칩: 소형 반경, 컨트롤 회색 면
- 변경된 마감은 원래 위치에 점선 유령 칩, 새 위치에 실선 칩 (`canvas/TasksCalendar.dc.html`)

### 7-10. 반영 로그

- 항목당 1줄, 최신순. `[모노 시각] 동작 — 대상` + 우측 `되돌리기`
- 자동 반영과 PM 승인은 문구로 구분. 색 마커 없음

### 7-11. 앱 셸 · 탭

- 헤더 76px. 좌측 마크 + 탭 5개 (`대시보드` `회의록` `태스크` `메시지` `팀`) → 우측 워크스페이스 셀렉트 + 아바타
- 활성 탭: 선택 면(`#F0F0F0`), 글자 먹 · 600. 하단 바 없음
- 태스크 화면 내부 뷰: `리스트` / `보드` / `간트` / `캘린더` 세그먼트 (4뷰 — 문서 구버전엔 3뷰로 적혀 있었다)

### 7-12. 선택 카드 · 세그먼티드

- 선택 카드: 선택 시 경계는 강조 테두리 `#C9C9C9` (먹이 아니다). hover 면은 아웃라인 버튼과 같은 `#EDEDED`. 테두리는 hover에서 바꾸지 않는다
- 세그먼티드: 선택 항목만 흰 면. 트랙은 컨트롤 회색. 항목 최소 높이 36px
- 카운터: `− [값] +` 형태. 값은 tabular

### 7-13. 상태 박스

유채 정보/성공/경고/오류 박스를 쓰지 않는다. 실패는 눌린 면 + 먹 본문 + **대체 경로 버튼**.

### 7-14. 처리 단계 리스트

`음성을 텍스트로 옮기기` → `누가 말했는지 나누기` → `결정사항 뽑아내기` → `담당자와 마감 맞추기`

- 완료: 체크 + 경과 시간(모노)
- 진행 중: 단계명 먹 + 경과 시간
- 대기: 미세 회색 + `대기`
- 고정 문구: `확인이 끝나기 전에는 Notion에 아무것도 쓰지 않아요`

### 7-15. 빈 상태

마스코트 96px → 제목 → 설명 → 액션 최대 2개 (주 액션 + 보조).
아이콘 32px · 주 액션 1개가 아니다 — 실측 3장(`EmptyTasks` `EmptyMeetings` `EmptyMessages`)이 같다.
세로 여백 넉넉히, 폭은 좁게 중앙 정렬.

### 7-16. 토스트

- 되돌릴 수 있는 동작에는 `되돌리기`
- 오류는 토스트로 처리하지 않는다

### 7-17. 테이블 (담당자 매핑)

- 헤더는 눌린 면, 행 구분선은 기본 선
- 미매칭 행은 확인 필요 표시. 미매칭이 남아 있으면 온보딩 완료 버튼 비활성

## 9. 카피 규칙

### 9-1. 이유 캡션 패턴

| 불확실한 것 | 캡션 | 화면에 있는가 |
|---|---|---|
| 담당자 후보 복수 | `담당자 후보가 둘 — 서연 / 지민` | 있음 |
| 담당자 미지정 | `회의에서 담당자가 정해지지 않음` | 있음 |
| 마감 모호 | `마감이 "다음 주쯤"으로만 언급됨` | 있음 |
| 수락 미확인 | `지명은 됐지만 본인 확인이 없음` | 아직 시연된 화면 없음 — 새로 만들 때 이 패턴을 쓴다 |
| 전사 불명 | `해당 구간 인식 불가 — 원문 8:15 확인 필요` | 아직 시연된 화면 없음 — 새로 만들 때 이 패턴을 쓴다 |

보류 캡션은 한 줄 더 붙일 수 있다: `— 정보가 더 필요해요`

### 9-2. 문장 규칙

- 숫자로 확신을 표현하지 않는다. `신뢰도 0.74` (✕) → `담당자 후보가 둘` (○)
- AI 판단은 단정하지 않는다. `진행률 50%입니다` (✕) → `답장 기준 50%로 봤어요` (○)
- 되돌릴 수 없는 버튼은 동작을 명시한다. `확인` (✕) → `이대로 발송` (○)
- 사용자를 주체로. `AI가 정리했습니다` (✕) → `정리해 드렸어요, 확인해 주세요` (○)
- 해요체. 오류도 해요체 + 원인 + 다음 행동
- 전문용어 비노출. `폴링` `MCP` `STT` (✕) → `1시간마다 확인` `연결` `음성 변환` (○)
- 화면 카피 예외: 태스크명·회의 맥락에 나온 말은 그대로 둘 수 있다 (`STT 파이프라인 튜닝`)

## 11. 접근성 체크리스트

캔버스는 정적 목업이라 상호작용 상태(포커스·호버)를 보여주지 않는다.
호버 값은 §7-6 · §7-12에 있다. 포커스는 §3-3 참고 — **아직 미결이다.**

- [ ] **모든 인터랙티브에 눈에 보이는 키보드 포커스 표시** — M2는 `outline: none`만 정했고 대체 표현이 없다 (§3-3, §13-1)
- [ ] 흑백 캡처로도 확정도·리스크가 구분되는가 (점 / 필 유무 / 테두리)
- [ ] `#666666`보다 연한 글자가 없는가
- [ ] 진행률·리스크가 텍스트로도 표기되는가
- [ ] 키보드만으로 승인 흐름을 통과할 수 있는가
- [ ] `prefers-reduced-motion`에서 회전 인디케이터·전환 정지 (매스 마스코트는 이미 대응 — `character.md` §3)

## 12. 금지 목록 (Don'ts)

| 금지 | 이유 |
|---|---|
| **`전체 승인` 버튼** | 게이트를 장식으로 만든다 |
| **신뢰도 소수점** (`0.74`) | 근거 없는 정밀도. 숫자를 본 PM은 원문을 읽지 않는다 |
| **`자동 반영됨`에 승인 버튼** | 자동화 주장이 사라진다. 되돌리기만 |
| **`보류`를 위험으로** | 보류는 정보가 부족한 것이다 |
| **`진행 중`·`시작 전`을 유색으로** | 라이프사이클은 리스크가 아니다 |
| **`#FF6969` 밖의 유채색 토큰** | 위험·경고 두 자리로 충분하다 |
| **기준 시각 없는 진행률** | 자기보고를 실시간 사실로 오해한다 |
| **AI 값과 PM 수정값의 무구분** | 로그·되돌리기 근거가 사라진다 |
| **이모지 아이콘 혼용** | 디스코드로 나가는 본문만 예외 |
| **팀원용 화면·권한 UI** | 웹은 PM 전용 |
| **디스코드 embed 디자인** | 디스코드는 알림만 |
| **요약된 근거 인용** | 원문 그대로여야 검증 가능하다 |
| **오류를 토스트로** | 사라지면 대체 경로를 놓친다 |
| **콘텐츠 면에 회색 채움** | 회색은 컨트롤·상태에만 |
| **순수 `#000000`** | 잉크는 `#171717` 하나 — 마스코트도 예외 없음 |

## 13. 미결 항목

| # | 항목 | 판정 방법 |
|---|---|---|
| 1 | 키보드 포커스 표시 | **절반만 정해졌다.** `outline` 링은 안 쓴다(M2 확정). 대체 표현은 **미정** — M4 화면 작업 전에 정한다. §3-3 |
| 2 | 반응형 하한 (<1024) | PM의 승인 시간·장소 관찰 후 |
| 3 | 팀원 `평균 진행률` 유지 여부 | 계산식을 밝힐 수 있는지로 판단 |
| 4 | 폴링 변경 감지 UI를 지금 그릴지 | 일정에서 첫 절삭 후보 |
| 5 | 다크 모드 | 현재 원안에 없음. 필요하면 토큰을 별도 램프로 추가한다 |
| 6 | §9-1의 "수락 미확인"·"전사 불명" 캡션 | 아직 어느 화면에도 없다. 해당 상황을 그릴 때 이 패턴대로 만든다 |
