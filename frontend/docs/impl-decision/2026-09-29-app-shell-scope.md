# 앱 셸·선택 화면·대시보드를 Main 캔버스와 어디까지 맞출 것인가

- 날짜: 2026-09-29
- 상태: 결정

## 고민

`Main.dc.html` 의 헤더와 팀 메뉴를 옮기다 네 곳에서 캔버스를 그대로 쓸 수 없었다.

1. **집계 숫자.** 탭 `태스크 3` · `메시지 2` 배지와 팀 줄의 `팀원 5명 · 확인 필요 3` 은 집계가 있어야 그린다.
   M4 는 대시보드·목록 집계를 요청하지 않는다(U4-4, 계획 ④).
2. **메뉴 문구.** 캔버스는 `새 팀 만들기`, `팀 설정 · 초대` 다. 결정문 D-068 은 메뉴 항목을 `새 워크스페이스 만들기` 로 적었고,
   초대 기능은 1차 범위 어디에도 없다.
3. **그림자.** 팀 메뉴(`.team-menu`)는 `box-shadow: 0 6px 20px rgba(23,23,23,0.09)` 다. m2-design-tokens §3-④ 는 그림자 토큰을
   만들지 않기로 하면서 "팝오버 한정 예외를 M4 에서 다시 논의"를 남겼다.
4. **캔버스가 없는 화면.** 워크스페이스 선택 화면은 전용 아트보드가 없다(개발 계획 M4). 대시보드 빈 상태 문구도 캔버스·결정에 없다.
5. **캔버스에 없는 아이콘.** M4 화면에 아이콘이 세 개 더 필요했다 — 온보딩 `나가기`(D-069), 비밀번호 `숨기기`, 계정 메뉴 `로그아웃`.

## 고른 길

1. 배지와 팀 줄 집계를 뺀다. 팀 줄의 보조 줄은 **내 역할**(`PM`·`팀원`)이고, 미완료 공간은 **`설정 미완료`**(D-070)다.
   메뉴 제목은 `내 워크스페이스 N` — N 은 이미 받은 목록의 길이라 새 요청이 없다.
2. 문구는 결정문을 따른다 — `새 워크스페이스 만들기`(D-068), `워크스페이스 설정`. 초대가 없으니 `· 초대` 를 붙이지 않는다.
   캔버스에 없는 `워크스페이스 목록` 항목을 더했다 — 헤더에서 선택 화면으로 가는 길이 필요하다.
   설정은 탭이 아니라 이 메뉴에서 연다(U4-2). 계정 메뉴(아바타)에는 이름·이메일·`로그아웃` 만 있다.
3. **팝오버에도 그림자를 쓰지 않는다.** `border-line` 한 겹과 흰 면으로 띄운다(`shared/ui/dropdown-menu`). 개발 서버(MSW)에서
   1024px 로 워크스페이스 메뉴를 열어, 흰 배경 위 메뉴가 테두리만으로 구분되는 것을 눈으로 확인했다. §3-④ 의 예외는 적용하지 않는다.
   Toast 는 이번에 실물 확인을 하지 않았다 — 같은 원칙으로 두고 M5 의 전역 토스트(`회의 정리가 끝났어요`) 때 다시 본다.
4. 선택 화면은 **Main 의 팀 메뉴를 한 화면으로 펼친 것**이다 — 같은 줄 모양(`WorkspaceRowContent`), 같은 진입 정책(`useEnterWorkspace`),
   아래에 `새 워크스페이스 만들기`. 제목 `워크스페이스 선택`, 안내 `들어갈 워크스페이스를 골라 주세요.` 는 새 문구다.
   대시보드는 빈 상태 컴포넌트에 `확인할 일이 여기에 모여요` / `회의 녹음을 올리면 … 지금은 회의록과 태스크에서 이어서 볼 수 있어요.` 와
   `회의록으로 가기` · `태스크 보기` 두 링크를 둔다. 이것도 새 문구다.
5. 아이콘은 **캔버스 아이콘에서 유도하고, 유도할 원본이 없으면 캔버스와 같은 격자·굵기로 그린다** (`shared/ui/icon/Icon.tsx`).
   모두 캔버스 아이콘과 같은 24 격자 · `stroke` 선 · 둥근 끝이고 채움이 없다.

   | 이름 | 쓰는 곳 | 출처 |
   |---|---|---|
   | `chevron-left` | 온보딩 카운터 옆 `이전 단계` | `Main`·`Landing` 캔버스의 `chevron-right`(`m9 6 6 6-6 6`)를 좌우로 뒤집었다(`m15 6-6 6 6 6`). 굵기는 원본과 같은 2 |
   | `arrow-left` | 온보딩 헤더 `나가기` | `SetupMembers` 캔버스의 `arrow-right`(`M5 12h14m-6-6 6 6-6 6`)를 좌우로 뒤집었다. 굵기는 `plus` 와 같은 1.9 |
   | `eye-off` | `PasswordField` 의 `숨기기` | `Login`·`Signup` 캔버스의 `eye`(눈 윤곽 + 동공, 1.7)에 좌상→우하 사선 `M4 4l16 16` 하나를 더했다 |
   | `logout` | 계정 메뉴 `로그아웃` | 유도할 캔버스 원본이 없다. 문 틀 + 오른쪽 화살표로 새로 그렸고, 도형은 Feather `log-out`(MIT)과 같다. 굵기는 캔버스 `search`·`play`·`external` 과 같은 1.8 |

## 왜

- 집계 없이 숫자를 그리면 틀린 숫자이거나 가짜 숫자다. 역할과 설정 상태는 이미 받은 목록에 있다(계약 §2.1).
- 결정문은 캔버스보다 나중에 합의한 문구다. 없는 기능(초대)을 메뉴에 약속하지 않는다.
- design-system.md §5 와 이슈 #36 은 그림자를 금지한다. 테두리만으로 충분히 구분되는 것을 확인했으니 예외를 만들 이유가 없다.
- 대시보드는 M4 에서 회의가 있는지 모른다(집계를 부르지 않는다). 그래서 "비어 있다"고 단정하지 않는 문구다 —
  데이터가 있는 공간(ws_01)에서도 틀린 말이 되지 않고, 다음 행동(회의록·태스크)만 안내한다.

## 다시 고민할 때

- 대시보드 집계 API(M7)가 생기면 탭 배지와 팀 줄의 `팀원 N명 · 확인 필요 N` 을 캔버스대로 되살린다. 대시보드 문구도 실제 상태
  (확인 대기 수 등)로 바꾼다.
- 초대 기능이 범위에 들어오면 메뉴의 `워크스페이스 설정` 을 캔버스의 `팀 설정 · 초대` 로 다시 본다.
- 실사용에서 메뉴가 배경과 구분되지 않는다는 보고가 있으면 그때 §3-④ 의 팝오버 예외를 다시 논의한다.
- 워크스페이스 선택 화면 캔버스가 나오면 그 구성으로 바꾸되, 진입 정책은 헤더 메뉴와 같은 함수를 계속 쓴다.
- 캔버스에 `나가기`·`숨기기`·`로그아웃` 아이콘이 생기면 그 도형으로 바꾼다.
