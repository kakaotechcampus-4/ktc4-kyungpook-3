# 온보딩 캔버스의 `이전`/`다음`·Notion 데이터베이스 블록을 어떻게 옮길 것인가

- 날짜: 2026-09-28
- 상태: 결정 (하단 이전·다음은 2026-09-29 에 뒤집음 — 맨 아래 절)

## 고민

`SetupTeam`·`SetupDiscord`·`SetupNotion`·`SetupMembers` 캔버스는 카드 아래에 `n / 4` 와 함께 `이전`·`다음` 버튼을 둔다.
그런데 단계를 저장하고 넘기는 버튼은 이미 카드 안에 있다 — `만들기`, `연결하기`/`건너뛰기`, `N명 확인 완료`/`나중에 하기`.
`다음` 은 카드 버튼과 같은 일을 두 번 하고, `이전` 은 정책이 없다. D-008 은 "이전 단계 이동 정책은 아직 결정하지 않았다"고 적었고
뒤이은 D-011·D-012 는 건너뛰기와 재개만 정했다. 만든 공간으로 1단계에 돌아가 무엇을 할지, 연결한 Discord 를 다시 할지 정해진 것이 없다.

`SetupNotion` 은 데이터베이스 이름·`바꾸기`·속성 매핑 표와 `이 보드로 연결` 버튼, `속성은 제가 맞춰 뒀어요` 말풍선을 담고 있다.
D-154 와 M4 계획은 Notion 데이터베이스 선택 화면을 만들지 않는다고 정했다.

연동 완료 줄(`디스코드 연동 완료 — #일반 채널`)의 이름 자리는 `display_name` 인데, 실 API 는 `"Discord 연결됨"` 같은 생성 문자열을 준다(계약 §4.0-②-7).

## 고른 길

M4 에서 조정자·사용자가 확정했다.

- 카드 아래에는 `n / 4` 표시만 둔다. `이전`·`다음` 은 두지 않는다. 진행은 카드 안 버튼이 서버 저장 뒤에 하고,
  저장된 상태가 바뀌면 단계 가드(`RequireValidOnboardingStep`)가 다음 미완료 단계로 옮긴다.
- 나가기는 왼쪽 위 뒤로가기 화살표 하나다(D-069). 기존 공간에서 시작했으면 그 대시보드, 아니면 워크스페이스 선택 화면이다.
- Notion 카드는 제목·설명과 `연결하기`/`건너뛰기` 만 둔다. 데이터베이스 블록·속성 매핑·`이 보드로 연결`·`속성은…` 말풍선은 옮기지 않는다.
- 연동 완료 줄은 이름 없이 `디스코드 연동 완료`·`노션 연동 완료` 만 쓴다.
- 팀원 연결 캔버스의 역할 글자(`백엔드` 등)는 서버에 없는 값이라 옮기지 않는다. 이름 칸은 입력(D-026)이고
  비어 있으면 `누구인가요?` 가 자리표시다. 확정 버튼은 적은 줄 수를 세어 `N명 확인 완료` 로 쓴다.

## 왜

- 같은 일을 하는 버튼이 두 곳에 있으면 어느 쪽이 저장하는지 헷갈린다. 정책 없는 `이전` 은 누르면 무엇이 되돌려지는지 약속할 수 없다.
- 데이터베이스를 고르는 API 가 없고(계약 §4.3), 결정도 그 화면을 만들지 않기로 했다. 흉내만 낸 표는 사용자가 바꿀 수 있다고 오해하게 한다.
- 생성 문자열은 사용자가 준 이름이 아니다. 화면에 그대로 쓰면 "Discord 연결됨 연동 완료" 처럼 읽힌다.

## 다시 고민할 때

- 이전 단계 이동 정책이 정해지면 `이전` 을 그 정책대로 넣는다. `다음` 은 카드 버튼과 겹치지 않을 때만 되살린다.
- Notion 데이터베이스 선택이 범위에 들어오면(D-154 변경) 캔버스의 데이터베이스 블록을 옮긴다.
- 실 API 가 서버·채널 이름을 `display_name` 으로 주면 연동 완료 줄에 이름을 붙인다.

## 2026-09-29 — 하단 이전·다음을 되살린다 (카운터 양옆 화살표)

사용자가 위의 "`이전`·`다음` 은 두지 않는다" 를 뒤집었다. 위 절은 그날의 판단으로 남기고, 하단 이동은 아래 정책을 따른다.
Notion 데이터베이스 블록·연동 완료 줄·팀원 역할 글자 결정은 그대로다.

### 고민

`이전` 을 넣으려면 "무엇이 되돌려지는가" 를 약속해야 한다(위 `왜`). 단계 상태를 되돌리면 연쇄 건너뜀(D-073)·재개(D-012)가 모두 흔들린다(D-073 은 같은 날 D-173 으로 개정됐다 — 아래 `범위 밖`).
`다음` 은 카드 버튼과 겹친다. 캔버스(SetupDiscord 하단 줄)는 카운터 오른쪽에 `이전` 글자 버튼과 회색 `다음` 버튼을 둔다.

### 고른 길

- **되돌리지 않고 둘러본다.** `이전` 은 앞 단계를 둘러보기 주소 `?review=1`(`paths.onboardingReview`)로 연다. 서버 상태는 바꾸지 않는다.
- **가드**(`RequireValidOnboardingStep`): `review=1` 이면 이어 갈 단계(`resumeStep`)보다 앞이고 저장된(완료·건너뜀) 단계만 보여 준다.
  이어 갈 단계 자신·그 뒤·pending·모르는 단계의 둘러보기는 표시 없는 이어 갈 단계로 보낸다. `review` 가 없으면 전과 같다 —
  지금 단계에서 저장하면 목록 캐시가 바뀌어 다음 단계로 옮겨진다. 온보딩을 마친 공간은 대시보드다.
- **모양은 캔버스와 다르다 — 사용자가 고른 카운터 양옆 꺾쇠 화살표** `‹ n / 4 ›`(`StepNav`). 글자 버튼을 두지 않는다.
  자리는 지금 카운터 자리(카드 아래 왼쪽)이고, 화살표는 `chevron-left`/`chevron-right` 아이콘 버튼이다(`chevron-left` 는 캔버스
  `chevron-right` 를 뒤집어 새로 넣었다 — 출처는 `2026-09-29-app-shell-scope.md` 아이콘 표). 크기·색은 나가기 화살표(ExitLink)와 같은
  36px 정사각·반경 9·`text-sub`, 비활성은 Button ghost 와 같은 `text-line-strong`. 접근 이름은 `이전 단계`·`다음 단계` 다
  (지금 단계의 오른쪽 화살표가 건너뛰기여도 이름은 `다음 단계`). 쓸 수 없는 화살표는 지우지 않고 비활성으로 둔다 — 카운터가 움직이지 않는다.
- **`이전 단계`**: 2~4단계에서 앞 단계 둘러보기로 간다. 1단계에서는 비활성. 공통 이동 관문을 탄다 — 팀원 연결에서 입력 중이면
  이탈 확인이 뜨고 `계속 작성하기` 면 남는다. 저장 중엔 막힌다.
- **지금 단계의 `다음 단계` = 건너뛰기.** Discord·Notion 은 연결 전이면 `건너뛰기` 와 같고, 연결됐는데 단계 저장만 실패했으면 완료 저장이다.
  팀원 연결은 `나중에 하기` 와 같다(같은 잠금). 1단계(새 공간·만든 공간 모두)에서는 비활성이다. 카드 버튼은 그대로 둔다.
- **둘러보기의 `다음 단계`**: 요청 없이 한 칸 앞으로. 다음 단계도 지난 단계면 그 둘러보기, 아니면 이어 갈 단계(표시 없음).
- **둘러보기 화면**
  - 1단계: 저장된 팀 이름을 읽기만 한다. `만들기` 는 없다. ~~카드 `다음` 도 없다.~~ 같은 날 사용자 결정으로 카드 `다음`(primary)을 둔다 —
    요청 없이 둘러보기의 다음 곳으로 간다(`›` 와 같다).
  - Discord·Notion: 연결됐으면 `연결됨` + 카드 `다음`. 건너뛰었으면 `연결하기` + `건너뛰기`(지금 단계와 같은 자리·모양).
    처음엔 "`연결됨` 만 / `연결하기` 만" 이었으나 같은 날 사용자가 카드에도 앞으로 가는 길을 되살렸다.
    둘러보기의 `다음`·`건너뛰기` 는 요청을 보내지 않는다(건너뛴 단계는 이미 건너뜀으로 저장돼 있다). 둘러보기의 다음 곳으로 옮기기만 한다.
    `연결하기` 의 OAuth `state` 는 둘러보기 주소라 그리로 돌아오고,
    복귀 표시만 지우고 `review=1` 은 남긴다(`withoutOAuthResult`). 복귀 확인은 지금 단계와 같다 — 연동 상태 재조회, `connected` 면 `연결됨`,
    취소·실패면 같은 안내. 이미 건너뜀인 단계의 완료 저장은 `planOnboardingUpdates` 가 걸러 요청이 나가지 않는다. 단계 상태 뜻은 바꾸지 않는다.
  - 팀원 연결은 마지막 단계라 둘러보기가 없다(끝내면 온보딩이 끝난다).
  - 일반 팀원 대기 화면에는 화살표가 없다(카운터만).

### 왜

- 둘러보기는 상태를 바꾸지 않아 연쇄·재개 규칙과 부딪히지 않는다. 가드 규칙 하나로 URL 직접 진입도 같은 답이 된다.
- 지금 단계의 `다음 단계` 를 건너뛰기로 두면 카드 버튼과 하는 일이 같아 "어느 쪽이 저장하나" 가 갈리지 않는다.
- 화살표는 사용자가 골랐다. 이름이 `이전 단계`·`다음 단계` 라 카드 안의 `다음`(연결 뒤 저장 재시도)과 접근 이름이 겹치지 않는다.

### 범위 밖

- 둘러보기에서 공간 이름 바꾸기.
- ~~Discord 를 다시 연결한 뒤 건너뜀으로 저장된 팀원 연결을 되살리기.~~ 같은 날 D-173(D-073 개정)으로 풀렸다 — Discord 를 건너뛰어도
  팀원 연결이 pending 으로 남아, 둘러보기에서 다시 연결하면 팀원 연결이 Discord 사용자를 불러온다. 이미 건너뜀으로 저장된 예전 데이터는 그대로다.
- 백엔드 변경.

### 다시 고민할 때

- 이름 바꾸기 API 가 생기면 1단계 둘러보기를 편집 가능하게 할지 본다.
- 건너뛴 단계를 완료로 바꾸는 서버 동작이 생기면 둘러보기 재연결 뒤의 단계 상태를 다시 본다.
