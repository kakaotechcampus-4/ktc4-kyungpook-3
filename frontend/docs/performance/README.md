# 성능 개선 거리

측정해서 찾았지만 아직 고치지 않은 성능 문제를 모아 둔다. 리팩토링할 때 한곳에서 보고 한 번에 고치기 위한 기록이다.

`plan/mN/basis-for-decision/`는 이미 고른 길을 적는 곳이다. 여기는 **아직 고르지 않은 개선 거리**를 둔다.
고치고 나면 그 결정은 해당 마일스톤의 `basis-for-decision/`에 남기고, 여기 문서의 상태를 `반영됨`으로 바꾼 뒤 그 결정 문서를 가리킨다.

발표용으로 적용한 개선과 보류한 시도를 함께 읽으려면 [프론트엔드 성능 개선](../performance.md)을 본다. 측정 원문과 재현 도구는 이 디렉터리에 유지한다.

## 파일 형식

이름은 `YYYY-MM-DD-영문-슬러그.md`. 날짜는 측정한 날이다.

```markdown
# 제목 — 무엇이 느린지 한 줄로

- 날짜: 2026-09-29
- 상태: 대기 | 반영됨(→ plan/mN/basis-for-decision/…)
- 영향 범위: 앱 전체 | 특정 화면

## 측정
조건(네트워크·빌드 종류·경로)과 숫자. 다시 재는 방법까지.

## 원인
숫자가 가리키는 병목.

## 고칠 거리
선택지와 각각의 대가. 관련 파일 경로.

## 고칠 때 확인할 것
회귀 위험, 함께 바꿔야 하는 곳, 고친 뒤 다시 잴 기준.
```
