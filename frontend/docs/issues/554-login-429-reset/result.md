# 결과 — 로그인 429 화면의 비밀번호 재설정 안내 (#554)

- 기록일: 2026-11-09
- 대상: [#554](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/554)(BE #549 후속)
- 기준: develop `33b071ac`(PR #458 병합 뒤)
- 상태: **요청 두 개를 반영했다.** MSW 기준으로 검증했다. BE 계약 변화는 없다.

## 작업 근거와 요약

마일스톤 계획에 없는 작업이다. 근거는 이슈 #554다. BE는 남의 이메일로 10번 틀려 그 이메일의 로그인을 15분 막는 위험을 줄이려고, 이미 있는 해제 경로(재설정 confirm이 그 이메일의 막힘을 푼다)를 로그인 화면에서 안내해 달라고 했다.

로그인이 429 `TOO_MANY_LOGIN_ATTEMPTS`를 받으면 폼 상단 오류가 서버 문구 뒤에 「비밀번호가 기억나지 않으면 재설정해 주세요.」를 붙이고, 같은 패널 안에 `/forgot-password`로 가는 「비밀번호 재설정하기」 링크를 둔다.

## 문구 제약

| BE 명세 | 화면 |
|---|---|
| 계정이 잠겼다고 단정하지 않는다. 있는 이메일과 없는 이메일의 응답이 같다 | 「잠겼」「잠금」을 쓰지 않는다. 테스트가 확인한다 |
| 재설정하면 바로 풀린다고 약속하지 않는다. IP 막힘은 재설정으로 풀리지 않는다 | 「풀려」「풀립」을 쓰지 않는다. 안내는 비밀번호를 잊은 경우의 경로만 말한다 |
| 예시 문구 「로그인 시도가 너무 많아요. 잠시 뒤 다시 시도하거나, 비밀번호가 기억나지 않으면 재설정해 주세요.」 | 앞 절은 서버 문구가 이미 말한다(#457 결정으로 그대로 보인다). 뒤 절만 같은 「~해 주세요」로 붙였다 |

## 실제 구현 및 관련 코드

- [LoginForm.tsx](../../../src/features/auth/ui/LoginForm.tsx): 폼 오류 상태를 `{ message, offerReset }`로 바꿨다. 회원가입 프로필 단계의 `{ message, conflict }`와 같은 모양이다. `TOO_MANY_LOGIN_ATTEMPTS`일 때만 안내 문장을 붙이고 `FormErrorPanel`의 `action` 자리에 링크를 둔다. 링크는 기존 회원가입 링크와 같은 `GuardedLink`와 글자 링크 모양이다.
- [API 계약](../../contracts/frontend-api-contract.md) §4.1.3의 「FE가 정한 동작」과 「현재 구현」을 고쳤다.
- 검증 기능 지도(`.cursor/skills/verify-managers-manager/features/auth-workspaces.md`)의 `auth-limits` 기대를 고쳤다.

## 설계 결정

| 결정 | 고른 길 | 대안과 버린 이유 |
|---|---|---|
| 안내 문장 | 서버 문구 뒤에 한 문장을 붙인다 | 예시 문구로 서버 문구를 바꾸기: #457에서 서버 문구를 그대로 보이기로 했고, 이 이슈는 「기존 폼 오류와 함께」를 요청했다 |
| 링크 모양 | 패널 안 글자 링크(`GuardedLink`) | 버튼 + `navigate`: 이동인데 링크가 아니게 된다. 새 탭 열기도 안 된다 |
| 선택 항목 | 남은 시간 표시, 이메일 미리 채우기 모두 하지 않는다 | 남은 시간: #457에서 보이지 않기로 했고 IP 막힘과 구분되지 않는다. 미리 채우기: 주소에 이메일을 싣지 않으려면 상태 전달이 필요하고, 재설정 화면은 이미 이메일 한 칸이다 |

## 검증

- Vitest: `authFlow.test.tsx` 429 경로(문장, 잠금·해제 단어 없음, 링크로 `/forgot-password` 이동)와 401에는 안내가 없음. 안내를 넣기 전 429 테스트가 실패하는 것을 확인했다.
- E2E(MSW): `auth-limits.e2e.ts`의 시도 제한 테스트가 alert 문장과 링크 이동을 확인한다.
- 실서버 429는 확인하지 않았다.
