# 결과 — 스플래시 끝맺음을 늘려 눈웃음이 다 지어진 뒤 사라지게 하기 (#506)

- 대상: [#506](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/506)의 할 일 5개
- 기준: develop `4c632f4a`. PR은 아직 만들지 않았다.
- 상태: **할 일을 모두 반영했다.** MSW 개발 서버(Chromium)로 끝맺음을 프레임 단위로 확인했다. 실서버·실제 기기는 미검증이다.

## 작업 근거와 요약

마일스톤 계획에 없는 작업이다. 근거는 이슈 #506과 사용자 결정(2026-11-07, A안)이다. [#430](../430-splash/result.md)의 로딩 스플래시가 「눈웃음이 끝나고 너무 빠르게 사라져서 어색하다」는 의견에 따랐다.

눈웃음은 지수 접근(λ 4.5)이라 90% 까지 약 0.5초가 걸린다. 그런데 눈웃음 단계가 0.6초라 다 지은 얼굴로 머무는 시간이 0.1초쯤뿐이었고, 바로 0.4초 동안 사라졌다.

| | 눈웃음 단계 `SMILE_MS` | 사라짐 `FADE_MS` | 준비 뒤 끝맺음 |
|---|---|---|---|
| 이전 | 600 | 400 | 1.0초 |
| 지금 (A안) | 1100 (지어짐 약 0.5 + 머묾 0.6) | 600 | 1.7초 |

다른 타이밍(등장 300, 둘러보기 시작 1500, 둘러보기 한 동작 1700, 준비 확인 100), 0.3초 안 준비는 보이지 않는 규칙, 랜딩 바로 걷힘, 움직임 줄이기 동작은 그대로다.

## 실제 구현 및 관련 코드

- [splashMachine.ts](../../../src/app/splash/splashMachine.ts): `SMILE_MS` 1100, `FADE_MS` 600. 눈웃음 단계 주석에 지어짐·머묾 나눔과 이유를 적었다.
- [index.html](../../../index.html): `.splash[data-phase='leave']` 의 `splash-out 0.4s` → `0.6s`. `FADE_MS` 와 짝이라는 주석을 더했다.
- 테스트
  - [SplashHost.test.tsx](../../../src/app/splash/SplashHost.test.tsx): 끝맺음 시각을 단언하는 곳을 고쳤다(눈웃음 600 → 1100, 사라짐 400 → 600, 합계 1000 → 1700, 움직임 줄이기 「사라짐 중에 켜면」의 준비 뒤 700 → 1300). 랜딩의 사라짐(400 → 600)도 같은 `FADE_MS` 라 함께 고쳤다. 「늦게 준비되면 …」은 준비 뒤 1.0초 동안 100ms 마다 아직 사라지지 않는지 보고, 1.1초에 사라짐, 1.7초에 걷힘을 본다.
  - [splash.test.tsx](../../../src/app/splash.test.tsx): 새로 접속·로그인 직후 두 흐름의 「준비됐어요」 뒤 걷힘 대기를 1000 → 1700ms 로.
  - [staticSplash.test.tsx](../../../src/app/splash/staticSplash.test.tsx): 새 검사 「사라짐 애니메이션이 덮개를 걷는 시각(FADE_MS)과 같은 길이다」. `index.html` 의 `splash-out` 길이를 읽어 `FADE_MS` 와 비교한다. 이전에는 두 값의 짝을 주석으로만 적었다.
- 문서: [결정 기록](../../plan/m2/basis-for-decision/2026-11-06-splash-direction-a-smile.md#이후-변경-끝맺음을-늘려-눈웃음이-다-지어진-뒤-사라지게-했다-506)에 「이후 변경 (#506)」 절을 더하고 5·6단계 표, 끝맺음 설명, 「그대로 둔 것」의 0.6+0.4초 표기에 #506 이후 값을 덧붙였다. [#430 결과](../430-splash/result.md) 머리의 「이후 변경」에 한 줄을 더했다.

## 설계 결정

| 결정 | 고른 길 | 대안과 버린 이유 |
|---|---|---|
| 끝맺음 값 | A안 `SMILE_MS` 1100, `FADE_MS` 600 | 사용자 결정. 시안 값(1600·600, 2.2초)은 고르지 않았다 |
| 두 사라짐 값의 짝 | `staticSplash.test.tsx` 가 `index.html` 의 `splash-out` 길이와 `FADE_MS` 를 비교한다 | 주석만: 한쪽만 바꾸면 판이 사라지는 도중에 끊기거나 다 사라진 판이 남는데 아무것도 알리지 않는다 |
| 테스트의 시간 값 | 숫자를 그대로 적는다(1100·600·1700) | 상수를 가져다 쓰기: 상수를 잘못 바꿔도 테스트가 따라가 결정 값을 지키지 못한다 |
| 랜딩의 사라짐 | 같은 `FADE_MS` 라 0.4 → 0.6초 | 랜딩만 0.4초: 이슈에 없다. 랜딩은 판 아래에 이미 그려져 있고 사라지기 시작할 때부터 누를 수 있어 기다리게 하지 않는다 |

## 검증

| 범위 | 명령·방법 | 결과 |
|---|---|---|
| 바꾼 곳 단위 | `npx vitest run src/app/splash src/app/splash.test.tsx --maxWorkers=1` | 3개 파일 25개 통과 |
| 테스트가 옛 값을 잡는지 | `SMILE_MS` 600, `FADE_MS` 400 으로 잠시 되돌려 같은 명령 | 7개 실패(SplashHost 6, staticSplash 새 검사 1). 확인 뒤 되돌렸다 |
| 타입 | `npm run typecheck` | 통과 |
| 린트 | `npm run lint` | 실패 14개는 모두 로컬 검증 스크립트 `.verify/506/splash.mjs`(git 제외, 브라우저 전역)다. `npx eslint . --ignore-pattern .verify` 통과 |
| 포맷 | `npm run format:check` | 경고 5개는 모두 `.verify/` 아래 로컬 파일이다. 바꾼 파일만 `npx prettier --check` 통과 |
| 빌드 | `npm run build` | 통과 |
| 전체 단위 테스트 | — | 미실행. 메모리 사정으로 CI 에 맡긴다 |
| 브라우저 | `.verify/506/splash.mjs`(로컬 전용, MSW 개발 서버 5276, Chromium 390×844, `msw-auth-delay=2500`) | 아래 |

브라우저 확인은 프레임마다 단계(`data-phase`)·상태 문구·눈웃음 곡선(`smile-l` 의 `d`)·판 불투명도를 기록하고, 「준비됐어요」 뒤 약 100~150ms 간격으로 스크린샷을 찍었다(`.verify/screens/`). 시각은 「준비됐어요」가 처음 보인 프레임부터 잰다. 눈웃음 진행은 곡선 양 끝 사이 폭(뜬 눈 약 1.7 → 웃는 눈 23.0, 마스코트 240 좌표)으로 셌다.

| 흐름 | 눈웃음 90% | 99% | 사라짐 시작 | 걷힘 | 사라짐 150·300·450ms 불투명도 |
|---|---|---|---|---|---|
| 새로 접속(대시보드, 로그인 확인 2.5초 늦춤) | 0.56초 | 1.07초 | 1.10초 | 1.71초 | 0.65 · 0.20 · 0.04 |
| 로그인 직후 공간 확인(`useEnterSession` 의 `showSplash`) | 0.55초 | 1.05초 | 1.10초 | 1.70초 | 0.53 · 0.17 · 0.03 |

- 두 흐름 모두 눈웃음이 90% 지어진 얼굴이 약 0.55초 보인 뒤 0.6초에 걸쳐 사라진다. 이전 값이라면 0.6초에 사라지기 시작해 90% 얼굴은 0.05초쯤뿐이다.
- 로그인 직후 흐름은 「로그인」을 누른 뒤 판이 덮고 「로그인 확인 중」을 거쳐 `/workspaces` 로 도착했다. 끝맺음은 새로 접속과 같다.
- 페이지 오류 없음. 검증 서버와 브라우저는 스크립트 끝에서 닫았다.
