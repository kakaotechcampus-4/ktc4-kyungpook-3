## 작업 근거와 요약

마일스톤 계획에 없는 작업이다. 근거는 이슈 #539 와 사용자 결정(2026-11-08)이다.

사용자 말: 로그인 뒤 대시보드에 들어갈 때 스켈레톤 → 스플래시 → 대시보드 순으로 보인다.

로그인 직후 스플래시(`showSplash()`)는 새로 접속과 같이 처음 0.3초(`REVEAL_MS`)를 보이지 않는 `hidden` 단계로 보냈고, 그동안 아무것도 덮지 않았다. 그 사이 대시보드 화면 코드를 기다리는 라우트 뼈대가 먼저 보였다. 로그인·가입은 사람이 누른 동작이라 번쩍임 방지 대기가 필요 없고, #510 에서 로그인 직후는 12시간 규칙과 상관없이 보이기로 했으므로 누른 순간 덮는다.

## 실제 구현 및 관련 코드

- [SplashHost.tsx](../../../src/app/splash/SplashHost.tsx)
  - 실행(`SplashRun`)마다 보이기 시작하는 시각 `revealAt` 을 갖는다. 새로 접속(`bootRun`)은 이전처럼 설치한 앱이면 0, 아니면 `REVEAL_MS`(300)다. 로그인 직후(`session`)와 `시작하기`(`start`)는 0이다. 이전에는 `initialState` 가 `standalone || mode === 'start'` 로 정했고 로그인 직후는 300이었다.
  - `hidden` 은 이제 새로 접속에만 있어, 그동안 덮을지 정하던 `coversWhileHidden` 을 지웠다. `hidden` 동안은 언제나 index.html 의 흰 판을 이어받아 덮는다(새로 접속은 이전과 같다).
  - 로그인 직후는 띄우는 순간 `enter` 라 보이고 바로 12시간 기록을 남긴다. 0.3초 안에 끝나도 끝맺음(눈웃음 1.1초 → 사라짐 0.6초)까지 보인다.
- [splashMachine.ts](../../../src/app/splash/splashMachine.ts): 주석만 고쳤다(`full` 모드와 `revealAt` 설명). 상태 기계는 그대로다.
- 그대로 둔 것: 새로 접속의 0.3초 대기, 12시간 규칙, 랜딩 바로 걷힘, `시작하기` 스플래시, 설치한 앱의 0.2초 사라짐, 끝맺음 값(`SMILE_MS` 1100, `FADE_MS` 600, `splash-out 0.6s`), CSS 등장. 로그인 직후는 흰 판이 바로 덮고 마스코트는 이전처럼 0.3초에 올라온다 — 이전에는 0.3초까지 뼈대가 보이다가 흰 판과 마스코트가 함께 나왔다.
- 결정 기록: [스플래시 결정 기록](../../plan/m2/basis-for-decision/2026-11-06-splash-direction-a-smile.md#이후-변경-로그인-직후-스플래시는-03초-대기-없이-바로-539)의 「이후 변경」에 절을 더했다.

## 검증

- 단위(RTL) [SplashHost.test.tsx](../../../src/app/splash/SplashHost.test.tsx)
  - 「로그인 직후」를 고쳤다. 띄우기 신호를 받는 순간 판이 있고 `data-settling` 이 없으며 마스코트가 보이고, 앱이 `inert`, 기록이 남는다. 0.3초 안에 놓아도 판이 남아 눈웃음 → 사라짐으로 끝난다. 「0.3초 안에 끝나면 띄우지 않는다」 등 대기를 전제한 세 테스트는 뜻이 바뀌어 지웠다.
  - 「기록 시점」의 로그인 직후 테스트를 바꿨다. 12시간 안 기록이 있어도 띄우는 순간 기록하고, 0.3초 안에 끝나도 그대로다.
  - 새로 접속의 0.3초 대기는 기존 테스트(「0.3초 안에 준비되면 보이기 전에 걷힌다」 등)가 그대로 지킨다.
  - 되돌림 확인: `SplashHost.tsx` 를 develop 의 것으로 바꾸면 새 로그인 직후 테스트 세 개가 실패한다. 로그인 직후만 `revealAt` 을 300으로 바꿔도 세 개 모두 실패한다.
  - `npx vitest run src/app/splash src/shared/lib/splash src/features/auth/model`: 6 파일 99 통과.
- E2E(MSW) [login-splash.e2e.ts](../../../e2e/login-splash.e2e.ts) — 새 파일만 돌렸다
  - 12시간 안에 다시 온 사람(접속 스플래시 건너뜀)이 `?next=` 대시보드로 로그인한다. 로그인을 누른 뒤 DOM 이 바뀔 때마다 스플래시보다 앱의 `aria-busy` 뼈대가 먼저 그려지는지 본다. 뼈대가 먼저 그려지지 않고, 스플래시가 걷힌 뒤 대시보드이고, 기록이 고정 시각으로 바뀐다.
  - 대시보드 화면 코드(`/src/pages/dashboard/**` 모듈)를 1.5초씩 늦춘 경우도 같다. 판이 「로그인 확인 중」으로 라우트 뼈대를 기다리고, 늦춘 요청이 실제로 있었는지도 본다.
  - `--repeat-each 3`: 6 통과. develop 의 `SplashHost.tsx` 로 되돌리면 `--repeat-each 2` 4번 모두 「뼈대가 먼저 그려졌다」로 실패한다.
  - 처음 돌린 한 번은 지연 테스트가 대시보드가 이미 뜬 상태로 실패했다. 새 워크트리의 첫 실행이라 Vite 의 의존성 최적화 새로고침으로 보고(지연이 실제로 걸렸는지 로그로 확인), 이후 반복 실행은 모두 통과했다.
