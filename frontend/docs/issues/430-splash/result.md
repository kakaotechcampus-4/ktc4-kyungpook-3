## 작업 근거와 요약

마일스톤 계획에 없는 작업이다. 근거는 이슈 #430과 사용자 결정(2026-11-06)이다. 방향 A(흰 바탕, 먹 마스코트, 먹 워드마크)와 움직임 3번(등장 → 둘러보기 → 눈웃음 → 사라짐)은 [결정 기록](../../plan/m2/basis-for-decision/2026-11-06-splash-direction-a-smile.md)에 있다.

1. JS 를 받는 동안 흰 화면이던 자리에 `index.html` 의 정적 마스코트가 먼저 그려진다. React 가 뜨면 같은 자리를 이어받아 둘러보기·눈웃음·사라짐을 한다. 로그인 직후의 공간 확인도 같은 스플래시가 덮는다.
2. 설치한 앱은 iOS 시작 이미지 29장이 같은 모양을 보인다. 안드로이드는 manifest 그대로다.
3. 랜딩의 `시작하기`를 이 기기에서 처음 누르면, 그리고 온보딩을 마친 계정이 처음 대시보드에 들어오면 매스가 말풍선 세 줄로 자기를 소개했다. #465 로 뺐다.
4. 마스코트에 눈웃음과 속도 옵션을 더했다. 옵션을 안 주면 이전과 같다.

## 실제 구현 및 관련 코드

### 마스코트

- [Mascot.tsx](../../../src/shared/ui/mascot/Mascot.tsx)에 `smile`, `dial`, `lambda`(기본 8), `dialHz`(기본 1.1), `ref`(`press()`)를 더했다.
- 눈웃음은 세로 캡슐 눈을 같은 3차 곡선의 퇴화형으로 보고 아치로 보간한다. 눈이 사라졌다 나타나지 않는다. 값은 결정 기록의 표와 같다.
- `smile` 이 0 이면 DOM 이 이전과 글자 그대로 같다. 움직임 줄이기면 바로 아치를 그린다.
- 숫자의 원본 두 곳도 함께 고쳤다. [mascot.js](../../mascot/mascot.js)에 `lambda`·`dialHz`·`setSmile`, [M2 계획 §8](../../plan/m2/plan.md)에 값과 props.

### 브라우저 로딩 스플래시

- [index.html](../../../index.html)이 탭 제목을 `Manager's Manager` 로 바꾸고, 인라인 CSS 와 정적 SVG 마스코트(정면 + 다이얼)를 JS 보다 먼저 그린다.
  - 0.3초 기다렸다 마스코트가 올라오고(0.8초) 0.3초 뒤 워드마크가 따라온다. 다이얼은 CSS 로 0.55Hz 에 흐른다.
  - 설치한 앱(`display-mode: standalone`)은 시작 이미지에서 이어지도록 등장 없이 처음부터 보인다.
  - 움직임 줄이기면 등장 없이 0.3초 뒤 바로 보이고 줄무늬가 멈춘다.
- [SplashHost.tsx](../../../src/app/splash/SplashHost.tsx)가 React 쪽이다. [main.tsx](../../../src/main.tsx)가 `App` 밖에 붙인다. 앱 테스트(`renderApp`)에는 없다.
  - 같은 클래스의 판을 `document.body` 에 그리고 같은 커밋에서 정적 판을 지운다. CSS 등장은 `--splash-shift`(경과 시간)로 이어 간다. Chromium 에서 정지 위치가 정적 판과 같다(1280×800 에서 `592, 335.2, 96`).
  - 덮는 동안 `#root` 는 `inert` 이고 상태 문구는 `role="status"` 다.
- 순서는 [splashMachine.ts](../../../src/app/splash/splashMachine.ts)의 상태 기계 하나다. 단계는 `hidden → enter → look → smile → leave → done` 이고 단계마다 끝나는 시각을 스플래시 시계에 고정한다.
  - 1.5초에 모자를 누르고 둘러보기(정면 → 왼쪽 → 오른쪽, 1.7초씩, 「로그인 확인 중」)를 시작한다.
  - 준비되면 다이얼을 멈추고 눈웃음(「준비됐어요」, 0.6초) 뒤 0.4초에 걸쳐 사라진다(사용자가 시안 1.6초 · 0.6초에서 줄였다). 시선 전환 λ 3.2, 다이얼 0.55Hz.
  - 준비가 둘러보기 전에 오면 둘러보기를 건너뛴다. 0.3초 안에 오면 보이지 않은 채 끝난다.
  - 움직임 줄이기면 정면과 다이얼만 보이고, 준비되면 바로 걷힌다.
  - 랜딩 `/` 는 최소 표시 시간 없이 React 가 뜨자마자 사라짐으로 간다. 랜딩 내용은 판 아래 DOM 에 그대로 있다.
- 준비는 [splashSignal.ts](../../../src/shared/lib/splash/splashSignal.ts)의 잡기 수로 판단한다. [RouteSkeleton.tsx](../../../src/app/router/RouteSkeleton.tsx)이 그려져 있는 동안 잡는다. 0 이 100ms 이어지면 준비다.
  - `GuardSkeleton`·`lazyPage` 대기도 이 뼈대를 그리므로 세션·공간 목록·소속 가드와 화면 코드를 한 곳에서 기다린다.
  - 대시보드 카드 데이터의 뼈대는 이 뼈대가 아니라 기다리지 않는다. 오류 화면도 잡지 않으니 스플래시가 걷히고 오류가 보인다.
- 로그인 직후는 [useEnterSession.ts](../../../src/features/auth/model/useEnterSession.ts)가 `showSplash()` 로 공간 확인부터 덮는다. 세션을 캐시에 넣기 전에 공간 목록을 받으므로 `RedirectIfAuthed` 에서는 늦다.
- 개발 MSW 에서 `?msw-auth-delay=<ms>` 가 `/auth/me`·`/workspaces` 를 늦춘다([browser.ts](../../../src/shared/mock/browser.ts)). 프로덕션 번들에는 없다.
- E2E 는 `playwright.config.ts` 의 `reducedMotion: 'reduce'` 로 준비되자마자 걷히는 스플래시를 지난다.

### 설치한 앱 시작 화면

- 안드로이드: [manifest.webmanifest](../../../public/manifest.webmanifest)의 이름, `background_color #ffffff`, 아이콘을 확인했고 바꾸지 않았다.
- iOS: [startup-images.mjs](../../../scripts/startup-images.mjs)(`npm run startup-images`)가 [Mascot.tsx](../../../src/shared/ui/mascot/Mascot.tsx)를 Vite SSR 로 그려 Playwright Chromium 으로 `public/splash/` 에 29장을 찍고, `index.html` 에 넣을 `<link>` 줄을 낸다. 두 번 돌리면 같은 바이트가 나온다.
  - 크기 목록은 iOS 26·iPadOS 26 지원 기기와 그 뒤 기기다. iPhone 11줄(세로), iPad 9줄(세로·가로)이다. 근거는 스크립트 머리에 있다.
  - 마스코트 96px, 간격 12px, 워드마크 18px 를 기기 픽셀 비율로 찍는다. 웹 스플래시와 같은 크기라 이어받을 때 튀지 않는다.
- `index.html` 에 `apple-mobile-web-app-capable` 을 더했다. iOS 가 시작 이미지를 쓰는 조건이다.

### 첫 방문 인트로 (#465 로 뺐다)

#465 에서 이 절의 코드를 모두 지웠다. 아래는 #430 때 넣은 모양이다.

- `widgets/first-visit-intro` 의 `FirstVisitIntro` 가 두 자리의 같은 컴포넌트였다. 매스 `talking`, 말풍선 세 줄(2.6초마다 넘기고 마지막 줄에서 멈춘다), 먹색 페이지 점(누르면 그 줄로), 늘 보이는 「건너뛰기」, 먹색 「시작하기」.
  - Radix Dialog 로 전체 화면을 덮었다. Escape 는 건너뛰기였다. 움직임 줄이기면 말풍선이 바로 바뀌었다.
- 본 기록은 `entities/user/model/introRecord.ts` 였다. 막힌 저장소에서는 읽기 실패를 「기록 없음」으로 보고, 쓰기 실패는 넘겼다.
  - 기기: `first-visit-intro:device`
  - 계정: `first-visit-intro:account:<사용자 ID>` = `pending` → `seen`. 잡아 둔 세션이 지금 세션일 때만 썼다.
- 랜딩: `pages/landing/ui/StartLink.tsx` 가 헤더·히어로·마무리의 `시작하기` 였다. 이 기기에서 처음 누르면 인트로를 먼저 보이고, 닫으면 원래 가던 `/login` 으로 갔다. 링크는 그대로 `<a href>` 였고 새 탭 열기는 가로채지 않았다.
- 대시보드: PM 은 `useOnboardingSave` 의 저장이 `completed` 로 돌아온 순간, 팀원은 「내 팀 확인」(`WorkspaceChoiceList` 온보딩 변형)에서 공간을 고르거나 온보딩 화면에서 초대를 받은 순간 `pending` 이 됐다. `DashboardPage` 가 `pending` 이면 열고 닫을 때 `seen` 으로 바꿨다.
- 스플래시가 덮는 동안 인트로가 열리지 않도록 `splashSignal` 에 「덮는 중」 신호가 있었다. #465 에서 함께 지웠다.

## 설계 결정

| 결정 | 고른 길 | 대안과 버린 이유 |
|---|---|---|
| 뼈대와의 관계 | 첫 부팅에도 `GuardSkeleton`·`RouteSkeleton` 은 그대로 그려지고 스플래시 아래에 가려진다. 뼈대가 그려져 있는 것이 「아직 준비 안 됨」 신호다 | 스플래시가 뼈대를 대신: 가드마다 첫 부팅과 앱 안 이동을 가르는 분기가 들어간다. 앱 안 이동은 지금 뼈대 그대로여야 한다 |
| 준비 판단 | 라우트 뼈대 잡기 수가 100ms 동안 0 | 세션·목록 쿼리 상태를 직접 본다: 화면 코드 대기와 이동 사이 빈틈을 따로 다뤄야 한다. 카드 데이터까지 기다린다: 결정상 스플래시가 기다리지 않는다 |
| 이어받기 | React 가 같은 클래스의 판을 그리고 정적 판을 같은 커밋에 지운다. 등장은 경과 시간으로 이어 간다 | 정적 DOM 을 그대로 쓰기: 로그인 직후에는 정적 판이 없어 두 경로가 된다 |
| 로그인 직후 신호 | `useEnterSession`(로그인·가입 공통 성공 경로) | `RedirectIfAuthed`: 세션을 볼 때는 공간 확인이 이미 끝나 덮을 것이 없다 |
| 랜딩 | 최소 표시 없이 React 가 뜨면 사라짐. 덮는 판일 뿐 랜딩 렌더를 막지 않는다 | 둘러보기·눈웃음까지: 랜딩이 늦게 보이고 검색 노출에 불리하다 |
| 움직임 줄이기 | 정면 + 다이얼만, 준비되면 바로 걷는다 | 눈웃음 시간을 그대로 둔다: 움직이지 않는 화면을 0.6초 더 보일 이유가 없다 |
| E2E | 설정에서 움직임 줄이기 | 제품 코드의 테스트 분기: 운영 번들에 시험용 길이 남는다 |
| 랜딩 인트로 위치(결정 변경, #465 로 뺐다) | 랜딩 `시작하기` 를 이 기기에서 처음 누른 직후. 닫으면 원래 목적지로 | 랜딩 앞 전체 화면: 검색 로봇은 저장소가 없어 매번 첫 방문이고, 랜딩을 덮는 전체 화면은 interstitial 로 본다. 로봇만 빼는 분기는 cloaking 소지라 만들지 않았다 |
| 대시보드 인트로 신호(안 C, #465 로 뺐다) | PM 은 온보딩 완료 저장, 팀원은 「내 팀 확인」에서 처음 공간을 고른 순간. 그 계정만 다음 첫 대시보드에서 한 번 | A(PM 신호만): 팀원은 온보딩 저장을 거치지 않아 빠진다. B(기록 없는 모든 계정): 배포 직후 기존 사용자 모두에게 뜬다 |
| 인트로 계정 기록 모양(#465 로 뺐다) | 계정당 키 하나, `pending → seen` | 신호·본 기록 키 두 개: 둘이 함께 있는 모순 상태가 생긴다 |
| 시작 이미지 크기 | 웹 스플래시와 같은 CSS 크기를 기기 비율로 | 화면 짧은 변에 비례: iPad 에서 이어받을 때 마스코트가 작아지며 튄다 |

## 검증

- 단위·통합(파일마다 `--maxWorkers=1`): 마스코트 50, 스플래시 16(`SplashHost` 12, `staticSplash` 2, `splash` 2), 인트로 37(`FirstVisitIntro` 10, `introRecord` 8, `firstVisitIntro` 19), 기존 온보딩·랜딩·인증·가드 회귀.
- Chromium 연속 스크린샷(개발 서버 MSW, `/auth/me` 6초 지연): 데스크톱·휴대폰 × 움직임 줄이기 켬·끔에서 등장 → 둘러보기(왼쪽 4.0~5.0초, 오른쪽 6.0~6.5초) → 눈웃음 → 사라짐 → 대시보드. 움직임 줄이기는 눈웃음·사라짐 없이 걷힌다. 걷힌 뒤 `#root` 에 `inert` 가 남지 않는다.
