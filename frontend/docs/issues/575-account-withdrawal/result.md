# #575 계정 탈퇴와 정리 상태 표시

2026-11-09 사용자 요청과 [#575](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/575)에 따라 첫 PM 이전 준비 이후 전체 탈퇴 화면을 구현했다. 전체 FE 계획·마일스톤 계획·이슈 목록은 수정하지 않았다. 확정 정책과 HTTP 규약은 [대표 API 계약](../../contracts/frontend-api-contract.md#계정-탈퇴와-정리-상태-575-2026-11-09), 계정 트랜잭션과 AI 정리 결과는 [BE M1 결과](../../../../backend/docs/plan/m1/result.md)에 있다.

## 구현

- 사용자 메뉴의 `/account/withdrawal`에서 전체 소속 공간과 보존·단독 공간 삭제·PM 이전 필요를 보여 준다. 삭제 범위를 확인해야 명령을 보낼 수 있다. PM 이전은 로그인 계정이 연결된 팀원에게 기존 역할 PATCH를 사용하며 본인의 PM 권한은 유지한다.
- 무작위 요청 키와 expected 계정 ID로 본인 탈퇴를 요청한다. 응답을 잃으면 같은 키로 재시도하며 새로고침 뒤에도 영수증을 복원한다. 삭제된 세션 없이 상태를 조회하고, 별도 정책 대화에서 승인한 `개인정보 정리 중`과 실제 확인 후의 `탈퇴 완료`를 구분한다.
- 다른 계정으로 로그인한 동안 도착한 옛 응답은 새 세션·캐시·브라우저 푸시를 바꾸지 않는다. 영수증의 401도 현재 새 계정의 인증 만료로 취급하지 않는다. 즉시 새 계정 가입과 새 초대 필요를 안내한다.
- 태스크·이력·승인·화자·대시보드에는 익명 기록 전용 Member 조회를 사용한다. 담당자 편집·팀 명단·초대·재촉에는 활성 명단을 사용하고 탈퇴 담당자의 재촉 버튼을 제거한다. MSW에도 탈퇴와 영수증·영구 익명 주체·역할 변경을 구현했다.

## 검증

최종 애플리케이션 소스 `a8719ec1`에서 Node 24.21.0으로 실행했다. 검증 전후 애플리케이션 소스 해시가 같고, 이후 문서 변경은 이 실행과 분리했다.

| 경계 | 결과 |
|---|---|
| 전체 Vitest | 286파일, 3,639 통과 |
| 정적 검사·빌드 | TypeScript, ESLint, Prettier, Vite build 통과 |
| 실제 Chromium과 MSW | `account-withdrawal.e2e.ts`, `member-roles.e2e.ts`, `password-reset.e2e.ts`, `auth-limits.e2e.ts`, `restore.e2e.ts`: 15 통과, 재시도 0. trace 보관 |
| 실제 API와 Chromium | MSW를 끄고 격리 HTTPS backend에 연결. 동의 전 버튼 비활성, 탈퇴, 개인정보 정리 중, 새로고침 뒤 영수증, 실제 AI 확인 뒤 완료 화면, 남은 PM의 익명 태스크 표시 확인. 화면·trace 보관 |

실제 API 검증에는 전체 공간 조건 위반 시 변경 없음, 다른 기기 세션 폐기와 WSS 4401, 즉시 같은 이메일로 새 계정 가입, 과거 소속·권한 미복원, 옛 초대 거절과 새 초대 수락, 옛 영수증 재요청 후 새 로그인 보존도 포함된다. API 70동작과 별도 AI claim·ack 4건을 확인했으며 이것을 MSW 시나리오 수와 합산하지 않는다.

전체 회귀에서 새 기록용 Member 요청 때문에 기존 요청 감사 10건이 실패했다. `a8719ec1`에서 정확한 현재 공간의 GET과 `include_withdrawn=true`만 감사에 반영했다. 다른 공간·POST·바뀐 쿼리는 계속 거절하고 인증·공간 선택 전 요청과 중복 업무 생성도 검사한다. 애플리케이션 동작을 시험 기대에 맞춰 바꾸지 않았다.

독립 리뷰에서 확인한 개인정보 사본 누락은 backend·AI 코드에서 수정하고 별도 검증자가 재현을 다시 통과했다. 같은 GPT 계열의 독립 검증이며 교차 모델 계열 검토는 아니다. 기존 계획·사람의 트러블슈팅 37파일은 시작 해시를 보존했다.

## 범위와 남은 확인

소유를 확인할 수 없는 과거 AI 자료나 활성 writer 때문에 정리가 지연되면 pending을 표시한다. 임의 공동 본문·음성의 전체 익명화와 외부에 게시한 Notion·Discord 결과 회수는 이 기능의 완료 범위가 아니다.

실제 공급사·운영 계정에 탈퇴를 실행하거나 배포하지 않았다. Windows에서 확인한 검사와 Linux 전체 CI는 구분하며 CI 결과를 미리 통과로 쓰지 않는다. #572의 다른 이슈·법률·공급사 검토까지 완료했다는 의미는 아니다.

## #584 CI 후속 통합

2026-11-09 사용자 요청으로 최신 develop `a6e9ea68`을 일반 merge했다. API 계약의 탈퇴 규약과 새 응답 검증 규약을 모두 보존했다. 새 메시지 시나리오의 두 번째 PM은 웹에서 쓴 메시지의 작성자이므로 `has_login_account: true`를 명시해 기존 Member 응답 규약에 맞췄다. TypeScript·ESLint·Prettier·build는 통과했다.

합쳐진 실제 Chromium에서 탈퇴·PM 이전·승인·메시지·인증 제한 29 시나리오가 재시도 없이 통과했다. 최초 전체 Vitest는 3,780 통과·10 실패였고, 실패한 팀 초대·별칭·미리 받기 3파일은 소스 변경 없이 분리 실행해 30개 모두 통과했다. 이 분리 실행을 전체 검사 성공으로 쓰지 않는다. 최종 전체 실행과 Linux CI 결과는 [PR #584](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/pull/584)에 연결한다.
