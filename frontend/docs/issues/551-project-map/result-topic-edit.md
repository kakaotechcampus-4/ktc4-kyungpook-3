## 실제 구현 및 관련 코드

- **응답 읽기.** [스키마](../../../src/shared/types/api/projectMap.ts)에 주제 `edited`, 결정 `state`·`edited` 를 더했다. `state` 는 어떤 고치기를 보일지 정하는 판별 값이라 `valid`·`invalid` 밖이면 `INVALID_RESPONSE` 다. 키가 없으면(#669 전 BE) `valid` 다. `edited` 는 표시용이라 모양이 틀리면 false 다(D-184).
- **고치기 요청과 캐시.** [고치기](../../../src/entities/project-map/api/topicEdit.ts)는 네 고치기(주제 이름·설명, 합치기, 떼기, 결정)를 합 타입 하나로 두고, 종류마다 요청(방법·경로·본문)과 캐시 계획을 표 하나에 둔다. 응답은 응답의 `topic_id` 주제 키에 쓴다. 합치기는 원래 주제 키를 지운다. 맵은 `project-map` 접두로 무효화한다(결정을 고치면 다른 주제의 `replaced_by` 도 바뀐다). 회의록은 이름 변경·합치기·결정일 때만 무효화한다. 회의록 캐시 모양은 다른 묶음이 고치므로 무효화만 한다.
- **쓰기 세션(#594).** [훅](../../../src/features/topic-edit/model/useTopicEdit.ts)은 누를 때 세션 범위를 잡고, `mutationFn` 첫 줄에서 끝난 세션이면 보내지 않으며 `signal` 을 싣는다. 끝난 세션의 응답·오류는 캐시와 화면에 아무것도 남기지 않는다. 패널이 다른 주제로 바뀌었으면 폼 닫기·포커스·합친 주제로 옮기기를 하지 않는다. 한 워크스페이스에서 고치기는 한 번에 하나다.
- **오류.** 응답을 읽지 못하면 `변경 결과를 확인하지 못했어요` 토스트와 `새로고침`(맵·회의록)이다. 409 `TOPIC_NAME_TAKEN` 은 `details.topic_id` 로 합치기를 권한다. 404 `TOPIC_NOT_FOUND`·`DECISION_NOT_FOUND`·`TASK_NOT_FOUND` 는 고치던 폼·확인 창 안 문구와 맵 다시 받기다. [오류 코드](../../../src/shared/api/errors.ts)·[문구](../../../src/shared/api/errorMessages.ts)에 `TOPIC_NAME_TAKEN`·`DECISION_NOT_FOUND` 만 더했다. `TRANSCRIPT_LINE_NOT_FOUND` 는 전사 고치기 묶음이 더한다.
- **화면.** [주제 패널](../../../src/widgets/project-map/ui/TopicPanel.tsx)은 패널이 여는 고치기를 상태 하나(`PanelMode`)로 둔다. [고치기 조각](../../../src/features/topic-edit/ui)은 주제 폼, 결정 문장 폼, 결정 메뉴, 합치기 창, 공용 확인 창이다.
  - 주제: `이름·설명 고치기`(패널 안 폼, 이름 1~100자, 설명 1000자 이하, 바뀐 칸만 보냄), `다른 주제와 합치기`(합칠 주제를 고르는 확인 창).
  - 태스크: 줄마다 `떼기` 와 확인 창.
  - 결정: 연필 단추 메뉴의 `문장 고치기`·`유효하지 않음으로 표시`(유효하지 않은 결정은 `유효로 되돌리기`)·`지우기`. 지우기는 확인 창이다. 지운 결정은 화면에서 되살릴 수 없다고 적는다.
  - 표시: `invalid` 는 흐리게 `유효하지 않음` 배지와 `팀원이 유효하지 않다고 표시했어요.`, 고친 결정은 `고침` 배지, 고친 주제는 `팀원이 고친 주제예요.` 다. 뒤집힌 결정의 `뒤집힘` 과 따로 붙는다.
  - 포커스: 폼·확인 창을 닫으면 연 단추로 돌아가고, 줄이 사라지면 그 묶음 제목(`결정`·`태스크`)으로 간다. 패널 제목으로 포커스를 옮기는 때를 제목이 바뀔 때에서 고른 항목이 바뀔 때로 바꿨다([맵 화면](../../../src/widgets/project-map/ui/ProjectMapView.tsx), [시트](../../../src/shared/ui/sheet/Sheet.tsx) `itemKey`). 이름을 고친 뒤 맵을 다시 받아 제목이 바뀌어도 포커스가 고친 단추에 남는다.
- **MSW.** [픽스처](../../../src/shared/mock/fixtures/projectMap.ts)에 주제 `edited`·`detached_task_ids`, 결정 `state`·`edited` 를 더하고, 배포·인프라에 유효하지 않은 결정(`dc_04`)을 하나 더했다. [핸들러](../../../src/shared/mock/handlers/projectMap.ts)의 네 경로는 BE `services/summary.py` 규칙을 따른다(이름 정규화 NFKC·소문자·글자와 숫자만, 409 `details.topic_id`, 합치기의 회의·항목·결정·뗀 표시 옮기기, 지운 결정을 뒤집은 쪽으로 가리키던 `replaced_by` 는 null). 모의 db 판을 24로 올렸다.

- 바꾼 곳 테스트(2026-11-10, `npx vitest run <파일> --maxWorkers=1`): `app/projectMapEdit.test.tsx`(새로 15개), `app/projectMap.test.tsx`, `entities/project-map`(새 통합 테스트 포함), `shared/ui/sheet`, `shared/mock`의 시나리오·저장·태스크 시나리오, `shared/api/errorMessages`. 10개 파일 145개 통과.
- `npm run typecheck`, `npm run build`, `npx prettier --check . '!.verify/**'` 통과. `npm run lint` 는 git 에서 빠진 로컬 검증 파일(`.verify/`)만 걸렸고, 그 폴더를 빼고 돌린 `eslint .` 는 통과했다.
- 전체 테스트(`npm run test`)는 돌리지 않았다. CI 가 돌린다(관리 세션 지시).
- 브라우저(Vite 개발 서버 + MSW, Playwright Chromium, 2026-11-10). 로컬 여정 세 개를 두 번씩 돌려 6번 모두 통과했다.
  - 1280 목록 보기: 유효하지 않은 결정 표시 → 이미 있는 이름으로 고치기(409 안내, `이 주제와 합치기` 창, 취소) → 새 이름 저장(제목·목록·`팀원이 고친 주제예요.`) → 결정 유효하지 않음 표시 → 태스크 떼기 → 다른 주제와 합치기(패널이 합친 주제로 감) → 새로고침 뒤에도 합친 결과·표시가 남음.
  - 1280 그래프 탭: 같은 패널에서 결정 지우기. 뒤집혔던 옛 결정의 `뒤집힘` 이 사라짐.
  - 390: 시트 안 패널, 고치기 폼, 결정 메뉴, 지우기 확인 창, 합치기 창. 각 단계 가로 넘침 0.
  - 입력 중 화면 높이를 바꿔도(1280→600, 390→450) 적던 값·포커스·열린 확인 창이 남았다(6번 통과). 화면 키보드가 높이를 바꾸는 휴대폰을 흉내 낸 것이다.
  - 처음 여정은 확인 창이 뜬 직후 전체 페이지 캡처(`fullPage`)를 찍으면 가끔(4번 중 1번) 확인 창이 닫혔다. 캡처를 빼면 18번 모두 열린 채였고 위 높이 변화로도 닫히지 않아, Chromium 캡처 에뮬레이션의 영향으로 보고 화면 크기 캡처로 바꿨다(추정. 닫히는 원인 자체는 확인하지 않았다).

## 남은 일

- BE #669 병합 뒤 실 API 로 네 경로와 409·404 를 확인한다.
- 다른 주제에 있는 옛 결정을 뒤집은 결정을 지울 때, 확인 창은 그 사실을 말하지 못한다. 패널은 이 주제의 결정만 안다.
- 결정을 지운 뒤에는 토스트가 없다. 줄이 사라지고 포커스가 `결정` 제목으로 간다. 합치기·떼기는 토스트가 있다.
- 저장하는 동안 다른 고치기 단추는 잠기지 않는다. 눌러도 한 번에 하나 규칙으로 아무 일도 하지 않는다.
