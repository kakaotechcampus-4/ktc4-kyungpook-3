## 작업 근거와 요약

마일스톤 계획에 없는 작업이다. 근거는 이슈 #472와 사용자 결정(2026-11-06)이다. [#430](../430-splash/result.md)이 넣은 로딩 스플래시의 매스와 로고 글자가 작다는 의견에 따라 값만 바꾼 미리보기를 보고 크기를 정했다.

| 항목 | 이전 | 지금 |
|---|---|---|
| 마스코트 | 96px | 176px |
| 워드마크 글자 | 18px | 24px |
| 둘 사이 간격 | 12px | 18px |
| 마스코트가 올라오는 거리 | 12px | 22px |
| 워드마크가 올라오는 거리 | 6px | 8px |

위 세 줄은 이슈의 값이다. 아래 두 줄은 큰 크기에서 등장 움직임을 보고 고른 값이다(설계 결정).

## 실제 구현 및 관련 코드

- [splashSize.ts](../../../src/app/splash/splashSize.ts)에 세 크기를 한 곳에 뒀다. 이전에는 `SplashHost`, 시작 이미지 스크립트, `index.html` 세 곳에 숫자를 따로 적었다.
  - [SplashHost.tsx](../../../src/app/splash/SplashHost.tsx)의 `<Mascot size>` 가 이 값을 쓴다.
  - [startup-images.mjs](../../../scripts/startup-images.mjs)가 Vite SSR 로 이 값을 읽어 찍는다.
  - [index.html](../../../index.html)은 JS 보다 먼저 그려야 해서 값을 손으로 적는다. 정적 SVG `width/height`, `.splash__mascot` 상자, `.splash__group` 간격, `.splash__word` 글자 크기를 바꿨다.
- [staticSplash.test.tsx](../../../src/app/splash/staticSplash.test.tsx)가 정적 SVG 를 `SPLASH_SIZE.mascot` 크기의 `Mascot` 과 비교하고, 새로 `index.html` CSS 의 상자·간격·글자 크기를 `SPLASH_SIZE` 와 비교한다. 글자 크기를 18px, 간격을 12px 로 되돌리면 이 테스트가 실패하는 것을 확인했다.
- `index.html` 의 `splash-rise`·`splash-follow` 시작 위치를 `translateY(22px)`·`translateY(8px)` 로 바꿨다. 순서·시간·곡선은 그대로다.
- iOS 시작 이미지 29장(`public/splash/*.png`)을 `npm run startup-images` 로 다시 만들었다. 기기 목록과 `<link>` 줄은 바뀌지 않았다.
- 문서: [결정 기록](../../plan/m2/basis-for-decision/2026-11-06-splash-direction-a-smile.md#이후-변경-마스코트와-워드마크를-키웠다-472)에 크기와 거리 변경을 더했고, [#430 결과](../430-splash/result.md)의 크기 값에 #472 이후 값을 덧붙였다.

## 설계 결정

| 결정 | 고른 길 | 대안과 버린 이유 |
|---|---|---|
| 크기 값을 둘 곳 | `src/app/splash/splashSize.ts` 하나. `index.html` 사본은 테스트가 본다 | 세 곳에 숫자: 이번처럼 바꿀 때 한 곳이 빠져도 아무것도 알리지 않는다 |
| 마스코트가 올라오는 거리 | 크기에 비례해 22px(높이의 1/8) | 12px 그대로: `scale(.9)` 가 176px 상자의 아래 끝을 혼자 8.8px 올려, 거리 12px 이면 아래 끝은 3.2px 만 올라온다(96px 때 7.2px). 올라오는 움직임이 제자리에서 커지는 움직임으로 바뀐다 |
| 워드마크가 올라오는 거리 | 크기에 비례해 8px(글자 크기의 1/3) | 6px 그대로: 마스코트와 같은 이유로 비율을 지킨다 |
| 바꾸지 않은 움직임 값 | 순서·시간·곡선, 끝맺음 0.6+0.4초, λ 3.2, 0.55Hz | 사용자 결정 값이다 |

| 전체 | `npm run typecheck`·`lint`·`format:check`·`build`·`test -- --maxWorkers=1` | 미실행. 메모리가 모자라 시스템이 첫 단계(`typecheck`) 중에 멈췄다. CI 에 맡긴다 |

브라우저 확인:

- 정지 위치(1280×800): 마스코트 `552, 288.6, 176×176`, 워드마크 폭 221.6px. 이전 `592, 335.2, 96`.
- 넘침: 390×844·360×640 에서 `scrollWidth` 가 화면 폭과 같다. 360 에서 워드마크 좌우 여백 69px.
- 이어받기(움직임 허용): 정적 판의 마지막 프레임과 React 판의 첫 프레임이 같은 등장 곡선 위에 있다. 390 에서 `109.7, 320.0, 폭 170.6, 불투명도 0.69` → `109.1, 318.1, 171.7, 0.76`, 1280 에서 `555.9, 302.1, 168.3` → `555.2, 299.8, 169.6`. 멈춘 뒤 정적 판과 같은 자리다.
- 이어받기(움직임 줄이기): 처음부터 `552, 288.6, 176`(1280), `107.0, 310.6, 176`(390)이고 이어받기 앞뒤가 같다.
- 등장 프레임(300~1500ms, 애니메이션을 시각마다 세움): 이전 96px, 176px·12px, 176px·22px 를 나란히 봤다. 정지 프레임으로는 12px·22px 가 거의 같다.
- 시작 이미지와 웹: iPhone 390×844 이미지(`1170x2532.png`)의 먹색 상자가 CSS 좌표 `86, 323.7 – 305.3, 532` 이고, 같은 화면의 웹 스플래시(움직임 줄이기)는 `86, 324 – 306, 532` 다. 29장 모두 먹색 상자가 219×208 CSS px 로 같다.
- 가로 iPad: 가장 낮은 `2266x1488`(iPad mini 가로, 1133×744)에서도 위아래 여백이 있어 잘리지 않는다.
- 페이지 오류 없음. 검증 서버와 브라우저는 스크립트 끝에서 닫았다.

`SplashHost.test.tsx` 의 「늦게 준비되면 모자를 누르고 둘러보다가 …」는 5초 시간 초과로 실패했다. 바꾸기 전 코드(`HEAD` 의 `index.html`·`SplashHost.tsx`)로 돌려도 같은 시간 초과(9.9초)라 이번 변경과 무관하고, 다른 워커와 함께 돈 부하로 본다.

## 미검증

- 실제 iOS 기기의 설치한 앱 시작 화면.
- 다이얼 줄무늬의 이어받기 위상. 최대 한 칸으로 176px 에서 약 7.1px 다(96px 때 3.9px). 마스코트 위치는 그대로다.
- Storybook play와 E2E는 CI에서 돈다. 스플래시 크기를 기대하는 스토리·E2E 는 없다.
