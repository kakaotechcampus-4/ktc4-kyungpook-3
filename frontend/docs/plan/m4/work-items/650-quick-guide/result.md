# #650 처음 쓰는 사람을 위한 ? 안내 패널과 빈 화면 방법 보기

2026-11-10 [#650](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/650)을 구현했다. 마일스톤 계획 밖 이슈 작업이며 전체 계획은 수정하지 않았다. 원고는 [#649](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/pull/649)의 [`docs/user/quick-guide.md`](../../../../../../docs/user/quick-guide.md)다.

## 배경

처음 쓰는 사람(심사위원 포함, #606)은 온보딩을 마치면 빈 대시보드만 본다. 회의를 웹이 아니라 Discord 음성 채널에서 `/join`·`/record`·`/stop`으로 기록한다는 것을 화면 어디에서도 알 수 없었다.

## 변경

- **안내 패널.** 새 슬라이스 `features/quick-guide`. 5단계 원고를 `QUICK_GUIDE_STEPS`(제목·본문·「팀원은」 줄) 표 하나로 두고 `<ol>` 한 번의 map 으로 그린다. 4단계는 원고처럼 팀원 줄이 없다. 넓은 화면은 공통 Modal(폭 560, 본문만 스크롤), 768px 미만은 공통 Sheet 다. 자동으로 열지 않고 단추로만 연다. 코치마크·튜토리얼 라이브러리는 쓰지 않았다.
- **원고와 맞춤.** 뜻은 원고 그대로이고, 단계 번호 표시와 줄바꿈·강조만 화면에 맞췄다. 슬래시 명령은 `<code>`, 5단계 표는 실제 표(표시 칸이 행 머리)다. Discord 도움말 링크 두 개와 아래 「자세히 보기 → 사용자 가이드」는 새 탭으로 열고, 바깥 링크 아이콘과 숨은 글자 「(새 탭)」을 단다. 원고 끝 문장 「더 자세한 내용은 사용자 가이드를 봐요.」는 이 링크로 바꿨다.
- **사용자 가이드 주소.** `mkdocs.yml` 의 문서 포털은 아직 배포 워크플로가 없다(#609 후속). 운영 주소가 없어 공개 저장소의 `docs/user/getting-started.md` GitHub 주소를 상수 `USER_GUIDE_URL` 하나에 두었다. 포털을 배포하면 이 값만 바꾼다.
- **입구 1, 헤더 ? 단추.** `AppHeader` 의 알림 종 옆, 모든 화면과 휴대폰 헤더에 둔다. 접근성 이름은 「도움말」이고, `aria-haspopup="dialog"`·`aria-expanded` 를 단다. 아이콘 세트에 물음표가 없어 `info` 의 원에 물음표를 그린 `help` 아이콘을 더했다. 768px 을 넘나들어도 다른 헤더 단추처럼 key 로 자리만 바꿔 다시 마운트되지 않는다. 단추가 늘어 768px 데스크톱 헤더의 계정 단추가 화면 밖으로 밀려서(리뷰), 탭 묶음은 줄지 않고 오른쪽 묶음이 남는 폭만 쓰게 했다. 1024px 아래는 오른쪽 간격을 8px 로 좁히고, 공간 메뉴는 이름을 말줄임해 줄어든다(768px 에서 「카테…」). 아이콘 단추(도움말·알림)는 줄지 않는다. 이 바람에 768px 의 「프로젝트 맵」 탭 줄바꿈도 없어졌다.
- **입구 2, 빈 화면 방법 보기.** 회의가 하나도 없을 때(녹음·정리 중·만료도 없을 때) 대시보드 최근 반영의 「아직 정리한 회의가 없어요」와 회의록 화면의 「아직 올린 회의가 없어요」의 설명을 「디스코드 음성 채널에서 `/record`로 첫 회의를 기록해 보세요.」로 바꾸고 「방법 보기」를 더했다. 두 곳이 같은 문장 컴포넌트를 쓴다. 대시보드는 정리 끝난 회의가 없을 때 같은 빈 상태를 쓰므로, 진행 중·만료 회의가 있으면 기존 문구 「회의를 정리하면 자동으로 반영한 일이 여기에 보여요.」만 남기고 방법 보기를 두지 않는다(리뷰). PM 에게는 기존 업로드 이동을 남기고, 회의록 빈 화면은 「만나서 회의했다면 녹음 파일을 올려도 돼요.」를 덧붙인다. 팀원에게도 방법 보기를 보인다.
- **입구 3, 온보딩.** 디스코드 연결 단계(`IntegrationStep`, provider 가 discord 일 때만) 카드 설명 아래에 작은 글자 링크 「어떻게 쓰나요?」를 둔다.
- **포커스.** 패널은 제목이 이름인 대화상자이고 포커스를 가둔다. 닫으면 연 단추로 포커스가 돌아간다. 모달은 열 때 포커스가 있던 요소로 돌린다. 시트는 트리거 없이 열어 `returnFocus` 로 연 단추를 준다. Safari 는 눌러도 단추에 포커스를 주지 않아, 단추가 누를 때 스스로 포커스를 잡는다. 패널은 연 때의 폭으로 모달·시트를 정하고 닫을 때까지 그 모양을 지킨다. 연 채 768px 을 넘을 때 모달·시트를 바꿔 끼우면 새 대화상자가 연 단추를 몰라 닫은 뒤 포커스가 body 로 빠졌다(리뷰). 휴대폰을 가로로 돌려도 시트가 그대로라 읽던 자리도 남는다. 닫고 다시 열면 지금 폭의 모양이다.

## 검증

- RTL(`--maxWorkers=1`, 6파일 226개 통과): `features/quick-guide/ui/QuickGuideButton.test.tsx`(5단계·「팀원은」 4줄·명령 코드·링크 새 탭, 모달 닫기·Esc 뒤 포커스 복귀, 휴대폰 폭은 끌어 닫히는 시트이고 닫기·Esc·끌기 뒤 포커스 복귀), `app/appShell.test.tsx`(헤더 도움말로 열기·닫기·복귀, 1024↔390 에서 같은 단추 유지), `app/dashboard.test.tsx`(회의 없음 빈 상태의 `/record` 문장과 방법 보기, 회의가 있으면 없음), `app/meetingMinutes.test.tsx`(PM·팀원 빈 화면 방법 보기, 회의가 있으면 없음), `app/onboardingIntegrations.test.tsx`(디스코드 단계에만 「어떻게 쓰나요?」), `app/onboardingReview.test.tsx`(카드 단추 목록 갱신). 시트 복귀 테스트는 `returnFocus` 를 빼면 실패하는 것을 확인했다. 리뷰 뒤 더한 것: 연 채 390→1024·1280→390 으로 바꾼 뒤 닫기·Esc·끌기로 닫아도 연 단추로 복귀(고치기 전 코드에서 실패 확인), 정리 중 회의만 있으면 대시보드에 첫 회의 안내·방법 보기가 없음(PM·팀원).
- E2E(로컬 Chromium·MSW, 126개 통과): `layout.e2e.ts`(768·1024·1280·1440 의 한 줄 검사에 도움말·알림을 넣고 `ratio: 1` 로 통째로 화면 안인지 본다. 390·360 헤더와 852·667 안전 영역 검사에도 도움말), `select-switch.e2e.ts`(Tab 순서에 도움말을 알림 앞에), `dashboard.e2e.ts`, 온보딩 세 파일. 고치기 전 헤더로 768px 한 줄 검사가 계정 단추 화면 안 비율 0.47 로 실패하는 것을 확인했다.
- 브라우저(MSW 개발 서버, Chromium): 온보딩을 마친 빈 공간으로 대시보드 빈 상태와 패널을 1280·390 폭으로 캡처했다. 두 폭 모두 패널이 화면 안에 들어오고 본문만 스크롤한다. 방법 보기·도움말로 열고 Esc·닫기로 닫은 뒤 연 단추에 포커스가 돌아왔다. `incomplete-workspace` 로 온보딩 디스코드 단계의 「어떻게 쓰나요?」를 열고 닫았고, 온보딩을 마친 빈 공간의 회의록 빈 화면을 캡처했다. `dashboard-no-meeting`(정리 중 회의만)에서는 첫 회의 안내가 없고, 390 에서 연 시트를 1024 로 넓힌 뒤 Esc 로 닫으면 도움말로 돌아왔다. 768·800·852(안전 영역 59)·900·1024·390 폭의 헤더를 재서 가로 스크롤과 넘침이 없음을 확인했다. 증거는 git 에서 제외한 `frontend/.verify/650/` 에 있다.
- `npm run typecheck`, `npm run build` 통과. `npm run lint`·`format:check` 는 git 에서 제외한 `.verify/` 의 캡처 스크립트만 걸려, 그 폴더를 빼고 돌려 통과했다.
