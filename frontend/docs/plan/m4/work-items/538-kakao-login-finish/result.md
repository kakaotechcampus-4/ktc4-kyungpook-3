## 작업 근거와 요약

마일스톤 계획에 없는 작업이다. 근거는 이슈 #538과 사용자 결정(2026-11-09, 관리 세션 경유)이다.

PR #454가 카카오 버튼, `useStartKakao`·`useKakaoLink`·`kakaoLogin`, 가입 단계 화면, MSW 모의 카카오를 이미 넣었다. 이 이슈는 그것을 다시 만들지 않고 빠진 것만 채웠다.

| 이슈가 든 확인 항목 | develop 에서 본 것 | 이번에 한 일 |
|---|---|---|

## 휴대폰 로그인 H-1 (D-185)

사용자 결정: 휴대폰 로그인을 H-1 시안(PwaLogin, 390×844)대로 전부 바꾼다. 지킬 것은 네 가지다. 카카오 문구 유지, 숨긴 라벨의 접근성 이름 유지, 데스크톱 배치 유지, #451 재설정 링크의 대상·동작 유지.

| 시안 | 화면 |
|---|---|
| 위 가운데 매스·제목·한 줄 소개 | 매스 88px(랜딩 링크, #510), 제목 22px, `회의가 끝나면 할 일은 매스가 챙겨요`. 남은 높이 가운데 |
| placeholder 입력 칸 | `이메일`·`비밀번호` placeholder. 라벨은 `sr-only` 로 칸에 이어 둔다(`getByLabelText` 로 찾힌다) |
| 52px·모서리 12 칸과 버튼, 16px | 입력(`auth-phone` 화면군, 테두리 `#949494`)·로그인(`auth-phone` 크기)·카카오 버튼 모두 52px |
| `또는` 없음 | 없다 |
| 맨 아래 `비밀번호를 잊으셨나요?`·`가입하기` | 같은 한 줄. 재설정은 `/forgot-password`, 가입은 넓은 화면처럼 `next` 를 든다 |
| 카카오 문구 `카카오로 계속하기` | **따르지 않았다.** `카카오 로그인`(D-182). 카카오 디자인 가이드의 허용 문구가 아니다 |
| 위 47·아래 34 여백 | 기기 안전 영역이라 `max(24px, env(safe-area-inset-*))` 로 비켰다 |

넓은 화면(768px 이상)은 바꾸지 않았다. 회원가입·비밀번호 재설정은 시안이 없어 그대로다. 라우트 뼈대(#510)도 같은 배치로 그려 글자가 움직이지 않는다.

## 실제 구현 및 관련 코드

- 뼈대: [AuthShellSkeleton](../../../../../src/widgets/auth-shell/ui/AuthShellSkeleton.tsx), [AuthFormSkeletons](../../../../../src/features/auth/ui/AuthFormSkeletons.tsx).

## 설계 결정

| 결정 | 고른 길 | 대안과 버린 이유 |
|---|---|---|
| 휴대폰 분기 | `useCompactScreen`(768px)으로 한쪽 트리만 그린다 | CSS 만으로 숨기기: 재설정 링크가 두 자리에 생겨 같은 링크가 둘이 되고, 라벨 옆 자리와 맨 아래 자리를 CSS 로 옮길 수 없다 |
| 카카오 문구 | `카카오 로그인` | 시안 `카카오로 계속하기`: 카카오 디자인 가이드의 허용 문구(`카카오 로그인`, 짧은 `로그인`)가 아니다 |
| 라벨 | 화면에서만 숨기고 칸에 잇는다 | 라벨 삭제 + `aria-label`: 사용자 결정이 숨긴 label 연결을 요구했고, placeholder 는 입력하면 사라진다 |
| 휴대폰 입력 글자 | 16px | 15px: iOS Safari 가 입력할 때 화면을 확대한다 |
| 제목 자간 | 넓은 화면 제목과 같은 `tracking-h3` | 전역 h1 자간(-0.045em): 뼈대의 `p` 와 글자 폭이 달라 뼈대에서 화면으로 바뀔 때 8px 움직였다 |

## 검증

- Vitest: `authFlow.test.tsx` 의 휴대폰 묶음(매스·소개·랜딩 링크, placeholder 와 숨은 라벨, `또는` 없음, 링크 줄과 이동, 429 안내). `Button.test.tsx` 의 `auth-phone` 크기.
- E2E(MSW): `signup-kakao.e2e.ts` 실패·대기 만료 뒤 다시 시작·기존 계정 연결, 360·390·1280px 화면, H-1 배치 측정. `route-skeleton.e2e.ts` 의 390px 로그인 뼈대.
- 실제 카카오 로그인은 확인하지 않았다. 앱 키·redirect URI 등록이 필요하다.

## 리뷰 반영 (2026-11-09)

독립 리뷰(Codex, Grok)의 지적 세 건을 고쳤다.

| 지적 | 원인 | 고친 것 |
|---|---|---|
| 높음: 768px 경계를 넘으면 입력값·칸 오류·429 안내·카카오 복귀 안내가 사라진다 | `AuthShell` 이 휴대폰과 넓은 화면에서 다른 모양의 트리를 그려, 폭이 바뀌면 React 가 `LoginForm` 을 지우고 새로 만들었다. 카카오 안내는 처음 마운트할 때 한 번 읽고 주소에서 지워 되살릴 수 없다 | 두 폭이 같은 요소(`main > div > section > div`)를 쓰고 클래스와 제목 묶음·안내 카드만 바꾼다. 넓은 화면의 폼 자리는 `display: contents` 라 배치가 그대로다 |
| 중간: 모의 카카오가 성공·`email_exists` 복귀에서 가입 대기를 남긴다 | BE 는 두 복귀에서 대기 쿠키를 지우는데 MSW 는 그대로 뒀다 | `finishMockKakao` 가 두 경우에 `db.kakao.pending` 을 비운다. 취소·실패는 BE 처럼 둔다 |
| 낮음: 계약의 callback 예외 문장이 BE 와 다르다 | 모든 예외가 실패 복귀한다고 적었다 | `OAuthConfigError` 만 `/login?next=%2F&oauth=kakao&oauth_result=failed` 로 가고, 그 밖은 전역 500 이라고 고쳤다 |

검증:

- `authFlow.test.tsx` 에 폭 전환 검사 6개를 더했다. 입력값, 429 안내와 링크, 주소에서 지운 카카오 실패 안내가 휴대폰 → 넓은 화면, 넓은 화면 → 휴대폰 두 방향에서 남는지 본다. 고치기 전 `AuthShell` 로 돌리면 6개 모두 실패한다.
- `mockKakao.test.ts` 에 성공·충돌 복귀가 대기를 지우는 경우(저장본 포함)와 취소·실패가 두는 경우를 더했다.
