# #565 정책 공개와 동의 활성화 결과

## 최신 작업: 사이트 게시 (2026-11-10)

사용자가 Elice 공식 자료 조사 내용을 추가해 사이트에 최종 정책을 적용하도록 요청했다. [사이트 본문 원본](../../../../../src/shared/config/publishedPolicies.ts)에 이용약관·개인정보처리방침을 넣고 게시 설정을 `published`로 전환했다. 판본과 시행일은 모두 `2026-11-10`이며 아래 1차 문서 작업 이후 상태를 대체한다.

### 실제 변경

- 공개 문의 이메일, 교육·평가용 시범 운영, 보관·삭제·탈퇴·재가입 정책을 실제 `/terms`·`/privacy` 화면에 표시한다.
- Elice 국내 처리 안내의 적용 범위와 API 보관·학습 조건의 미확인 범위를 구분했다. pyannoteAI의 음성·결과 보관과 DPA상 다른 항목의 보관도 구분했다. 공식 자료는 화면에서 열리는 링크로 제공한다.
- 가입자는 두 필수 항목을 각각 선택하고 동의 저장 후 진행한다. 기존 초안 동의자는 새 판본에 다시 동의한다. 과거 동의 기록은 보존하며 FE·BE 판본을 함께 올렸다.
- 본문에서 Markdown을 생성하는 `policy:docs`와 문서·FE·BE 판본 일치를 검증하는 `policy:check`를 추가했다. 관련 코드·루트 정책 문서·BE 판본 변경 PR에도 프론트엔드 CI가 실행된다.
- 업무 흐름 테스트의 기존 사용자에게 이미 동의한 계정이라는 전제를 명시했다. 신규 가입·재동의 시나리오는 실제 UI 동의와 저장 결과를 검사하며 자동 동의 처리로 바꾸지 않았다.

### 검증 범위

실제 Chromium에서 정책 직접 접근·랜딩 링크·휴대폰 폭·키보드 이동, 실제 공개 판본의 가입·재동의·새로고침 뒤 기록을 검사한 E2E 9개를 재시도 없이 통과했다. 별도 로컬 프론트엔드 검증 스킬의 가입→공간 생성→모의 연동→대시보드 여정 1개도 통과했다. 실행 ID는 `2026-11-09T15-13-56-126Z-auth-2e2726c9`이며 실행 중 소스 동일성과 종료 후 포트 폐쇄를 확인했다. trace·화면·결과는 로컬 `.verify/`에 보관하며 스킬과 증거는 커밋하지 않는다.

BE 동의 API 테스트는 SQLite 14개 통과, PostgreSQL 매개변수·동시성 등 22개는 로컬에서 건너뛰었다. 초안 동의가 새 판본에 재사용되지 않고 과거 요청은 거절되며 새 동의 이력이 저장되는지 확인했다. 실제 PostgreSQL 검증은 GitHub Actions 결과와 구분한다.

브라우저 여정의 API는 MSW이며 실제 외부 로그인·메일·AI·Notion·Discord 처리나 운영 계정의 동의 저장을 검증한 것은 아니다. 프론트엔드 전체 테스트 3,967개, 타입·린트·포맷·정책 일치·프로덕션 빌드 검사와 변경 Python 파일의 Ruff 검사를 통과했다. 보호 문서 245개가 시작 해시와 같으며 새 결과·정책 안내의 상대 링크 12개와 diff 검사를 통과했다. 원격 CI·배포 결과는 이 PR 및 Actions 기록으로 확인한다.

### 첫 PR CI 실패와 후속 수정

첫 PR CI에서 FE 4,033개와 BE 5,255개(67개 skip), 빌드가 통과했으나 일반 E2E는 305개 통과·22개 실패했다. 동의 조회 대기의 별도 제목 화면이 앱 셸을 대체해 헤더 위치가 76px 움직였고, 라우트 뼈대 비교가 동의 상태 조회를 업무 요청으로 붙잡았다. Enter로 가입하는 테스트 1개에는 필수 체크 동작이 빠져 있었다.

동의 가드가 조회 대기에 앱에서 받은 `GuardSkeleton`을 유지하도록 수정했다. 업무 화면을 미리 열거나 위치 오차 기준을 늘리지 않았다. 라우트 뼈대 테스트의 인증 준비 요청에 동의 조회를 추가하고 가입 테스트에서 두 동의를 선택하게 했다. 동의·라우터·스플래시 테스트 143개와 수정 파일의 타입·린트·포맷·정책 일치 검사가 통과했다. 관련 E2E 53개 중 52개가 통과했고 설정 화면 1개는 Vite의 `@react-refresh` 연결 거절로 빈 화면에서 실패했다. 같은 코드로 단독 재실행한 설정 1개는 통과했다. 이를 제품 수정 완료 근거로 혼동하지 않고 trace에 네트워크 실패와 재실행을 구분해 보관한다. 후속 전체 CI 결과는 연결된 PR에서 확인한다.

### 유지하는 경계

이 작업은 기본 두 문서 게시와 동의 활성화다. 별도 국외 이전·제3자 제공 동의 API, 모든 업무 API의 서버 동의 일괄 차단, 공급사 원격 삭제나 법률 검토 완료를 뜻하지 않는다. 회의 삭제 운영 플래그는 켜지 않는다. 업체 실제 이용 조건·국외 처리 근거·내부 잔여 기록·백업·담당자·책임자 확인은 [#565](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/565)·[#578](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/578)에 남긴다.
