# 공간 생성 전 시작 작업 선택

- 기록일: 2026-11-03
- 관련 마일스톤: M4 인증·온보딩·공간 선택
- 작업 근거: 사용자가 로그인 후 일반 팀원에게 팀 생성을 요구하지 않도록 팀원 작업과 PM 작업을 고르는 앞단을 요청했다.

## 문제와 제약

기존 `postLoginPath`는 소속 공간이 없으면 바로 생성 온보딩으로 이동했다. 반면 서버의 역할은 계정이 아닌 공간별 `Member.role`에 있다. 같은 사람이 공간마다 다른 역할을 가질 수 있으므로 시작 화면의 선택으로 계정 역할이나 권한을 저장할 수 없다.

현재 서버에는 로그인 계정을 다른 사람의 공간에 연결하는 초대·가입 API가 없다. Discord 명단의 팀원 생성 API도 계정 연결을 받지 않는다. 이번 변경은 현재 소속 확인과 PM 생성으로 나누며, 새로운 가입 기능의 계약을 추정하지 않는다.

## 실제 검토한 선택지

| 선택지                         | 검토 결과                                                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| 별도 시작 화면                 | 생성 전 작업 선택을 기존 공간 진행과 분리하고, 명시적 새 공간 생성과 기존 소속 진입을 보존한다. 채택했다.                             |
| 공간 선택 화면에 URL 의도 통합 | 기존 경로를 재사용하지만 다중 소속 선택 화면에 의도 파싱과 패널 분기가 추가된다. 빈 상태 재확인 아이디어만 별도 팀원 화면에 반영했다. |
| 생성 화면 내부 mode            | 팀원도 생성 화면의 문맥에 진입하며 생성 호출자가 mode를 알아야 한다. 배제했다.                                                        |

독립 설계 후보 두 개를 비교하고 위 동작·경계 기준으로 판단했다.

## 선택과 이유

`/onboarding/start`는 `create`와 `join` 작업 의도를 나타내는 링크를 제공한다. 의도는 화면 이동에만 쓰며 서버·localStorage·sessionStorage에 역할 값으로 저장하지 않는다. PM 선택은 기존 생성 화면, 팀원 선택은 `/onboarding/member`의 소속 확인 화면이다.

소속 0개 인증 후 목적지만 바꾼다. 기존 1개·복수 소속과 마지막 공간 우선, 미완료 온보딩 재개, 명시적 새 공간 생성은 유지한다. 선택 링크는 히스토리를 추가하므로 뒤로가기로 선택을 바꿀 수 있다.

역할 선택은 workspace가 생기기 전이므로 서버 `OnboardingStep`에 추가하지 않는다. 기존 생성·Discord·Notion·팀원 연결의 네 단계와 API 입력은 그대로다.

## 장단점과 감수한 제약

일반 팀원은 생성 요청 없이 현재 소속을 확인할 수 있다. 기존 다중 소속 화면에 상태 분기를 늘리지 않는 대신 시작 화면과 팀원 화면의 경로 두 개가 추가된다.

소속 확인은 새로운 팀 가입이 아니다. 기존 API가 연결된 소속을 반환하지 않으면 빈 상태로 남는다. 실제 가입을 제공하려면 초대 수단과 Discord 명단의 계정 연결 규칙부터 별도로 정해야 한다.

## 영향 범위와 재검토 조건

### 디자인 통일 보완

2026-11-03 사용자가 기존 온보딩과의 디자인 차이를 지적해 화면 조립 방식을 수정했다. 별도 경로라는 선택은 유지하되, 별도 앱 헤더·열을 만들지 않고 기존 `OnboardingLayout`·`OnboardingCard`를 재사용한다. 프레임이 중앙 열과 말풍선·계정 메뉴를 소유하고, 각 페이지는 내용과 작업 링크만 조립한다.

공간 생성 전 화면은 진행 단계가 아니므로 단계 표시를 생략한다. 공통 props의 합 타입으로 단계 없는 화면에 단계 nav를 넘기는 것을 막았다. 목록은 온보딩용 표현에서 중복 상자를 제거한다. 기존 생성 카드와 새 두 카드의 브라우저 스타일 비교 검사가 수정 전 불일치를 잡고 수정 후 통과했다. 이 선택은 경로·역할·네 단계 서버 계약을 변경하지 않는다.

### 기능 범위

프론트엔드 진입 경로와 화면·테스트를 변경한다. 서버 요청·응답 스키마와 권한 검사에는 변경이 없다. 기존 M4 계획의 네 단계는 수정하지 않으며, 이번 사용자 추가 요구와 기존 계획의 차이는 결과 기록에 남긴다.

초대 링크·코드 등 참여 방식이 정해지면 팀원 화면의 다음 행동과 인증 후 복귀를 재검토한다. 선택 URL만으로 가입·권한 부여를 완료하지 않는 불변식은 유지한다.
