# 비밀번호 가림 문자가 보이지 않는다 — NanumSquare 의 U+2022 글리프가 비어 있다

- 날짜: 2026-09-29
- 상태: 결정

## 고민

회원가입·로그인의 비밀번호 칸에 입력해도 칸이 빈 것처럼 보였다. 계산된 글자색은 먹(`#171717`)이라 색 문제가 아니었다.
Chromium 은 비밀번호를 `•`(U+2022)로 가린다. 캔버스에 그려 보니 NanumSquare 의 U+2022 는 폭(15px 에서 13.65px)만 있고
칠해지는 픽셀이 0 이다. 폰트가 글리프를 갖고 있다고 답하니 브라우저가 폴백 폰트로 넘어가지 않는다.
`●`(U+25CF, Firefox 의 가림 문자)·`·`·`∙` 는 정상이고 비어 있는 것은 U+2022 하나다.

길은 둘이었다.

1. 비밀번호 입력에만 다른 `font-family` 를 준다
2. `@font-face` 의 `unicode-range` 에서 U+2022 만 빼서 그 문자를 폴백 폰트가 그리게 한다

## 고른 길

2번. `fonts.css` 의 네 벌 모두에 적는다.

```css
unicode-range: U+0-2021, U+2023-10FFFF;
```

그 문자만 `font-family` 의 다음 폰트(Apple SD Gothic Neo · Malgun Gothic · system-ui)가 그린다.

## 왜

- 비어 있는 것은 폰트의 한 글자다. 폰트 정의에서 고치면 비밀번호 칸뿐 아니라 화면 어디에 `•` 가 나와도 함께 고쳐진다.
- 1번은 비밀번호 칸이 `보기`로 평문이 되면 폰트가 바뀌어 글자 모양이 흔들리고, 다른 자리의 `•` 는 그대로 빈칸이다.
- jsdom 은 폰트를 그리지 않는다. `global.test.ts` 는 네 벌의 `unicode-range` 문장을 고정하고, 실제로 보이는지는 브라우저에서 봤다.

## 다시 고민할 때

- NanumSquare 파일을 새 버전으로 바꾸면 U+2022 글리프가 채워졌는지 다시 그려 보고, 채워졌으면 `unicode-range` 를 뺀다.
