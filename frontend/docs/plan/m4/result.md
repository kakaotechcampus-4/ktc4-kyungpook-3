# M4 시작 작업 선택 추가 결과

## 작업 근거와 요약

2026-11-03 사용자가 일반 회원은 로그인 후 팀 만들기가 필요하지 않으므로, 팀원 작업과 PM 작업을 선택하는 앞단을 요청했다. 기존 M4의 인증·온보딩·공간 선택 영역에 이 추가 요구를 구현했다. 과거 M4 전체 완료조건을 이번 변경으로 다시 판정하지 않는다.

소속 공간이 없는 계정은 `/onboarding/start`에서 시작 방식을 고른다. 팀원은 `/onboarding/member`에서 현재 소속 팀을 확인하고, PM은 기존 `/onboarding/create_workspace`로 이동한다. 선택은 권한이나 계정 역할을 저장하지 않는다.

## 실제 구현 및 관련 코드

- [공간 진입 규칙](../../../src/entities/workspace/lib/entryPath.ts)의 0개 소속 분기를 바꾸고, 기존 소속과 마지막 공간·미완료 재개 규칙은 유지한다.
- [시작 화면](../../../src/pages/onboarding-start/ui/OnboardingStartPage.tsx)은 두 작업의 링크를 제공한다.
- [팀원 화면](../../../src/pages/onboarding-member/ui/OnboardingMemberPage.tsx)은 기존 소속 목록과 빈 상태·재확인을 제공한다.
- [공간 목록](../../../src/widgets/app-shell/ui/WorkspaceChoiceList.tsx)은 팀원 화면에서만 생성 행을 숨긴다. 기존 명시적 새 공간 생성은 유지한다.
- [라우트](../../../src/app/router/routes.tsx)의 두 정적 경로는 인증을 요구하며 생성된 공간의 소속 가드 바깥에 있다.

## 검증 내역

변경 전 Chromium에서 기존 가입 후 생성 직행 흐름을 재현했다. 실행 ID는 `2026-11-03T10-31-33-842Z-auth-fc3c5ab1`이며 `.verify/managers-manager/`에 trace·스크린샷·결과를 보관했다. 1개 테스트가 통과했고 cleanup은 포트 닫힘을 확인했다. 이는 변경 후 동작의 증거가 아니다.

변경 후 Node v24.11.0에서 아래 검증을 수행했다.

브라우저 실행 ID는 `2026-11-03T10-49-54-165Z-auth-ba9dbb60`이다. 결과 JSON (`.verify/managers-manager/2026-11-03T10-49-54-165Z-auth-ba9dbb60/results.json`)과 HTML 보고서 (`.verify/managers-manager/2026-11-03T10-49-54-165Z-auth-ba9dbb60/report/index.html`)에 요청·화면·동작 trace와 테스트별 PNG를 보관했다. `.verify/`는 로컬 증거이며 Git에는 포함하지 않는다.

시작 선택 화면의 별도 캡처를 추가한 뒤 팀원 여정 1개를 다시 통과했다. 실행 ID는 `2026-11-03T10-53-29-298Z-auth-eda83dd9`다. 시작 화면 (`.verify/managers-manager/2026-11-03T10-53-29-298Z-auth-eda83dd9/start-choices.png`)과 팀원 빈 상태 (`.verify/managers-manager/2026-11-03T10-53-29-298Z-auth-eda83dd9/member-empty.png`)를 실제로 열어 확인했다. 추가 실행도 종료 후 포트가 닫혔고 증거를 보존했다.

추가 주석 검토에서 시나리오를 반복하는 테스트 주석 1줄을 제거했다. 공개 진입 함수의 반환 계약 주석은 유지했다. 앱의 동작을 바꾸는 검토 수정은 없었다.

## 디자인 통일 보완

2026-11-03 사용자가 새 두 화면이 기존 온보딩과 다른 디자인이라고 지적했다. 초기 구현이 공간 선택 화면의 헤더와 별도 열을 사용한 것이 원인이었다. 앞 절의 초기 시작 화면 캡처는 보완 전 상태이며, 아래 캡처가 디자인을 통일한 상태다.

- 시작·팀 확인 화면이 기존 `OnboardingLayout`과 `OnboardingCard`를 직접 재사용하도록 변경했다. 중앙 512px 열, 매스 말풍선, 카드 반경·테두리·padding·제목 스타일, 왼쪽 위 나가기 화살표를 통일했다.
- 공간 생성 전 화면은 단계 번호·점·카운터 없이 같은 프레임을 사용한다. 기존 공간 온보딩은 네 단계 그대로다. 공통 props는 단계 번호가 없는 경우 단계 nav도 받지 못하는 합 타입으로 표현했다.
- 계정 메뉴는 공통 프레임의 오른쪽 위에 유지했다. 팀원 목록의 중복 외곽 상자를 제거하고 목록 재확인 버튼을 기존 온보딩 버튼 크기·색·오른쪽 정렬에 맞췄다.
- 진입 경로·선택 링크·소속 조회·생성·권한 동작은 유지했다.

[브라우저 디자인 비교 검사](../../../e2e/onboarding-design.e2e.ts)를 추가했다. 수정 전 실행 `2026-11-03T13-24-10-066Z-auth-56d10159`는 시작 화면에 온보딩 카드가 없어 실패했다. 정리 후 포트가 닫힌 것도 확인했다.

수정 후 실행 `2026-11-03T13-28-45-967Z-auth-3a1af193`는 디자인 비교와 기존 사용자 흐름을 포함해 Chromium 12개 테스트가 통과했다. 기존 생성 카드와 새 두 카드의 실제 폭·중앙 위치·반경·테두리·padding·제목 크기·굵기를 비교하며, 시작 화면에 앱 헤더나 공간 단계 점이 없는지도 확인한다. 통일한 시작 화면 (`.verify/managers-manager/2026-11-03T13-28-45-967Z-auth-3a1af193/unified-start.png`)과 통일한 팀 확인 화면 (`.verify/managers-manager/2026-11-03T13-28-45-967Z-auth-3a1af193/unified-member.png`)을 실제로 열어 확인했다. 이 실행도 포트 종료와 증거 보존을 확인했다.

타입·린트·빌드·변경 파일 포맷 검사는 통과했다. 첫 단위·통합 실행은 228개 통과와 `onboardingStart.test.tsx` 두 테스트의 5초 시간 초과였다. 코드나 시간 제한을 바꾸지 않은 해당 파일의 단독 실행은 11개 모두 통과했다. 동시 실행 수를 2로 줄인 전체 묶음에서도 기존 테스트들의 시간 초과가 추가로 발생해 통과로 처리하지 않았다.

PowerShell 출력 리다이렉션을 거치지 않는 Node 직접 실행도 시도했으나 완료된 결과 JSON을 확보하지 못해 중단했으며 통과 근거로 사용하지 않았다. 시간 초과 원인은 확정하지 않았다. 앱 코드·단언·시간 제한을 임의로 바꾸지 않았다. 이번 디자인 보완에서 전체 단위 묶음 통과는 확인하지 못한 상태로 남긴다. 검사 명령·원본 로그·단독 실행 근거는 `.verify/onboarding-design/`에 보관한다.

## 계획 대비 변경

[기존 계획](plan.md)의 공간별 네 단계 앞에 사용자 요청의 시작 작업 선택을 추가했다. 공간이 생성되기 전의 선택이므로 서버 `OnboardingStep`과 네 단계 진행·저장 형식은 바꾸지 않는다. 전체 계획과 기존 M4 계획 원문은 보존한다.

## 남은 작업과 제한 사항

현재 서버에는 로그인 계정을 다른 사람의 공간에 연결하는 초대·가입 API가 없다. 팀원 화면은 현재 소속을 확인하며 새로운 가입을 완료하지 않는다. 초대 링크·코드와 명단 계정 연결은 별도 제품 결정과 API가 필요하다. 실제 백엔드·외부 OAuth 연동 검증과 MSW UI 검증은 구분한다.

파트 간 요청·응답·권한 규약은 변경하지 않았다. 이 추가 화면 때문에 서버 계약을 새로 만들지 않는다.
