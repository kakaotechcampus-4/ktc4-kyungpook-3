## 목표와 배경

간트 보기([GanttView.tsx](../../../src/widgets/task-board/ui/GanttView.tsx))의 `groupRows`는 팀원마다 일정이 있는 태스크와 확인 필요 생성 승인을 처음부터 다시 걸러 묶음을 만든다. 팀원 M명, 항목 N건이면 비교가 약 M×N번이다. `useMemo`로 감싸 있어 매 렌더가 아니라 팀원·태스크·승인 데이터가 바뀔 때의 비용이다. 2026-11-04 선행 조사는 구조만 기록했고 비용은 재지 않았다.

담당자별 분류를 항목을 한 번 훑어 만들고, 화면에 보이는 묶음·순서·문구는 그대로 둔다. 동작 변경이 아니라 구조 변경이다.

## 현재 동작 (바꾸지 않는 계약)

| 항목 | 현재 동작 |
|---|---|
| 묶음 순서 | 팀원 목록 순서 → `알 수 없는 담당자` → `미지정` |
| 묶음 안 순서 | 받은 태스크·승인 순서 그대로. 태스크와 승인은 따로 담는다 |
| 알 수 없는 담당자 | 담당자가 있지만 팀원 목록에 없는 일. 담당자가 여럿이어도 한 묶음에 받은 순서로 둔다 |
| 빈 묶음 | 태스크·승인이 모두 없는 묶음은 그리지 않는다 |
| 일정이 없는 일 | 마감이 없는 태스크·승인은 담당자와 관계없이 묶음에서 빼고 받은 순서대로 `일정이 없는 일`로 보낸다 |
| 표시 문구 | 팀원은 이름과 `PM`·`팀원`, 나머지 두 묶음은 고정 문구 |
| 메모이제이션 | `useMemo(() => groupRows(...), [members, tasks, approvals])` |

- 제외

  - `TaskBoard.tsx`의 데이터 조회와 메모이제이션 경계.
  - `frontend/README.md`(병합 때 반영. 넣을 문장은 작업 보고에 둔다).
  - 전체 계획·기존 마일스톤 계획 수정.

## 작업 순서

1. **옮기기.** `groupRows`와 `Group`을 `lib/ganttGroups.ts`로 글자 그대로 옮기고 `GanttView`는 가져다 쓴다. 옮긴 본문이 원본과 같은지 diff로 확인한다.
2. **고정.** 위 표의 계약을 단위 테스트로 묶는다(담당자 순서, 미지정 위치, 빈 목록, 담당자 변경, 승인 포함, 일정 없는 일, 받은 객체 그대로). 옮긴 코드에서 통과시킨다.
3. **측정 기준.** 옮긴 코드를 양쪽에 두고 비교해 측정 잡음을 확인한다.
4. **바꾸기.** 팀원 ID별 묶음을 `Map`으로 만들고 태스크·승인을 한 번씩 훑어 넣는다. `알 수 없는 담당자`·`미지정`은 별도 묶음이다. 고정 테스트를 그대로 통과시킨다.
5. **동치·비용 확인.** 변경 전 함수와 무작위 데이터에서 출력이 같은지 비교하고, 담당자·항목 수를 달리해 분류 비용과 간트 전체 렌더 비용 대비 몫을 잰다.
6. **유지 판단.** 출력이 같고 읽는 부담이 늘지 않으면 유지한다. 측정한 이득이 없고 읽기도 나아지지 않으면 4단계를 되돌린다.
7. **기록.** 결과 문서에 실제 구현·측정 조건·수치·검증 결과를 적는다.
