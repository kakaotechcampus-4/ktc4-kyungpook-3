## D-174 메시지 정책

**노출 범위**

- production과 실 API 모드에서는 `준비 중`을 유지한다.
- 개발 서버에서 MSW를 켠 경우에만 시안 화면을 보인다.
- 메시지 E2E(D-117)와 polling(D-136)은 계속 보류한다.

**정책 1 — 발송 방식**

| 메시지 | 발송 시점 |
|---|---|
| 태스크 안내 DM | 자동 반영(`gate=auto`) 태스크는 생성 즉시 보낸다. 확인 필요·보류 태스크는 PM이 승인할 때 보내고, 반려하면 보내지 않는다 |
| 진행 재촉 DM | AI가 제안하고 PM이 승인하면 보낸다. 설정의 `재촉 자동 승인`으로 바꿀 수 있다 |
| #회의록 채널 요약 | 회의 정리가 끝나면 자동으로 올린다. 확인 필요 항목은 내용 없이 개수만 싣는다 |

**정책 2 — 검토 단위와 합치기**

- 검토는 `태스크 하나 × 수신자 한 명` 단위로 하고, 발송할 때 합친다.
- 재촉은 수신자와 발송 시각이 같으면 한 통으로 보낸다. `지금 바로`는 5분 동안 모아서 보낸다.
- 태스크 안내는 한 회의록의 자동 반영분을 수신자별로 한 통에 담는다. 승인분은 승인할 때마다 바로 보낸다.
- 답장이 어느 태스크에 대한 것인지는 AI가 판단한다. 판단하지 못하면 PM이 대화 화면에서 태스크를 고른다.
  - 이 경우 대화 목록에 `답장 확인 필요`를 표시한다.
  - PM이 고르는 동안 72시간 시계를 멈추고, 고르지 않은 태스크는 남은 시간부터 다시 센다.

**정책 3 — 재발송과 응답 처리**

- 자동 재발송은 없다. 72시간 동안 응답이 없으면 `막힘`으로 바꾸고 PM에게만 알린다.
- PM 알림 방식은 `웹`·`Discord DM`·`둘 다` 중에서 고르고, 기본값은 `둘 다`다.
- 재촉 제안은 발송 3일 전에 올린다. 남은 시간이 3일보다 짧으면 바로 올린다.
- 발송 직전에 다시 확인해서 응답이 있으면 자동으로 취소한다. 응답으로 인정하는 것은 Discord 답장, 웹 답장, 태스크 상태 변경이다.
- 담당자는 웹 메시지 페이지에서 자기에게 온 메시지에 답장할 수 있다.
  - 웹 답장은 웹에만 남고 Discord로 보내지 않는다.
  - 대화에는 `웹에서 답장` 표시가 붙는다.
- `재촉 자동 승인`은 기본값이 꺼짐이고, 재촉에만 적용한다.
  - 켜짐: PM이 막지 않으면 예정 시각에 자동으로 보낸다.
  - 꺼짐: 예정 시각이 지난 뒤 승인하면 발송 시각을 다시 고르게 한다.
  - 공통: 마감일이 지나면 만료된다.

**정책 4 — 발송 권한**

- 재촉 승인·수정·취소, 발송 시각 선택, 답장 판정, 메시지 설정 변경은 PM만 할 수 있다.
- 일반 팀원은 자기 대화를 보고 답장만 할 수 있다.

**정책 5 — 예약 발송**

- 백엔드 스케줄러가 시각 계산과 판정을 맡고, 메시지 기록의 원본을 만든다.
- 웹은 그 기록을 조회해서 보여 준다.
- Discord 봇은 DM을 전달하고 Discord 답장을 받는다.
- 서버가 멈춰 예약을 놓친 경우, 복구 시점이 마감일 전이면 응답 여부를 다시 확인한 뒤 보낸다. 마감일이 지났으면 만료한다.

**검토 장소와 설정**

- 재촉 검토는 `보내기 전 확인` 화면에서만 한다. 대화 화면에서는 `승인`·`반려`를 없앤다. 이로써 M8 C-10의 상충이 해소된다.
- 설정의 알림 토글 세 개는 기본값을 켜짐으로 한다.
- 시안 문구 두 개를 바꾼다. 캔버스 파일은 고치지 않고 구현할 때 반영한다.
  - `문구는 보내기 전에 항상 확인합니다` → `자동 승인을 켜지 않으면 보내기 전에 문구를 확인합니다`
  - `확인이 끝난 항목만 올라갑니다` → `확인 중인 항목은 개수만 올라갑니다`

## D-175 태스크 보기

- **보드**
  - 컬럼은 `시작 전`(todo)·`진행 중`(in_progress·blocked)·`완료`(done) 세 개다.
  - 확인 필요 항목은 컬럼으로 두지 않고, 보드 아래에 안내 줄로 표시한다.
  - 막힘은 카드 배지로 표시하고, 배지를 누르면 `blocker`를 볼 수 있게 한다. 배지는 아직 구현되지 않았다.
- **간트**: `start_date`부터 `due_date`까지 그린다. `start_date`가 없으면 `created_at`을 쓴다(D-170).
- **캘린더**
  - 마감일 칸 하나에만 놓는다. 확인 필요는 제안된 마감일에, 회의는 회의 날짜에 놓는다.
  - 날짜가 없는 항목은 `마감일 없음` 영역에 모은다.
- **조회**: 1차에서는 전량 조회만 한다. 페이지네이션과 검색은 하지 않고, 지금 있는 필터를 유지한다.
- **정렬 선택**
  - 리스트와 보드에 `마감 빠른 순`(기본값)·`최근 생성순`·`최근 변경순`을 둔다.
  - 선택값은 URL `sort`에 저장하고, 정렬은 프론트엔드에서만 한다.

## D-176 대시보드

- **`채워 넣기`로 들어온 경우**
  - 보완 폼을 자동으로 열고, 처음 비어 있는 필수 칸에 포커스한다.
  - `확인하기`로 들어오면 폼을 열지 않는다.
  - 폼을 열지 여부는 URL에 남기지 않는다.
  - 보완 기능을 쓸 수 없는 모드(현재 실 API 모드)에서는 열지 않는다.
- **`막힌 일 N`**
  - 리스트의 마감 조건 필터에 `막힘`을 추가한다.
  - `막힌 일 N`을 누르면 이 필터를 건 리스트로 이동한다.
  - 나머지 세 요약 항목은 계속 누를 수 없다.
- **최근 반영**
  - 남은 화면 높이를 재서 최소 3개, 최대 8개를 보여 준다.
  - 다 보여 주지 못하면 `외 N건 · 회의록에서 보기` 링크로 해당 회의록 화면에 연결한다.
  - `전체 로그`는 비활성 상태를 유지한다.
  - 근거는 2026-11-03 MSW 실측이다. 목록이 시작하는 높이가 PM 화면은 696px, 팀원 화면은 356px였다. 한 줄 높이는 약 50px(PM)와 약 46px(팀원)였다.

## D-177 팀원 연결과 로그아웃

- 온보딩 뒤의 팀원 연결 창에서는 PM 체크를 요구하지 않는다.
- PM의 Discord가 연결되지 않았으면 PM 알림을 웹으로만 보낸다. 팀원 연결 창과 설정에 그 이유를 안내한다.
- 로그아웃이 성공하면 로그인 화면(`/login`)으로 `replace` 이동한다. 현재 구현을 그대로 확정한 것이다.

## 백엔드·AI 요청 (합의 여부 확인 필요)

요청의 전체 내용은 계약 §8 「2026-11-03에 새로 열린 것」에 있다.

- **백엔드**
  - 메시지 기록 API
  - 스케줄러: 예약 발송, 5분 합치기, 3일 전 제안, 발송 직전 재확인, 72시간 판정과 시계 정지, 놓친 예약 처리
  - 알림 설정 저장 API
  - PM의 Discord가 연결되지 않았을 때 웹으로만 알리는 판정
- **AI·봇**
  - DM 발송과 답장 수신
  - 답장이 어느 태스크에 대한 것인지 판정
  - 재촉 문안 제안
  - #회의록 요약 게시

## 남은 미결

- 재촉을 보내면 72시간 시계를 처음부터 다시 셀지 정하지 않았다.
- 태스크 상태 변경을 72시간 막힘 판정에서도 응답으로 인정할지 정하지 않았다. 재촉 제안과 자동 취소에서는 응답으로 인정한다.
