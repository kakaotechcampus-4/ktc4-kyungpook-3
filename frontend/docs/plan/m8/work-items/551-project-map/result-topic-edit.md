## 실제 구현 및 관련 코드

- **응답 읽기.** [스키마](../../../../../src/shared/types/api/projectMap.ts)에 주제 `edited`, 결정 `state`·`edited` 를 더했다. `state` 는 어떤 고치기를 보일지 정하는 판별 값이라 `valid`·`invalid` 밖이면 `INVALID_RESPONSE` 다. 키가 없으면(#669 전 BE) `valid` 다. `edited` 는 표시용이라 모양이 틀리면 false 다(D-184).
- **고치기 요청과 캐시.** [고치기](../../../../../src/entities/project-map/api/topicEdit.ts)는 네 고치기(주제 이름·설명, 합치기, 떼기, 결정)를 합 타입 하나로 두고, 종류마다 요청(방법·경로·본문)과 캐시 계획을 표 하나에 둔다. 응답은 응답의 `topic_id` 주제 키에 쓴다. 합치기는 원래 주제 키를 지운다. 맵은 `project-map` 접두로 무효화한다(결정을 고치면 다른 주제의 `replaced_by` 도 바뀐다). 회의록은 이름 변경·합치기·결정일 때만 무효화한다. 회의록 캐시 모양은 다른 묶음이 고치므로 무효화만 한다.
- **쓰기 세션(#594).** [훅](../../../../../src/features/topic-edit/model/useTopicEdit.ts)은 누를 때 세션 범위를 잡고, `mutationFn` 첫 줄에서 끝난 세션이면 보내지 않으며 `signal` 을 싣는다. 끝난 세션의 응답·오류는 캐시와 화면에 아무것도 남기지 않는다. 패널이 다른 주제로 바뀌었으면 폼 닫기·포커스·합친 주제로 옮기기를 하지 않는다. 한 워크스페이스에서 고치기는 한 번에 하나다.
- **오류.** 응답을 읽지 못하면 `변경 결과를 확인하지 못했어요` 토스트와 `새로고침`(맵·회의록)이다. 409 `TOPIC_NAME_TAKEN` 은 `details.topic_id` 로 합치기를 권한다. 404 `TOPIC_NOT_FOUND`·`DECISION_NOT_FOUND`·`TASK_NOT_FOUND` 는 고치던 폼·확인 창 안 문구와 맵 다시 받기다. [오류 코드](../../../../../src/shared/api/errors.ts)·[문구](../../../../../src/shared/api/errorMessages.ts)에 `TOPIC_NAME_TAKEN`·`DECISION_NOT_FOUND` 만 더했다. `TRANSCRIPT_LINE_NOT_FOUND` 는 전사 고치기 묶음이 더한다.
- **화면.** [주제 패널](../../../../../src/widgets/project-map/ui/TopicPanel.tsx)은 패널이 여는 고치기를 상태 하나(`PanelMode`)로 둔다. [고치기 조각](../../../../../src/features/topic-edit/ui)은 주제 폼, 결정 문장 폼, 결정 메뉴, 합치기 창, 공용 확인 창이다.
  - 주제: `이름·설명 고치기`(패널 안 폼, 이름 1~100자, 설명 1000자 이하, 바뀐 칸만 보냄), `다른 주제와 합치기`(합칠 주제를 고르는 확인 창).
  - 태스크: 줄마다 `떼기` 와 확인 창.
  - 결정: 연필 단추 메뉴의 `문장 고치기`·`유효하지 않음으로 표시`(유효하지 않은 결정은 `유효로 되돌리기`)·`지우기`. 지우기는 확인 창이다. 지운 결정은 화면에서 되살릴 수 없다고 적는다.
  - 표시: `invalid` 는 흐리게 `유효하지 않음` 배지와 `팀원이 유효하지 않다고 표시했어요.`, 고친 결정은 `고침` 배지, 고친 주제는 `팀원이 고친 주제예요.` 다. 뒤집힌 결정의 `뒤집힘` 과 따로 붙는다.
  - 포커스: 폼·확인 창을 닫으면 연 단추로 돌아가고, 줄이 사라지면 그 묶음 제목(`결정`·`태스크`)으로 간다. 패널 제목으로 포커스를 옮기는 때를 제목이 바뀔 때에서 고른 항목이 바뀔 때로 바꿨다([맵 화면](../../../../../src/widgets/project-map/ui/ProjectMapView.tsx), [시트](../../../../../src/shared/ui/sheet/Sheet.tsx) `itemKey`). 이름을 고친 뒤 맵을 다시 받아 제목이 바뀌어도 포커스가 고친 단추에 남는다.
- **MSW.** [픽스처](../../../../../src/shared/mock/fixtures/projectMap.ts)에 주제 `edited`·`detached_task_ids`, 결정 `state`·`edited` 를 더하고, 배포·인프라에 유효하지 않은 결정(`dc_04`)을 하나 더했다. [핸들러](../../../../../src/shared/mock/handlers/projectMap.ts)의 네 경로는 BE `services/summary.py` 규칙을 따른다(이름 정규화 NFKC·소문자·글자와 숫자만, 409 `details.topic_id`, 합치기의 회의·항목·결정·뗀 표시 옮기기, 저장 불가 글자 400). 결정은 뒤집은 결정 목록(`replaces`)을 저장하고, `replaced_by` 는 읽을 때 지우지 않은 결정 중 가장 이른 회의의 것으로 계산한다(BE `_relink` 와 같다). 모의 db 판을 25로 올렸다.

## 리뷰 반영 (2026-11-10, PR #674 독립 리뷰)

Codex·Grok 리뷰의 다섯 가지를 고쳤다. 건마다 테스트를 먼저 쓰고 고치기 전 코드에서 실패하는 것을 본 뒤 고쳤다.

1. 409 합치기 권유가 받아 둔 맵에 그 주제가 있을 때만 나왔다(둘 다). 이제 `details.topic_id` 가 문자열이면 늘 권하고, 그 주제 상세로 이름을 채우며, 409 뒤 맵을 다시 받는다. 그 주제가 404 면 권하지 않는다. 합친 주제가 아직 맵에 없어도 패널이 그 주제로 옮겨 열린 채 있다(고른 항목에 받은 이름을 함께 둔다). 테스트는 첫 맵 뒤 생긴 주제로 409 를 받고 맵 응답을 붙잡아 둔 채 합친다.
2. 고치기 사이를 옮기면 쓰던 초안이 사라졌고, 앞 저장의 응답이 새로 연 폼을 닫았다(Codex). 저장하는 동안 다른 고치기 진입을 잠그고, 쓰던 폼을 두고 옮기면 앱 공용 미저장 확인(`guardLeave`)을 거친다. 저장 완료는 그 저장을 시작한 폼일 때만 닫는다.
3. 휴대폰 시트에서 합친 뒤 닫으면 사라진 원래 주제 줄로 포커스를 돌리려다 `body` 에 남았다(Codex). 닫을 때 연 단추가 없으면 고른 노드의 목록 줄(`data-node-id`), 그것도 없으면 고른 보기 탭으로 간다. 넓은 화면 패널도 같다.
4. 모의 쓰기 핸들러가 BE 가 거절하는 NUL·짝 없는 서로게이트를 받았다(Codex). 400 `INVALID_REQUEST` 다. 짝이 맞는 서로게이트(이모지)는 저장한다.
5. 결정을 지운 뒤 같은 옛 결정을 뒤집은 다른 결정이 이어받는 경우를 MSW 와 확인 문구가 빠뜨렸다(Grok). MSW 모델을 위처럼 바꾸고, 문구를 `이 결정이 뒤집었던 결정은, 그 결정을 뒤집은 다른 결정이 없으면 다시 유효해져요.` 로 바꿨다.

검사: 바꾼 곳 테스트 13개 파일 175개 통과(`--maxWorkers=1`). typecheck, `.verify` 를 뺀 eslint·prettier, build 통과. 브라우저(MSW)는 기존 여정 세 개를 두 번씩 6번, 새 여정 두 개(1280 쓰던 결정 문장을 두고 주제 고치기를 열면 묻고 계속 쓰면 남음, 390 합친 뒤 시트를 닫으면 합친 주제 줄로 포커스)를 두 번씩 4번 돌려 모두 통과했다.

### 재리뷰 반영 (2026-11-11, Grok)

앞 다섯 지적은 고쳐진 것으로 확인됐고 낮음 두 가지를 더 고쳤다. 둘 다 테스트를 고치기 전 코드에서 실패시킨 뒤 고쳤다.

1. 그래프 탭에서 패널을 닫으면 돌아갈 곳을 `[data-node-id]` 로 찾다가 포커스를 받지 못하는 그래프 노드(SVG)를 잡아 `body` 에 남았다. 목록 단추(`button[data-node-id]`)만 찾고, 없으면 고른 보기 탭이다.
2. 패널 안 고치기 전환이 앱 공용 이탈 확인(「지금 나가면…」, `변경 내용 버리고 나가기`)을 썼고, `계속 작성하기` 뒤 포커스가 누른 단추에 남았다. 패널 전용 확인(`쓰던 내용은 버려지고 다른 고치기가 열려요.`, `계속 작성하기`·`버리기`)으로 바꾸고, 계속 쓰면 마지막으로 쓰던 칸으로 돌아간다. 화면을 떠나는 링크는 앱 공용 확인 그대로다(테스트로 확인).

마지막 리뷰(Grok)의 낮음 한 가지도 고쳤다. 패널 전환 확인이 열린 채 브라우저 뒤로가기를 하면 같은 제목의 앱 이탈 확인이 그 위에 하나 더 열렸다. 이제 이탈 확인이 열리면 패널 전환 확인만 닫고 쓰던 폼은 둔다. `계속 작성하기` 면 쓰던 칸으로 돌아가고 `변경 내용 버리고 나가기` 면 떠난다. 이탈 확인의 문구와 `guardLeave` 는 그대로다. 테스트는 고치기 전 대화상자 둘로 실패했다. 브라우저(MSW)에서도 뒤로가기 뒤 대화상자 하나와 초안·포커스 유지를 두 번 확인했다.

같은 날 origin/develop(#665, D-190)을 병합했다. 결정 기록 충돌은 D-190 뒤에 D-191 을 두어 풀었다. 검사: 바꾼 곳 테스트 15개 파일 197개 통과(`--maxWorkers=1`), typecheck, `.verify` 를 뺀 eslint·prettier, build 통과. 브라우저(MSW): 새 여정 세 개(패널 전환 확인 문구와 계속 쓴 칸 포커스, 그래프로 바꾼 뒤 닫으면 그래프 탭 포커스, 390 합친 뒤 닫기) 두 번씩 6번과 기존 여정 세 개가 통과했다.

- 다른 주제에 있는 옛 결정을 뒤집은 결정을 지울 때, 확인 창은 그 사실을 말하지 못한다. 패널은 이 주제의 결정만 안다.
- 쓰던 폼을 둔 채 다른 노드를 고르거나 패널을 닫으면 묻지 않고 초안이 사라진다(리뷰 범위 밖).
- 합친 직후 원래 주제 단추가 아직 목록에 있을 때 패널을 닫으면 그 단추로 포커스가 가고, 맵을 다시 받아 단추가 빠지면 포커스가 빈다. 토스트가 첫 Esc 를 받아 이 틈은 좁다. 브라우저로 그 타이밍은 재지 않았다.
