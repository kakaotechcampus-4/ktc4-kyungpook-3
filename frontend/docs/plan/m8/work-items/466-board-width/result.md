## 작업 근거와 요약

마일스톤 계획에 없는 작업이다. 근거는 이슈 #466과 사용자 결정(2026-11-06)이다. 보드(E-2)의 좌우 폭을 리스트(E-1)에 맞추고, 캘린더·간트는 셸 폭 그대로 둔다.

전에는 리스트가 960px 컨테이너(본문 864px), 보드가 셸 폭 1360px 안의 1000px 단을 썼다. 리스트와 보드를 오가면 제목·보기 전환·도구줄이 좌우로 움직였다. 1280px 화면에서 본문 단의 왼쪽 끝이 208px ↔ 140px, 오른쪽 끝이 1072px ↔ 1140px였다. 이제 두 보기 모두 208px~1072px다.

## 실제 구현 및 관련 코드

- [TaskBoard.tsx](../../../../../src/widgets/task-board/ui/TaskBoard.tsx)의 `main` 폭을 보기별 표 `PAGE: Record<TaskView, string>`로 정한다. 리스트·보드는 `max-w-[960px]`, 캘린더·간트는 `max-w-shell`이다. 전에는 `PAGE`·`PAGE_LIST` 두 상수를 `view === 'list'` 삼항으로 골랐다.
- 리스트·보드 단의 `max-w-column`(1000px)을 지웠다. 960px 컨테이너에서 좌우 48px을 빼면 864px라 이 제한은 걸리지 않는다.
- 주석 「보드·캘린더·간트는 시안 셸 폭을 유지한다」를 리스트·보드 960px, 캘린더·간트 셸 폭으로 고쳤다.
- 보드 카드는 고치지 않았다. 칸 폭이 321px에서 276px로 줄어도 카드 제목은 이미 `wrap-anywhere`로 접히고 담당자 이름은 말줄임이다. 배지 묶음과 마감일은 줄지 않는다. 아래 검증에서 넘침·겹침이 없었다.
- 블록 사이 간격은 시안대로 리스트 28px, 보드 22px다. 그래서 도구줄의 세로 위치는 6px 다르다(1280px에서 215px ↔ 209px). 이슈의 결정은 좌우 폭이라 바꾸지 않았다.

### 테스트

[task-views.e2e.ts](../../../../../e2e/task-views.e2e.ts)에 1280px·1440px에서 리스트 → 보드 → 리스트로 바꾸며 제목의 왼쪽·위, 보기 전환의 왼쪽·오른쪽·위, 도구줄의 왼쪽·오른쪽이 같은지 재는 테스트를 더했다. 보드 세 칸의 좌우 끝도 도구줄과 같은지 본다. develop의 `TaskBoard.tsx`로 돌리면 두 너비 모두 실패한다(보드 왼쪽 140px·220px). 기존 1024·1440·1920px 보드 넘침 테스트(AC-A-03)는 그대로 통과한다.

## 검증

화면 측정과 스크린샷은 MSW 시나리오 `tasks-long-content`(긴 제목, 줄바꿈할 곳 없는 제목, 긴 담당자 이름)에서 했다. 스크린샷은 커밋하지 않는 로컬 증거다.

- 1280·1440px 리스트·보드 전후 스크린샷을 찍었다. 바꾼 뒤 두 너비 모두 리스트와 보드의 본문 단·제목·보기 전환·도구줄 가로 좌표가 같다. 같은 탭에서 보기 버튼으로 바꿔도 같다.
- 864px 본문의 보드에서 DOM을 쟀다. 문서 가로 넘침 0, 세 칸 각 276px, 말줄임이 아닌데 `scrollWidth > clientWidth`인 요소 0개, 칸 밖으로 삐져나온 요소 0개, 카드 제목과 배지·담당자와 마감일의 겹침 0건이다.
- 막힘 알약 글자를 가장 긴 `자동 막힘`으로 바꾸고(픽스처에 자동 막힘이 없다) 세 칸의 `직접 추가` 입력을 모두 연 상태에서도 넘침·겹침이 없었다. 입력 안에서 긴 글자가 스크롤되는 것만 있다.
- 390px 보드는 전후 스크린샷이 픽셀 단위로 같다. DOM 측정도 지운 클래스 이름을 빼면 같다.

## 남은 작업과 제한 사항

- 리스트 행에서 줄바꿈할 곳이 없는 긴 제목이 담당자 자리 밑으로 들어가 겹친다(develop에서도 같다). 이번 범위 밖이라 고치지 않았다.
- [디자인 문서](../../../../design/design-system.md)의 「앱 셸 본문 최대 1360px, 안쪽 컬럼 1000px」는 셸 전체의 기준이라 그대로 두었다.
- 실서버 연동은 폭과 무관해 따로 확인하지 않았다.
