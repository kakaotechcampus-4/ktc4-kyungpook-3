# 실제 메시지 API 연결 때 서버에 경로·값이 없는 화면 요소를 뺀 선택

- 기록일: 2026-11-04
- 관련 마일스톤: M8-C 메시지(#315, 이전 #245)

## 문제와 제약

- 메시지 화면은 [2026-11-01 결정](2026-11-01-message-ui-scope-design-canvas-msw.md)으로 디자인 캔버스의 항목을 MSW 목 위에 모두 만들었다. 그 응답 모양(`reviews`, `reviews/{id}/send` 등)은 MSW 에만 있었다.
- 백엔드 메시지 API(#310·#314)가 배포됐고 봇 DM 발송(#324)·스케줄러(#329)가 병합됐다. 화면을 production 에서 열려면 [계약 §5.7](../../../contracts/frontend-api-contract.md)의 실제 모양으로 옮겨야 한다.
- 실제 API 에는 시안의 일부 항목에 대응하는 경로나 응답 값이 없다(`backend/app/schemas/message.py`, `backend/app/api/messages.py` 확인). 백엔드·AI 코드는 이 작업에서 고치지 않는다.

## 실제 검토한 선택지

이슈 #315 의 작업 계획 댓글(2026-11-04)과 작업 지시가 각 항목의 처리를 정했다. 항목마다 「빼기」와 「서버 대응을 기다리며 MSW 에 남기기」가 있었고, 지시는 MSW 와 실제 API 가 같은 응답을 쓰게 하는 쪽을 택했다. 그 밖의 대안 검토 기록은 없다.

## 선택과 이유

서버에 경로나 값이 없는 것은 화면·MSW·테스트에서 지운다. MSW 가 실제 API 와 다른 모양을 주면 개발 서버에서만 되는 기능이 다시 생긴다.

| 지운 것 | 이유 | 대신 |
|---|---|---|
| 답장의 태스크 판정(`답장 확인 필요`, 태스크 고르기, `needs_attribution`) | 판정 입력·결과 경로가 없다(§5.7 「아직 없는 것」) | 없음. BE 에 생기면 다시 붙인다 |
| 보낼 시각의 `지금 바로` | BE 는 `scheduled_at` 만 받고 지난 시각은 409 다 | `마감 하루 전`(가장 이른 `due_date` 의 전날 09:00 KST, 화면 계산)과 `직접 정한 시각` |
| 채널 대화(`kind: channel`), 상대의 팀 역할, `Discord에서 열기` 주소 | 대화 응답에 없다 | 대화는 팀원 한 명과의 DM 뿐이다 |
| ~~재촉 이유 문장·근거 링크·목록 요약~~ | 묶음 응답에 없다 | 묶은 태스크 목록(제목·마감·메모), 목록 행은 태스크 제목. **#394 에서 되살렸다**(아래 재검토 조건) |
| 취소·만료된 재촉 줄 | 대화 응답에는 나간 메시지와 예정 묶음만 온다 | 그리지 않는다 |
| 봇 메시지의 `자동 발송`·`○○ 승인`, 예약의 승인자 이름 | 메시지·묶음 응답에 승인자가 없다 | 예정 묶음은 `승인함` 만 쓴다 |

그리고 [2026-10-31 결정](2026-10-31-messages-screen-msw-mode-only.md)의 「MSW 모드에서만 새 화면」을 거둔다. 그 기록의 재검토 조건(「실제 메시지 API가 생기면 모드 분기를 없앤다」)이 충족됐다.

## 장단점과 감수한 제약

- 시안과 달라진 점이 늘었다. 디자인 차이는 [M8-C 결과](../result-c.md#2026-11-04-실제-메시지-api-연결-315)에 있다.
- PM 이 답장이 어느 태스크에 대한 것인지 화면에서 정할 수 없다. D-174 의 「판정하지 못하면 PM 이 확인하고 그동안 72시간 시계를 멈춘다」는 BE 판정 경로가 생겨야 이어진다.
- 직접 정한 시각이 우연히 `마감 하루 전` 시각과 같으면 그 카드가 골라져 보인다. 서버가 고른 방식을 저장하지 않기 때문이다.

## 영향 범위와 재검토 조건

- BE 에 답장 판정, 즉시 발송, 채널 대화, 재촉 이유 같은 값이 생기면 그 항목을 다시 붙인다.
- 충족(2026-11-08, #394): BE 가 #418 에서 묶음 응답에 `summary`, 리마인드마다 `reason`·`evidence` 를 더해 재촉 이유 문장·근거 링크·목록 요약을 되살렸다. 이유와 근거는 묶은 태스크 행마다 보이고, 근거 링크는 Discord 주소가 아니라 앱 안의 대화(`답장 보기`)·태스크 상세(`변경 보기`)다. 결과는 [#394 결과](../work-items/394-bundle-reason/result.md).
- 다시 붙이지 않기로 정했다(사용자, #394 첫 댓글 2026-11-05): 보낼 시각의 `지금 바로`, 채널 대화·팀 역할·`Discord에서 열기`, 취소·만료 재촉 줄, `자동 발송`·승인자 이름. 이 넷은 위 조건과 상관없이 [M8-C 결과](../result-c.md)의 디자인 차이로 남는다. 다시 보려면 새 제품 결정이 필요하다.
- 답장 판정은 #344 에서 다시 붙었다([M8-C 결과](../result-c.md#2026-11-06-리마인드-답장-판단-결과-연결-344)).
- 영향 코드: `src/shared/types/api/message.ts`, `src/entities/message`, `src/features/message-action`, `src/widgets/message-inbox`, `src/pages/messages`, `src/shared/mock`의 메시지 handler·픽스처·상태.
