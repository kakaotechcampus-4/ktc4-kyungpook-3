# 보내기 전 확인 항목 선택을 검색 파라미터 `review`로 임시 표현한 선택

- 기록일: 2026-10-31
- 관련 마일스톤: M8-C 메시지(#245)

## 문제와 제약

- 계획 C-6 3단계는 목록의 선택을 URL로 표현해 새로고침·뒤로가기에서 복원하라고 한다. 고른 대화는 경로 `messages/threads/:threadId`로 정했다(1단계).
- 같은 1단계는 「검토 항목의 경로는 결정 4 이후 정한다」고 했다. 검토 단위·검토 장소·발송 흐름이 결정 4의 범위라, 지금 경로 구조를 정하면 결정 전 가정이 URL 규약이 된다.
- URL 상태는 검색 파라미터로 다루고 값은 페이지 경계에서 한 번 검증한다(D-132).

## 실제 검토한 선택지

구현 워커가 이 충돌을 코디네이터에게 질문했고, 코디네이터가 선택지 B(검색 파라미터 `messages?review=<id>`)를 승인했다. 구현 보고에는 승인된 B만 남아 있고 다른 선택지의 내용은 기록되지 않았다. 리뷰(V2)는 별도 경로 `/messages/reviews/:id`를 확정하지 않았는지를 확인 항목으로 삼았다.

**이 선택은 사용자 결정이 아니다.** 코디네이터가 승인한 임시 표현이며 결정 4 뒤 바뀔 수 있다.

## 선택과 이유

검색 파라미터 `review`로 고른 검토 항목을 표현했다([경로 함수](../../../../src/shared/config/routes.ts)의 `paths.messageReview`, `MESSAGE_PARAMS`).

- 경로 구조를 새로 만들지 않아 결정 4 전에 검토 항목의 URL 규약을 정하지 않는다. 코드 주석에도 「경로 구조를 정하지 않으려고 검색 파라미터로 고른다」, 「규약이 아니다」를 적었다.
- 3단계의 「선택은 URL로」는 지킨다. 선택을 따로 저장하는 상태 없이 URL에서 파생하므로 새로고침·주소 공유에서 같은 항목이 열린다.
- 값은 [MessagesPage](../../../../src/pages/messages/ui/MessagesPage.tsx)에서 `parseRouteId`로 한 번 검증한다(D-132). 목록에 없는 id나 모양이 틀린 id는 오류 화면 없이 **선택 없음**으로 처리한다([MessageInbox](../../../../src/widgets/message-inbox/ui/MessageInbox.tsx)가 현재 목록과 대조).

## 장단점과 감수한 제약

- 대화(경로)와 검토 항목(검색 파라미터)의 선택 표현이 서로 다르다.
- 알 수 없는 id를 조용히 무시하므로, 지워진 항목의 주소로 들어온 사람은 「선택 없음」 화면을 본다. 별도 안내 문구는 없다.

## 영향 범위와 재검토 조건

결정 4에서 검토 단위·검토 장소가 정해지면 검토 항목의 경로 구조를 다시 정한다. 그때 `paths.messageReview`, `MESSAGE_PARAMS`, 이를 쓰는 화면·테스트를 함께 바꾼다.
