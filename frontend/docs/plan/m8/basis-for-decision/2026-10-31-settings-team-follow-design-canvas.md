# 설정·팀 화면의 항목 범위를 디자인 캔버스 아트보드로 정한 선택 (결정 5 해결)

- 기록일: 2026-10-31
- 관련 마일스톤: M8-B(#244) — [계획](../plan.md) B 「선행 결정」의 5·5-a·5-b, 구현 순서 8~12

## 문제와 제약

- 계획 B 절은 결정 5 "설정·팀 화면의 항목 범위와 배분"을 열어 둔 채 B-1(설정 Discord·Notion 연결)만 구현했다. 팀 화면은 `팀원 화면은 이후 마일스톤에서 만들어요.`와 이름 목록뿐인 자리표시자였고, 설정은 이름 입력 한 칸과 두 연결 영역뿐이었다.
- 사용자가 브라우저(MSW)로 두 화면을 보고 디자인대로 되어 있지 않다고 지적하며 **두 화면을 디자인 캔버스 그대로 만들라**고 요청했다(2026-10-31, 코디네이터 지시로 전달).
- 백엔드 변경과 새 API 요청은 B 범위 밖이다(계획 「제외 범위」). 자동 반영 기준·알림·워크스페이스 이름·팀 삭제·Discord 채널·Notion 속성 맞추기에는 서버 API가 없다([계약](../../../contracts/frontend-api-contract.md) §5.8 "그 밖의 설정 항목은 결정 대기"). 연결 해제(`DELETE …/integrations/{provider}`)와 팀원 생성·수정은 있다.
- 지원 폭은 데스크톱 1024px 이상이다(D-123·D-124, [디자인 시스템](../../../design/design-system.md) §10 "<1024 범위 미결").

## 실제 검토한 선택지

1. 계획의 임시 기본값 — 연결 관리와 D-011·D-074~D-076만 다루고 캔버스의 `자동 반영`·`알림`·`이 팀 삭제하기`, 팀 진행률·위험 표시는 넣지 않는다.
2. 디자인 캔버스의 Settings·Team 아트보드를 기준으로 화면 전체를 만든다.

## 선택과 이유

**결정 5는 "디자인 캔버스의 Settings·Team 아트보드를 기준으로 한다"로 정한다(사용자 결정, 2026-10-31).** 사용자가 직접 요청한 범위다. 이에 따라 5-a·5-b도 아트보드로 정해진다.

- **5-a 배치:** 팀원 연결 재진입과 `연결되지 않은 계정`은 **팀 화면**에 둔다. Team 아트보드에 `팀원 관리` 버튼과 `연결되지 않은 계정` 카드(`연결` 버튼)가 있다. 재진입 형태는 팀 화면 위의 **팀원 연결 창**(모달)이다. 창은 주소의 `connect=members`가 쥐므로 D-074의 이동 목적지가 `/workspaces/:id/members?connect=members` 하나로 정해진다. 별도 경로를 만들지 않은 이유는 아트보드에 별도 화면이 없고, 창이 팀 화면의 두 버튼과 같은 자리에서 열리기 때문이다.
- **5-b 추가 조작:** 아트보드의 `연결 끊기`·`채널 바꾸기`·`속성 다시 맞추기`를 모두 둔다. API가 있는 `연결 끊기`는 확인 모달 뒤 서버 성공으로 반영한다(D-137). API가 없는 둘은 버튼을 그리고 누르면 "아직 준비 중"만 알린다.
  - 후속(2026-11-07, #505): 사용자 결정으로 Discord 의 `채널 바꾸기` 를 지웠다. 카드 아래 `회의 채팅 채널` 칸(#429)과 뜻이 겹쳤기 때문이다. Notion 의 `속성 다시 맞추기` 는 그대로다([결과](../../../issues/505-discord-channel-button/result.md)).
- **API가 없는 아트보드 항목:** 자동 반영 기준·알림은 아트보드의 기본 상태로 그리고 화면 안에서만 바뀐다(새로 열면 기본값). 팀 삭제는 "준비 중"을 알린다. MSW에 새 엔드포인트를 만들지 않았다. 실제 서버에 없는 계약을 프론트 API 계층에 들이면 실 서버에서 404가 나기 때문이다.
- **권한:** 서버가 PM에게만 허용하는 쓰기(연결·끊기·팀원 생성·수정)는 PM에게만 보인다. 일반 팀원은 팀 화면과 `연결되지 않은 계정`을 읽고, 설정의 워크스페이스 이름·선택지·토글은 꺼진 채로 보며, 팀 삭제는 보지 않는다. 일반 팀원이 읽는 범위를 따로 비교한 기록은 없다 — 서버 조회 권한(소속 팀원 누구나)을 따랐다.
- **온보딩 뒤 PM 체크(계획 질문 6):** 팀원 연결 창은 PM 체크를 요구하지 않는다. D-075가 아무도 잇지 않고 나가는 것을 허용하므로 저장 조건을 온보딩 `확인 완료`보다 좁히지 않았다. 대안 검토 기록 없음.

## 장단점과 감수한 제약

- 아트보드에 있으나 데이터가 없는 값은 다른 값으로 대신하거나 뺐다. 목록은 [B 결과](../result-b.md) 「아트보드 영역·상태와 현재 화면의 차이」에 있다(직무 → `PM`/`팀원`, 진행률 출처 → 태스크 수정일, `09/15 → 09/17` 점선 칩 없음, Discord 읽는 채널·Notion 마지막 쓰기 → 연결 시각).
- 설정에는 아트보드 본문에 없는 `일반` 절(워크스페이스 이름)을 맨 앞에 두었다. 목차의 첫 항목이 `일반`이고, 이 입력이 이탈 확인 회귀 테스트의 대상이기 때문이다. 그래서 첫 화면의 맨 위는 아트보드(`연결` 절부터)와 다르다.
- 설정에서 Discord 연결이 확인되면 이제 설정에 머물지 않고 팀원 연결 창으로 간다(D-074). B-1의 "성공 뒤 설정 유지" 단언(`settingsConnections.test.tsx`, `settings-team.e2e.ts`)을 바꿨다.
- 저장되지 않는 선택지·토글은 사용자가 저장된다고 오해할 수 있다. 서버 API가 생기면 그 절을 실제 저장으로 바꾼다.
