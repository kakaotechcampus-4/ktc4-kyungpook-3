# 회의 채팅 채널을 저장 전 안내와 저장 버튼으로 바꾸는 방식

- 기록일: 2026-11-07
- 관련 마일스톤: M8-B 설정(#429)

## 문제와 제약

- #429 는 PM 이 설정에서 디스코드 텍스트 채널 하나를 골라 매일 09:00 채팅 자동 수집을 켜게 한다. 저장 전에 안내를 보이라고 했고, 확인 방식은 기존 설정 화면 패턴을 따르라는 작업 지시였다. 안내 문구는 이슈 본문 예시를 그대로 쓰고 끝맺음만 해요체로 다듬는다(#429 의 FE 진행 기본값 댓글, 2026-11-07).
- 서버(`backend/app/services/chat_channel.py` `set_chat_channel`)는 채널 확인과 읽기 확인을 거친 뒤 켬 공지를 채널에 보내고 나서야 저장한다. 저장은 되돌릴 수 없는 외부 메시지를 남긴다. 고르는 순간 바로 저장하면 PM 이 목록을 훑는 동안 공지가 여러 채널에 나간다.
- 설정 화면에는 두 가지 쓰기 방식이 있다. 알림 절은 고르면 바로 저장한다(#340). 연결 끊기는 확인 창을 거친다. 워크스페이스 이름 칸은 바꾼 값을 칸에 두고 `되돌리기` 를 보인다.
- 공용 선택 상자 `shared/ui/select`(#471)가 아직 develop 에 없다.

## 실제 검토한 선택지

- 고르면 바로 저장(알림 절 방식)
- 고르면 확인 창에 안내를 보이고 확인 창에서 저장(연결 끊기 방식)
- 고른 값을 칸에 두고, 칸 아래에 안내와 `저장`·`되돌리기` 를 보이기(워크스페이스 이름 칸 방식)

## 선택과 이유

- 세 번째를 골랐다. 고른 값이 저장된 값과 다르면 칸 아래에 `저장`·`되돌리기` 가 보인다. 켜거나 다른 채널로 바꾸려 할 때만 안내를 칸 아래에 보이고 `aria-describedby` 로 칸에 잇는다.
- 바로 저장은 공지가 원치 않는 채널에 나갈 수 있어 뺐다.
- 확인 창은 실패 안내(봇 권한)를 보인 뒤 다른 채널을 다시 고르는 흐름이 창 안팎을 오간다. 칸 아래 방식은 실패 문구가 고른 칸 바로 아래 남고, 다른 채널을 고르면 문구가 지워진다.
- `사용 안 함` 저장은 안내 없이 DELETE 를 보낸다. 끄는 것은 서버가 끔 공지를 시도하고 실패해도 끄기가 성공한다(`off_notice_sent`). 공지를 남기지 못했으면 성공 토스트에 그 사실을 덧붙인다.
- 선택 칸은 네이티브 `<select>` 하나를 `ChannelSelect.tsx` 에 가둬 두었다. #471 이 병합되면 이 파일만 공용 선택 상자로 바꾼다.

## 장단점과 감수한 제약

- 바꾼 값을 저장하지 않고 나가면 이탈 확인(`useUnsavedChanges`)이 묻는다. 워크스페이스 이름 칸과 같다.
- 안내는 저장 직전에만 보인다. 이미 켜진 채널을 볼 때는 안내가 없다. 지금 값이 무엇을 하는지는 칸 이름(`회의 채팅 채널`)만 알린다.
- 네이티브 `<select>` 는 제품 입력 칸과 높이·경계만 맞췄다. 펼친 목록의 모양은 브라우저 기본이다.
