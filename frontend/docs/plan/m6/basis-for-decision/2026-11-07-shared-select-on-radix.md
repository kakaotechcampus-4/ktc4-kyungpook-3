# 서비스 선택 상자는 Radix Select 위의 공용 부품으로 만든다

- 기록일: 2026-11-07 (감독 결정 2026-11-06)
- 관련 마일스톤: M6 후속, 이슈 #471, 후속 #477

## 문제와 제약

서비스에는 기본 `<select>` 가 여섯 곳 있다. 열린 목록의 모양을 브라우저가 정해서 서비스의 필터 메뉴(`DropdownMenu`)와 맞지 않는다. [이슈 #471](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/471) 댓글에서 승인 확인(E-6)의 담당자 칸을 직접 만든 선택 상자로 바꾸기로 했다. 시안은 `select-design.html` 「1. 담당자」다(작업 워크트리의 Git 제외 경로 `frontend/.verify/reports/`).

제약은 다음과 같다.

- 나머지 다섯 곳(승인 카드 담당자, 상태, 재촉 팀원·태스크, 설정 두 개)과 560px 아래 시트는 후속 #477 에서 같은 부품으로 바꾼다. API 가 그 다섯 곳을 받을 수 있어야 한다.
- 「미정」을 고를 수 있어야 하고, 폼에는 null 로 들어가야 한다.
- 키보드(↑ ↓ Enter Esc, 글자 입력)와 포커스 복귀는 지금 `DropdownMenu` 수준이어야 한다.

## 실제 검토한 선택지

감독(t15)이 2026-11-06 에 정했다. 담당 세션이 정리한 선택지는 다음과 같다.

| 선택지 | 판단 |
|---|---|
| 기본 `<select>` 유지 | 열린 목록을 꾸밀 수 없어 시안을 못 맞춘다 |
| `DropdownMenu` 로 흉내 | 메뉴 역할(menu)이라 값 고르기(listbox)의 접근성 의미가 틀린다 |
| 직접 listbox 구현 | 키보드·포커스·바깥 클릭·스크롤 잠금을 다시 만들어야 한다 |
| `@radix-ui/react-select` 공용 부품 | 채택. 이미 쓰는 Radix 계열과 같은 동작 규칙을 쓴다 |

## 선택과 이유

- `@radix-ui/react-select` 2.3.7 을 정확한 버전으로 더한다. 지금 쓰는 `@radix-ui/react-dropdown-menu` 2.1.24 와 같은 날 함께 나온 판이고, 같은 `@radix-ui/react-popper` 1.3.7 을 쓴다.
- 목록은 `position="popper"` 로 트리거 아래에 연다. 폭은 트리거 이상이다. Radix 기본인 item-aligned(고른 줄이 트리거 위에 겹치게 여는 방식)는 쓰지 않는다. 서비스의 다른 메뉴가 모두 아래로 열리기 때문이다.
- Radix 는 빈 문자열을 항목 값으로 받지 않는다. 「미정」은 부품 안에서만 쓰는 값으로 두고, 바깥으로는 null 로 바꿔 낸다.
- 모양은 `DropdownMenu` 와 같다(반경 14, 줄 반경 10, 고른 줄 `surface-selected`, 그림자 없음). 트리거는 높이 44(작은 크기 36), 반경 9, `input-border` 테두리다. 승인을 막는 빈 칸은 레드 R2 규칙(라벨·경계 `accent`, 플레이스홀더 `accent-solid`, 포커스 `accent-point`)을 따른다.
- API 는 크기 2종, 옵션 앞 아이콘 자리, 옵션 보조줄 자리, 비활성 옵션, 비활성 트리거를 갖는다. #477 의 다섯 곳이 그대로 쓴다.

## 장단점과 감수한 제약

- 의존성이 하나 늘어난다.
- 찾기 칸이 있는 태스크 고르기는 Radix Select 로 만들 수 없다(목록 안에 입력을 둘 수 없다). #477 에서 Popover 와 목록으로 따로 본다.
- 이번 PR 은 E-6 담당자 칸에만 쓴다. 나머지 기본 `<select>` 는 #477 전까지 그대로 남는다.

## 영향 범위와 재검토 조건

- 새 공용 부품 `src/shared/ui/select`. 이번에 쓰는 곳은 승인 확인(E-6)의 담당자 칸 하나다.
