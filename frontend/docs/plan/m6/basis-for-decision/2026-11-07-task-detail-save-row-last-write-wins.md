# 태스크 상세 저장 줄은 바뀐 필드만 보내고 버전 충돌을 따로 다루지 않는다

- 기록일: 2026-11-07 (감독 결정 2026-11-07)
- 관련 마일스톤: M6 후속, 이슈 #471

## 문제와 제약

[이슈 #471](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/471)의 태스크 상세(E-5)는 담당자·마감을 고친 뒤 저장 줄의 「저장」으로 한 번에 보낸다. 이슈는 「409(버전 충돌)면 다시 받아 알린다」고 적었다.

확인한 사실: 저장에 쓰는 `PATCH /tasks/{id}`(`backend/app/api/tasks.py` `update_task`)는 PM 만 부를 수 있고, 행을 잠근 뒤 보낸 필드(`exclude_unset`)를 그대로 덮어쓴다. 요청에 버전이 없고 409 를 내지 않는다. 409 를 내는 것은 자동 막힘 되돌리기와 답장 반영 되돌리기다.

## 실제 검토한 선택지

담당 세션이 관리 세션(t13b)에 물었고 감독(t15)이 정했다.

| 선택지 | 판단 |
|---|---|
| A. 바뀐 필드만 보내고 409 처리 코드를 두지 않음. 동시 수정은 마지막 저장이 이김 | 채택 |
| B. 저장 직전 상세를 다시 받아 version 이 다르면 알림 | 경합을 없애지 못하고 요청만 늘린다 |
| C. BE 에 `expected_version` 을 더하는 이슈 | 지금 열지 않는다 |

## 선택과 이유

- 앱의 다른 태스크 수정(상태 바꾸기 등)도 마지막 저장이 이긴다. 저장 줄만 다르게 두지 않는다.
- 바뀐 필드만 보내므로 다른 사람이 고친 다른 필드는 덮지 않는다. 같은 필드를 두 사람이 고치면 나중 값이 남는다.
- 서버 오류는 저장 줄에 보여 주고 입력은 남긴다. 다시 저장할 수 있다.

## 장단점과 감수한 제약

- 같은 필드의 동시 수정은 알리지 않는다. 변경 이력에는 두 변경이 모두 남는다.
- 이슈의 「409」 체크 항목은 이 결정으로 대신한다. 결과 문서와 PR 에 그렇게 적는다.

## 영향 범위와 재검토 조건

- 태스크 상세 저장 줄만 해당한다. 승인 처리의 충돌 확인([2026-11-04 결정](2026-11-04-approval-edits-and-conflict-confirmation.md))은 그대로다.
- BE 가 태스크 수정에 버전 비교를 더하면 409 를 받아 다시 받고 알리는 경로를 붙인다.
