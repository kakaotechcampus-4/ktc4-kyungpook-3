# 승인 수정값과 충돌 확인을 함께 관리한다

- 기록일: 2026-11-04
- 관련 마일스톤: M6 후속, 이슈 #311

## 문제와 제약

[이슈 #311](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/311)은 생성 승인 보완을 실 API에 연결하고 수정 승인에도 상태·마감 보완을 추가한다. 담당자·마감은 미정을 허용한다. 키 생략은 원래 제안 유지이고 명시적 `null`은 미정이므로 둘을 구분해야 한다.

기존 충돌 화면은 마지막 mutation 오류의 버전을 재승인에 사용한다. 수정 폼이 추가되면, PM이 확인한 내용과 다시 보내는 수정값이 달라질 수 있다. 값을 바꿨다가 되돌리거나 폼을 취소해도 이전 충돌 확인을 재사용하지 않는 것이 #311의 요구다.

[기존 결정](2026-10-11-approval-overrides-held-until-approve.md)의 승인 한 번에 보완값을 싣는 방식은 유지한다. 그 기록의 담당자·마감 필수와 MSW 전용 조건은 이번 후속 요구로 대체한다. 기존 결정과 보호 계획 원문은 수정하지 않는다.

## 실제 검토한 선택지

두 독립 설계 보고서를 비교하고 별도 검토자가 평가했다. 보고서와 선택 기록은 작업 워크트리의 Git 제외 경로 `frontend/.verify/issue-311/`에 있다.

| 선택지 | 장점 | 비용과 확인한 문제 |
|---|---|---|
| 편집값과 mutation 오류를 승인 기능에서 함께 관리 | 기존 mutation의 pending·오류·캐시 처리를 재사용한다. 상세와 목록 카드가 같은 규칙을 쓴다 | 폼 확정 시점에만 오류를 지우면 입력 후 취소에서 과거 확인이 남는다 |
| 입력·제출·충돌·완료를 별도 세션 상태 기계로 관리 | 입력 revision과 제출 사본의 관계가 드러난다 | Query mutation이 가진 요청 생명주기를 다시 표현하고 폼 전체를 제어 입력으로 바꾸는 비용이 크다 |

## 선택과 이유

첫 번째 설계를 기준으로 기존 mutation을 유지한다. 두 번째 설계에서 입력 변경 즉시 확인 해제와 제출한 수정값 보존 규칙을 가져온다. 폼의 보완·확정 상호작용은 재사용한다.

- 생성·수정·반려 요청을 구분하는 타입과 부분 수정 맵으로 허용 필드를 나타낸다. 제목·상태에는 `null`을 허용하지 않는다.
- 원래 제안·근거와 PM 수정값을 분리한다. 완료 화면은 서버가 저장한 수정값을 원래 제안에 적용한다. 명시적 `null`은 원래 값으로 되돌리지 않는다.
- 수정 제안에서 편집하지 않은 필드는 생략한다. 현재 태스크를 다시 조회했다고 미편집 필드가 전송 대상이 되지 않는다.
- 충돌 확인은 당시 제출한 수정값에만 유효하다. 입력을 바꾸면 확인을 해제하고, 값을 되돌려도 과거 확인을 복원하지 않는다. 재승인은 같은 수정값과 해당 충돌 응답 버전을 보낸다.
- 현재 Task의 진행률은 제거하되 과거 진행률 이력은 읽기 전용으로 보존한다. 기존 이력 UI에는 되돌리기 액션이 없으므로 새 액션을 만들지 않는다.

독립 검토도 이 조합에 동의했다. 특히 입력 변경 후 원래 값으로 복구하고 폼을 취소하는 경우를 회귀 검증에 포함하도록 지적했다. 구현과 실행 검증 상태는 [M6 결과](../result.md)에 별도로 기록한다.

## 장단점과 감수한 제약

화면마다 충돌 버전·편집값을 별도로 맞추는 규칙과 두 번째 요청 상태 기계를 줄인다. 대신 모든 편집 경로가 확인 해제 규칙을 사용해야 하므로 상세 폼과 목록 카드의 요청을 함께 검증한다. 승인 전 초안은 서버에 저장하지 않으며, 페이지를 떠나면 사라지는 기존 제약과 이탈 확인을 유지한다.

BE 변경이 아직 배포되지 않은 서버는 새 보완값을 지원한다고 볼 수 없다. 이 FE 변경은 [PR #307](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/pull/307)의 규약을 대상으로 한다. MSW 성공으로 실서버·DB·Notion 반영을 판정하지 않는다.

## 영향 범위와 재검토 조건

승인 엔티티·요청 매핑, 승인 기능과 폼, 상세·목록 승인 UI, MSW 승인·태스크 상태, 현재 Task 진행률 소비 화면이 대상이다. BE가 보완 승인 계약을 바꾸거나 서버에 초안을 저장하는 API가 생기면 다시 검토한다.
