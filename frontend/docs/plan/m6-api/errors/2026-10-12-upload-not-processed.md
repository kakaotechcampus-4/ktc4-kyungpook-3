# 업로드한 회의가 처리되지 않고 처리 중으로 남음

- 구분: BE 보완
- 상태: 보류. 실제 연동 검증에서 업로드를 제외하고, 이미 처리가 끝난 회의 조회부터 검증한다. 배포 서버에서 실제로 재현됐다.

## 현상

- 업로드 요청은 202와 `meeting_id`를 정상 응답한다.
- 그 회의는 계속 `processing`으로 남아 처리 진행 화면(「정리 중」)의 polling이 끝나지 않는다.
- 같은 공간의 다음 업로드는 409 `MEETING_PROCESSING_IN_PROGRESS`로 막힌다(코드 확인, 다시 업로드해 보지는 않았다).

실제 관찰(2026-10-12): 테스트 워크스페이스(`f40058ef-eb02-4df4-b100-c4d049095c59`)에 사용자가 업로드한 회의 `fd74b790-d34f-46c0-b379-c63f3a6aa57f`(`videoplayback.m4a`)가 시작 시각 13:17:23 UTC 이후 `processing`, 처리 완료 시각 `null`로 남아 있다. `GET /workspaces/{id}/meetings`로 확인했다.

## 원인

`POST /workspaces/{id}/meetings/upload`(`backend/app/api/workspaces.py:231`)는 회의를 `processing`으로 만든 뒤 파일을 저장하지도, 처리로 넘기지도 않는다. 코드에 `TODO: 파일 저장 및 큐 전송 등 비동기 처리 연결`이 남아 있다. 저장소에서 업로드 회의를 이어 처리하는 코드를 찾지 못했다.

함께 확인한 차이: `attendee_member_ids`는 문자열 하나로 받는다. 프론트가 여러 번 보내도 마지막 값 하나만 받으며, 그 값도 쓰지 않는다.

## 주의

배포 서버에서 업로드를 한 번 실행하면 그 공간의 업로드가 막힌다. 웹 API로는 풀 수 없다. 회의를 실패로 바꾸는 `PATCH /meetings/{id}/fail`은 봇 경로라 서비스 토큰이 필요하다. 위 회의는 BE에 상태 변경이나 삭제를 요청해야 한다.
