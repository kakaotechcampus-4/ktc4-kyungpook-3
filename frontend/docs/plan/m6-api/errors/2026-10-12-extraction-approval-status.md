# 추출 항목에서 수정 제안의 승인 상태를 알 수 없음 (#211)

- 구분: BE 보완
- 상태: BE 논의 대기. 프론트 판정 코드는 바꾸지 않았다.
- 관련 이슈: [#211](https://github.com/kakaotechcampus-4/ktc4-kyungpook-3/issues/211)

## 현상

회의록에서 대기 중이거나 반려된 수정 제안이 「반영됨」으로 보인다. PM의 「확인이 필요한 일」에서도 빠지고, 일반 팀원에게도 반영 완료처럼 보인다.

## 원인

- 프론트는 `task_id`가 있으면 반영됨으로 판정한다(`frontend/src/entities/extraction/lib/extractionView.ts`).
- 서버는 수정 제안을 만들 때 승인 전부터 대상 태스크를 `task_id`에 넣는다(`backend/app/api/extractions.py:362`).
- 생성 제안을 승인해도 추출 항목의 `approval_id`를 지우지 않는다(`backend/app/api/approvals.py:141`).
- 추출 응답에는 승인 상태와 생성·수정 구분이 없다.

그래서 아래 세 경우가 응답에서 같은 모양(`approval_id`와 `task_id`가 모두 있음)이다.

| 상황 | 반영 여부 |
|---|---|
| 생성 제안, 승인됨 | 반영됨 |
| 수정 제안, 대기 | 반영 안 됨 |
| 수정 제안, 반려 | 반영 안 됨 |

## 검토한 대응

- **PM 화면:** `GET /approvals`는 상태를 지정하지 않으면 대기·승인·반려를 모두 주고 종류도 담는다(`approvals.py:251`). 추출 항목의 `approval_id`와 맞춰 보면 #211 전에도 정확하게 분류할 수 있다.
- **일반 팀원 화면:** D-163에 따라 승인 API를 호출하지 않아 구분할 수 없다. 승인이 걸린 항목을 숨기면 승인으로 새로 만든 태스크도 함께 빠진다.
- **BE에서 고를 방식:**
  - A. 추출 항목에 `approval_status` 추가(#211 제안)
  - B. 생성·수정 승인 때 추출 항목의 `approval_id`를 지움. 이미 쌓인 데이터 정리가 필요하고, 추출 항목에서 승인으로 가는 연결이 끊긴다.

BE와 방식을 정한 뒤 프론트 판정을 바꾼다.
