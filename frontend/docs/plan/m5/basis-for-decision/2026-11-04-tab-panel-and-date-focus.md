# 탭 패널은 안에 누를 것이 없을 때만 Tab 정지점이 되고, 회의 날짜는 기본 날짜 입력을 유지한다

- 기록일: 2026-11-04
- 관련 마일스톤: M5 회의 업로드·회의록 보완(태스크 목록 탭은 M6 화면에 같은 기준 적용), 이슈 #337
- 근거: 2026.10.30 접근성 상세 이슈 보고서(KWCAG 2.2) 슬라이드 8·9·16

## 문제와 제약

보고서는 두 가지를 지적했다.

1. 회의록 `추출된 일` 탭에서 상호작용이 없는 `role="tabpanel"`에 `tabindex="0"`이 있어 Tab 초점이 패널에 들어간다. 개선안은 `tabindex="0"` 제거다.
2. 회의 올리기의 `회의 날짜`에서 Tab이 `+ 추가` 다음 `정리 시작하기`로 넘어가지 않고 연·월·일 칸 안을 맴돈다. 개선안은 `role="spinbutton"` 제거다.

WAI-ARIA APG 탭 패턴은 패널 안에 초점을 받을 요소가 없을 때 패널에 `tabindex="0"`을 두라고 권한다. 따라서 모든 패널에서 일괄 제거하면 `요약`·`전사문`처럼 글만 있는 패널에 키보드로 닿을 방법이 줄어든다. `spinbutton`은 Chrome이 기본 `<input type="date">` 안에 만드는 역할이라 코드에서 지울 수 없다.

## 재현

현재 develop(eede45a0)을 MSW 모의 서버로 띄우고 실제 브라우저에서 Tab을 눌러 초점이 간 접근성 노드를 차례로 기록했다. Playwright Chromium 153과 설치된 Google Chrome 156(한국어 UI)을 사용했다.

| 화면 | 변경 전 Tab 순서 |
|---|---|
| 회의록 `요약` | 탭 → **패널** → 페이지 밖 |
| 회의록 `추출된 일` | 탭 → **패널** → `로그인 API 연동` 링크 → … |
| 태스크 `전체` | 탭 → 마감 조건 → 담당자 → 정렬 → **패널** → `알림 문구 검토` 링크 → … |
| 회의 올리기(빈 폼·파일과 참석자 선택 뒤·제출 실패 뒤 모두) | 회의 제목 → 연도 → 월 → 일 → 날짜 선택도구 → (참석자 빼기) → `추가` → `정리 시작하기` → 페이지 밖 |

- 탭 패널: 지적이 재현됐다. 링크가 있는 패널에서 Tab이 빈 패널을 한 번 더 거친다. 태스크 목록도 같다.
- 회의 날짜: 갇힘은 재현되지 않았다. 연·월·일과 날짜 선택도구 버튼을 한 번씩 지나 `추가`, `정리 시작하기`로 간다. Shift+Tab도 역순으로 빠져나간다. 날짜를 일부만 입력한 상태와 참석자 메뉴를 열었다 닫은 뒤에도 같다. 연·월·일 칸마다 Tab이 멈추는 것은 Chrome의 기본 날짜 입력 동작이다. 보고서 환경(Chrome 155)은 그대로 재현하지 못했고, 그 앞뒤 버전에서 확인했다.

## 실제 검토한 선택지

탭 패널:

- 모든 패널에서 `tabIndex`를 뺀다. 보고서 개선안 그대로지만 글만 있는 패널에서 APG 권고와 어긋난다.
- 탭마다 호출부가 `focusable` 같은 값을 넘긴다. `추출된 일`과 태스크 목록은 불러오기·오류(다시 시도 버튼)·빈 상태·목록에 따라 안에 누를 것이 있기도 하고 없기도 해서, 정적 값으로는 맞출 수 없다.
- 패널 DOM 안에 Tab으로 갈 요소가 있는지 보고 없을 때만 `tabindex="0"`을 둔다. 내용이 바뀌면 다시 본다.

회의 날짜:

- 기본 날짜 입력을 유지한다.
- 연·월·일을 한 칸으로 만든 직접 구현이나 커스텀 날짜 선택기로 바꾼다. 달력·키보드·스크린리더 지원을 직접 책임지게 되어 부담이 크다. 이슈에서 별도 결정으로 미뤘다.

## 선택과 이유

- 세 번째 안을 고른다. `shared/lib/tab-panel`의 `panelTabStop`을 `role="tabpanel"`의 ref로 건다. 패널 안에 활성 링크·버튼·입력·`tabindex`가 음수가 아닌 요소가 없으면 패널에 `tabindex="0"`을 붙이고, 있으면 뗀다. `MutationObserver`로 DOM이 바뀔 때마다 다시 판단한다. `MinutesTabs`와 태스크 목록 `BoardTabs`에 같은 기준을 적용했다. 패널에는 `tabIndex` prop을 함께 주지 않는다. React가 다시 그리면서 그 값으로 덮기 때문이다.
- React 상태 대신 DOM 속성을 직접 바꾼다. 관찰 결과로 다시 그릴 필요가 없고, 테스트에서 act 밖 갱신 경고도 생기지 않는다.
- 회의 날짜는 기본 입력을 유지하고 코드를 바꾸지 않는다. 재현 기록에 갇힘이 없고, `role="spinbutton"`은 브라우저가 붙이는 것이다.

## 장단점과 감수한 제약

변경 뒤 `추출된 일`과 태스크 목록에서는 Tab이 패널을 건너 첫 링크로 간다. `요약`·`전사문`처럼 글만 있는 패널과 빈 상태처럼 누를 것이 없는 패널에는 지금처럼 Tab으로 닿는다. 화면에 숨겨진(`display: none`) 요소나 비활성 `fieldset` 안의 버튼은 Tab 대상으로 셀 수 있으며, 현재 두 패널에는 그런 구성이 없다.

회의 날짜는 칸마다 Tab이 네 번 멈춘다. 검수 측이 다른 환경(보조기술, 확장 프로그램, 다른 Chrome 설정)에서 갇힘을 다시 보이면 그 환경의 재현 절차를 받아 원인을 다시 찾는다.

## 다시 고민할 때

- 검수 측이 회의 날짜 갇힘을 다른 환경에서 재현한 절차를 보내 줄 때
- 탭 패널 안에 숨김 요소나 비활성 `fieldset`이 들어와 판단이 틀릴 때
- 커스텀 날짜 선택기를 도입하기로 따로 결정할 때
