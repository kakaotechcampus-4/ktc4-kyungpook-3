# 스플래시는 A 먹 마스코트와 움직임 3번으로 하고, 마스코트에 눈웃음을 더한다

- 기록일: 2026-11-06
- 관련 마일스톤: 마일스톤 밖 이슈 #430. 마스코트 사양(M2 §8)을 바꾸므로 M2 결정에 둔다.
- 상태: 사용자 결정(2026-11-06). 구현은 #430 브랜치에서 진행했다. 같은 날 준비 뒤 끝맺음(눈웃음·사라짐)을 줄이기로 다시 정했다. 같은 날 첫 방문 인트로를 빼기로 다시 정했다(#465, 아래 「이후 변경」). 다음 날 마스코트·워드마크를 키웠다(#472, 아래 「이후 변경」). 같은 날 준비 뒤 끝맺음을 다시 늘렸다(#506, 아래 「이후 변경」).

## 문제와 제약

앱에는 스플래시가 없었다. JS 를 받는 동안 `index.html` 의 빈 `#root` 라 흰 화면이었고, 로그인 확인(`/auth/me`) 중에는 회색 뼈대(`GuardSkeleton`)가 나왔다. 설치한 앱은 manifest 의 흰 배경과 아이콘으로 기기가 시작 화면을 만들었고 iOS 시작 이미지는 없었다.

세 화면(브라우저 로딩, 설치한 앱 시작, 첫 방문 인트로)을 한 방향으로 맞춰야 했다. 제약은 아래와 같다.

- 로딩 신호는 스피너가 아니라 마스코트의 다이얼(모자 줄무늬가 흐르는 동작)이다(공통 UI 규칙).
- 마스코트는 오버슈트 없는 지수 접근으로만 움직인다(M2 §8-1).
- 움직임 줄이기 설정에서는 정지 프레임이다(M2 §8-5).

## 실제 검토한 선택지

비교 화면(사용자와 맞춘 HTML, 원본 checkout 의 `frontend/.verify/refs/splash-430.html`)에서 네 방향을 나란히 봤다.

| 방향 | 모양 |
|---|---|
| A | 흰 바탕, 먹 마스코트, 먹 워드마크 |
| B | 레드 무대(빨간 바탕) |
| C | 레드 마스코트 |
| D | 먹 무대(검은 바탕) |

움직임은 같은 화면에서 세 안을 봤다.

| 안 | 내용 |
|---|---|
| 1. 둘러보기 | 다이얼을 돌리며 왼쪽·오른쪽·위를 살피고 한 바퀴마다 눈웃음 |
| 2. 스톱워치 | 모자를 박자에 맞춰 누르고 위를 올려다본 뒤 눈웃음 |
| 3. 등장에서 끝까지 | 등장 → 둘러보기 → 눈웃음 → 사라짐 |

## 선택과 이유

**A · 먹 마스코트 + 움직임 3번.** 사용자가 모자까지 먹색으로 통일하라고 했고 A 를 골랐다. 스플래시에는 빨강을 쓰지 않는다. 인트로의 페이지 점도 먹색이다.

움직임 3번의 순서와 시간(시안 값)은 아래와 같다.

| 순서 | 동작 | 시간 |
|---|---|---|
| 1 | 마스코트가 `translateY(12px) scale(.9)`, 투명도 0 에서 제자리로 (#472 부터 `22px`) | 0.8초, `cubic-bezier(.2,.7,.2,1)` |
| 2 | 워드마크가 `translateY(6px)` 에서 제자리로 (#472 부터 `8px`) | 0.3초 뒤 시작, 0.8초 |
| 3 | 모자를 한 번 누른다 | 이름이 뜬 뒤 |
| 4 | 다이얼을 돌리며 정면 → 왼쪽 → 오른쪽 → 정면, 「로그인 확인 중」 | 동작마다 약 1.7초 |
| 5 | 다이얼을 멈추고 눈웃음, 「준비됐어요」 | 눈웃음 단계 0.6초 (시안 1.6초. #506 부터 1.1초: 지어짐 약 0.5초 + 머묾 0.6초) |
| 6 | 전체가 흐려지며 사라진다 | 0.4초 (시안 0.6초. #506 부터 0.6초) |

사용자가 원래 속도를 「너무 빠르다」고 해 스플래시에서는 시선 전환 계수를 λ 3.2(원래 8), 다이얼을 0.55Hz(원래 1.1Hz)로 낮췄다. 원래 값은 마스코트의 기본값으로 남기고, 스플래시가 옵션으로 고른다. 준비가 일찍 끝나면 4단계를 건너뛴다. 연출 때문에 사용자를 기다리게 하지 않는다.

**눈웃음.** 마스코트에 없던 동작이다. 사용자와 다섯 번 맞춘 값이다.

| 항목 | 값 (마스코트 240 좌표, `R = 84`, 눈 중심 `cx, cy`) |
|---|---|
| 모양 | 3차 곡선 `M (cx-11.5, cy+4) C (cx-4.6, cy-5) (cx+4.6, cy-5) (cx+11.5, cy+4)` |
| 두께 | 원래 눈 캡슐 폭 `eyeW × R`(약 14.8), 양 끝 둥글게 |
| 미간 | 웃는 동안 눈 중심을 가운데에서 1.18배 바깥으로 |
| 변화 속도 | 지수 접근 λ 4.5 |
| 이어짐 | 눈이 사라졌다 나타나지 않는다. 뜬 눈을 같은 곡선의 퇴화형(아래 끝에서 위를 찍고 돌아오는 세로선)으로 그려 두 모양을 같은 점끼리 보간한다 |

## 장단점과 감수한 제약

- 눈웃음은 기존 8개 포즈에 더하지 않고 `smile` 옵션으로 얹었다. 포즈 표(M2 §8-2)와 정적 아트보드의 숫자가 그대로 맞고, 어느 포즈 위에서든 눈웃음으로 넘어갈 수 있다.
- 눈웃음은 사각형 눈 대신 선(path)으로 그린다. 웃지 않을 때의 DOM 은 이전과 같다.
- 준비가 일찍 끝나도 눈웃음과 사라짐(약 1초, #506 부터 약 1.7초)은 보인다. 사용자가 고른 연출의 끝맺음이라 감수한다. 처음에는 시안 값(눈웃음 1.6초 + 사라짐 0.6초, 약 2.2초)이었고 사용자가 준비 뒤 끝맺음을 줄이기로 해 눈웃음 0.6초 · 사라짐 0.4초로 줄였다(2026-11-06). 이때 눈웃음이 지어지는 시간까지 잘려, 다음 날 눈웃음 1.1초 · 사라짐 0.6초(약 1.7초)로 다시 늘렸다(#506, 아래 「이후 변경」). 0.3초 안에 끝나는 로딩은 스플래시를 아예 보이지 않는다.

## 영향 범위와 재검토 조건

- 마스코트 사양: `Mascot.tsx`, 원본 `docs/mascot/mascot.js`, M2 계획 §8.
- 스플래시 화면과 iOS 시작 이미지. 첫 방문 인트로는 #465 로 뺐다.
- 다른 화면에서 눈웃음을 쓰려면 같은 값을 쓴다. 값을 바꾸려면 세 곳(코드·원본 스크립트·§8)을 함께 고친다.

## 이후 변경: 첫 방문 인트로를 뺐다 (#465)

- 기록일: 2026-11-06. 사용자 결정(2026-11-06), 이슈 #465.

#430 은 스플래시와 함께 매스 인트로(말풍선 세 줄, 「건너뛰기」·「시작하기」)를 두 자리에 넣었다. 랜딩 `시작하기` 를 이 기기에서 처음 누를 때, 그리고 온보딩을 마친 계정이 처음 대시보드에 들어올 때다. 데스크톱 배치를 다시 그리다가 사용자가 인트로 자체가 필요 없다고 정했다.

- 이유: 서비스 소개는 랜딩(A-1)이 이미 다 한다. 인트로는 같은 이야기를 한 번 더 했다.
- 「시작하기」와 「건너뛰기」가 같은 일을 하는 버튼 두 개였던 문제도 함께 사라진다.
- 초대 링크로 바로 온 팀원은 랜딩 소개를 거치지 않는다. 대시보드의 빈 상태·안내로 충분하다고 봤다.

두 자리 모두 뺐다. 랜딩 `시작하기` 는 #430 이전처럼 바로 `/login` 으로 간다(D-003). 인트로 컴포넌트, 기기·계정 본 기록(`localStorage` 의 `first-visit-intro:*` 키), 온보딩 완료·「내 팀 확인」 첫 선택의 신호를 지웠다. 스플래시가 인트로를 위해 알리던 「덮는 중」 신호(`setSplashCovering`·`useSplashCovering`)도 인트로만 썼으므로 지웠다.

- 이미 저장된 `first-visit-intro:*` 키는 지우는 코드를 두지 않았다. 읽는 코드가 없어 남아도 동작에 영향이 없고, 정리 코드는 그것만을 위해 계속 남는다.
- 그대로 둔 것: 스플래시(로딩, 끝맺음 0.6+0.4초 — #506 에서 1.1+0.6초로 바꿨다, 움직임 줄이기), iOS 시작 이미지, 탭 제목, 마스코트 눈웃음·속도 옵션. 위의 「선택과 이유」 중 인트로 페이지 점 색은 더 쓰이지 않는다.
- 대안 검토 기록 없음. 한 자리만 남기는 안은 이슈에 없고, 사용자가 두 자리 모두 빼기로 정했다.
- 결과: [#465 결과](../../../issues/465-remove-intro/result.md).

## 이후 변경: 마스코트와 워드마크를 키웠다 (#472)

- 기록일: 2026-11-07. 크기는 사용자 결정(2026-11-06), 이슈 #472. 올라오는 거리는 구현 중 선택이다.

사용자가 스플래시의 매스와 로고 글자가 작다고 했다. 값만 바꾼 미리보기(서비스 화면 지도 A-5)를 보고 아래 값으로 정했다. 휴대폰 390 너비에서 넘치지 않는 것도 미리보기로 봤다.

| 항목 | 이전 | 지금 |
|---|---|---|
| 마스코트 | 96px | 176px (몸 원 약 123px) |
| 워드마크 글자 | 18px | 24px |
| 둘 사이 간격 | 12px | 18px |
| 마스코트가 올라오는 거리 | 12px | 22px |
| 워드마크가 올라오는 거리 | 6px | 8px |

- 올라오는 거리는 크기에 비례해 키웠다(마스코트 높이의 1/8, 워드마크 글자 크기의 1/3). `scale(.9)` 는 상자를 가운데로 줄이므로 176px 에서는 아래 끝이 혼자 8.8px 올라온다. 거리를 12px 로 두면 아래 끝은 3.2px 만 올라와 「아래에서 올라오는」 움직임이 「제자리에서 커지는」 움직임으로 바뀐다. 96px 때는 7.2px 였다. 비례로 키우면 사용자가 고른 움직임과 같은 모양이 된다. 정지 프레임으로는 두 안이 거의 같아 보였다.
- 그대로 둔 것: 움직임 3번의 순서·시간·곡선, 끝맺음 0.6+0.4초(#506 에서 1.1+0.6초로 바꿨다), λ 3.2, 다이얼 0.55Hz, 다이얼 줄무늬 속도(SVG 좌표 기준이라 크기와 무관하다).
- 크기 값은 [splashSize.ts](../../../../src/app/splash/splashSize.ts) 한 곳에 둔다. `SplashHost` 와 iOS 시작 이미지 스크립트가 읽고, `index.html` 의 사본은 `staticSplash.test.tsx` 가 같은지 본다. 이전에는 세 곳에 숫자를 따로 적었다.
- 대안: 거리를 12px 로 둔다. 위 이유로 버렸다. 그 밖의 대안 검토 기록 없음.
- 결과: [#472 결과](../../../issues/472-splash-size/result.md).

## 이후 변경: 끝맺음을 늘려 눈웃음이 다 지어진 뒤 사라지게 했다 (#506)

- 기록일: 2026-11-07. 사용자 결정(2026-11-07), 이슈 #506.

사용자가 「끝에 눈웃음이 끝나고 너무 빠르게 사라져서 오히려 어색해」라고 했다. 원인은 눈웃음이 지어지는 시간이다.

- 눈웃음은 지수 접근(λ 4.5)으로 지어진다. 90% 까지 약 0.5초(ln 10 / 4.5 ≈ 0.51초)가 걸린다.
- 2026-11-06 에 끝맺음을 1.6+0.6초에서 0.6+0.4초로 줄이면서, 눈웃음 단계(0.6초)가 지어지는 시간과 거의 같아졌다. 다 지은 얼굴로 머무는 시간은 0.1초쯤뿐이었다.
- 바로 0.4초 동안 사라져, 웃는 중에 꺼지는 것처럼 보였다.

사용자가 A 안을 골랐다.

| 안 | 눈웃음 단계 | 사라짐 | 준비 뒤 끝맺음 |
|---|---|---|---|
| 이전 | 0.6초 | 0.4초 | 1.0초 |
| **A (결정)** | **1.1초** (지어짐 약 0.5 + 머묾 0.6) | **0.6초** | **1.7초** |
| 시안 값 | 1.6초 | 0.6초 | 2.2초 |

- 값: [splashMachine.ts](../../../../src/app/splash/splashMachine.ts) 의 `SMILE_MS` 1100, `FADE_MS` 600, [index.html](../../../../index.html) 의 `splash-out 0.6s`. 두 사라짐 값이 같은지는 `staticSplash.test.tsx` 가 본다. 이전에는 주석으로만 짝을 적었다.
- 그대로 둔 것: 등장(0.3초)·둘러보기 시작(1.5초)·둘러보기 한 동작(1.7초)·준비 확인(0.1초), 0.3초 안 준비는 보이지 않는 규칙, 랜딩 바로 걷힘, 움직임 줄이기 동작, λ 4.5. 랜딩의 사라짐도 같은 `FADE_MS` 라 0.4초에서 0.6초가 됐다. 랜딩은 사라지는 판 아래에 이미 그려져 있고 판이 사라지기 시작할 때부터 누를 수 있다.
- 대안: 시안 값(2.2초)은 사용자가 고르지 않았다. 그 밖의 대안 검토 기록 없음.
- 결과: [#506 결과](../../../issues/506-splash-ending/result.md).

## 이후 변경: 스플래시는 12시간에 한 번, 다시 온 사람은 로그인으로 (#510)

- 기록일: 2026-11-08. 사용자 결정(2026-11-07), 이슈 #510. `시작하기` 스플래시 길이(안 1)는 관리 세션 결정(2026-11-08)이다.

사용자가 「새로고침할 때마다 스플래시가 뜬다. 바로 띄울 수 있는 화면도 스플래시 뒤에 가려진다」고 했다. 준비가 0.3초를 넘으면(프로덕션 실측 약 0.6초) 매번 보이고, 준비된 뒤에도 끝맺음 1.7초 동안 화면을 가렸다.

- **전체 스플래시는 12시간에 한 번.** localStorage `splash-last-shown:v1`(epoch ms, D-147)에 전체 스플래시가 실제로 보인 시각을 남긴다. 값이 없거나 12시간이 지났거나 읽지 못하면 지금 순서 그대로 보인다. 0.3초 안에 준비돼 보이지 않은 채 끝나면 기록하지 않는다.
- **12시간 안이면 건너뛴다.** `index.html` 의 `<head>` 인라인 스크립트가 첫 페인트 전에 값을 읽어 `<html data-splash="skip">` 을 붙이고 CSS 가 정적 판을 그리지 않는다. `SplashHost` 는 이 표시를 보고 판을 지운 뒤 아무것도 띄우지 않는다. 가드 대기는 화면 뼈대(`RouteSkeleton`)가 보이고 준비되면 바로 화면이다. 인라인 스크립트는 JS 번들보다 먼저 돌아야 해서 `splashRecord.ts` 의 판정을 옮긴 사본이다. 둘이 같은지는 `staticSplash.test.tsx` 가 기록 시각 일곱 경우로 본다.
- **설치한 앱(`display-mode: standalone`)** 도 같은 규칙이다. 건너뛸 때도 iOS 시작 이미지는 OS 가 띄우므로 `data-splash="quick"` 으로 정적 판을 그리고, 준비되면 둘러보기·눈웃음 없이 0.2초(`QUICK_FADE_MS`, `index.html` 의 `data-fade='quick'`)에 사라진다. 이 짧은 사라짐은 전체 스플래시가 아니라 기록하지 않는다.
- **로그인 직후 공간 확인** 은 12시간 규칙과 상관없이 지금처럼 보이고, 보였으면 기록한다.
- **랜딩 `시작하기` → 로그인.** 같은 값·12시간 규칙으로 스플래시를 띄운다. 누른 순간 정적 판과 같은 정면으로 등장 없이 보이고, 0.1초에 모자를 누르며 왼쪽을 한 번 본 뒤(0.8초까지) 눈웃음 1.1초 → 사라짐 0.6초, 약 2.5초에 끝난다. 끝맺음은 #506 A안 그대로다. 누르기·Enter·Esc 로 건너뛴다. 새 탭 열기(보조 키·가운데 버튼)는 가로채지 않는다. 로그인 화면 코드가 0.8초 안에 오지 않으면 둘러보며 기다린다. 움직임 줄이기면 정면으로 0.8초 머문 뒤 바로 걷힌다. 0.8초 전에 준비됐다가 다시 잡히면 그 준비는 버리고 새로 풀린 뒤를 기다린다. 판은 포커스를 받는 대화상자이고 건너뛰는 법을 화면에 보이지 않는 안내로 읽힌다. 걷히기 시작하면 로그인 화면의 첫 입력으로 포커스가 간다. 보이는 건너뛰기 버튼은 두지 않았다(디자인 결정 몫).
- **랜딩의 바로 걷힘** 은 처음 온 사람(기록 없음, 검색 로봇 포함)만이다. 기록이 있는 사람이 `/` 로 오면 로그인으로 가므로(D-183) 전체 스플래시 규칙을 따른다. 바로 걷힘은 전체 스플래시가 아니라 기록하지 않는다.

`시작하기` 스플래시 길이의 대안:

| 안 | 순서 | 전체 | 판단 |
|---|---|---|---|
| **1 (결정)** | 정면으로 바로 보임 → 0.1초 모자 누르고 왼쪽 한 번 보기 → 눈웃음 1.1 → 사라짐 0.6 | 약 2.5초 | 지시서의 「약 2.5초 안쪽」과 A안 끝맺음 고정을 둘 다 지킨다 |
| 2 | 등장 0.8초 → 한쪽 보기 0.6 → 눈웃음·사라짐 1.7 | 약 3.1초 | 2.5초를 넘는다 |
| 3 | 새로 접속 순서 그대로, 2.5초에 준비로 보고 눈웃음·사라짐 | 약 4.2초 | 2.5초를 크게 넘고, 2.5초 안에는 머리를 돌리지 않아 둘러보기가 아니다 |

- 그대로 둔 것: 끝맺음 A안(`SMILE_MS` 1100, `FADE_MS` 600, `splash-out 0.6s`), 등장·둘러보기 시각, 0.3초 안 준비는 보이지 않는 규칙, 움직임 줄이기 동작.
- 건너뛸 때 보이는 라우트 뼈대는 화면마다 그 화면이 데이터를 기다릴 때와 같은 틀로 나눴다(#508 2단계 뒤). 코드를 받아 화면 안 뼈대로 바뀌어도 제목·틀이 움직이지 않는다.
