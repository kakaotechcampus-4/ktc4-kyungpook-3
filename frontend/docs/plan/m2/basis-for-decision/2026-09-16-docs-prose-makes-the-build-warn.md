# 글에서 샌 클래스가 이제 죽은 CSS 가 아니라 **빌드 경고**를 낸다

- 날짜: 2026-09-16
- 상태: 확인 필요 — 검증 단계에서 관찰만 했다. 제품 파일을 고치지 않았다.
- 딸린 글: 2026-09-16-tailwind-scans-docs-markdown.md

## 관찰

`npm run build` 가 초록(exit 0)인데 중간에 경고를 한 줄 뱉는다.

```
Found 1 warning while optimizing generated CSS:

│   }
│   .\[color\:var\(\.\.\.\)\] {
│     color: var(...);
┆                ^-- Unexpected token Delim('.')
```

빌드는 실패하지 않는다. 그래서 T6 의 자체 점검(typecheck · lint · test · build)에서 아무도 안 봤다.

## 출처 — 글 한 줄이다

이 경고를 내는 규칙은 `src/` 어디에도 없다.
출처는 `2026-09-16-tailwind-scans-docs-markdown.md` **본문 54번째 줄**이다.
그 줄이 "v4 는 이 문법을 받는다"고 설명하면서 그 이름을 백틱 안에 적었는데,
괄호 안이 실제 변수 이름이 아니라 **말줄임표**다.
Tailwind 추출기는 백틱 안을 그대로 클래스로 줍고, 그래서 값이 말줄임표인 선언이 CSS 로 나간다.
lightningcss 가 그 값을 파싱하다 걸린다.

## 증거 — 빼 봤다

```bash
mv docs/impl-decision/2026-09-16-tailwind-scans-docs-markdown.md /tmp/
npm run build            # 경고 0건
wc -c dist/assets/*.css  # 24,516 B → 24,479 B (-37 B)

mv /tmp/2026-09-16-tailwind-scans-docs-markdown.md docs/impl-decision/
npm run build            # 경고 1건, 24,516 B
```

글 파일 하나를 넣었다 뺐다 하는 것만으로 빌드 경고가 켜졌다 꺼진다.

## 딸린 글에서 한 발 나간 지점

딸린 글은 "글에 적은 클래스가 **죽은 CSS** 를 만든다"까지 적었다.
여기서 한 칸 더 간다 — **죽은 CSS 로 끝나지 않고 빌드 경고까지 만든다.**
값 자리에 진짜 CSS 가 아닌 것(말줄임표·자리표시자·`...` 류)을 적으면 그렇게 된다.
즉 **문법을 설명하려고 적은 예시일수록** 값이 가짜라서 경고가 될 확률이 높다.

## 고른 길

지금은 **아무것도 고치지 않는다.** 검증은 제품 파일을 고치지 않고, 이건 빌드를 깨지도 않는다.

다시 볼 때 순서는 이렇다.

1. 딸린 글이 이미 적어 둔 `@source` 를 `src/app/styles/index.css` 에 건다.
   범위가 `src/` 와 `index.html` 로 좁혀지면 이 경고도 37 B 도 같이 사라진다.
   그게 `@source` 가 실제로 걸렸다는 확인이기도 하다.
2. `@source` 를 미룬다면, 글에서 **값이 가짜인 예시**는 백틱 대신 맨 줄로 적는다.
   딸린 글의 실험대로 구분자가 없으면 추출기가 안 줍는다.

이 글은 그 함정을 다시 밟지 않으려고 문제의 이름을 백틱으로 감싸지 않았다.
위 경고 블록 안에 있는 것은 **이스케이프된 선택자**라 원래 이름과 글자가 달라서 다시 주워지지 않는다.

## 다시 고민할 때

`@source` 를 걸고 빌드했을 때 경고가 0건이고 CSS 가 24,516 B 보다 작아지는지 본다.
경고가 남으면 범위가 안 좁혀진 것이다.
