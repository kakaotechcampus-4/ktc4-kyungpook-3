# 마일스톤 결과 기록

## 공통 작업 경계

- 적용되는 진입점과 docs/agent-rules.md를 따른다. 현재 컨텍스트에서 확인했고 변경되지 않았다면 재읽지 않는다. 새 세션·내용 소실·알려진 변경 시 다시 읽는다. 문서 구조·양식이 필요할 때만 docs/README.md를 확인한다. 공통 규칙이 없으면 기존 지침을 따르고 부재를 보고하며 권한이 불명확한 변경만 보류한다. 초기 구조화는 대신 수행하지 않는다. <part>와 mN은 자리표시자다.
- 대상 파트·마일스톤은 사용자 지시와 작업 맥락으로 정한다. 불명확하면 필요한 식별자만 묻고 가장 큰 번호를 임의로 선택하지 않는다.
- 목표 구조가 없으면 누락 경로를 보고한다. 이 스킬로 전체 문서를 이관하거나 마일스톤을 추정해 생성하지 않는다.
- 공통 구조는 배타적인 폴더 목록이 아니다. design/, mascot/, performance/ 등 파트 고유 문서·자산은 기존 위치를 유지하고 필요할 때만 참조한다. 명확히 대응되는 문서에만 공통 규약을 적용하고 추가 폴더를 구조 오류로 판단하지 않는다.
- 애플리케이션 코드, 전체 개발 계획, 사람의 trouble-shooting/ 기록은 수정하지 않는다. 다른 문서의 쓰기 범위는 아래에 명시한다.
- 기존 사용자 변경과 유효한 기록을 보존한다. 한국어와 상대 링크를 사용하며, 없는 문서의 링크를 만들지 않는다.
- 보호 문서의 작업 시작 상태를 확인할 수 있으면 내용 또는 해시를 확보한다. 종료 시 비교하며, 기준이 없으면 변경 주체를 검증할 수 없다고 보고한다. HEAD 차이를 작업 시작 기준으로 간주하지 않는다.

## 쓰기 범위

현재 마일스톤의 result.md와 해당 파트 README.md만 생성·갱신한다. plan.md는 빈 파일이어도 쓰지 않는다. 의사결정 문서가 필요하면 확인된 내용과 대상 경로를 보고하거나 사용 가능한 decision-record 절차를 사용한다. 해당 스킬이 없어도 result 작성은 진행한다.

## 기록 절차

1. plan.md, 전체 계획, 기존 result, 작업 변경 내역과 실제 검증 출력을 읽는다.
2. [결과 양식](assets/result-template.md)에 따라 이번 결과를 기존 기록에 통합한다. 유효한 과거 기록을 지우거나 같은 실행 기록을 반복 추가하지 않는다.
3. 완료조건의 기존 ID와 의미를 보존한다. ID가 없으면 원문 조건을 인용해 대응시키며 계획 파일에는 ID를 추가하지 않는다.
4. 직접 확인한 검증 근거로 충족·미충족·미검증을 구분한다. 코드 존재만으로 실행 결과를 증명하지 않는다. 이전 검증이 현재 변경에 유효한지 불명확하면 이전 기록과 현재 미검증 상태를 구분한다.
5. 계획이 비어 있으면 사용자의 실제 작업 지시와 계획 부재를 명시한다. 완료조건을 발명하거나 마일스톤 완료로 표시하지 않는다.
6. 계획과 달라진 구현, 이유, 영향, 미완료 작업을 기록한다. 이유를 모르면 확인 필요로 남긴다.
7. README의 해당 상태와 존재하는 결과 링크를 갱신한다. 모든 완료조건과 필수 검증이 충족된 경우에만 완료 상태를 사용한다.

문서화 요청만으로 구현을 수정하거나 무관한 테스트를 실행하지 않는다. 이번 작업에서 허용된 검증 범위의 결과를 사용하고 없으면 미검증으로 기록한다.

## 종료 보고

작성한 문서, 완료조건 상태, 계획 대비 차이, 남은 검증을 보고한다.
