# 문서 구조와 기록 검사

## 공통 작업 경계

- 적용되는 진입점과 docs/agent-rules.md를 따른다. 현재 컨텍스트에서 확인했고 변경되지 않았다면 재읽지 않는다. 새 세션·내용 소실·알려진 변경 시 다시 읽는다. 문서 구조·양식이 필요할 때만 docs/README.md를 확인한다. 공통 규칙이 없으면 기존 지침을 따르고 부재를 보고하며 권한이 불명확한 변경만 보류한다. 초기 구조화는 대신 수행하지 않는다. <part>와 mN은 자리표시자다.
- 대상 파트·마일스톤은 사용자 지시와 작업 맥락으로 정한다. 불명확하면 필요한 식별자만 묻고 가장 큰 번호를 임의로 선택하지 않는다.
- 목표 구조가 없으면 누락 경로를 보고한다. 이 스킬로 전체 문서를 이관하거나 마일스톤을 추정해 생성하지 않는다.
- 공통 구조는 배타적인 폴더 목록이 아니다. design/, mascot/, performance/ 등 파트 고유 문서·자산은 기존 위치를 유지하고 필요할 때만 참조한다. 명확히 대응되는 문서에만 공통 규약을 적용하고 추가 폴더를 구조 오류로 판단하지 않는다.
- 애플리케이션 코드, 전체 개발 계획, 사람의 trouble-shooting/ 기록은 수정하지 않는다. 다른 문서의 쓰기 범위는 아래에 명시한다.
- 기존 사용자 변경과 유효한 기록을 보존한다. 한국어와 상대 링크를 사용하며, 없는 문서의 링크를 만들지 않는다.
- 보호 문서의 작업 시작 상태를 확인할 수 있으면 내용 또는 해시를 확보한다. 종료 시 비교하며, 기준이 없으면 변경 주체를 검증할 수 없다고 보고한다. HEAD 차이를 작업 시작 기준으로 간주하지 않는다.

## 읽기 전용 검사

어떤 파일도 작성·수정·삭제·이동하지 않는다. 기본 범위는 현재 작업한 파트와 마일스톤이다. 저장소 전체 검사는 사용자가 전체 점검을 요청했을 때 수행한다.

## 검사 항목

1. **구조:** 전체 계획에서 명시적으로 정의된 마일스톤과 실제 폴더를 비교한다. plan.md 존재 여부를 확인한다. 빈 계획은 초기화에서는 정상이며 개발 완료 판정에는 근거 부족이다. 사용 시점에 따라 분류한다.
2. **선택적 기록:** result 및 개별 의사결정·요청·트러블슈팅 파일은 기록할 내용이 없으면 부재 자체를 오류로 보지 않는다. 사람의 트러블슈팅 작성 여부로 에이전트 작업 완료를 막지 않는다.
3. **링크:** 대상 Markdown의 실제 링크를 문서 위치 기준으로 해석한다. 인라인·참조 링크, 이미지, 공백·한글·URL 인코딩, 조각 식별자를 고려한다. 코드 예시와 자리표시자는 실제 파일 링크로 검사하지 않는다. 외부 URL은 기본 검사에서 제외한다. 앵커를 확정할 수 없으면 수동 확인 필요로 남긴다.
4. **계획과 결과:** 완료조건 누락, 근거 없는 충족 표시, README와 result의 상태 불일치, 계획 대비 변경 기록 누락을 확인한다. 코드가 있다는 사실과 테스트 성공을 구분한다.
5. **계약:** 관련 계약의 코드 근거와 합의 상태가 분리되어 있는지, 대표 문서가 중복되었는지 확인한다.
6. **보호 문서:** 작업 시작 시점의 내용·해시·신뢰 가능한 스냅샷과 비교한다. HEAD diff만 있으면 미커밋 변경의 작성 주체를 단정하지 않는다. 기준이 없으면 검증 불가로 표시한다. 파일 추가·삭제·이동도 고려한다.
7. **허용된 예외:** 최초 구조화의 빈 plan 생성과 내용 보존 이동, 명시적으로 요청된 milestone-plan 작업의 대상 파일만 예외로 구분한다. 승인 범위 밖 계획과 trouble-shooting 원문은 여전히 보호 대상이다.

초기 구조화 직후라는 맥락에서는 새 plan의 0바이트 여부도 확인한다. 이후 사람이 작성한 계획이 비어 있지 않다는 이유로 오류를 내지 않는다.

## 보고 양식

각 발견을 '항목 / 파일 위치 / 근거 / 영향 / 권장 조치'로 정리한다. 판정은 통과·문제 발견·확인 필요·검증 불가를 구분한다. 검사 범위와 제외 항목을 명시한다. 문제를 자동으로 고치거나 사용자 변경을 되돌리지 않는다.
