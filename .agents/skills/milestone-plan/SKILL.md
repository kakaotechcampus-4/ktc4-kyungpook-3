# 마일스톤 계획 작성

## 공통 작업 경계

- 적용되는 진입점과 docs/agent-rules.md를 따른다. 현재 컨텍스트에서 확인했고 변경되지 않았다면 재읽지 않는다. 새 세션·내용 소실·알려진 변경 시 다시 읽는다. 문서 구조·양식이 필요할 때만 docs/README.md를 확인한다. 공통 규칙이 없으면 기존 지침을 따르고 부재를 보고하며 권한이 불명확한 변경만 보류한다. 초기 구조화는 대신 수행하지 않는다. <part>와 mN은 자리표시자다.
- 대상 파트·마일스톤은 사용자 지시와 작업 맥락으로 정한다. 불명확하면 필요한 식별자만 묻고 가장 큰 번호를 임의로 선택하지 않는다.
- 목표 구조가 없으면 누락 경로를 보고한다. 이 스킬로 전체 문서를 이관하거나 마일스톤을 추정해 생성하지 않는다.
- 공통 구조는 배타적인 폴더 목록이 아니다. design/, mascot/, performance/ 등 파트 고유 문서·자산은 기존 위치를 유지하고 필요할 때만 참조한다. 명확히 대응되는 문서에만 공통 규약을 적용하고 추가 폴더를 구조 오류로 판단하지 않는다.
- 애플리케이션 코드, 전체 개발 계획, 사람의 trouble-shooting/ 기록은 수정하지 않는다. 다른 문서의 쓰기 범위는 아래에 명시한다.
- 기존 사용자 변경과 유효한 기록을 보존한다. 한국어와 상대 링크를 사용하며, 없는 문서의 링크를 만들지 않는다.
- 보호 문서의 작업 시작 상태를 확인할 수 있으면 내용 또는 해시를 확보한다. 종료 시 비교하며, 기준이 없으면 변경 주체를 검증할 수 없다고 보고한다. HEAD 차이를 작업 시작 기준으로 간주하지 않는다.

## 권한과 입력

사용자가 이 스킬을 호출해 계획 작성을 요청했거나 해당 마일스톤 계획 작성·수정을 명시적으로 지시한 경우에만 대상 plan.md에 쓴다. 초안·검토만 요청하면 응답으로 제시한다. 일반 구현 요청은 계획 변경 권한이 아니다. 전체 <part>-plan.md는 읽기 전용이다.

전체 계획의 해당 마일스톤, 기존 plan.md, 파트 README, 관련 계약·요청, 선행 마일스톤 결과 및 관련 코드를 확인한다. 전체 계획과 요청이 충돌하거나 목표·범위를 확정할 수 없으면 구체적인 미결 사항을 질문하고 사실처럼 채우지 않는다.

## 작성 절차

1. 목표와 현재 구현 간 차이, 선행 조건을 확인한다.
2. 기존 완료조건 식별자가 있으면 보존한다. 새 조건에만 AC-01 등의 고유 식별자를 부여한다.
3. [계획 양식](assets/plan-template.md)을 참고해 구체적인 작업 순서, 산출물, 관찰 가능한 완료조건과 검증 방법을 작성한다. 변경 API·데이터·호환성은 해당될 때만 기술한다.
4. 기존 계획 수정 시 요청 범위의 차이와 이유를 문서에 짧게 기록하고 무관한 내용을 보존한다.
5. 이미 구현된 작업을 사전 계획처럼 작성하지 않는다. 사용자 요청으로 소급 정리하면 사후 정리임을 표시한다. 구현과 계획의 차이만 보고 싶다는 요청이면 결과 문서에 기록할 내용을 제안한다.
6. 범위·작업·완료조건·검증이 서로 대응하는지, 관련 링크가 존재하는지 확인한다.

## 종료 보고

작성한 경로 또는 초안, 주요 완료조건, 남은 의사결정만 보고한다. 계획 작성이 구현이나 테스트 성공을 뜻하지 않으며 완료를 선언하지 않는다.
