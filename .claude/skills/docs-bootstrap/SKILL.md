# 문서 초기 구조화

## 사용 범위

사용자가 이 스킬을 호출하거나 문서 초기 구조화·재정리를 명시적으로 요청했을 때만 실행한다. 일반 개발, 결과 기록, 검사 요청으로 문서를 이동하지 않는다. 초안·검토만 요청하면 변경 없이 대응표를 제시한다.

애플리케이션 코드와 도구 설정·스킬 설치는 변경하지 않는다. 이 스킬 호출은 git commit, push, 게시를 허용하지 않는다.

## 시작

1. 적용되는 진입점과 기존 docs/agent-rules.md를 확인한다. 현재 컨텍스트에 있고 변경되지 않았다면 반복해서 읽지 않으며, 새 세션·내용 소실·알려진 변경 시 다시 읽는다. 공통 규칙이 처음에 없어도 정상이며 아래 절차로 생성한다. 관련 문서만 필요한 범위에서 확인한다.
2. [구조와 문서 규약](references/document-structure.md)을 읽는다. 실제 파트, 코드 경계, 기존 문서, 전체 계획과 사용자 변경을 조사한다.
3. 이동 전 보호 문서(전체 계획, 마일스톤 계획, 사람의 트러블슈팅)의 경로와 내용 또는 해시, 관련 자산·링크를 기록한다. Git 상태만으로 작업 시작 내용을 대체하지 않는다.
4. 기존 경로 → 목표 경로 대응표를 정한다. 같은 역할의 문서만 대응시킨다. 대상 파일 충돌 시 서로 다른 내용을 덮어쓰지 말고 해당 이동을 보류한다.

## 구조화

- 계약·계획·요청 문서는 `<part>/docs/` 아래의 `contracts/`, `plan/`, `requests/`에 배치한다. 파트 루트에 이 폴더를 만들지 않으며 요청 폴더는 복수형 `requests/`를 사용한다.
- design/, mascot/, performance/ 같은 파트 고유 문서·자산과 여러 마일스톤이 공유하는 자료는 기존 위치에 둔다. 역할이 불명확한 자료도 유지하고 README에서 안내한다.
- 명확히 대응되는 일반 문서만 이동·통합하고 유효한 내용을 보존한다. 보호 문서는 내용 변경 없이 이동만 허용한다. 보호 문서 내부 링크가 깨질 경우 이동을 보류하거나 미해결 링크로 보고하며 임의 수정하지 않는다.
- 현재 코드에서 파트 간 계약을 찾아 `<part>/docs/contracts/` 대표 문서에 정리한다. 같은 계약은 중복 생성하지 않는다. 실제 구현과 합의 상태를 구분하고 기존 합의와 코드의 차이를 보존한다.
- 기존 전체 계획을 내용 변경 없이 `<part>/docs/plan/<part>-plan.md`에 배치한다. 정의된 번호·순서에 맞는 모든 마일스톤 폴더를 `<part>/docs/plan/` 아래에 준비한다. 누락되거나 모호한 계획은 추정하지 않고 해당 생성을 보류한다.
- 각 마일스톤에서 plan.md가 없을 때만 0바이트 파일로 만든다. 기존 계획을 채우거나 수정하지 않는다. milestone-plan의 작성 예외는 이 초기화에 적용하지 않는다.
- `<part>/docs/contracts/`, `<part>/docs/requests/`와 마일스톤의 basis-for-decision/, trouble-shooting/ 폴더를 준비한다. 필요하면 저장소 관례에 맞춰 .gitkeep만 생성한다.
- result.md와 개별 요청·결정·트러블슈팅 기록은 미리 생성하지 않는다. 과거 결과·선택 이유를 추정해 소급 작성하지 않는다.
- docs/README.md, docs/파트별 전체 흐름.md, 파트 README와 `<part>/docs/README.md`를 실제 근거로 생성·보완한다. 기존 실행·설치 안내 등 유용한 내용은 유지한다.
- 독립적으로 확정할 수 있는 작업은 계속하고, 중대한 분류·경로 충돌만 구체적인 후보와 함께 확인한다.

## 공통 규칙과 진입점

[공통 규칙 양식](assets/agent-rules-template.md)을 바탕으로 docs/agent-rules.md를 생성·보완한다. 이 파일은 작업 의무·수정 권한·스킬 사용 시점의 원본이고, docs/README.md는 탐색·문서별 양식의 원본이다.

- 기존 프로젝트 고유 지침을 보존한다. 명확히 대응되는 문서 운영 규칙만 공통 파일로 통합하고 이관한 내용에 한해서 중복을 참조로 대체한다. 해결할 수 없는 충돌은 숨기거나 지우지 말고 보고한다.
- 기존 지침 파일의 대소문자와 적용 범위를 유지한다. 한 도구만 사용하면 해당 진입점만 갱신하고, 둘 다 사용하거나 양쪽 지원을 요청하면 둘 다 갱신한다.
- 파일이 없다면 사용자 지정 도구의 진입점을 생성한다. 지정이 없고 사용 도구도 확인되지 않으면 AGENTS.md를 기본으로 생성하고 이를 보고한다.
- 진입점에는 작업 시작 시 docs/agent-rules.md를 읽고 따르되 현재 컨텍스트에 있고 변경되지 않았다면 재읽지 않도록 적는다. 새 세션·내용 소실·알려진 변경 시 다시 읽고, 구조·양식이 필요할 때만 docs/README.md를 확인한다. 공통 규칙을 읽지 못하면 보고하고 그 규칙에 의존하는 변경만 보류한다.
- 상시 규칙은 보호 범위·작업 의무·스킬 선택 기준으로 간결하게 작성한다. 상세 절차와 양식은 스킬·참조 문서에 두고, 필요한 스킬만 읽도록 한다. 기존 프로젝트 고유 제약은 길이를 줄인다는 이유로 삭제하지 않는다.
- 도구별 스킬 경로는 실제 존재할 때만 안내한다. 사용자 PC의 설치 경로를 프로젝트 경로로 하드코딩하거나 이 작업으로 스킬 폴더를 복제·설치하지 않는다.
- 하위 지침에서 추가하거나 제한하는 규칙을 확인하고 새 참조가 적용 범위를 바꾸지 않도록 한다.

## 검증과 보고

- 전체 계획에 정의된 마일스톤과 폴더, 새 plan의 0바이트 여부를 확인한다.
- 보호 문서 내용은 시작 스냅샷과 대조하고 이동 전후 대응을 확인한다. 초기화 이전 사용자 변경은 되돌리지 않는다.
- 수정 가능한 문서의 링크를 갱신하고 첨부 자산이 유지되었는지 확인한다. 없는 선택적 기록에 링크를 만들지 않는다.
- 진입점 → 공통 규칙 → 상세 문서 연결과 지침 간 충돌을 검사한다.
- 앱 코드가 이번 작업에서 변경되지 않았는지 확인한다. 기준이 없다면 검증 불가를 명시한다.
- 반복 실행 시 기존 기록·규칙을 중복 추가하거나 갱신일만 바꾸지 않는다. 이미 충족된 항목은 그대로 둔다.
- docs-audit이 있으면 보조 검사에 사용할 수 있으나 설치를 전제로 하지 않는다.

최종 응답은 최종 구조, 유지한 추가 영역, 주요 생성·이동·갱신, 진입점 경로, 검증 결과, 보류 항목을 제시한다. 저장소를 구조화했다고 해서 마일스톤 구현 완료를 선언하지 않는다.
