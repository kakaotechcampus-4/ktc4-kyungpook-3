# 태스크·확인 필요 승인

PM이 회의에서 추출된 확인 필요 항목을 보완·승인하면 회의록과 태스크 목록에 같은 생성 태스크가 나타난다. 일반 팀원은 승인 화면에 접근하지 못한다.

## Sub-features

- `approve-from-minutes`는 회의록에서 승인 상세로 이동해 담당자·마감을 채우고 승인한다.
- `approval-side-effects`는 회의록과 태스크 목록에서 생성 태스크 링크와 남은 승인 수를 확인한다.
- `member-denied`는 직접 승인 URL의 권한 제한을 확인한다.
- `tasks-keyboard`는 목록 탭 전환과 보완 오류·승인을 키보드로 진행한다.

## How to get to it (user POV)

- `/workspaces/ws_01/meetings/mt_09`의 **추출된 일** 탭에서 **알림 문구 검토 채워 넣기**를 연다.
- 헤더 **태스크**의 **확인 필요** 목록에서 승인 상세를 연다.
- 직접 `/workspaces/ws_01/approvals/ap_01`에 진입한다.

## Driving it with Playwright

Preconditions:

- `tasks-default`는 PM, 태스크 10개, 대기 생성 승인 3개를 제공한다. `ap_01`은 담당자·마감이 비어 있다.
- `tasks-member`는 같은 공간의 일반 팀원이다.

- **실행.** `node .cursor/skills/verify-managers-manager/scripts/verify.cjs run tasks`는 UI 보완·승인, 팀원 권한, 키보드의 세 테스트를 선택한다.
- **보완과 승인.** 회의록의 `getByRole('tab', { name: /추출된 일/ })`에서 항목을 열고 **보완하기**를 누른다. **확정할 값 보완** 그룹의 **담당자**를 `박민수`, **마감**을 `2026-10-20`으로 입력한다. **보완 완료** 후 **승인**을 누르면 `approval-result`에 승인 결과와 생성 태스크 링크가 나타난다.
- **후속 상태.** 뒤로 돌아가 회의록의 **확인이 필요한 일 2**와 생성 태스크 링크를 확인한다. 헤더 **태스크**로 이동하면 전체 13, 확인 필요 2, 진행 중 8, 완료 3이며 같은 태스크 ID 링크가 목록에 있다.
- **목록 진입과 키보드.** 같은 실행의 `키보드 — 목록 탭` 테스트가 목록 탭을 화살표로 바꾸고 보완 폼 오류·승인을 확인한다. trace에서 목록을 통한 진입과 URL·포커스 단언을 읽는다.
- **권한.** `일반 팀원이 승인 URL` 테스트는 목록으로 돌아가 권한 안내를 보며 승인 조회가 0회인지 확인한다.

## Gotchas

- 보완 완료는 저장이 아니다. 승인 후 다른 화면의 변화까지 확인한다.
- MSW 승인 경로는 보완값을 지원한다. 실제 API의 보완 지원과 PM 조회 제한을 이 결과로 판단하지 않는다.
- 기존 전체 파일에는 내부 모의 Notion 상태를 직접 `synced`로 바꾸는 테스트가 있다. 기본 필터는 이를 제외한다. 실제 Notion 반영의 증거로 사용하지 않는다.
- 보드·캘린더·간트 및 수동 태스크 생성은 초기 지도의 범위 밖이다. 별도 요청이면 지도를 확장한다.
